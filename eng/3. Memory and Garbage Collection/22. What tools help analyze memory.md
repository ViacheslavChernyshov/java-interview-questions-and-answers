# What tools help analyze memory?

---

## 🟢 Junior Level

Diagnosing memory consumption, garbage collection overhead, and memory leaks in Java requires a specialized suite of **JDK command-line utilities**, **graphical dump analyzers**, and **continuous production profilers**.

### Modern Java Memory Toolset Summary

| Tool | Category | Primary Use Case | Overhead / Production Safe? |
|---|---|---|---|
| **Eclipse MAT** | Desktop GUI Analyzer | Deep offline analysis of `.hprof` Heap Dumps | **0%** (Offline post-mortem) |
| **`jcmd`** | JDK CLI Utility | Fast diagnostics, live histograms, triggering dumps | **Minimal** (Standard CLI tool) |
| **JFR / JMC** | Continuous Profiler | Low-overhead production telemetry & leak sampling | **< 1% CPU** (100% Production-Safe) |
| **VisualVM** | Desktop Monitor | Real-time heap, thread, and CPU inspection | **Medium** (Dev / Staging) |
| **JProfiler / YourKit** | Commercial Profiler | Live object allocation tracing and memory graphing | **High** (Development only) |

## 🟡 Middle Level

### 1. `jcmd`: The Modern JDK CLI Standard

> [!NOTE]
> Legacy utilities like `jmap`, `jstack`, and `jinfo` are superseded by **`jcmd`**, which uses the unified JVM Attach API and supports rich diagnostic sub-commands:

```bash
# 1. Quick In-Memory Class Histogram (Count & Bytes per Class):
jcmd <PID> GC.class_histogram

# 2. Trigger an immediate HPROF Heap Dump:
jcmd <PID> GC.heap_dump /tmp/heapdump.hprof

# 3. Inspect Metaspace and ClassLoader allocations:
jcmd <PID> VM.metaspace

# 4. Inspect Native OS Off-Heap Memory:
jcmd <PID> VM.native_memory summary
```

### 2. Eclipse Memory Analyzer Tool (MAT)

Eclipse MAT is the industry standard for analyzing multi-gigabyte HPROF files:
- **Dominator Tree:** Ranks objects by total **Retained Heap** to reveal memory hoarders.
- **Path to GC Roots (Excluding Weak/Soft):** Uncovers the exact chain of active strong references preventing deallocation.
- **Leak Suspects Report:** Automated statistical heuristic report highlighting suspected memory leaks.
- **Duplicate Strings Detector:** Identifies RAM wasted by redundant String values.

## 🔴 Senior Level

### 3. Native Memory Tracking (NMT)

When an application crashes with an OS OOM-Killer or native memory leak while the Java Heap is mostly empty, enable NMT:

```bash
# JVM Startup Flag:
-XX:NativeMemoryTracking=detail

# Capture a Baseline in Production:
jcmd <PID> VM.native_memory baseline

# Compare Growth after Load (Delta Diff):
jcmd <PID> VM.native_memory detail.diff
```
**NMT Output Categories:** `Java Heap`, `Class` (Metaspace), `Thread` (Stacks), `Code` (JIT Cache), `GC` (Card Tables, R-Sets), `Symbol` (Interned Strings), `Arena Chunk`.

### 4. Interactive Live Troubleshooting: Alibaba Arthas

For complex production environments where deploying heavy GUI agents is impossible, **Arthas** allows hot-attaching to a running JVM via SSH:

```bash
# Launch interactive Arthas shell:
java -jar arthas-boot.jar

[arthas]$ dashboard      # Live real-time memory and CPU dashboard
[arthas]$ memory         # Detailed breakdown of Heap, Metaspace, and CodeCache
[arthas]$ vmtool         # Force-execute operations directly on in-memory objects
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Eclipse MAT:** Premier tool for HPROF dump analysis (Dominator Tree, Retained Heap, GC Root paths, OQL).
- **`jcmd`:** Official modern replacement for `jmap`/`jstack`; triggers dumps, class histograms, and NMT.
- **JFR & JMC:** Java Flight Recorder provides continuous production profiling with $<1\%$ CPU overhead; `OldObjectSample` tracks leaks without STW pauses.
- **NMT (`-XX:NativeMemoryTracking=detail`):** Diagnoses off-heap native memory consumption (Metaspace, Stacks, Direct Buffers, CodeCache).
- **Heap Dump Warning:** Generating a heap dump causes a Stop-The-World pause that scales with heap size and disk I/O speed.

**Common Follow-up Questions:**
- *"Why should you use `jcmd GC.class_histogram` before taking a full heap dump?"* → A class histogram executes in milliseconds with minimal STW impact, providing a fast high-level count of live instances before committing to a heavy, multi-gigabyte disk dump.
- *"What is the main limitation of Heap Dumps when diagnosing native off-heap leaks?"* → Heap dumps contain only on-heap Java objects; off-heap memory (C-heap allocations, Netty buffers, thread stacks) is completely invisible in an HPROF dump and requires Native Memory Tracking (NMT).
- *"How does JFR achieve <1% overhead in production?"* → It records events into JVM ring buffers in native memory without string formatting or thread locks, flushing asynchronously to disk.

**Red Flags (DO NOT Say):**
- ❌ *"I use `jmap -dump:live` in production because it's the newest tool."* (`jmap` is legacy; `jcmd` is the standard tool for all modern JDKs).
- ❌ *"A Heap Dump captures all memory used by the operating system process."* (It only captures JVM Heap memory; Metaspace and native buffers are excluded).
- ❌ *"Running JProfiler with object allocation recording enabled in production is completely fine."* (Commercial live profilers add heavy 20–50% overhead and should only be used in dev/staging).
