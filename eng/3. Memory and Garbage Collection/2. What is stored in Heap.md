# What is stored in Heap?

---

## 🟢 Junior Level

The **JVM Heap** is the primary runtime data area created when the JVM starts up, shared globally across all threads, where all **class instances and arrays are allocated**.

**What is stored in Heap:**
1. **All Object Instances:** Anything instantiated with `new` (e.g. `new User()`, `new ArrayList<>()`).
2. **All Arrays:** Including primitive arrays (`int[]`, `byte[]` are full heap objects).
3. **The String Constant Pool:** Interned string literals (`"hello"`).
4. **Static Variables:** Stored on the heap as part of their respective `java.lang.Class` instance.

```java
public class StorageExample {
    // Static field: Stored in the Class mirror object on the Heap
    private static final String APP_NAME = "OrderEngine";

    public void process() {
        int orderCount = 5;                  // Primitive local -> Stack
        String code = "ORD-99";              // Reference -> Stack, String literal -> Heap String Pool
        User user = new User("Alice", 30);   // Reference -> Stack, User instance -> Heap
        byte[] payload = new byte[1024];     // Reference -> Stack, Array payload -> Heap
    }
}
```

## 🟡 Middle Level

### Java Object Memory Layout (JOL Deep-Dive)

Every object residing in the JVM Heap is structured into three distinct memory segments:

```
  64-Bit HotSpot JVM Object Layout (with Compressed OOPs enabled):
  ┌────────────────────────────────────────────────────────┐
  │ 1. OBJECT HEADER (12 to 16 Bytes)                      │
  │    ├── Mark Word (8 Bytes)                             │
  │    │     • Identity Hash Code (31 bits)                │
  │    │     • GC Tenuring Age (4 bits: max value 15)      │
  │    │     • Lock State Tags (2 bits: Biased/Thin/Fat)   │
  │    └── Klass Pointer (4 Bytes via Compressed OOPs)     │
  │          • Pointer to Class Metadata in Metaspace      │
  │    └── [Array Length] (4 Bytes - ONLY present in Arrays│
  ├────────────────────────────────────────────────────────┤
  │ 2. INSTANCE DATA (Variable Size)                       │
  │    Primitive fields & Reference pointers               │
  ├────────────────────────────────────────────────────────┤
  │ 3. PADDING (0 to 7 Bytes)                              │
  │    Pads total object footprint to a multiple of 8 bytes│
  └────────────────────────────────────────────────────────┘
```

#### Footprint Calculations:
- **`new Object()`:** 8B (Mark Word) + 4B (Klass Pointer) + 4B (Padding) = **16 bytes**.
- **`new Integer(42)`:** 8B (Mark Word) + 4B (Klass) + 4B (`int` value) = **16 bytes**.
- **`new Long(42L)`:** 8B (Mark Word) + 4B (Klass) + 8B (`long` value) + 4B (Padding) = **24 bytes**.

## 🔴 Senior Level

### Hardware-Level Memory Alignment & Word Access

Modern 64-bit CPUs fetch memory in **64-bit (8-byte) words** or 64-byte cache lines. If an object is not aligned to an 8-byte boundary, reading a primitive field might span across two CPU memory bus cycles:

```
  Unaligned Memory Access (2 CPU Bus Reads):
  Word 0: [  |  |  |Data_Part1]   Word 1: [Data_Part2|  |  |  ]

  Aligned Memory Access (1 CPU Bus Read):
  Word 0: [Data_Part1 + Data_Part2 |  |  |  ]
```
The JVM enforces strict **8-byte padding** to guarantee single-cycle CPU memory loads.

### Internal Heap Sub-Allocations: TLAB & PLAB

```
  Heap Eden Space Allocations:
  ┌────────────────────────────────────────────────────────┐
  │ Thread 1: [ TLAB #1 (64 KB) ] ──> Lock-free allocation │
  │ Thread 2: [ TLAB #2 (64 KB) ] ──> Bump-the-pointer     │
  │ Shared Eden: Large Objects > TLAB ──> Global CAS lock  │
  └────────────────────────────────────────────────────────┘
```

- **TLAB (Thread Local Allocation Buffer):** Eliminates contention by giving each worker thread its own private slice of Eden.
- **PLAB (Promotion Local Allocation Buffer):** Used during GC survival copying. Worker GC threads claim PLAB buffers in Survivor/Tenured space to copy surviving objects concurrently without lock contention.

### String Pool Evolution (PermGen $\to$ Heap)

Prior to Java 7, `String.intern()` and the string literal pool resided in **PermGen** (Permanent Generation), which had a fixed size and frequently failed with `OutOfMemoryError: PermGen space`. 
Since Java 7, the String Constant Pool was moved directly into the **main JVM Heap**, allowing it to be reclaimed during standard Young/Mixed GC cycles.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Heap Contents:** All objects created with `new`, all arrays (`int[]`, `Object[]`), String Constant Pool, and static class fields.
- **Object Layout:** Header (**Mark Word** 8B + **Klass Pointer** 4B/8B) + **Instance Fields** + **8-byte Alignment Padding**.
- **Minimum Object Size:** A bare `new Object()` occupies **16 bytes** on a 64-bit JVM with Compressed OOPs.
- **Mark Word Contents:** Identity hashcode, 4-bit GC tenuring age (max 15), synchronization/lock state tags, bias lock bits.
- **PLAB vs TLAB:** TLAB is for mutator thread allocations in Eden; PLAB is for GC worker thread promotions into Old Gen.

**Common Follow-up Questions:**
- *"Why does an array require 16 to 24 bytes of header memory?"* → Because in addition to the 8-byte Mark Word and 4-byte Klass Pointer, arrays include a 4-byte `length` field in their header.
- *"Where are static variables stored in modern Java?"* → On the Heap, attached to the `java.lang.Class` mirror instance representing the loaded class.
- *"Why can an object's GC age never exceed 15?"* → The Mark Word allocates exactly 4 bits for the age counter ($2^4 - 1 = 15$).

**Red Flags (DO NOT Say):**
- ❌ *"Primitive arrays like `byte[]` are stored on the Stack."* (All arrays in Java are true objects and always reside on the Heap).
- ❌ *"The String Pool is located in Metaspace."* (Moved from PermGen to the Heap in Java 7).
- ❌ *"An empty `new Object()` takes 0 bytes in memory."* (It takes 16 bytes due to the object header and 8-byte alignment padding).
