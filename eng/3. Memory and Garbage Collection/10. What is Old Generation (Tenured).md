# What is Old Generation (Tenured)?

---

## 🟢 Junior Level

The **Old Generation (Tenured Space)** is the area of the JVM Heap reserved for **long-lived objects** that have survived multiple Minor GC collection cycles in the Young Generation.

**Why it exists:** Since objects in the Old Generation have proven their longevity, the JVM collects them **infrequently** using space-efficient Mark-Sweep-Compact algorithms, avoiding the overhead of constantly copying persistent data.

```
  Ingress Paths into Old Generation:
  1. Tenuring Age: Survived Minor GCs until reaching MaxTenuringThreshold (1..15)
  2. Survivor Overflow: Survivor spaces exhausted -> Pushed to Tenured space
  3. Humongous Allocation: Large objects (>50% G1 region) allocated directly in Old Gen
```

- **Sizing:** Typically accounts for **$\sim 66\%$ (2/3)** of total Heap memory (`-XX:NewRatio=2`).
- **Collection Cycle:** Cleaned via **Major GC** or **Mixed GC** (and defragmented via **Full GC**).

---

## 🟡 Middle Level

### Collection Algorithms: Mark-Sweep vs. Mark-Compact

| Strategy | Operational Mechanism | Advantage | Critical Drawback |
|---|---|---|---|
| **Mark-Sweep** | Marks live objects; marks dead slots as free in **Free Lists** | Fast; concurrent execution | Causes severe **memory fragmentation** |
| **Mark-Compact** | Marks live objects and **slides them contiguously** to heap start | Eliminates fragmentation; restores bump-the-pointer | Requires longer **Stop-The-World (STW)** pauses |

### G1 Mixed GC vs. Full GC

In modern G1 GC, the JVM **avoids monolithic Full GCs**:
1. **Initiating Heap Occupancy Percent (IHOP):** When Old Gen occupancy crosses `-XX:InitiatingHeapOccupancyPercent=45` (default 45%), G1 launches background Concurrent Marking.
2. **Mixed GC:** Once marking finishes, G1 executes a sequence of Mixed GCs, collecting all Young regions alongside a selected subset of the **most fragmented Old Gen regions** (Collection Set), strictly respecting `-XX:MaxGCPauseMillis=200`.

### The Promotion Failure Catastrophe

```
  1. Minor GC attempts to promote surviving object to Old Gen
                                  │
                                  ▼
  2. Old Gen is fragmented / full -> No contiguous space found!
                                  │
                                  ▼
  3. PROMOTION FAILURE! ──> JVM triggers an emergency Full GC (Multi-second STW freeze!)
```

## 🔴 Senior Level

### Free Lists vs. Bump-the-Pointer in Tenured Space

In generational collectors that do not compact on every cycle (like CMS or unconsolidated G1 regions), Old Gen memory cannot use simple pointer bumping:
- The JVM manages **Free Lists** (linked lists of available memory blocks grouped by byte size).
- When promoting an object, the JVM must perform a search algorithm (**Best-Fit / First-Fit**) to locate a memory chunk large enough to house the object, introducing CPU overhead.

### Floating Garbage in Concurrent Marking

During concurrent Old Gen marking (SATB in G1 / Colored Pointers in ZGC), application threads continue running and allocating:
- If an object that was marked alive at the beginning of the marking phase becomes unreferenced *during* the marking run, the collector cannot safely collect it in the current cycle.
- This memory is termed **Floating Garbage**; it is harmlessly reclaimed during the *next* GC iteration.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Contents:** Long-lived domain singletons, caching buffers, Spring application context beans, and Humongous objects.
- **Three Ingress Paths:** Age tenuring threshold reached, Survivor space overflow (Premature Promotion), or Humongous object allocation.
- **G1 Mixed GC:** Collects all Young regions + the highest-yield Old Gen regions incrementally to avoid Full GC pauses.
- **IHOP (`-XX:InitiatingHeapOccupancyPercent`):** Threshold (default 45%) triggering concurrent marking before Old Gen fills up.
- **Promotion Failure:** Occurs when Old Gen cannot accommodate promoted objects, triggering an emergency Stop-The-World Full GC.
- **Floating Garbage:** Objects dying mid-cycle that are naturally reclaimed in the subsequent collection pass.

**Common Follow-up Questions:**
- *"What is the difference between a Major GC and a Full GC?"* → Major GC collects only the Old Generation; Full GC collects the entire JVM Heap (Young Gen + Old Gen + Metaspace metadata cleanup).
- *"How do you resolve frequent Promotion Failures?"* → Increase overall heap (`-Xmx`), enlarge Survivor spaces (`-XX:SurvivorRatio`), or lower IHOP (`-XX:InitiatingHeapOccupancyPercent=35`) so concurrent marking starts earlier.
- *"Why does ZGC rarely suffer from Promotion Failure?"* → ZGC performs concurrent relocation/compaction on every cycle, continuously eliminating memory fragmentation without STW pauses.

**Red Flags (DO NOT Say):**
- ❌ *"Old Generation is cleaned using the exact same Copying algorithm as Young Generation."* (Copying requires a duplicate empty space; Old Gen uses Mark-Sweep-Compact or region evacuation).
- ❌ *"Full GC is an expected and harmless event in low-latency microservices."* (Full GC causes multi-second Stop-The-World application freezes).
- ❌ *"Floating garbage indicates a fatal memory leak."* (It is an expected byproduct of concurrent non-blocking collectors).
