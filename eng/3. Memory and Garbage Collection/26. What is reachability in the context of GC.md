# What is reachability in the context of GC?

---

## 🟢 Junior Level

**Reachability** defines the lifecycle status of an object in the JVM Heap, determining whether it can be accessed by active application threads or whether it is eligible for reclamation by the Garbage Collector.

The JVM defines **5 distinct Reachability levels**:
1. **Strongly Reachable:** Standard references (`User u = new User()`). Never collected while reachable.
2. **Softly Reachable:** Accessible only via `SoftReference`. Retained until the JVM approaches an OutOfMemory state.
3. **Weakly Reachable:** Accessible only via `WeakReference`. Cleared on the **very next GC cycle**.
4. **Phantom Reachable:** Finalized, but referenced via `PhantomReference` to monitor post-mortem cleanup.
5. **Unreachable:** Completely disconnected from all GC Roots; memory is reclaimed by the collector.

---

## 🟡 Middle Level

### Reference Strength & Reclamation Matrix

| Reachability Level | How It Is Created | When GC Clears It | Typical Use Case |
|---|---|---|---|
| **Strong** | Standard assignment: `Obj o = new Obj()` | **Never**, while rooted | Core application business domain |
| **Soft** | `new SoftReference<>(obj)` | Only on **low heap memory** | Memory-sensitive caches |
| **Weak** | `new WeakReference<>(obj)` | On the **next GC cycle** | `WeakHashMap`, canonical mappings |
| **Phantom** | `new PhantomReference<>(obj, queue)` | Memory reclaimed; ref enqueued | Safe native cleanup (`Cleaner`) |

```java
// 1. Soft Reference (Memory-sensitive cache)
SoftReference<byte[]> imageCache = new SoftReference<>(new byte[10 * 1024 * 1024]);
byte[] data = imageCache.get(); // Returns null if JVM cleared it to prevent OOM!

// 2. Weak Reference (WeakHashMap canonicalization)
Map<ClassLoader, AppMetadata> registry = new WeakHashMap<>();

// 3. Phantom Reference (Post-mortem tracking)
ReferenceQueue<HeavyNativeResource> queue = new ReferenceQueue<>();
PhantomReference<HeavyNativeResource> phantom = new PhantomReference<>(resource, queue);
// phantom.get() ALWAYS returns null!
```

## 🔴 Senior Level

### The SoftReference Eviction Formula

HotSpot JVM calculates the survival lifespan of a `SoftReference` using the following formula:

$$\text{Evict if: } (\text{Current Time} - \text{Last Access Time}) > \text{Free Heap (MB)} \times \text{-XX:SoftRefLRUPolicyMSPerMB}$$

- **Default Value:** `-XX:SoftRefLRUPolicyMSPerMB=1000` (1 second per MB of free heap).
- On a 32GB heap with 16GB free, a soft reference could technically survive for $16{,}000\text{ seconds}$ (~4.4 hours) after its last access. Under high-throughput allocation pressure, tune this down (e.g. `-XX:SoftRefLRUPolicyMSPerMB=100`) to evict cached buffers more aggressively.

### The `Reference Handler` Daemon Thread & `ReferenceQueue`

```
  1. Garbage Collector marks object as Soft/Weak/Phantom Reachable
                           │
                           ▼
  2. HotSpot adds Reference to native JVM [ Pending List ]
                           │
                           ▼
  3. High-Priority JVM Daemon Thread: [ Reference Handler ]
                           │
                           ▼
  4. Enqueues Reference into Java-level [ ReferenceQueue ]
                           │
                           ▼
  5. Application polls ReferenceQueue to perform native memory deallocations
```

### Modern Resource Deallocation: `java.lang.ref.Cleaner` (Java 9+)

`java.lang.ref.Cleaner` replaces `finalize()`, eliminating object resurrection and finalizer thread locks:

```java
public class NativeDataBuffer implements AutoCloseable {
    private static final Cleaner CLEANER = Cleaner.create();
    private final Cleaner.Cleanable cleanable;
    private final long nativeAddress;

    public NativeDataBuffer(int sizeBytes) {
        this.nativeAddress = allocateNativeMemory(sizeBytes);
        // Cleanable action MUST NOT capture 'this' pointer in its closure!
        long addressToFree = this.nativeAddress;
        this.cleanable = CLEANER.register(this, () -> freeNativeMemory(addressToFree));
    }

    @Override
    public void close() {
        cleanable.clean(); // Manual deterministic cleanup
    }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **5 Reachability Tiers:** Strongly $\to$ Softly $\to$ Weakly $\to$ Phantom $\to$ Unreachable.
- **SoftReference:** Retained until low memory; eviction depends on `-XX:SoftRefLRUPolicyMSPerMB`.
- **WeakReference:** Cleared on the very next GC run; powers `WeakHashMap`.
- **PhantomReference:** `.get()` always returns `null`; used strictly with `ReferenceQueue` to monitor memory liberation.
- **`Reference Handler` Thread:** High-priority JVM daemon moving pending references into `ReferenceQueue`.
- **Modern Cleaners:** `java.lang.ref.Cleaner` provides leak-safe post-mortem cleanup, fully replacing deprecated `finalize()`.

**Common Follow-up Questions:**
- *"Why does `PhantomReference.get()` always return null?"* → To prevent callers from reviving an object that has already been finalized and prepared for deallocation.
- *"How does `Cleaner` prevent the Object Resurrection bug of `finalize()`?"* → The `Cleaner` runnable executes on a background daemon and cannot capture a reference to the target instance (`this`).
- *"Why should you not rely solely on SoftReference for enterprise caching?"* → SoftReferences can cause erratic GC thrashing and unpredictable pause spikes under memory pressure; dedicated caching libraries like **Caffeine** with explicit size and weight bounds are preferred.

**Red Flags (DO NOT Say):**
- ❌ *"SoftReference and WeakReference are identical."* (Soft references survive until heap exhaustion; weak references are collected on the next GC run).
- ❌ *"PhantomReference allows you to resurrect an object before it is deleted."* (Phantom references explicitly prevent access by always returning `null` on `get()`).
- ❌ *"Setting a variable to null guarantees that its reachability immediately drops to Unreachable."* (Other strong references might still exist from other methods or static collections).
