# What types of OutOfMemoryError exist?

---

## 🟢 Junior Level

An **`OutOfMemoryError`** in Java is not a single generic error; the JVM provides specific error messages detailing **exactly which memory subsystem ran out of space**.

### The 5 Most Common OOME Types

| Error Message | Meaning | Primary Culprit |
|---|---|---|
| **`Java heap space`** | JVM Heap is full | Memory leak or undersized `-Xmx` |
| **`GC overhead limit exceeded`** | GC runs continuously with zero progress | Heap thrashing ($>98\%$ CPU spent on GC) |
| **`Metaspace`** | Class metadata memory exhausted | Dynamic proxies / `ClassLoader` leaks |
| **`Direct buffer memory`** | Off-heap NIO memory exhausted | Unpooled Netty / `DirectByteBuffer` leaks |
| **`Unable to create new native thread`** | OS cannot allocate another thread | Thread leak or OS `ulimit -u` hit |

---

## 🟡 Middle Level

### Deep-Dive: Root Causes & Remediation

#### 1. `Java heap space`
- **Cause:** Active live objects referenced by GC Roots exceed the maximum allowable heap size (`-Xmx`).
- **Remediation:** Generate an automatic heap dump (`-XX:+HeapDumpOnOutOfMemoryError`) and inspect the **Dominator Tree** in Eclipse MAT.

#### 2. `GC overhead limit exceeded`
- **Cause:** The default HotSpot heuristic triggered when the application spends **$>98\%$ of CPU time executing GC while reclaiming $<2\%$ of the heap**.
- **Remediation:** Do not disable this flag (`-XX:-UseGCOverheadLimit`); fix the underlying memory leak causing the heap to remain pinned.

#### 3. `Metaspace` & `Compressed class space`
- **Cause:** Excessive runtime bytecode generation (Spring AOP, Hibernate, CGLIB, Groovy) combined with ClassLoader leaks.
- **Remediation:** Inspect metadata via `jcmd <PID> VM.metaspace` and set `-XX:MaxMetaspaceSize=512m`.

#### 4. `Direct buffer memory`
- **Cause:** Off-heap buffers allocated via `ByteBuffer.allocateDirect()` or Netty unpooled allocators exceed `-XX:MaxDirectMemorySize` (which defaults to `-Xmx`).
- **Remediation:** Track native allocations with Native Memory Tracking (`-XX:NativeMemoryTracking=detail`).

#### 5. `Unable to create new native thread`
- **Cause:** Each platform thread claims a native OS stack (`-Xss1m`). This error occurs when physical RAM is exhausted or the OS kernel thread limit is reached.
- **Remediation:** Check Linux thread ceilings via `ulimit -u`, reduce thread pool sizes, or migrate blocking I/O to Java 21 **Virtual Threads**.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`Java heap space`:** Live reachable heap objects exceed `-Xmx`.
- **`GC overhead limit exceeded`:** Heuristic trigger preventing infinite GC spinning (>98% CPU spent on GC, <2% memory freed).
- **`Metaspace`:** Class metadata storage exhausted in native memory.
- **`Direct buffer memory`:** Native off-heap allocations (`ByteBuffer.allocateDirect()`) exceed `-XX:MaxDirectMemorySize`.
- **`Unable to create new native thread`:** Native OS stack space exhausted or OS `ulimit -u` process limit reached.
- **`Requested array size exceeds VM limit`:** Allocation of an array larger than $2^{31}-2$ elements.
- **Linux OOM-Killer:** Not a Java exception; kernel sends `SIGKILL 9` (Exit code 137) when process RSS violates container cgroup memory limits.

**Common Follow-up Questions:**
- *"Why does `Direct buffer memory` OOM occur when JVM Heap is 90% empty?"* → DirectByteBuffers allocate off-heap native memory; `-Xmx` only caps on-heap objects, while native memory is capped separately by `-XX:MaxDirectMemorySize`.
- *"How do Virtual Threads (Java 21) prevent `Unable to create new native thread`?"* → Platform threads require ~1MB of dedicated OS stack memory; Virtual Threads are cheap Java continuation objects on the heap (~2KB initial size) multiplexed over a tiny pool of carrier threads.
- *"What is the difference between `Metaspace` and `Compressed class space` OOME?"* → Metaspace holds method bytecodes and constant pools; Compressed Class Space (default 1GB) specifically holds 32-bit `InstanceKlass` C++ pointers.

**Red Flags (DO NOT Say):**
- ❌ *"All OutOfMemoryErrors are caused by the JVM Heap filling up."* (Metaspace, Direct Buffer, and Native Thread errors occur in native OS RAM outside the Heap).
- ❌ *"Disabling `-XX:-UseGCOverheadLimit` resolves memory issues."* (It only disables the heuristic warning, leading to a catastrophic CPU freeze followed by `Java heap space` OOM).
- ❌ *"The JVM handles Linux OOM-Killer crashes by catching the exception."* (The Linux Kernel issues an uncatchable `SIGKILL`, immediately terminating the container without running JVM code).
