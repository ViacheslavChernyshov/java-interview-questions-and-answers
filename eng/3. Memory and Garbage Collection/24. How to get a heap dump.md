# How to get a heap dump?

---

## 🟢 Junior Level

A **Heap Dump** can be captured either **automatically on failure** or **on-demand** using standard JDK command-line tools.

### The 3 Core Methods to Capture a Heap Dump

```bash
# 1. Automatic Capture on OutOfMemoryError (Mandatory in Production)
java -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath=/var/log/dumps/ -jar app.jar

# 2. Manual On-Demand Capture via jcmd (Official Standard)
jcmd <PID> GC.heap_dump /tmp/heapdump.hprof

# 3. Graphical Interface (Development & Staging)
# Open VisualVM -> Right-click target Java process -> Select "Heap Dump"
```

**How to find the Java Process ID (PID):**
```bash
jps -v
# Output: 48201 PaymentServiceApplication
```

---

## 🟡 Middle Level

### The `jcmd` CLI Standard (Recommended)

```bash
# Capture full uncompressed heap dump:
jcmd <PID> GC.heap_dump /tmp/heap.hprof

# Capture with Gzip compression enabled on the fly (Java 11+):
jcmd <PID> GC.heap_dump -gz=1 /tmp/heap.hprof.gz

# Capture live objects only (Note: Forces a Stop-The-World Full GC first!):
jcmd <PID> GC.heap_dump -all=false /tmp/heap_live.hprof
```

### Capturing Dumps Inside Kubernetes Pods

In containerized environments without graphical tools, execute the dump via `kubectl`:

```bash
# 1. Execute dump inside the container (Java is usually PID 1):
kubectl exec -it payment-service-78d4-x9z2q -- jcmd 1 GC.heap_dump -gz=1 /tmp/dump.hprof.gz

# 2. Copy the compressed dump to your local machine:
kubectl cp payment-service-78d4-x9z2q:/tmp/dump.hprof.gz ./dump.hprof.gz

# 3. Clean up container storage immediately:
kubectl exec -it payment-service-78d4-x9z2q -- rm /tmp/dump.hprof.gz
```

## 🔴 Senior Level

### Programmatic Capture via JMX (`HotSpotDiagnosticMXBean`)

You can expose an administrative management endpoint (e.g. Spring Boot Actuator or custom JMX bean) to capture a dump programmatically:

```java
import com.sun.management.HotSpotDiagnosticMXBean;
import java.lang.management.ManagementFactory;

public class DiagnosticsService {
    public static void dumpHeap(String outputFilePath, boolean liveOnly) throws Exception {
        HotSpotDiagnosticMXBean mxBean = ManagementFactory.newPlatformMXBeanProxy(
            ManagementFactory.getPlatformMBeanServer(),
            "com.sun.management:type=HotSpotDiagnostic",
            HotSpotDiagnosticMXBean.class
        );
        // Generates .hprof file directly to disk
        mxBean.dumpHeap(outputFilePath, liveOnly);
    }
}
```
> [!NOTE]
> `com.sun.management.HotSpotDiagnosticMXBean` is a HotSpot-specific internal API and is not portable to non-HotSpot runtimes (e.g., OpenJ9 or GraalVM Native Images).

### Live Production Best Practices

1. **Traffic Drain First:** Before triggering an on-demand heap dump on a production pod, remove the pod from service via Kubernetes labels or service mesh routing to prevent incoming user requests from encountering the dump's Stop-The-World pause.
2. **Persistent Volume Mounting:** Always ensure `-XX:HeapDumpPath` writes to a mounted Persistent Volume or shared cloud storage so dumps survive container pod crashes and restarts.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Primary CLI Command:** `jcmd <PID> GC.heap_dump /path/to/dump.hprof`.
- **Auto-Capture Flag:** `-XX:+HeapDumpOnOutOfMemoryError` and `-XX:HeapDumpPath=/dumps/`.
- **Streaming Compression:** Use `-gz=1` with `jcmd` or `-XX:+HeapDumpGzip` to shrink dumps by 70%+.
- **Live vs All:** `-all=false` writes only live objects but forces an immediate Stop-The-World Full GC.
- **Kubernetes PID 1:** Inside containerized Docker images, the Java process typically runs as `PID 1` (`jcmd 1 GC.heap_dump ...`).
- **Programmatic API:** `HotSpotDiagnosticMXBean.dumpHeap(path, live)`.

**Common Follow-up Questions:**
- *"Why should you avoid using `jmap -dump:live,format=b,file=...`?"* → `jmap` is legacy tooling; `jcmd` is the unified, actively maintained JDK standard.
- *"What happens if a pod crashes after throwing OOME before you can copy the dump out?"* → If `-XX:HeapDumpPath` points to the ephemeral container disk, the dump is permanently lost upon pod restart. Always mount an external Persistent Volume.
- *"How do you isolate a production pod before triggering a manual dump?"* → Remove the pod's routing labels (e.g., `kubectl label pod <pod_name> app-`) so the Service stops routing live customer traffic to it during the STW pause.

**Red Flags (DO NOT Say):**
- ❌ *"I use `jmap` because `jcmd` cannot create heap dumps."* (`jcmd` is the primary and recommended tool for heap dumps).
- ❌ *"Taking a live dump (`-all=false`) is faster than dumping all memory."* (Live dump forces a synchronous Stop-The-World Full GC before writing).
- ❌ *"Heap dumps should be stored directly on the container's root filesystem."* (Can fill ephemeral storage and trigger kubelet pod eviction).
