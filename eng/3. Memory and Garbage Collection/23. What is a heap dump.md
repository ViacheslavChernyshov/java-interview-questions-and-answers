# What is a heap dump?

---

## 🟢 Junior Level

A **Heap Dump** is a complete, binary snapshot of the **JVM Heap memory** at a specific point in time, typically stored in the standardized **HPROF (`.hprof`)** file format.

**Simple Analogy:** A frozen photograph of a physical warehouse. It allows forensic engineers to inspect every single box (object), its contents (fields), and its relationship to other boxes (references) offline.

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │                 What a Heap Dump CONTAINS              │              What a Heap Dump DOES NOT CONTAIN         │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ • Every live on-heap object and array                  │ • Method execution stack traces (Thread Dump)          │
  │ • All instance fields and primitive values             │ • Off-heap native memory (DirectByteBuffers, C-heap)   │
  │ • Static class variables and loaded `Class` objects    │ • JIT compiled machine code in CodeCache               │
  │ • The complete object reference graph (GC Root paths)  │ • Metaspace native internals                           │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

---

## 🟡 Middle Level

### The Operational Danger: Stop-The-World Freezes

Capturing a heap dump requires the JVM to freeze all application mutator threads in a **Stop-The-World (STW)** pause to ensure memory consistency while serializing gigabytes of heap memory to disk.

```
  Writing 32 GB Heap to Storage:
  ┌────────────────────────────────────────────────────────┐
  │ Standard NVMe SSD:  ████ (5 – 15 second STW Pause)     │
  │ Standard HDD / EBS: ████████████████████ (30 – 60s STW)│
  └────────────────────────────────────────────────────────┘
```

> [!WARNING]
> In Kubernetes, a 30-second STW pause will cause the **Liveness Probe to timeout**, causing the orchestrator to forcefully terminate and restart the pod mid-dump!

### Live Objects vs. All Objects

When generating a heap dump via `jcmd`:
- **`-all=true` (Default):** Dumps all memory as-is (both live objects and uncollected dead objects). *Fastest capture, but produces a larger file.*
- **`-all=false` (Live Only):** Forces the JVM to **execute a Full GC first** to sweep dead objects before dumping. *Smaller file, but adds extra STW GC latency!*

## 🔴 Senior Level

### Modern Production Optimizations: On-the-Fly Gzip Compression

Writing uncompressed multi-gigabyte files saturates disk I/O and network transfer pipes. Java 11+ supports streaming Gzip compression:

```bash
# Compress the heap dump on the fly during generation:
java -XX:+HeapDumpOnOutOfMemoryError \
     -XX:+HeapDumpGzip \
     -XX:HeapDumpPath=/var/log/dumps/dump.hprof.gz \
     -jar app.jar
```
- **Benefit:** Shrinks a 32GB heap dump down to **~6GB–8GB**, drastically reducing disk write times and storage requirements.

### Security, Compliance & PII Exposure

> [!CAUTION]
> Heap dumps contain raw plaintext data stored in Java memory, including **unmasked passwords, database credentials, API secret keys, and customer PII (credit card numbers, SSNs)**.
> - Never upload unredacted production heap dumps to unencrypted public storage.
> - Use tools like **`RedactHprof`** or Eclipse MAT anonymization scripts to sanitize strings before distributing dumps to development teams.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Binary snapshot (HPROF format) of all on-heap Java objects, primitives, static fields, and reference graphs at a single moment.
- **Exclusions:** Does not contain thread stack traces (Thread Dumps) or off-heap native memory (NMT).
- **STW Impact:** Serializing heap to disk freezes all application threads for seconds to minutes.
- **Live vs All:** `-all=false` runs a Full GC before dumping to purge garbage; `-all=true` writes the full heap immediately.
- **Gzip Compression:** `-XX:+HeapDumpGzip` compresses dumps on the fly (Java 11+), cutting file size by 70%+.
- **Security Warning:** Heap dumps contain sensitive in-memory PII and credentials; never transmit them unencrypted.

**Common Follow-up Questions:**
- *"What is the difference between a Heap Dump and a Thread Dump?"* → A Heap Dump records all objects and memory references on the Heap; a Thread Dump records the current execution stack traces and lock states of all running threads.
- *"Why should you never write heap dumps to the ephemeral container root filesystem in Kubernetes?"* → Dumps can fill the container root overlay filesystem, triggering eviction by the kubelet. Always mount a dedicated external Persistent Volume (`-XX:HeapDumpPath=/dumps/`).
- *"How do you analyze a 100GB+ heap dump if your laptop only has 16GB of RAM?"* → Use **Eclipse MAT in headless batch mode** (`ParseHeapDump.sh`) on a high-memory cloud server to generate summary HTML reports and dominator tree tables.

**Red Flags (DO NOT Say):**
- ❌ *"A Heap Dump contains all thread stack traces."* (Thread stack traces are captured via Thread Dumps, not Heap Dumps).
- ❌ *"Taking a heap dump in production has zero impact on application latency."* (Writing gigabytes of heap memory to disk causes an extended Stop-The-World pause).
- ❌ *"Live dump `-all=false` is always faster than `-all=true`."* (Live dump forces an extra Stop-The-World Full GC before writing).
