# What Does the substring() Method Do and How Did It Work Before Java 7?

---

## 🟢 Junior Level

The **`substring()`** method returns a newly constructed `String` containing a slice of characters from the original string, starting at `beginIndex` (inclusive) and ending at `endIndex` (exclusive):

```java
String text = "Hello, World!";
String sub1 = text.substring(0, 5); // "Hello"
String sub2 = text.substring(7);    // "World!"
```

```
  Historical Architecture Evolution:
  • Before Java 7u6: `substring()` shared the original parent string's backing character array.
    ⚡ Fast (O(1)), but caused severe MEMORY LEAKS!
  • Java 7u6 onwards: `substring()` performs a defensive copy of only the requested characters.
    🛡️ Safe & predictable (O(N)), allowing the parent string to be garbage collected.
```

---

## 🟡 Middle Level

### Before Java 7u6: The Shared Array Memory Leak

Prior to Java 7 Update 6, `java.lang.String` contained three internal fields:
- `char[] value` (The shared character array)
- `int offset` (Starting index in the array)
- `int count` (Length of the string)

```
  Java 6 Memory Leak Scenario:
  1. String largeDocument = read100MbFile(); // Allocates 100MB char[] array
  2. String title = largeDocument.substring(0, 10); // Points to the same 100MB char[] with count=10!
  3. largeDocument = null; // Developer expects 100MB to be garbage collected...
  💥 BUT `title` holds a strong reference to the entire 100MB char[] array! 
     100MB remains pinned in RAM indefinitely!
```

```java
// Java 6 Workaround (Forced defensive copy):
String title = new String(largeDocument.substring(0, 10)); // Force-copied array
```

## 🔴 Senior Level

### Source Code Evolution Across Java Generations

#### 1. Java 6 (Shared Array Architecture — $O(1)$)

```java
// JDK 6 private constructor:
String(int offset, int count, char[] value) {
    this.value = value;   // Shared reference!
    this.offset = offset;
    this.count = count;
}

public String substring(int beginIndex, int endIndex) {
    return new String(offset + beginIndex, endIndex - beginIndex, value);
}
```

#### 2. Java 7u6 through Java 8 (Defensive Copy Architecture — $O(N)$)

`offset` and `count` were completely removed from `String`:

```java
// JDK 7u6+:
public String substring(int beginIndex, int endIndex) {
    int subLen = endIndex - beginIndex;
    return new String(value, beginIndex, subLen); // Calls Arrays.copyOfRange()
}
```

#### 3. Java 9+ (Compact Strings Architecture — $O(N)$ with `byte[]`)

```java
// JDK 9+ Compact Strings:
public String substring(int beginIndex, int endIndex) {
    int subLen = endIndex - beginIndex;
    return isLatin1()
        ? StringLatin1.newString(value, beginIndex, subLen)
        : StringUTF16.newString(value, beginIndex, subLen);
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Function:** Returns a string slice from `beginIndex` to `endIndex - 1`.
- **Pre-Java 7u6:** Reused the parent's `char[]` array using `offset` and `count` fields ($O(1)$ time).
- **The Memory Leak:** A tiny substring pinned massive parent arrays in memory, causing unexpected `OutOfMemoryError`.
- **Java 7u6+ Fix:** Removed `offset`/`count` and introduced defensive array copying ($O(N)$ time).
- **Java 9+ Compact Strings:** Copies `byte[]` arrays with encoding awareness (`LATIN1` vs `UTF16`).
- **Modern Redundancy:** Calling `new String(str.substring(...))` in modern Java is an anti-pattern.

**Common Follow-up Questions:**
- *"Why is `new String(str.substring(...))` considered bad practice in modern Java?"* → In Java 7+, `substring()` already performs a defensive copy; wrapping it in `new String(...)` allocates a redundant second copy on the heap.
- *"What is the time complexity of `substring()` in Java 17/21?"* → $O(N)$ where $N$ is the length of the extracted substring.
- *"What happens if `beginIndex < 0` or `endIndex > length()`?"* → Throws `StringIndexOutOfBoundsException`.

**Red Flags (DO NOT Say):**
- ❌ *"`substring()` in modern Java operates in $O(1)$ constant time."* (It operates in $O(N)$ linear time due to array copying).
- ❌ *"You should always wrap `substring()` in `new String()` to prevent memory leaks in Java 17."* (This was only needed in Java 6; in modern Java it creates useless garbage).
- ❌ *"`substring()` modifies the original string in place."* (Strings are immutable; it always returns a new `String` object).
