# Difference Between replace() vs replaceAll()

---

## 🟢 Junior Level

Both **`replace()`** and **`replaceAll()`** replace **ALL** occurrences of matching text within a string. The critical difference is **how** they search:

```
  ┌──────────────────┬──────────────────────────┬──────────────────────────────────────────────────┐
  │ Method           │ Search Mechanism         │ Scope of Replacement                             │
  ├──────────────────┼──────────────────────────┼──────────────────────────────────────────────────┤
  │ **`replace()`**  │ **Literal Substring**    │ **Replaces ALL occurrences** (Exact text match)  │
  │ **`replaceAll()`**│ **Regular Expression**  │ **Replaces ALL occurrences** (Regex pattern match)│
  └──────────────────┴──────────────────────────┴──────────────────────────────────────────────────┘
```

```java
String text = "a.b.c";

// 1. replace() treats "." literally:
System.out.println(text.replace(".", "/"));    // "a/b/c"

// 2. replaceAll() treats "." as a regex matching ANY character:
System.out.println(text.replaceAll(".", "/")); // "/////" (Replaced every character!)
```

> [!WARNING]
> **The Naming Trap:** Despite its singular name, `replace()` replaces **ALL** occurrences, not just the first. To replace only the first match, use `replaceFirst(regex, replacement)`.

## 🟡 Middle Level

### The Replacement String Traps in `replaceAll()`

In `replaceAll(regex, replacement)`, the `replacement` string itself has special regex semantics:
- **`$` represents capturing groups** (e.g. `$1`, `$2`).
- **`\` acts as an escape character**.

```java
// 💥 HAZARDOUS CRASH:
String price = "Cost: 100";
// Throws IllegalArgumentException: No group 1 found!
price.replaceAll("100", "$100");

// ✅ SAFE FIX (Quotes replacement literals):
price.replaceAll("100", Matcher.quoteReplacement("$100")); // "Cost: $100"
```

### Complete Method Comparison Matrix

```
  ┌─────────────────────────────────┬──────────────────┬──────────────────────────┬────────────────────────┐
  │ Method Signature                │ Input Type       │ Internal Mechanism       │ Relative Performance   │
  ├─────────────────────────────────┼──────────────────┼──────────────────────────┼────────────────────────┤
  │ `replace(char, char)`           │ Single Character │ Direct byte array scan   │ ⚡ **Fastest (~10 ns)**│
  │ `replace(CharSeq, CharSeq)`     │ Literal String   │ `Pattern.LITERAL` scan   │ 🚀 **Fast (~50 ns)**   │
  │ `replaceAll(regex, repl)`       │ Regex Pattern    │ Full Regex Engine        │ 🐢 **Slower (~300 ns)**│
  │ `replaceFirst(regex, repl)`     │ Regex Pattern    │ Stops after first match  │ 🐢 **Slower (~250 ns)**│
  └─────────────────────────────────┴──────────────────┴──────────────────────────┴────────────────────────┘
```

## 🔴 Senior Level

### OpenJDK Source Code Disassembly

```java
// java.lang.String.replace() implementation:
public String replace(CharSequence target, CharSequence replacement) {
    String tgtStr = target.toString();
    String replStr = replacement.toString();
    
    // Fast-path: Single character replacement delegates to direct byte scan:
    if (tgtStr.length() == 1 && replStr.length() == 1) {
        return replace(tgtStr.charAt(0), replStr.charAt(0));
    }
    
    // Uses Pattern.LITERAL to disable regex metacharacter parsing:
    return Pattern.compile(tgtStr, Pattern.LITERAL)
                  .matcher(this)
                  .replaceAll(Matcher.quoteReplacement(replStr));
}
```

```java
// java.lang.String.replaceAll() implementation:
public String replaceAll(String regex, String replacement) {
    // Uses dynamic regex compilation and matcher execution:
    return Pattern.compile(regex).matcher(this).replaceAll(replacement);
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`replace()`:** Replaces all occurrences of a literal `CharSequence` or `char`.
- **`replaceAll()`:** Replaces all occurrences matching a `regex` pattern.
- **Both Replace All:** Neither method stops at the first occurrence (use `replaceFirst()` for single replacements).
- **Dot Danger:** `"a.b".replaceAll(".", "/")` replaces every single character because `.` matches anything in regex.
- **Dollar Danger:** Unescaped `$` in `replaceAll` replacement arguments is interpreted as a regex capturing group.
- **Security:** Never pass raw user input into `replaceAll()` without `Pattern.quote()` (prevents Regex Injection Denial of Service / ReDoS).

**Common Follow-up Questions:**
- *"How can you replace only the first occurrence of a literal string without using regex?"* → Use `int idx = str.indexOf(target);` and reconstruct the string using `str.substring(0, idx) + replacement + str.substring(idx + target.length())`.
- *"Why is `replace('a', 'b')` much faster than `replace("a", "b")`?"* → `replace(char, char)` performs a direct linear scan over the backing `byte[]` array without creating `Pattern` or `Matcher` wrapper objects.
- *"What does `Matcher.quoteReplacement(str)` do?"* → It escapes all `\` and `$` characters in the replacement string so they are treated as literal characters.

**Red Flags (DO NOT Say):**
- ❌ *"`replace()` only replaces the first occurrence of the target string."* (It replaces all occurrences).
- ❌ *"`replaceAll()` is faster than `replace()` because it uses regular expressions."* (Regex parsing is significantly slower than literal substring matching).
- ❌ *"`replaceAll()` is completely safe to use with arbitrary user input."* (It is vulnerable to syntax errors and ReDoS attacks unless quoted with `Pattern.quote()`).
