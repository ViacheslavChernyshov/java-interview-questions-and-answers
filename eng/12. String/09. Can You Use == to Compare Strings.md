# Can You Use == to Compare Strings?

---

## 🟢 Junior Level

Technically **yes**, but in 99.9% of application logic, doing so is a **critical bug**:

```
  ┌───────────────┬──────────────────────────────────────────┬────────────────────────────────────────────────┐
  │ Operator      │ What It Compares                         │ Recommended Use Case                           │
  ├───────────────┼──────────────────────────────────────────┼────────────────────────────────────────────────┤
  │ **`==`**      │ **Memory References (Pointers)**         │ Checking for `null` (`str == null`)            │
  │ **`equals()`**│ **Character Content Sequence**           │ **All business logic string equality checks**  │
  └───────────────┴──────────────────────────────────────────┴────────────────────────────────────────────────┘
```

```java
String s1 = "Hello";
String s2 = new String("Hello");

System.out.println(s1 == s2);      // false (Different objects in memory!)
System.out.println(s1.equals(s2)); // true  (Identical character contents)
```

## 🟡 Middle Level

### Reference Identity Matrix: When Does `==` Return `true`?

```java
// 1. String Literals (Shared in String Pool):
"Java" == "Java";                                  // true

// 2. Constant Folding (Compile-Time merged):
"Java" + 21 == "Java21";                           // true

// 3. Dynamic Concatenation (Evaluated at Runtime):
String ver = "21";
"Java" + ver == "Java21";                          // false!

// 4. Strings from I/O (Database, Network, Files):
resultSet.getString("status") == "ACTIVE";        // false! (Always allocated in regular heap)

// 5. Explicit Interning:
s1.intern() == s2.intern();                        // true
```

### Best Practice Pattern: Yoda Conditions & `Objects.equals`

```java
// ❌ Dangerous (Throws NullPointerException if status is null):
if (status.equals("ACTIVE")) { ... }

// ✅ Null-Safe Literal Comparison:
if ("ACTIVE".equals(status)) { ... }

// ✅ Clean Standard Comparison:
if (Objects.equals(status, expectedStatus)) { ... }
```

### The G1 GC String Deduplication Trap

```java
// Under JVM flag: -XX:+UseStringDeduplication
String s1 = new String("Deduplicated");
String s2 = new String("Deduplicated");

// G1 GC detects identical char bytes and points s1.value and s2.value to the SAME byte[] array.
// BUT s1 and s2 are still TWO SEPARATE java.lang.String object wrappers!

System.out.println(s1 == s2);      // STILL FALSE! (Deduplication does not alter object identity)
System.out.println(s1.equals(s2)); // true
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Core Rule:** `==` compares object reference memory addresses; `.equals()` compares character sequences.
- **Literal Pooling:** `==` returns `true` for identical literals because they share the same String Pool instance.
- **I/O Reality:** Strings loaded from databases, REST APIs, or file systems are distinct heap objects where `==` evaluates to `false`.
- **Fast-Path:** `.equals()` begins with `if (this == anObject) return true;` so checking identical references is already $O(1)$.
- **G1 Deduplication Trap:** G1 String Deduplication unifies backing `byte[]` arrays, but leaves `String` object instances separate; `==` remains `false`.
- **Null Safety:** Use `"CONSTANT".equals(var)` or `Objects.equals(a, b)` to prevent `NullPointerException`.

**Common Follow-up Questions:**
- *"Is `==` ever acceptable for string comparison in high-performance computing?"* → Only in ultra-low-latency systems where all strings are strictly interned upfront or represented as enums/symbols; otherwise, one uninterned instance causes silent logical failure.
- *"Why does `"A" + "B" == "AB"` return true while `a + "B" == "AB"` returns false?"* → `"A" + "B"` is folded by the compiler into `"AB"` at compile time, whereas `a + "B"` is dynamically evaluated at runtime via `invokedynamic`, producing an unpooled Heap instance.
- *"How fast is `String.equals()` on modern hardware?"* → HotSpot utilizes SIMD vector registers (AVX-512 / NEON) to compare 16 to 64 bytes per CPU cycle, making `equals()` nearly as fast as `==`.

**Red Flags (DO NOT Say):**
- ❌ *"`==` compares string content if both strings are short."* (`==` always compares memory addresses).
- ❌ *"G1 String Deduplication merges strings so that `==` returns true."* (Deduplication only shares the backing `byte[]`, not the `String` object).
- ❌ *"`equals()` is always slow because it iterates character by character."* (It has an instant identity fast-path and uses hardware SIMD vectorization).
