# What is String Deduplication in G1 GC?

---

## 🟢 Junior Level

**String Deduplication (JEP 192)** is an automated memory optimization in the **G1 Garbage Collector** (and Shenandoah GC) that identifies identical strings in the Heap and merges their internal byte arrays in the background:

```
  Before Deduplication (2 separate objects, 2 separate arrays):
  String A ──► byte[] {'H','e','l','l','o'} (5 bytes)
  String B ──► byte[] {'H','e','l','l','o'} (5 bytes)

  After G1 String Deduplication (2 separate objects, 1 SHARED array):
  String A ──┐
             ├──► byte[] {'H','e','l','l','o'} (5 bytes) ──► Reclaims 5 bytes on GC!
  String B ──┘
```

```bash
# Enable G1 String Deduplication on startup:
java -XX:+UseG1GC -XX:+UseStringDeduplication -jar app.jar
```

```
  Key Invariant:
  • String objects remain separate; only the backing `byte[]` array is shared.
  • `s1.equals(s2)` is `true`, but `s1 == s2` STILL EVALUATES TO `false`!
```

## 🟡 Middle Level

### `String.intern()` vs. G1 GC String Deduplication

```
  ┌──────────────────────────────┬──────────────────────────────────┬──────────────────────────────────────────────────┐
  │ Characteristic               │ `String.intern()`                │ G1 String Deduplication (`-XX:+UseStringDedup`) │
  ├──────────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **What is Merged**           │ Whole `java.lang.String` objects │ Backing `byte[]` arrays only                     │
  │ **Execution Timing**         │ **Synchronous** (During call)    │ **Asynchronous** (Background GC thread)          │
  │ **Code Modifications**       │ Explicit Java code changes       │ **Zero code changes** (JVM startup flag only)    │
  │ **Reference Equality (`==`)**│ Evaluates to **`true`**          │ Evaluates to **`false`** (Objects are distinct)  │
  │ **Garbage Collector**        │ Works with all GC algorithms     │ Limited to **G1 GC** and **Shenandoah GC**       │
  │ **CPU Overhead**             │ JNI native call + table lock     │ Low-priority background thread (~2–5% CPU)       │
  └──────────────────────────────┴──────────────────────────────────┴──────────────────────────────────────────────────┘
```

## 🔴 Senior Level

### The Internal Deduplication Pipeline

```
  1. GC Evacuation Phase (Candidate Identification):
     • G1 identifies String objects surviving Young GC cycles.
     • Strings with age >= StringDeduplicationAgeThreshold (Default: 3) are enqueued.

  2. Concurrent Background Deduplication Thread:
     • Dequeues String references asynchronously without blocking application threads.
     • Computes 32-bit hash of the `byte[]` array.
     • Looks up the hash in the native off-heap Deduplication Table.

  3. Verification & Atomic Pointer Swap:
     • If a hash match is found, performs a SIMD byte-by-byte comparison to eliminate collisions.
     • Executes an atomic CAS (Compare-And-Swap) operation to redirect `String.value` to the shared `byte[]`.
     • The orphan `byte[]` is collected in the subsequent Minor GC pass!
```

### Production Monitoring & Diagnostic Commands

```bash
# Inspect runtime deduplication statistics:
jcmd <pid> GC.string_deduplication_statistics
```

```
  String Deduplication Statistics:
    Executed: 412 times
    Deduplicated: 841,200 strings (1.4 GB memory saved)
    Skipped: 120,400 strings (already deduplicated)
    Table Size: 24.5 MB native memory
```

> [!TIP]
> If the background thread causes CPU spikes ($>5\%$), increase the age threshold via `-XX:StringDeduplicationAgeThreshold=5` to ignore transient short-lived strings.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Function:** Transparently merges identical backing `byte[]` arrays during G1/Shenandoah GC passes.
- **Reference Identity Trap:** Does NOT merge the `String` object instances; `==` remains `false`.
- **Zero Code Changes:** Enabled purely via `-XX:+UseG1GC -XX:+UseStringDeduplication`.
- **Age Threshold:** Defaults to 3 GC cycles (`-XX:StringDeduplicationAgeThreshold=3`) to ignore short-lived strings.
- **Typical Savings:** Reclaims 10–25% of Heap in string-heavy microservices (JSON API gateways, logs).
- **GC Limitation:** Supported on G1 and Shenandoah; not supported on ZGC.

**Common Follow-up Questions:**
- *"Why doesn't G1 String Deduplication make `==` return true?"* → It mutates the internal private `byte[] value` pointer, leaving the separate `java.lang.String` object wrappers and their identities untouched.
- *"Why does String Deduplication require an age threshold?"* → Most strings die in Eden (Young Generation); attempting to deduplicate short-lived strings wastes CPU on objects that will be collected in milliseconds anyway.
- *"What happens if two strings have identical characters but different `coder` values?"* → Deduplication fails because one array is Latin-1 (1 byte/char) and the other is UTF-16 (2 bytes/char); their byte arrays are physically different.

**Red Flags (DO NOT Say):**
- ❌ *"Enabling String Deduplication makes `s1 == s2` return true for identical strings."* (`==` still compares object memory addresses and returns `false`).
- ❌ *"String Deduplication is an instant replacement for `String.intern()` in all scenarios."* (`intern()` is still superior for small, static dictionary sets like enum codes).
- ❌ *"String Deduplication works with the ZGC collector."* (ZGC does not support this flag).
