## 🔗 Key Topic Connections

### Topic: String Pool

```
Q01 (String Pool) ──► Q02 (Literal vs new) ──► Q03 (intern())
      │
      ▼
Q11 (Where stored) ──► Q12 (OOM from String Pool)
```

- **Q01 ↔ Q11:** String Pool resides in Java Heap (since Java 7u6).
- **Q03 ↔ Q12:** Unbounded `intern()` calls $\to$ native `StringTable` bucket collision $\to$ performance collapse and OOM.
- **Q02 ↔ Q03:** `new String("...").intern()` creates an unnecessary heap garbage object before resolving against the pool.

### Topic: Immutability & Modification

```
Q04 (Immutability) ──► Q05 (StringBuilder vs StringBuffer) ──► Q06 (Why StringBuffer is slower)
```

- **Q04 ↔ Q05:** String immutability allocates new objects on every modification; `StringBuilder` avoids allocation via mutable internal arrays.
- **Q05 ↔ Q06:** `StringBuffer` methods synchronize on `this`, causing monitor contention overhead.

### Topic: Concatenation

```
Q07 (+ Operator) ──► Q08 (Compiler Optimization)
```

- **Q07 ↔ Q08:** Java 8 used `StringBuilder`; Java 9+ compiles `+` to `invokedynamic` calling `StringConcatFactory` (JEP 280).

### Topic: Memory & Low-Level Internals

```
Q19 (Compact Strings) ──► Q20 (String Size) ──► Q21 (Reflection) ──► Q22 (Deduplication)
```

- **Q19 ↔ Q20:** `coder` byte flag selects `LATIN1` (1 byte/char) vs `UTF16` (2 bytes/char).
- **Q20 ↔ Q22:** G1 String Deduplication re-points identical backing `byte[]` arrays to a single shared array during GC.
- **Q21 ↔ Q04:** Java Module System (JEP 261 / JEP 396) strictly encapsulates internal fields, preventing `setAccessible(true)` on `String.value`.

## 🎓 Cheat Sheet: What to Know for Each Level

### 🟢 Junior
- `String` is immutable — its character contents cannot change after creation.
- Literals reference the String Pool; `new String(...)` allocates a distinct heap object.
- Use `StringBuilder` for non-thread-safe modifications in loops; `StringBuffer` is synchronized.
- `==` checks reference identity; `.equals()` checks character content equality.
- Use `+` for simple 1-2 item concatenation; use `StringBuilder` inside loops.

### 🟡 Middle
- String Pool is located in the Java Heap (since Java 7u6); `intern()` ensures unique string instances.
- Compact Strings (Java 9+): Uses `byte[]` with a `coder` flag (`LATIN1` = 1 byte/char, `UTF16` = 2 bytes/char).
- `split()` uses Fast Path for single-character regex delimiters, avoiding pattern compilation.
- `replace()` does literal string replacement; `replaceAll()` compiles a regex pattern.
- Always pass explicit `StandardCharsets.UTF_8` when converting strings to `byte[]`.

### 🔴 Senior
- HotSpot `StringTable`: Native C++ hash table, resizable since JDK 11 (JEP 341).
- `substring()` memory leak fix: Java 6 shared the backing `char[]`; Java 7+ creates a defensive copy.
- `invokedynamic` concatenation (JEP 280): `StringConcatFactory.makeConcatWithConstants` optimizes bytecode at runtime.
- `@Stable` annotation, `coder` field, and SIMD vector instructions for hardware-accelerated `equals()` and hashing.
- Reflection attacks on `String.value` blocked by Strong Encapsulation (Java 16+ JEP 396).
- G1 GC String Deduplication (`-XX:+UseStringDeduplication`): Reclaims duplicate `byte[]` without altering object headers.
