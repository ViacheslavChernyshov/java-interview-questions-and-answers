# Can You Modify String Contents via Reflection?

---

## 🟢 Junior Level

Historically in Java 8 and earlier, **technically yes**, but doing so is a **dangerous anti-pattern** that violates JVM language guarantees:

```java
// 🚫 DANGEROUS HISTORICAL ANTI-PATTERN (Breaks JVM invariants):
String s = "Hello";
Field field = String.class.getDeclaredField("value");
field.setAccessible(true); // Modifies private access

byte[] value = (byte[]) field.get(s); // In Java 9+; char[] in Java 8
value[0] = (byte) 'J';

System.out.println(s); // Prints "Jello"!
```

```
  💥 Catastrophic Side Effects:
  1. String Pool Contamination: Mutating `"Hello"` changes the literal for ALL code in the entire JVM!
  2. Map Key Corruption: `HashMap.get()` fails because the cached `hash` field no longer matches the mutated text.
  3. Blocked in Modern Java: Java 16+ strictly forbids this by throwing `InaccessibleObjectException`.
```

---

## 🟡 Middle Level

### The Java Module System Defense (Java 16+ JEP 396 / JEP 403)

In modern Java (Java 16, 17, 21+), **Strong Encapsulation of JDK Internals** is enabled by default:

```java
// Running this on Java 17+ fails immediately:
Field field = String.class.getDeclaredField("value");
field.setAccessible(true); 
// 💥 Throws: java.lang.reflect.InaccessibleObjectException: 
// Unable to make field private final byte[] java.lang.String.value accessible: 
// module java.base does not "opens java.lang" to unnamed module
```

> [!IMPORTANT]
> Reflective access to `java.lang.String.value` is strictly prohibited unless explicitly bypassed with the JVM command-line flag: `--add-opens java.base/java.lang=ALL-UNNAMED`.

### The HashMap Corruption Breakdown

```java
String key = "admin";
Map<String, String> permissions = new HashMap<>();
permissions.put(key, "ALL_ACCESS"); // Computed hash for "admin", placed in bucket X

// Mutate internal bytes via reflection:
byte[] value = (byte[]) valueField.get(key);
value[0] = 'b'; // Changes text to "bdmin", but `hash` field remains hash("admin")!

// Lookups fail completely:
permissions.get("admin"); // Returns null (Value "bdmin" != "admin")
permissions.get("bdmin"); // Returns null (Hash("bdmin") searches bucket Y, but entry is in bucket X!)
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Technically Possible:** Modifying `value` was possible in Java 8 via `Field.setAccessible(true)`.
- **Java 16+ Strong Encapsulation:** Throws `InaccessibleObjectException` unless `--add-opens java.base/java.lang=ALL-UNNAMED` is supplied.
- **Global Pool Hazard:** Mutating a pooled literal modifies every identical literal in the JVM.
- **`@Stable` Invalidation:** Array mutation violates HotSpot C2 `@Stable` assumptions, breaking constant folding.
- **HashMap Destruction:** Desynchronizes the cached `int hash` from character contents, permanently losing map entries.
- **Concurrency Danger:** Lacks memory barriers, causing undefined behavior and data races.

**Common Follow-up Questions:**
- *"Why does `Field.setAccessible(true)` fail on Java 17 by default?"* → JEP 403 strongly encapsulates all internal elements of JDK modules, disallowing reflective access into `java.base/java.lang` packages from external modules.
- *"What happens to HotSpot JIT-compiled code when a String's value is mutated?"* → If C2 has constant-folded the string into native assembly, the running code will continue using the old value; if a dependency invalidation is triggered, the JVM must deoptimize the compiled method back to bytecode interpretation.
- *"If you must clear sensitive data like passwords from memory, what should you use instead of String?"* → Store passwords in a mutable `char[]` or `byte[]` array, and overwrite it with zeros (`Arrays.fill(pwd, '0')`) immediately after use.

**Red Flags (DO NOT Say):**
- ❌ *"Modifying String via reflection is a standard way to implement string pooling in production."* (It is a catastrophic anti-pattern).
- ❌ *"`setAccessible(true)` works without restriction in Java 17 and 21."* (Strong encapsulation blocks it by default).
- ❌ *"Strings are thread-safe even if their backing array is mutated via reflection."* (Immutability is destroyed, creating multithreaded data races).
