# How Does the String Pool Work?

---

## 🟢 Junior Level

The **String Pool** (also known as the String Intern Pool) is a dedicated cache inside the Java Virtual Machine (JVM) that stores **exactly one canonical copy** of each unique string literal:

```java
String s1 = "Java"; // Stored in the String Pool
String s2 = "Java"; // Reuses the existing "Java" instance from the pool

System.out.println(s1 == s2); // true (Both references point to the same memory address!)
```

```
  Why the String Pool exists:
  • In typical enterprise Java applications, String objects account for 25% - 40% of total heap memory.
  • Reusing identical string literals prevents millions of duplicate character allocations.
```

## 🟡 Middle Level

### How Strings Enter the Pool: Literals vs. `intern()`

```
  ┌───┬──────────────────────────────────────────┬────────────────────────────────────────────────────────────┐
  │ # │ Ingress Path                             │ Behavior                                                   │
  ├───┼──────────────────────────────────────────┼────────────────────────────────────────────────────────────┤
  │ 1 │ **String Literal (`"text"`)**            │ Automatically resolved and pooled at class loading time.   │
  │ 2 │ **`new String("text")`**                 │ Allocates a **new distinct object on the Heap** (Unpooled).│
  │ 3 │ **`new String("text").intern()`**        │ Queries the pool; returns pooled canonical reference.      │
  └───┴──────────────────────────────────────────┴────────────────────────────────────────────────────────────┘
```

```java
String s1 = "Hello";                  // Pooled
String s2 = new String("Hello");      // Regular Heap object (different reference)
String s3 = s2.intern();             // Returns the pooled reference pointing to s1

System.out.println(s1 == s2);        // false (Different memory addresses)
System.out.println(s1 == s3);        // true  (Both point to the canonical pooled instance)
```

## 🔴 Senior Level

### HotSpot JVM Internals: The `StringTable`

In HotSpot JVM, the String Pool is implemented as a native C++ hash table called **`StringTable`**:

```cpp
// HotSpot OpenJDK internal representation (src/hotspot/share/classfile/stringTable.hpp)
class StringTable : public RehashableHashtable<oop, mtSymbol> {
    // oop = ordinary object pointer referencing the java.lang.String in Java Heap
};
```

### Memory Area Evolution Across Java Versions

```
  ┌──────────────────────────┬──────────────────────────────────┬──────────────────────────────────────────────────┐
  │ Java Version             │ String Pool Memory Location      │ GC Behavior & Constraints                        │
  ├──────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **Java 6 and earlier**   │ **PermGen (Permanent Gen)**      │ Fixed size; frequent `OOM: PermGen space` errors.│
  │ **Java 7+**              │ **Java Heap** (Tenured / Old Gen)│ Collected by normal Garbage Collection cycles.   │
  │ **Java 8+ (Metaspace)**  │ **Java Heap** (NOT Metaspace!)   │ Constrained only by `-Xmx` heap limit.           │
  └──────────────────────────┴──────────────────────────────────┴──────────────────────────────────────────────────┘
```

> [!IMPORTANT]
> **Major Interview Trap:** With the introduction of **Metaspace** in Java 8, class metadata moved to off-heap native memory, but the **String Pool remained inside the Java Heap**.

### Tuning and Performance

- **Table Sizing:** Controlled via `-XX:StringTableSize=N` (Default is $60,013$ buckets in Java 8+; previously $1,009$).
- **Dynamic Resizing:** Starting in Java 11 (JEP 341), the `StringTable` supports concurrent lock-free dynamic resizing when load factors rise.
- **Diagnostic Command:** Inspect string table density using:
  ```bash
  jcmd <pid> VM.stringtable -verbose
  ```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** A JVM cache storing unique string instances to conserve memory.
- **Location:** Resides in the **Java Heap** (since Java 7u6, NOT in Metaspace).
- **Literals:** Added automatically to the pool via JVM `ldc` bytecode resolution.
- **`intern()`:** Explicitly registers/retrieves the canonical string reference from `StringTable`.
- **GC Behavior:** Strings in the pool are standard heap objects and are garbage collected when unreferenced.
- **JVM Parameter:** `-XX:StringTableSize=60013` configures the underlying hash bucket count.

**Common Follow-up Questions:**
- *"How many objects are created by `String s = new String("abc");`?"* → **Two objects**: one literal `"abc"` placed into the String Pool (if not already present), and one new `String` instance allocated on the Heap.
- *"Can string interning cause an OutOfMemoryError?"* → Yes, in Java 7+, massive uncontrolled interning of unique strings can exhaust the standard heap (`java.lang.OutOfMemoryError: Java heap space`).
- *"What is G1 GC String Deduplication?"* → A JVM feature (`-XX:+UseStringDeduplication`) where G1 GC detects identical backing `byte[]` arrays across different `String` instances and points them to a single array without modifying the `StringTable`.

**Red Flags (DO NOT Say):**
- ❌ *"The String Pool is located in Metaspace in Java 8+."* (It is located in the Java Heap).
- ❌ *"String Pool objects are permanent and can never be garbage collected."* (In Java 7+, unreferenced pooled strings are reclaimed by standard GC cycles).
- ❌ *"Using `==` to compare strings is safe as long as they have the same characters."* (Only guaranteed for literals or explicitly interned instances; always use `.equals()`).
