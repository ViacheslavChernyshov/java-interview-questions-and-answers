# How to Properly Convert String to byte[] and Back

---

## 🟢 Junior Level

When converting between a `String` and a `byte[]` (for file storage, network transmission, or cryptography), **ALWAYS explicitly declare the `Charset`**:

```java
import java.nio.charset.StandardCharsets;

String original = "Hello, World!";

// 1. String ──► byte[] (Encoding)
byte[] bytes = original.getBytes(StandardCharsets.UTF_8);

// 2. byte[] ──► String (Decoding)
String restored = new String(bytes, StandardCharsets.UTF_8);

System.out.println(restored); // "Hello, World!"
```

```
  ❌ NEVER RELY ON PARAMETERLESS METHODS:
  • `str.getBytes()`           <-- BANNED in Production!
  • `new String(bytes)`        <-- BANNED in Production!

  Why? Parameterless methods use the OS-default charset. 
  Text encoded on Windows (Windows-1252) will corrupt into unreadable "mojibake" () on Linux (UTF-8)!
```

## 🟡 Middle Level

### Recommended Conversion Standards

```java
// 1. Preferred Modern Standard (Constant reference, zero lookup overhead):
byte[] utf8Bytes = text.getBytes(StandardCharsets.UTF_8);
String utf8String = new String(utf8Bytes, StandardCharsets.UTF_8);

// 2. Dynamic / Legacy Encodings:
Charset win1251 = Charset.forName("Windows-1251");
byte[] winBytes = text.getBytes(win1251);
String winString = new String(winBytes, win1251);

// 3. High-Performance Streaming I/O:
try (BufferedReader reader = Files.newBufferedReader(filePath, StandardCharsets.UTF_8)) {
    String line = reader.readLine();
}
```


## 🔴 Senior Level

### Deep Dive: `CharsetDecoder` Error Handling Strategies

By default, `new String(bytes, StandardCharsets.UTF_8)` silently replaces malformed or truncated byte sequences with the Unicode replacement character (`\uFFFD` / ).

In security-sensitive or financial systems, you must configure a strict **`CharsetDecoder`**:

```java
public static String decodeStrictly(byte[] bytes) throws CharacterCodingException {
    CharsetDecoder decoder = StandardCharsets.UTF_8.newDecoder()
        .onMalformedInput(CodingErrorAction.REPORT)    // 💥 Throws MalformedInputException on bad bytes
        .onUnmappableCharacter(CodingErrorAction.REPORT);

    return decoder.decode(ByteBuffer.wrap(bytes)).toString();
}
```

> [!WARNING]
> `CharsetEncoder` and `CharsetDecoder` are **stateful and NOT thread-safe**. Never share a decoder instance across multiple concurrent threads. Use per-thread instances or `ThreadLocal<CharsetDecoder>`.

### Stripping the UTF-8 Byte Order Mark (BOM)

Files created in legacy Windows tools often prefix UTF-8 streams with the 3-byte BOM sequence (`0xEF`, `0xBB`, `0xBF`). Standard UTF-8 decoding leaves an invisible zero-width space `\uFEFF` at index 0, corrupting headers and JSON keys:

```java
public static String decodeAndStripBom(byte[] rawBytes) {
    if (rawBytes.length >= 3 &&
        rawBytes[0] == (byte) 0xEF &&
        rawBytes[1] == (byte) 0xBB &&
        rawBytes[2] == (byte) 0xBF) {
        // Strip the 3-byte BOM header:
        return new String(rawBytes, 3, rawBytes.length - 3, StandardCharsets.UTF_8);
    }
    return new String(rawBytes, StandardCharsets.UTF_8);
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Standard Syntax:** Always use `str.getBytes(StandardCharsets.UTF_8)` and `new String(bytes, StandardCharsets.UTF_8)`.
- **Operating System Trap:** Parameterless `getBytes()` relies on `Charset.defaultCharset()`, creating cross-environment mojibake bugs.
- **`StandardCharsets` Enum:** Use `StandardCharsets.UTF_8` constants to avoid checked exceptions and string lookups.
- **Binary Data Rule:** Never convert raw binary streams (crypto keys, images, compressed data) into `String`; keep them as `byte[]` or `ByteBuffer`.
- **BOM Handling:** UTF-8 BOM (`0xEF 0xBB 0xBF`) yields `\uFEFF`, breaking prefix matching; strip leading 3 bytes.
- **Thread Safety:** `StandardCharsets` is thread-safe; `CharsetEncoder`/`CharsetDecoder` are mutable and single-threaded.

**Common Follow-up Questions:**
- *"What happens when invalid UTF-8 bytes are passed to `new String(bytes, UTF_8)`?"* → The JVM replaces invalid bytes with the replacement character `\uFFFD` () without throwing an exception.
- *"How can you detect and reject malformed encoding in input streams?"* → Use `CharsetDecoder.onMalformedInput(CodingErrorAction.REPORT)`.
- *"Why is `StandardCharsets.UTF_8` preferred over `Charset.forName("UTF-8")`?"* → `StandardCharsets.UTF_8` is a pre-initialized static constant that avoids hash table lookups and cannot throw `UnsupportedCharsetException`.

**Red Flags (DO NOT Say):**
- ❌ *"It is safe to omit the charset if all servers run Linux."* (Relying on platform defaults is fragile and violates architectural portability).
- ❌ *"`CharsetDecoder` can be stored in a `static final` field and reused by all worker threads."* (Decoders are stateful and will produce race condition data corruption).
- ❌ *"`String.length()` matches the size of its UTF-8 `byte[]` array."* (In multi-byte encodings like UTF-8, non-ASCII characters occupy 2 to 4 bytes per character).
