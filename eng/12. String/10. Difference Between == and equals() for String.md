# Difference Between == and equals() for String

---

## 🟢 Junior Level

In Java, **`==`** and **`equals()`** serve two fundamentally different purposes when working with strings:

```
  ┌───────────────┬──────────────────────────────────────────┬────────────────────────────────────────────────┐
  │ Comparison    │ What It Evaluates                        │ Output for Identical Content in Different Objs │
  ├───────────────┼──────────────────────────────────────────┼────────────────────────────────────────────────┤
  │ **`==`**      │ **Memory Address Identity** (Pointers)   │ ❌ `false` (Different heap addresses)          │
  │ **`equals()`**│ **Logical Character Content Equality**   │ ✅ `true`  (Identical text sequence)           │
  └───────────────┴──────────────────────────────────────────┴────────────────────────────────────────────────┘
```

```java
String s1 = "Hello";
String s2 = "Hello";
String s3 = new String("Hello");

System.out.println(s1 == s2);      // true  (Both point to the same String Pool instance)
System.out.println(s1 == s3);      // false (s3 is a separate instance on the Heap)
System.out.println(s1.equals(s3)); // true  (Character sequence is identical!)
```

## 🟡 Middle Level

### The 5-Step Evaluation Pipeline of `String.equals()`

```java
// OpenJDK java.lang.String internal implementation:
public boolean equals(Object anObject) {
    // Step 1: Fast-Path Reference Identity Check:
    if (this == anObject) return true; 

    // Step 2: Type verification:
    if (anObject instanceof String aString) {
        // Step 3: Encoding Coder match (Latin1 vs UTF16):
        if (coder == aString.coder) {
            // Step 4 & 5: Length & SIMD Vectorized Byte Array Comparison:
            return isLatin1()
                ? StringLatin1.equals(value, aString.value)
                : StringUTF16.equals(value, aString.value);
        }
    }
    return false;
}
```

```
  Comparison Steps:
  1. `this == anObject` ──► If true, returns immediately in O(1) time!
  2. `instanceof String` ──► Returns false if null or wrong class type.
  3. `coder == another.coder` ──► Returns false if encodings differ.
  4. `value.length == another.value.length` ──► Returns false if lengths differ.
  5. `HotSpot Intrinsic SIMD comparison` ──► Compares 16 to 64 bytes per CPU cycle.
```

## 🔴 Senior Level

### Security Consideration: Timing Attacks on `String.equals()`

Because standard `String.equals()` uses early-exit optimization (returning `false` on the very first mismatched byte), it is **vulnerable to Timing Attacks** when comparing cryptographic tokens or API keys:

```
  Attacker guesses API key characters:
  • "Axxxx" fails on byte 0 -> takes 1.2 ns
  • "Bxxxx" fails on byte 0 -> takes 1.2 ns
  • "Kxxxx" matches byte 0, fails on byte 1 -> takes 2.4 ns! (Attacker deduces 'K' is correct!)
```

```java
// 🛡️ Production Cryptographic Defense (Constant-Time Comparison):
public boolean verifyApiKey(byte[] expectedKey, byte[] providedKey) {
    // Compares all bytes unconditionally; time elapsed does not leak matching prefixes:
    return MessageDigest.isEqual(expectedKey, providedKey);
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`==`:** Compares 32/64-bit object memory references in $O(1)$ time (`if_acmpeq` bytecode).
- **`equals()`:** Compares logical character values across the backing byte array.
- **Fast-Path:** `equals()` begins with an identity check (`this == anObject`), guaranteeing $O(1)$ performance for identical references.
- **Coder Check:** Rejects comparison early if one string is `LATIN1` and the other is `UTF16`.
- **Hardware Acceleration:** HotSpot replaces array comparison loops with SIMD vector intrinsic CPU instructions.
- **Security:** Standard `equals()` is vulnerable to timing side-channel attacks; use `MessageDigest.isEqual()` for secret tokens.

**Common Follow-up Questions:**
- *"Why does `Objects.equals(a, b)` prevent NullPointerExceptions?"* → It evaluates `(a == b) || (a != null && a.equals(b))`, handling null references safely.
- *"What is the contract between `equals()` and `hashCode()` for String?"* → If `s1.equals(s2)` is `true`, then `s1.hashCode() == s2.hashCode()` must strictly evaluate to `true`.
- *"How does `equalsIgnoreCase()` work internally?"* → It performs case folding (converting characters to uppercase and lowercase equivalents) across Unicode code points.

**Red Flags (DO NOT Say):**
- ❌ *"`==` compares characters for string literals and compares references for `new String()`."* (`==` ALWAYS compares memory references).
- ❌ *"`equals()` always runs in $O(N)$ time even for identical object references."* (The fast-path `this == anObject` check resolves in $O(1)$).
- ❌ *"It is safe to use `String.equals()` to verify cryptographic passwords and HMAC signatures."* (It is vulnerable to timing attacks; constant-time comparison is required).
