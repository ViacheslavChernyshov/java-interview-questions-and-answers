# Difference Between Creating String via Literal and via new

---

## 🟢 Junior Level

In Java, there are two primary ways to instantiate a `String`:

```java
// Method 1: String Literal (⭐️ Recommended)
String s1 = "Hello";
String s2 = "Hello";

System.out.println(s1 == s2); // true (Both refer to the same canonical String Pool object)
```

```java
// Method 2: new String() Constructor (🚫 Anti-Pattern for literals)
String s3 = new String("Hello");

System.out.println(s1 == s3);      // false (s3 is a separate instance in regular Heap memory)
System.out.println(s1.equals(s3)); // true  (Character sequence is identical)
```

```
  Key Takeaway:
  • String literals reuse memory by pulling from the JVM String Pool.
  • `new String("...")` forces the JVM to allocate a redundant duplicate object on the Heap.
```

---

## 🟡 Middle Level

### The Classic Interview Question: "How Many Objects Are Created?"

```java
String str = new String("Hello");
```

```
  Two Objects are created (under cold JVM conditions):
  1. The Literal Object: The string literal "Hello" is loaded into the Constant Pool / String Pool.
  2. The Heap Object: The `new` operator allocates a separate `java.lang.String` instance on the Heap.

  If "Hello" was already loaded into the String Pool prior to this line:
  • Exactly ONE object is created (the Heap instance).
```

### Valid Use Cases for `new String(...)`

| Use Case | Example | Why `new` is necessary |
| -------- | ------- | ---------------------- |
| **I/O Byte Decoding** | `new String(bytes, StandardCharsets.UTF_8)` | Decodes raw byte streams into UTF-16/Latin1 characters |
| **Char Array Conversion** | `new String(charArray)` | Defensive copy from a mutable `char[]` buffer |
| **Code Point Array Conversion** | `new String(codePoints, 0, count)` | Decodes 32-bit Unicode surrogate code points |

## 🔴 Senior Level

### Bytecode Disassembly Analysis

```java
public void createStrings() {
    String a = "Hello";
    String b = new String("Hello");
}
```

```
  Bytecode for `String a = "Hello"`:
    0: ldc           #2      // String "Hello" (Resolves from Constant Pool)
    2: astore_1

  Bytecode for `String b = new String("Hello")`:
    3: new           #3      // class java/lang/String (Allocates uninitialized heap memory)
    6: dup                   // Duplicates object reference for constructor invocation
    7: ldc           #2      // String "Hello" (Loads literal from Constant Pool)
    9: invokespecial #4      // Method java/lang/String."<init>":(Ljava/lang/String;)V
   12: astore_2
```

### Constant Folding vs. Dynamic Evaluation

```java
// 1. Constant Folding (Evaluated at Compile Time):
String s1 = "Java" + "21"; // javac compiles this directly into bytecode as `ldc "Java21"` (Pooled)

// 2. Dynamic Runtime Concatenation:
String prefix = "Java";
String s2 = prefix + "21"; // Evaluated at runtime via invokedynamic / StringConcatFactory (Unpooled Heap)

System.out.println(s1 == s2); // false!
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Literal:** Resolves via `ldc` against the String Pool; allocates zero new objects if already pooled.
- **`new String()`:** Always allocates a brand new object on the Java Heap, bypassing the String Pool.
- **Object Count:** `new String("abc")` creates 1 or 2 objects depending on whether `"abc"` is already pooled.
- **Constant Folding:** Compile-time constants (`"a" + "b"`) are folded by `javac` into single pooled literals.
- **Runtime Variables:** Concatenating variables (`var + "b"`) produces an unpooled Heap object at runtime.
- **Proper Use:** Use `new String(byte[], Charset)` for I/O decoding; never use `new String("literal")`.

**Common Follow-up Questions:**
- *"How can you move an unpooled heap string into the String Pool?"* → Call `.intern()` on the instance (`String pooled = heapString.intern();`).
- *"Why did early Java code use `new String(largeString.substring(0, 5))`?"* → In Java 6, `substring()` shared the parent string's backing `char[]`, causing memory leaks; wrapping it in `new String(...)` forced a defensive array copy. Java 7+ fixed this.
- *"Is `String.valueOf(123)` pooled?"* → No, it dynamically creates a new `String` on the Heap.

**Red Flags (DO NOT Say):**
- ❌ *"Using `new String("abc")` is useful when you want to ensure the string cannot be modified."* (Strings are immutable regardless of how they are instantiated).
- ❌ *"Constant folding works on all variables."* (Only applies to compile-time constants and `final` variables with literal initializers).
- ❌ *"`==` works reliably for all strings in production."* (Only reliable for string literals and interned strings; never use `==` for business logic).
