# What Happens When Concatenating Strings with the + Operator?

---

## 🟢 Junior Level

When you use the **`+` operator** to concatenate strings, Java creates a **brand new `String` object** containing the combined character sequence. Because `String` is immutable, the original operands remain completely unchanged:

```java
String s1 = "Hello";
String s2 = "World";
String result = s1 + " " + s2; // Creates a new String "Hello World"
```

### The Catastrophic Loop Anti-Pattern ($O(N^2)$ Churn)

```java
// ❌ CATASTROPHIC ANTI-PATTERN (O(N^2) allocations & GC churn):
String result = "";
for (int i = 0; i < 1000; i++) {
    result += i; // Allocates a new String & buffer on EVERY iteration!
}

// ✅ RECOMMENDED BEST PRACTICE (O(N) single buffer mutation):
StringBuilder sb = new StringBuilder(1000);
for (int i = 0; i < 1000; i++) {
    sb.append(i);
}
String result = sb.toString();
```

## 🟡 Middle Level

### Constant Folding vs. Runtime Concatenation

```
  ┌───┬──────────────────────────────────────────┬────────────────────────────────────────────────────────────┐
  │ # │ Concatenation Type                       │ Compiler & Runtime Execution                               │
  ├───┼──────────────────────────────────────────┼────────────────────────────────────────────────────────────┤
  │ 1 │ **Compile-Time Literals (`"A" + "B"`)**  │ **Constant Folding:** `javac` folds into `"AB"` (0 runtime)│
  │ 2 │ **Runtime Variables (`a + " " + b`)**    │ Evaluated dynamically at runtime (Heap allocation)         │
  └───┴──────────────────────────────────────────┴────────────────────────────────────────────────────────────┘
```

```java
// Compile-time evaluation:
String s1 = "Java" + 21; // Bytecode contains only `ldc "Java21"`

// Runtime evaluation:
String name = "Java";
String s2 = name + 21;   // Dynamically evaluated at runtime via invokedynamic
```

## 🔴 Senior Level

### Bytecode Evolution: Java 8 vs. Java 9+ (JEP 280)

#### Java 5 through Java 8: `StringBuilder` Bytecode Desugaring

`javac` compiled `a + " " + b` into hardcoded bytecode instructions:

```java
// Java 8 compiled bytecode equivalent:
new StringBuilder().append(a).append(" ").append(b).toString();
```

#### Java 9+ (JEP 280): `invokedynamic` & `StringConcatFactory`

Starting in Java 9, string concatenation compiles to **`invokedynamic`**:

```
  0: aload_1 // a
  1: aload_2 // b
  2: invokedynamic #7, 0 // InvokeDynamic #0:makeConcatWithConstants:(Ljava/lang/String;Ljava/lang/String;)Ljava/lang/String;
  7: astore_3
```

- **Runtime Strategy Optimization:** At startup, `StringConcatFactory` calculates the exact total length of all parameters, allocates a single `byte[]` array of the precise required size, and encodes the characters directly.
- **Zero Intermediate Garbage:** Eliminates the overhead of intermediate `StringBuilder` object headers and repeated array resizing.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Immutability:** Original strings are untouched; a new string object is returned.
- **Constant Folding:** Concatenating compile-time constants (`"A" + "B"`) is pre-computed by `javac` into a single pooled literal.
- **Java 8 Mechanism:** Hardcoded `new StringBuilder().append().toString()` bytecode.
- **Java 9+ (JEP 280):** Dynamic runtime concatenation via `invokedynamic` and `StringConcatFactory`.
- **Loop Trap:** Using `+=` in loops creates $O(N^2)$ garbage objects; always use `StringBuilder` initialized with capacity.
- **Null Safety:** Concatenating `null` evaluates to the string literal `"null"` via `String.valueOf(null)`.

**Common Follow-up Questions:**
- *"Why did Java 9 switch string concatenation to `invokedynamic`?"* → To allow JVM engineers to improve concatenation algorithms at the runtime/JIT level without requiring developers to recompile their Java source code.
- *"Does the Java compiler optimize `+=` inside a `for` loop into a single `StringBuilder`?"* → No; `javac` processes each statement in isolation, creating a new `StringBuilder` (or `invokedynamic` call) on every iteration.
- *"What happens when concatenating primitives like `int` or `boolean`?"* → `StringConcatFactory` handles primitive types directly without boxing them into wrapper objects.

**Red Flags (DO NOT Say):**
- ❌ *"The Java compiler automatically converts loops with `+=` into a single efficient StringBuilder."* (It allocates a new buffer per iteration).
- ❌ *"`+` concatenation modifies the first string variable in-place."* (Strings are immutable; it always creates a new object).
- ❌ *"In Java 17, `+` is slower than manually instantiating `StringBuilder` for single-line expressions."* (In modern Java, `invokedynamic` is faster than manual `StringBuilder` for single expressions because it pre-sizes the byte array).
