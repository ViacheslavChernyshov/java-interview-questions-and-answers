# Difference between constructor, setter and field injection

---

## 🟢 Junior Level

In Spring, dependencies can be wired into components using three primary strategies:

```java
// 1. Constructor Injection (Recommended Standard)
@Service
public class OrderService {
    private final OrderRepository repo;
    public OrderService(OrderRepository repo) { this.repo = repo; }
}

// 2. Setter Injection (For Optional Dependencies)
@Service
public class OrderService {
    private OrderRepository repo;
    @Autowired public void setRepo(OrderRepository repo) { this.repo = repo; }
}

// 3. Field Injection (Anti-Pattern - Avoid)
@Service
public class OrderService {
    @Autowired private OrderRepository repo; // Injected via reflection directly into field
}
```

---

## 🟡 Middle Level

### Comprehensive Comparison Matrix

| Criteria | Constructor Injection | Setter Injection | Field Injection |
|---|---|---|---|
| **Immutability** | **Guaranteed (`final` fields)** | No (Mutable fields) | No (Cannot use `final`) |
| **Null Safety** | **100% (No uninitialized state)** | Partial (Can be left uncalled) | Vulnerable (Fields are `null` in plain constructors) |
| **POJO Unit Testing** | **Trivial (`new Service(mockRepo)`)** | Moderate (Must invoke setters) | **Complex (Requires Mockito reflection or Spring Context)** |
| **Single Responsibility (SRP)** | **Clear (Many params = Code Smell)** | Obscured | **Concealed (Easy to add 15+ fields unnoticed)** |
| **Circular Dependencies** | **Fails Fast at Startup** | Resolved silently | Resolved silently (Hidden risk) |
| **Industry Recommendation** | **MANDATORY DEFAULT (99%)** | Optional / Reconfiguration | **ANTI-PATTERN** |

### Bean Instantiation Execution Order

Understanding the sequential lifecycle is critical to avoid `NullPointerException` bugs:

```
  1. Class Constructor Invoked (Constructor Injection resolved)
         │
         ▼
  2. Field Injection (`@Autowired` fields populated via reflection)
         │
         ▼
  3. Setter Injection (Methods annotated with `@Autowired` invoked)
         │
         ▼
  4. Initialization Phase (`@PostConstruct` methods executed)
```

> [!WARNING]
> **Constructor Field Access Trap:** If you declare `@Autowired private UserRepository repo;` via Field Injection and try to call `repo.findUser()` inside your **class constructor**, it will throw a `NullPointerException` because field injection occurs **after** the constructor returns. Use Constructor Injection or place post-construction logic in `@PostConstruct`.

## 🔴 Senior Level

### Autowiring Mechanics: `AutowiredAnnotationBeanPostProcessor`

Field and Setter injection are performed reflectively by Spring's **`AutowiredAnnotationBeanPostProcessor`**:
- During the bean lifecycle's `populateBean()` phase, Spring scans class metadata for `@Autowired` annotations and uses `Field.setAccessible(true)` to bypass Java access modifiers.
- **Constructor Injection Optimization:** In Spring 4.3+ and Spring 6.x+, if a class declares **a single constructor**, the `@Autowired` annotation is **completely optional**. Spring automatically chooses that constructor to wire dependencies without reflection scans on fields.

### Clean Code with Lombok

To eliminate boilerplate constructors in production:

```java
@Service
@RequiredArgsConstructor // Generates constructor for all `final` fields automatically
public class OrderProcessingService {
    private final OrderRepository orderRepository;
    private final PaymentGateway paymentGateway;
    private final NotificationService notificationService;
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Constructor Injection:** The golden production standard. Enables `final` fields, prevents partially constructed objects, and makes POJO unit tests effortless.
- **Field Injection:** Uses reflection via `AutowiredAnnotationBeanPostProcessor`. Major anti-pattern because it violates encapsulation, hides SRP violations, and makes unit testing without Spring cumbersome.
- **Setter Injection:** Used strictly for optional dependencies (`@Autowired(required = false)`) or dynamic JMX reconfiguration.
- **Single Constructor Rule:** If a bean has only one constructor, `@Autowired` is not required (Spring 4.3+ / 6+).
- **Execution Order:** Constructor $\to$ Field Injection $\to$ Setter Injection $\to$ `@PostConstruct`.

**Common Follow-up Questions:**
- *"What happens if you try to use an `@Autowired` field inside a class constructor?"* → It throws a `NullPointerException` because field injection runs during the `populateBean` phase *after* the constructor has completed.
- *"Why does constructor injection prevent circular dependencies?"* → Because Spring cannot instantiate either bean without first resolving the constructor parameters of the other, triggering a fail-fast `BeanCurrentlyInCreationException`.
- *"Why should you avoid heavy computation in a Spring Bean's constructor?"* → Because CGLIB dynamic subclasses invoke the superclass constructor during proxy creation, potentially executing heavy initialization logic multiple times. Move initialization logic to `@PostConstruct`.

**Red Flags (DO NOT Say):**
- ❌ *"Field injection is preferable because it requires less code than constructor injection."* (Lombok `@RequiredArgsConstructor` eliminates boilerplate while keeping constructor benefits).
- ❌ *"Setter injection is recommended for all mandatory dependencies."* (Mandatory dependencies should always be passed via constructors).
- ❌ *"You must put `@Autowired` on every constructor in Spring Boot 3."* (Single constructors do not require `@Autowired`).
