# How to create a Bean in Spring?

---

## 🟢 Junior Level

In Spring and Spring Boot, you can create and register beans using two primary mechanisms:

```java
// 1. Stereotype Annotations (For your application code):
@Service
public class OrderService {
    // Automatically detected by @ComponentScan
}

// 2. Explicit Java Configuration (For 3rd-party libraries & complex setups):
@Configuration
public class AppConfig {
    @Bean
    public ObjectMapper objectMapper() {
        return new ObjectMapper(); // 3rd party class configured as a managed bean
    }
}
```

**Golden Rule:**
- Use **Stereotype Annotations** (`@Service`, `@Component`, `@Repository`, `@Controller`) for your own domain code.
- Use **`@Bean` methods** inside `@Configuration` classes for third-party libraries and framework infrastructure.

---

## 🟡 Middle Level

### The 4 Stereotype Annotations

- **`@Component`:** General-purpose Spring-managed component.
- **`@Service`:** Semantic marker for business logic services.
- **`@Repository`:** Persistence layer component. Enables automatic DAO **persistence exception translation** (converting JDBC/Hibernate exceptions into Spring's unified `DataAccessException` hierarchy).
- **`@Controller` / `@RestController`:** Web layer presentation controller.

### `FactoryBean<T>`: Specialized Complex Instantiation

When bean construction requires complex branching logic, JNDI lookups, or legacy factory adaptation, implement **`FactoryBean<T>`**:

```java
public class SecurityClientFactoryBean implements FactoryBean<SecurityClient> {
    @Override
    public SecurityClient getObject() throws Exception {
        return SecurityClientBuilder.create().withTls().build();
    }

    @Override
    public Class<?> getObjectType() { return SecurityClient.class; }

    @Override
    public boolean isSingleton() { return true; }
}
```
- Calling `context.getBean("securityClient")` returns the `SecurityClient` object produced by `getObject()`.
- Calling `context.getBean("&securityClient")` (prefix `&`) returns the `FactoryBean` instance itself.

## 🔴 Senior Level

### `@Configuration` CGLIB Interception (Full vs. Lite Mode)

```java
@Configuration // Full Mode (Default)
public class DatabaseConfig {
    @Bean
    public DataSource dataSource() { return new HikariDataSource(); }

    @Bean
    public EntityManagerFactory entityManagerFactory() {
        // Direct method invocation! Does it create a 2nd DataSource?
        return new CustomEntityManagerFactory(dataSource());
    }
}
```
- **How it Works:** Spring subclasses `@Configuration` classes via **CGLIB**. When `entityManagerFactory()` invokes `dataSource()`, the CGLIB proxy intercepts the call and returns the cached singleton `DataSource` bean from `ApplicationContext`.
- **Lite Mode (`proxyBeanMethods = false`):** Disables CGLIB proxying. Direct method invocations behave as plain Java calls (creating new unmanaged instances). Use Lite mode to accelerate startup time in Spring Boot 2.2+.

### Dynamic Registration: `ImportSelector` & `ImportBeanDefinitionRegistrar`

All Spring `@Enable*` annotations (e.g. `@EnableCaching`, `@EnableAsync`, `@EnableScheduling`) use dynamic metadata selectors:

```java
public class CustomFeatureImportSelector implements ImportSelector {
    @Override
    public String[] selectImports(AnnotationMetadata importingClassMetadata) {
        return new String[] { "com.app.feature.FeatureCoreService", "com.app.feature.FeatureAuditAspect" };
    }
}

// Annotation definition:
@Target(ElementType.TYPE)
@Retention(RetentionPolicy.RUNTIME)
@Import(CustomFeatureImportSelector.class)
public @interface EnableCustomFeature {}
```

### Functional Bean Registration (Spring 5+ / GraalVM Native AOT)

To eliminate reflection scanning overhead and enable Ahead-Of-Time (AOT) compilation for **GraalVM Native Images**:

```java
GenericApplicationContext context = new GenericApplicationContext();

// Programmatic, reflection-free bean registration:
context.registerBean(PaymentService.class, () -> new PaymentService(context.getBean(PaymentGateway.class)));
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Primary Methods:** Stereotypes (`@Component`, `@Service`, `@Repository`) for app code; `@Bean` in `@Configuration` for third-party libraries.
- **Classpath Scanning:** `@ComponentScan` uses the **ASM library** to read bytecode metadata without classloading overhead.
- **`@Configuration` CGLIB Proxy:** Intercepts internal `@Bean` method calls to preserve singleton semantics (Full Mode).
- **`FactoryBean<T>`:** Specialized factory interface for complex bean construction (use `&beanName` to fetch the factory itself).
- **Dynamic Registration:** `@Import` with `ImportSelector` or `ImportBeanDefinitionRegistrar` powers all `@Enable*` features.
- **GraalVM AOT Support:** `context.registerBean(Class, Supplier)` enables reflection-free functional bean creation.

**Common Follow-up Questions:**
- *"What happens if you invoke a `@Bean` method inside another `@Bean` method in a `@Component` class instead of a `@Configuration` class?"* → In `@Component` (Lite Mode), CGLIB proxying is inactive, so calling the method executes plain Java code and instantiates a duplicate unmanaged object.
- *"How do you access the `FactoryBean` instance instead of the product it creates?"* → Prefix the bean name with an ampersand (`context.getBean("&myFactoryBean")`).
- *"Why does `@Repository` have special behavior compared to `@Component`?"* → Spring automatically applies `PersistenceExceptionTranslationPostProcessor` to `@Repository` beans, converting native SQL/JPA exceptions into Spring's unchecked `DataAccessException` hierarchy.

**Red Flags (DO NOT Say):**
- ❌ *"Declaring @Bean methods inside @Component classes works identically to @Configuration classes."* (@Component runs in Lite Mode and does not intercept inter-bean method calls via CGLIB).
- ❌ *"You should create beans for JPA entity classes using @Bean."* (Entities are stateful domain objects managed by Hibernate/JPA, not Spring singletons).
- ❌ *"FactoryBean and @Bean methods are completely identical."* (FactoryBean is a formal programmatic interface for complex dynamic lifecycles).
