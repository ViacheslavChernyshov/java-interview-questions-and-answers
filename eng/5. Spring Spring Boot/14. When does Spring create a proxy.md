# When does Spring create a proxy?

---

## 🟢 Junior Level

Spring creates a **Dynamic Proxy** around a bean when it detects annotations that require **aspect-oriented behavior** or **dynamic runtime interception**.

### The Most Common Proxy Triggers

| Feature / Annotation | Interceptor Role |
|---|---|
| **`@Transactional`** | Opens DB transactions, commits on success, rolls back on exceptions |
| **`@Async`** | Offloads method execution to a background `TaskExecutor` thread pool |
| **`@Cacheable` / `@CacheEvict`** | Checks/updates distributed or local cache before invoking the method |
| **`@PreAuthorize` / `@Secured`** | Verifies caller permissions and roles before method execution |
| **`@Retryable`** | Intercepts exceptions and retries failed calls automatically |

```java
@Service
public class OrderProcessingService {

    @Transactional // Triggers Transaction Proxy creation
    public void submitOrder(Order order) { ... }

    @Async // Triggers Async Proxy creation
    public CompletableFuture<Void> sendOrderEmail(Order order) { ... }
}
```

## 🟡 Middle Level

### The 4 Major Architectural Categories of Proxies

1. **AOP & Cross-Cutting Annotations:**
   - Evaluated by **`AnnotationAwareAspectJAutoProxyCreator`** during the bean lifecycle (`postProcessAfterInitialization`).
2. **Scoped Proxies:**
   - Configured via `@Scope(proxyMode = ScopedProxyMode.TARGET_CLASS)` (or `@RequestScope` / `@SessionScope`).
   - Injects a placeholder proxy into singletons to resolve dynamic request attributes from `RequestContextHolder`.
3. **`@Configuration` Classes (Full Mode):**
   - Classes annotated with `@Configuration(proxyBeanMethods = true)` are enhanced via CGLIB to intercept inter-bean `@Bean` method calls and guarantee singleton caching.
4. **Lazy Injection (`@Lazy`):**
   - When `@Lazy` is placed on a dependency parameter, Spring injects a dynamic proxy stub that delays real bean resolution until the first method invocation.

## 🔴 Senior Level

### Under the Hood: `AnnotationAwareAspectJAutoProxyCreator`

```
  Spring Container Pipeline:
  Instantiation ──> Population ──> Initialization (@PostConstruct)
                                                 │
                                                 ▼
               [AnnotationAwareAspectJAutoProxyCreator.postProcessAfterInitialization()]
                                                 │
                  ┌──────────────────────────────┴──────────────────────────────┐
                  │ 1. Scans Bean methods for `@Transactional`, `@Async`, `@Aspect`│
                  │ 2. Evaluates Pointcut expressions (`PointcutAdvisor`)        │
                  │ 3. If match found -> Wraps Target Bean in CGLIB/JDK Proxy!  │
                  └─────────────────────────────────────────────────────────────┘
                                                 │
                                                 ▼
                             Proxy Registered in Singleton Cache
```

### Granularity Invariant: Whole-Bean Proxying

> [!IMPORTANT]
> **A Proxy Encloses the Entire Bean:** Even if only a single method in a class of 20 methods is annotated with `@Transactional`, Spring wraps the **entire bean class** in a dynamic proxy. All external calls to that bean pass through the proxy interceptor chain.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Primary Triggers:** `@Transactional`, `@Async`, `@Cacheable`, `@PreAuthorize`, `@Retryable`, and custom `@Aspect` classes.
- **Structural Triggers:** Scoped proxies (`@RequestScope`), `@Configuration(proxyBeanMethods = true)`, and `@Lazy` dependencies.
- **Creator Component:** `AnnotationAwareAspectJAutoProxyCreator` (a `BeanPostProcessor` running in `postProcessAfterInitialization`).
- **Bean-Level Scope:** Proxies are created around the entire bean instance, not individual methods.
- **Execution Overhead:** Proxy invocation overhead is negligible (typically a few nanoseconds).

**Common Follow-up Questions:**
- *"How does Spring know whether to create a proxy for a bean?"* → During `postProcessAfterInitialization()`, `AbstractAutoProxyCreator` queries all registered `Advisor` beans (pointcuts) to see if any advisor matches the target bean's class or methods.
- *"Why does `@Lazy` on an injection point create a proxy?"* → It creates a `TargetSource` proxy that postpones querying the `BeanFactory` until a method is actually called on the dependency.
- *"What happens if a class has no AOP annotations and is singleton scoped?"* → Spring does not create a proxy; the raw Java instance is stored directly in `singletonObjects`.

**Red Flags (DO NOT Say):**
- ❌ *"Spring creates proxies for all beans in the container by default."* (Only beans matching AOP pointcuts, scoped proxies, `@Lazy`, or `@Configuration` are proxied).
- ❌ *"Proxies are created on a per-method basis."* (The entire bean instance is wrapped in a single proxy containing an interceptor chain).
- ❌ *"CGLIB proxies require you to define interfaces for every class."* (CGLIB subclasses concrete classes directly).
