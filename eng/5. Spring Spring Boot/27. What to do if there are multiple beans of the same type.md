# What to do if there are multiple beans of the same type?

---

## 🟢 Junior Level

When the Spring IoC container finds **multiple candidate beans of the same interface or type** during dependency injection, startup will fail with a **`NoUniqueBeanDefinitionException`**.

```java
public interface PaymentGateway { void pay(BigDecimal amount); }

@Component public class StripeGateway implements PaymentGateway { ... }
@Component public class PayPalGateway implements PaymentGateway { ... }
```

### The 3 Common Disambiguation Solutions

#### 1. `@Primary` (Global Default)
```java
@Primary // Selected automatically if no @Qualifier is specified
@Component
public class StripeGateway implements PaymentGateway { ... }
```

#### 2. `@Qualifier` (Explicit Target)
```java
@Service
public class CheckoutService {
    public CheckoutService(@Qualifier("payPalGateway") PaymentGateway paymentGateway) { ... }
}
```

#### 3. Match `byName` (Parameter / Field Name Fallback)
```java
@Service
public class CheckoutService {
    // If parameter name matches bean name, Spring resolves it:
    public CheckoutService(PaymentGateway payPalGateway) { ... }
}
```

## 🟡 Middle Level

### Precedence Resolution Order

When Spring resolves an ambiguous dependency, it checks candidate criteria in strict hierarchical order:

```
  1. `@Qualifier`
     Explicit qualifier or custom meta-qualifier. (⭐ HIGHEST PRECEDENCE)
             │
             ├── Found -> ✅ Injected
             ▼
  2. `@Primary`
     Selects the bean marked with `@Primary`.
             │
             ├── Found -> ✅ Injected
             ▼
  3. Match `byName`
     Matches parameter/field variable name with bean ID.
             │
             ├── Found -> ✅ Injected
             ▼
  4. `@Priority` (Jakarta Standard: `jakarta.annotation.Priority`)
     Selects the candidate with the lowest numerical priority value.
             │
             ├── Found -> ✅ Injected
             ▼
  ❌ FAILURE: Throws `NoUniqueBeanDefinitionException`
```

### The Strategy Pattern via Map & List Injection

Instead of picking a single bean, you can inject **all implementations** to build dynamic, extensible strategy dispatchers:

```java
@Service
public class PaymentDispatcherService {

    // 1. Injects Map<BeanName, BeanInstance>:
    private final Map<String, PaymentGateway> gateways;

    public PaymentDispatcherService(Map<String, PaymentGateway> gateways) {
        this.gateways = gateways;
    }

    public void processPayment(String providerName, BigDecimal amount) {
        PaymentGateway gateway = gateways.get(providerName);
        if (gateway == null) {
            throw new IllegalArgumentException("Unknown payment gateway: " + providerName);
        }
        gateway.pay(amount); // O(1) Dynamic runtime dispatch without if-else!
    }
}
```

## 🔴 Senior Level

### Type-Safe Custom Qualifiers (Eliminating Brittle Strings)

Hardcoding string values in `@Qualifier("stripeGateway")` is vulnerable to silent typos. Create **custom type-safe meta-annotations**:

```java
// 1. Declare custom qualifier annotation:
@Target({ElementType.FIELD, ElementType.PARAMETER, ElementType.TYPE, ElementType.METHOD})
@Retention(RetentionPolicy.RUNTIME)
@Qualifier
public @interface Stripe { }

// 2. Apply to Bean:
@Component
@Stripe
public class StripeGateway implements PaymentGateway { ... }

// 3. Apply to Injection Point:
@Service
public class OrderService {
    public OrderService(@Stripe PaymentGateway paymentGateway) {
        // Compiler verified, refactoring safe!
    }
}
```

### Diagnostic Output in Spring Boot

If multiple beans cause a conflict, Spring Boot's **`FailureAnalyzer`** formats the crash into a clean report:

```
***************************
APPLICATION FAILED TO START
***************************

Description:
Parameter 0 of constructor in com.app.CheckoutService required a single bean, but 2 were found:
	- stripeGateway: defined in file [StripeGateway.class]
	- payPalGateway: defined in file [PayPalGateway.class]

Action:
Consider marking one of the beans as @Primary, updating the consumer to use @Qualifier,
or changing the name of the parameter to match the name of the bean.
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **The Ambiguity Error:** Multiple beans of the same type throw `NoUniqueBeanDefinitionException`.
- **Precedence Pipeline:** 1. `@Qualifier` $\to$ 2. `@Primary` $\to$ 3. Match `byName` $\to$ 4. `@Priority`.
- **`@Qualifier` Trumps `@Primary`:** An explicit `@Qualifier` always overrides `@Primary`.
- **Strategy Pattern:** Inject `Map<String, T>` (bean name $\to$ instance) to avoid hardcoded `switch`/`if-else` blocks.
- **Custom Qualifiers:** Use `@Qualifier` as a meta-annotation to build type-safe, refactoring-resilient qualifiers.

**Common Follow-up Questions:**
- *"What happens if two beans of the same type are both annotated with `@Primary`?"* → Spring throws `NoUniqueBeanDefinitionException` because it cannot determine which `@Primary` bean takes precedence.
- *"How does `@Priority` differ from `@Order`?"* → `@Priority` (Jakarta) disambiguates single bean injection points; `@Order` (Spring) controls sorting order inside injected `List<T>` collections.
- *"Can `@Qualifier` be placed on `@Bean` factory methods?"* → Yes, `@Qualifier` can annotate `@Bean` methods in `@Configuration` classes to give the resulting bean a specific qualifier alias.

**Red Flags (DO NOT Say):**
- ❌ *"@Primary overrides @Qualifier."* (@Qualifier has higher precedence than @Primary).
- ❌ *"Injecting a Map<String, T> only injects the @Primary bean."* (It injects all beans of type T keyed by their bean IDs).
- ❌ *"Spring resolves by variable name before checking @Primary."* (@Primary is checked before falling back to variable name).
