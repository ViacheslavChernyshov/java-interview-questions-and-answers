# What are the Bean Lifecycle stages?

---

## 🟢 Junior Level

When Spring boots up, every managed bean progresses through a deterministic lifecycle sequence:

```
  1. Instantiation (Constructor executed)
         │
         ▼
  2. Property Population (@Autowired dependencies injected)
         │
         ▼
  3. Initialization (@PostConstruct executed)
         │
         ▼
  4. Ready for Use (Servicing business requests)
         │
         ▼
  5. Destruction (@PreDestroy executed upon application shutdown)
```

```java
@Service
public class MetricReporterService {
    private final MetricRepository repository;

    // 1. Instantiation
    public MetricReporterService(MetricRepository repository) {
        this.repository = repository;
    }

    // 3. Initialization
    @PostConstruct
    public void startScheduler() {
        System.out.println("Scheduler started successfully.");
    }

    // 5. Destruction
    @PreDestroy
    public void shutdownScheduler() {
        System.out.println("Flushing metrics and shutting down.");
    }
}
```

## 🟡 Middle Level

### The Complete 12-Step Lifecycle Pipeline

```
  ┌─────────────────────────────────────────────────────────────────────────────────────────┐
  │ 1. Instantiation                                                                        │
  │    Spring allocates the Java object in heap via constructor reflection.                 │
  ├─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 2. Property Population (`populateBean()`)                                               │
  │    `AutowiredAnnotationBeanPostProcessor` populates fields and setters.                │
  ├─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 3. Aware Interface Callbacks                                                            │
  │    Spring injects infrastructure references: `BeanNameAware`, `BeanFactoryAware`,       │
  │    `ApplicationContextAware`.                                                          │
  ├─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 4. `BeanPostProcessor.postProcessBeforeInitialization()`                               │
  │    `CommonAnnotationBeanPostProcessor` scans and executes `@PostConstruct`.             │
  ├─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 5. `InitializingBean.afterPropertiesSet()` Interface callback.                          │
  ├─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 6. Custom `init-method` declared via `@Bean(initMethod = "customInit")`.                │
  ├─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 7. `BeanPostProcessor.postProcessAfterInitialization()`                                │
  │    ⭐ CRITICAL: AOP Proxies (CGLIB/JDK) generated here (`@Transactional`, `@Async`).     │
  ├─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 8. BEAN IS READY (Registered in `singletonObjects` Level 1 Cache)                      │
  ├─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 9. Context Shutdown Initiated                                                           │
  ├─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 10. `@PreDestroy` methods executed via `CommonAnnotationBeanPostProcessor`.             │
  ├─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 11. `DisposableBean.destroy()` Interface callback.                                      │
  ├─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 12. Custom `destroy-method` declared via `@Bean(destroyMethod = "customCleanup")`.      │
  └─────────────────────────────────────────────────────────────────────────────────────────┘
```

## 🔴 Senior Level

### Instantiation vs. Initialization

- **Instantiation:** The JVM executes `new MyService()` via reflection. Memory is allocated on the heap, but fields are still `null`.
- **Initialization:** Occurs **after** all dependencies are injected. Runs `@PostConstruct`, `afterPropertiesSet()`, and wraps the bean in AOP dynamic proxies.

### The Premature BPP Initialization Hazard

```
  Container Startup Sequence:
  1. Register all `BeanPostProcessor` beans first.
  2. Instantiate regular application beans second.
```

> [!WARNING]
> **Naked Bean Hazard:** If a custom `BeanPostProcessor` declares a direct constructor or field dependency on an application bean (e.g. `UserService`), Spring is forced to instantiate `UserService` **prematurely** before auto-proxy creators (`AnnotationAwareAspectJAutoProxyCreator`) are registered.
> - **The Result:** `UserService` will bypass all subsequent BPPs and remain **unproxied**—silently disabling `@Transactional`, `@Async`, and `@Cacheable` on that bean!
> - **Remediation:** Declare dependencies inside BPPs with **`@Lazy`** or resolve them on-demand using `ObjectProvider<T>`.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **12 Steps:** Instantiation $\to$ Property Population $\to$ Aware Interfaces $\to$ BPP Before $\to$ `@PostConstruct` $\to$ `afterPropertiesSet` $\to$ `initMethod` $\to$ BPP After (Proxies!) $\to$ Ready $\to$ `@PreDestroy` $\to$ `DisposableBean` $\to$ `destroyMethod`.
- **Aware Interfaces:** Provide access to Spring infrastructure (`BeanNameAware`, `ApplicationContextAware`, `EnvironmentAware`).
- **Proxy Creation Point:** Step 7 (`BPP.postProcessAfterInitialization`) wraps the bean in a CGLIB/JDK proxy *after* `@PostConstruct` has finished.
- **Singleton vs. Prototype:** Singletons undergo all 12 stages; prototypes stop after Step 7 (Spring never invokes steps 9–12 for prototypes).
- **Premature BPP Injection:** Injecting domain beans into custom BPPs bypasses proxy creation, disabling transactions on those beans.

**Common Follow-up Questions:**
- *"In what exact order do `@PostConstruct`, `afterPropertiesSet()`, and `initMethod` execute?"* → 1. `@PostConstruct`, 2. `InitializingBean.afterPropertiesSet()`, 3. `@Bean(initMethod = "...")`.
- *"Why is `@PostConstruct` preferred over `InitializingBean`?"* → `@PostConstruct` is a standard Jakarta annotation (`jakarta.annotation.PostConstruct`) that avoids coupling your domain code directly to Spring framework interfaces.
- *"What event fires when all beans across the context are initialized and proxied?"* → `ContextRefreshedEvent` (or `ApplicationReadyEvent` in Spring Boot).

**Red Flags (DO NOT Say):**
- ❌ *"In a bean's constructor, all @Autowired dependencies are already injected."* (Unless using constructor injection, fields and setters are populated *after* the constructor returns).
- ❌ *"@PreDestroy is called for prototype beans when the ApplicationContext closes."* (Spring does not manage the destruction phase of prototype beans).
- ❌ *"BeanPostProcessors can safely inject any application service without side effects."* (Direct injection causes premature bean instantiation and breaks AOP proxying).
