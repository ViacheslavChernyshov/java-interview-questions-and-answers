# What is a Bean in Spring?

---

## 🟢 Junior Level

In Spring, a **Bean** is any Java object that is instantiated, assembled, configured, and managed by the **Spring IoC Container** (`ApplicationContext`).

### Regular POJO vs. Spring Managed Bean

```java
// 1. Regular POJO: You control lifecycle and dependencies manually via `new`
User user = new User("Alice");

// 2. Spring Managed Bean: Spring creates, wires, proxies, and manages lifecycle
@Service
public class UserService {
    private final UserRepository userRepository;

    public UserService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }
}
```

| Feature | Regular Java Object (POJO) | Spring Managed Bean |
|---|---|---|
| **Instantiation** | Created explicitly via `new` | Instantiated reflectively by Spring Container |
| **Dependency Wiring** | Manually passed into constructors | Injected automatically by Spring IoC |
| **Lifecycle Hooks** | Manual method calls | `@PostConstruct` & `@PreDestroy` called automatically |
| **Aspect Enhancements** | None | Wrapped in Dynamic Proxies (`@Transactional`, `@Async`, `@Cacheable`) |

## 🟡 Middle Level

### The Bean Blueprint: `BeanDefinition`

Before creating any runtime bean instance, Spring first parses configuration metadata into a **`BeanDefinition`** object:

```
  Configuration Source (@Component, @Bean, XML)
                        │
                        ▼
                 [BeanDefinition]
  ├── Class Name (`com.app.service.UserService`)
  ├── Scope (`singleton`, `prototype`, `request`)
  ├── Constructor Arguments & Properties
  ├── Autowiring Mode & Primary / Qualifier Tags
  └── Init & Destroy Method Names
                        │
                        ▼
  Spring Instantiation Engine (`DefaultListableBeanFactory`)
```

### 2 Primary Ways to Declare Beans

1. **Stereotype Annotations (Classpath Scanning):**
   - `@Component` (Generic component)
   - `@Service` (Business logic layer)
   - `@Repository` (Data access layer with DAO exception translation)
   - `@Controller` / `@RestController` (Spring MVC / REST endpoints)
2. **Explicit Java Configuration (`@Configuration` + `@Bean`):**
   - Ideal for third-party classes you cannot annotate directly (e.g. `ObjectMapper`, `RestTemplate`, `DataSource`).

## 🔴 Senior Level

### Under the Hood: Container Storage & Registries

The core implementation of the Spring IoC container is **`DefaultListableBeanFactory`**:
- **`beanDefinitionMap`:** A `ConcurrentHashMap<String, BeanDefinition>` storing bean metadata blueprints.
- **`singletonObjects`:** A `ConcurrentHashMap<String, Object>` (Level 1 Cache) holding fully initialized singleton bean instances.

### Dynamic Proxies: CGLIB vs. JDK Dynamic Proxies

When a bean uses aspect-oriented features (`@Transactional`, `@Cacheable`, `@Secured`), Spring replaces the raw bean with a **Dynamic Proxy**:

```
  Client Call ──> [Dynamic Proxy Interceptor] ──> [Actual Target Bean]
                        │
                  (Opens Transaction / Checks Security / Checks Cache)
```

- **JDK Dynamic Proxy:** Used when target class implements an interface (`java.lang.reflect.Proxy`). Proxies interface methods only.
- **CGLIB / ByteBuddy:** Generates a runtime subclass of the target bean. Default in Spring Boot 2.x/3.x (`spring.aop.proxy-target-class=true`).

> [!WARNING]
> **The `final` Method Proxy Trap:** Because CGLIB creates a runtime subclass to override methods, **`final` classes and `final` methods cannot be overridden**. Annotating a `final` method with `@Transactional` will fail silently without opening a transaction!

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** An object managed by the Spring IoC container (`ApplicationContext`) across its complete lifecycle.
- **`BeanDefinition`:** The metadata specification blueprint describing how to construct, wire, and initialize the bean.
- **Creation Methods:** Stereotype component scanning (`@Component`, `@Service`, `@Repository`) vs explicit `@Configuration` with `@Bean` methods.
- **Dynamic Proxying:** Spring wraps beans in proxies for cross-cutting concerns (`@Transactional`, `@Async`).
- **CGLIB `final` Trap:** CGLIB subclassing cannot override `final` methods, rendering `@Transactional` non-functional on final methods.
- **What NOT to make a Bean:** DTOs, JPA Entities, Value Objects, utility helper classes, and short-lived request payload records.

**Common Follow-up Questions:**
- *"What is the difference between a Bean and a Component?"* → `@Component` is a class-level stereotype annotation that tells Spring to create a bean. A Bean is the resulting managed object instance inside the container.
- *"Can you modify a `BeanDefinition` before the bean is instantiated?"* → Yes, using a custom implementation of **`BeanFactoryPostProcessor`** (e.g. `PropertySourcesPlaceholderConfigurer`).
- *"Why does Spring Boot default to CGLIB proxies over JDK dynamic proxies?"* → To allow injecting concrete class types directly into controllers and services without forcing developers to create interfaces for every bean.

**Red Flags (DO NOT Say):**
- ❌ *"Every Java object in a Spring Boot application should be registered as a Spring Bean."* (Domain entities, DTOs, and value objects must remain unmanaged POJOs).
- ❌ *"Spring Beans are a special Java type distinct from normal classes."* (Any regular Java class can become a Spring bean when managed by the container).
- ❌ *"@Transactional works on final methods when using Spring Boot."* (CGLIB cannot override final methods; transactions will not be initiated).
