# What is aspect, advice, pointcut, join point?

---

## 🟢 Junior Level

These four concepts represent the foundational building blocks of **Aspect-Oriented Programming (AOP)**:

| Term | Meaning | Concrete Example |
|---|---|---|
| **Aspect** | The modular class containing cross-cutting code | `@Aspect public class AuditLoggingAspect { ... }` |
| **Join Point** | The candidate execution point in the program | `UserService.registerUser(User user)` |
| **Pointcut** | The predicate expression matching target Join Points | `@annotation(org.springframework.transaction.annotation.Transactional)` |
| **Advice** | The action taken and execution timing | *"Log method execution duration and record metrics"* |

```java
@Aspect
@Component
public class PerformanceMonitoringAspect { // 1. ASPECT

    // 2. POINTCUT: Matches any method annotated with @Monitored
    @Around("@annotation(com.app.annotation.Monitored)") 
    public Object monitorExecutionTime(ProceedingJoinPoint joinPoint) throws Throwable { // 3. ADVICE
        long startTime = System.currentTimeMillis();
        try {
            // 4. JOIN POINT: Invocation of the business method
            return joinPoint.proceed();
        } finally {
            long duration = System.currentTimeMillis() - startTime;
            System.out.println(joinPoint.getSignature().getName() + " took " + duration + "ms");
        }
    }
}
```

## 🟡 Middle Level

### The 5 Advice Types

```java
// 1. Before: Executes before the target method
@Before("execution(* com.app.service.*.*(..))")
public void logBefore(JoinPoint jp) { ... }

// 2. After Returning: Executes only upon successful (exception-free) return
@AfterReturning(pointcut = "execution(* com.app.service.*.*(..))", returning = "result")
public void logSuccess(JoinPoint jp, Object result) { ... }

// 3. After Throwing: Executes only if an exception is thrown
@AfterThrowing(pointcut = "execution(* com.app.service.*.*(..))", throwing = "ex")
public void logException(JoinPoint jp, Exception ex) { ... }

// 4. After (Finally): Executes unconditionally regardless of success or error
@After("execution(* com.app.service.*.*(..))")
public void cleanupResources(JoinPoint jp) { ... }

// 5. Around: Wraps the method entirely (can modify args, catch exceptions, skip invocation)
@Around("@annotation(Cached)")
public Object handleCaching(ProceedingJoinPoint pjp) throws Throwable {
    return pjp.proceed();
}
```

### Static vs. Dynamic Pointcuts

- **Static Pointcuts (`execution()`, `@annotation()`, `within()`):** Evaluated **once at container startup** when Spring generates dynamic proxies. Zero runtime evaluation penalty.
- **Dynamic Pointcuts (`args()` with runtime evaluation):** Must be evaluated on **every single method invocation** at runtime, introducing CPU inspection overhead.

## 🔴 Senior Level

### `JoinPoint` & `ProceedingJoinPoint` API Internals

```java
@Around("execution(* com.app.service.*.*(..))")
public Object profile(ProceedingJoinPoint pjp) throws Throwable {
    MethodSignature signature = (MethodSignature) pjp.getSignature();
    Object[] args = pjp.getArgs();      // ⚠️ Creates a defensive clone of arguments array
    Object target = pjp.getTarget();    // Raw underlying target bean instance
    Object proxy = pjp.getThis();       // Dynamic proxy wrapper object

    return pjp.proceed(args);           // Can pass modified argument array!
}
```

### Concurrency Invariant: Aspects are Singletons

In Spring, `@Aspect` classes are standard Spring singletons by default:
- **Critical Thread Safety Rule:** Never store mutable request-scoped state inside fields of an `@Aspect` class. If cross-advice state sharing is required, store data in a `ThreadLocal` or pass attributes via request attributes.

```java
@Aspect
@Component
public class UnsafeAspect {
    // ❌ DANGEROUS: Race conditions across concurrent requests!
    // private long requestStartTime;

    // ✅ PROPER IMPLEMENTATION:
    private final ThreadLocal<Long> requestStartTime = new ThreadLocal<>();
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Join Point:** The point in program flow (in Spring AOP, strictly `public` method executions).
- **Pointcut:** The matching rule/expression (`execution`, `@annotation`, `within`).
- **Advice:** The action (`@Before`, `@AfterReturning`, `@AfterThrowing`, `@After`, `@Around`).
- **Aspect:** The class uniting Pointcuts and Advices (`@Aspect`).
- **Advisor:** Spring internal construct combining exactly one Pointcut with one Advice.
- **`@Around` Rule:** Always call `joinPoint.proceed()` unless explicitly implementing short-circuit caching or security blocking.
- **Aspect State:** Aspects are singletons; fields must be thread-safe (`ThreadLocal`).

**Common Follow-up Questions:**
- *"What is the difference between `joinPoint.getTarget()` and `joinPoint.getThis()`?"* → `getTarget()` returns the raw underlying Java bean instance; `getThis()` returns the dynamic proxy object currently handling the call.
- *"Why is `@AfterReturning` different from `@After`?"* → `@After` behaves like a `finally` block (always runs); `@AfterReturning` executes strictly when the method returns without throwing an exception.
- *"How does Spring represent an Aspect internally?"* → Spring converts `@Aspect` methods into `Advisor` objects composed of a `Pointcut` and a `MethodInterceptor`.

**Red Flags (DO NOT Say):**
- ❌ *"A Join Point in Spring AOP can be a field modification or constructor call."* (Spring AOP only supports method execution join points; field and constructor join points require AspectJ).
- ❌ *"It is fine to store request metrics in instance variables of an @Aspect class."* (Aspects are singletons shared across all threads; mutable fields cause race conditions).
- ❌ *"Dynamic pointcuts are just as fast as static pointcuts."* (Dynamic pointcuts evaluate arguments at runtime on every invocation, adding CPU overhead).
