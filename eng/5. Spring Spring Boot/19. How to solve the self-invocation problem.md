# How to solve the self-invocation problem?

---

## 🟢 Junior Level

The cleanest and most robust way to solve the self-invocation problem is to **extract the transactional or asynchronous method into a separate Spring-managed service**.

```java
// ❌ Problem: Self-invocation bypasses the proxy
@Service
public class UserService {
    public void registerUser(User user) {
        saveWithAudit(user); // Bypasses proxy!
    }
    @Transactional public void saveWithAudit(User user) { ... }
}

// ✅ Solution: Extract to a separate collaborator service
@Service
public class UserService {
    private final UserPersistenceService persistenceService;

    public UserService(UserPersistenceService persistenceService) {
        this.persistenceService = persistenceService;
    }

    public void registerUser(User user) {
        // Calls through the injected proxy of UserPersistenceService!
        persistenceService.saveWithAudit(user);
    }
}

@Service
public class UserPersistenceService {
    @Transactional
    public void saveWithAudit(User user) {
        // Transaction is initiated properly!
    }
}
```

## 🟡 Middle Level

### The 4 Practical Solutions Compared

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ Solution Strategy                                      │ Code Pattern & Trade-offs                              │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **1. Separate Component (Best Practice)**              │ Extract method to a new `@Service` bean.               │
  │                                                        │ -> Adheres to Single Responsibility Principle.         │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **2. Self-Injection via `@Lazy`**                      │ `@Autowired @Lazy private OrderService self;`          │
  │                                                        │ -> Spring injects a dynamic proxy to itself.           │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **3. Programmatic `TransactionTemplate`**              │ `transactionTemplate.execute(status -> { ... });`      │
  │                                                        │ -> Completely avoids proxy mechanics.                  │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **4. `ObjectProvider<T>` Resolution**                  │ `selfProvider.getObject().innerMethod();`              │
  │                                                        │ -> Explicit on-demand proxy lookup.                    │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

## 🔴 Senior Level

### Deep Dive: 4 Solutions in Code

#### Solution 1: Refactoring to a Collaborator Bean (Architectural Standard)
Separates orchestration logic from transactional persistence logic.

#### Solution 2: Self-Injection with `@Lazy`
```java
@Service
public class PaymentService {
    private final PaymentRepository repository;
    private PaymentService self; // Self-proxy reference

    public PaymentService(PaymentRepository repository) {
        this.repository = repository;
    }

    @Autowired
    public void setSelf(@Lazy PaymentService self) {
        this.self = self; // Injects CGLIB proxy stub
    }

    public void processPayment() {
        self.chargeAndLog(); // ✅ Routes through the proxy!
    }

    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void chargeAndLog() { ... }
}
```

#### Solution 3: Programmatic `TransactionTemplate` (Zero Proxy Overhead)
```java
@Service
public class AccountService {
    private final TransactionTemplate transactionTemplate;

    public AccountService(TransactionTemplate transactionTemplate) {
        this.transactionTemplate = transactionTemplate;
    }

    public void updateAccount() {
        // Runs fine-grained transaction block without AOP proxies:
        transactionTemplate.executeWithoutResult(status -> {
            performDatabaseUpdates();
        });
    }
}
```

#### Solution 4: `AopContext.currentProxy()` (Discouraged Anti-Pattern)
```java
// Requires @EnableAspectJAutoProxy(exposeProxy = true)
@Service
public class LegacyService {
    public void outer() {
        // ⚠️ FRAGILE: Couples business code directly to Spring AOP internals
        ((LegacyService) AopContext.currentProxy()).inner();
    }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Best Solution:** Extract the annotated method into a dedicated collaborator bean (clean architecture & SRP).
- **Self-Injection:** Use `@Lazy` on a self-referencing dependency to inject the dynamic proxy stub.
- **Programmatic Alternative:** Use `TransactionTemplate` (for transactions) or `TaskExecutor` (for async) to bypass proxies entirely.
- **`ObjectProvider<T>`:** Dynamically retrieves the proxy from the `ApplicationContext` on-demand.
- **Anti-Pattern:** `AopContext.currentProxy()` requires `exposeProxy = true`, adds `ThreadLocal` overhead, and breaks unit testing.

**Common Follow-up Questions:**
- *"Why does `@Lazy` allow a service to inject itself without a circular dependency crash?"* → `@Lazy` instructs Spring to inject a lightweight dynamic proxy stub at startup, postponing real target resolution until the first method invocation.
- *"When should you choose `TransactionTemplate` over `@Transactional`?"* → When you need fine-grained programmatic transaction boundaries inside a large method, or when doing batch processing where opening/closing transactions in tight loops is required.
- *"Why is `AopContext.currentProxy()` discouraged in modern Spring Boot?"* → It ties application domain code to Spring internal APIs, degrades performance due to `ThreadLocal` synchronization, and throws exceptions in unit tests where no AOP proxy exists.

**Red Flags (DO NOT Say):**
- ❌ *"AopContext.currentProxy() is the recommended solution for self-invocation."* (It is a legacy workaround; extracting a new bean is the best practice).
- ❌ *"Making the method private solves the self-invocation problem."* (Spring AOP ignores private methods; self-invocation will still bypass proxies).
- ❌ *"TransactionTemplate requires dynamic proxies to work."* (TransactionTemplate manages transactions programmatically via the `PlatformTransactionManager` without proxies).
