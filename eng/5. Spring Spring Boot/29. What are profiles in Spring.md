# What are profiles in Spring?

---

## 🟢 Junior Level

**Spring Profiles** provide a core configuration mechanism to segregate parts of your application configuration and make them available only in specific environments (e.g. `dev`, `test`, `staging`, `prod`).

```yaml
# application-dev.yml (Local Development)
spring:
  datasource:
    url: jdbc:h2:mem:devdb

# application-prod.yml (Production Environment)
spring:
  datasource:
    url: jdbc:postgresql://postgres-cluster:5432/proddb
```

### Activating a Profile at Startup
```bash
# Via command-line argument:
java -jar app.jar --spring.profiles.active=prod

# Via environment variable:
export SPRING_PROFILES_ACTIVE=prod
```

---

## 🟡 Middle Level

### Conditional Bean Activation with `@Profile`

You can attach the **`@Profile`** annotation to `@Component`, `@Service`, or `@Bean` factory methods so that beans are instantiated **only when that profile is active**:

```java
@Configuration
public class DataSourceConfig {

    @Bean
    @Profile("dev")
    public DataSource devDataSource() {
        return new EmbeddedDatabaseBuilder().setType(EmbeddedDatabaseType.H2).build();
    }

    @Bean
    @Profile("prod")
    public DataSource prodDataSource() {
        return new HikariDataSource(prodConfig());
    }
}
```

### Boolean Expressions in `@Profile` (Spring 5.1+)

Spring supports sophisticated boolean operators (`!`, `&`, `|`):

```java
@Component
@Profile("prod & !cloud") // Active in Production, but ONLY on-premise (not in AWS/GCP)
public class OnPremiseMetricsSender implements MetricsSender { ... }

@Component
@Profile("dev | test") // Active in either Dev OR Test
public class MockEmailService implements EmailService { ... }
```

## 🔴 Senior Level

### Modern Multi-Document YAML Configuration (Spring Boot 2.4+)

In modern Spring Boot, environment profiles can be organized within a single `application.yml` using standard multi-document YAML separators (`---`):

```yaml
# Global Configuration:
server:
  port: 8080
---
# Dev Profile:
spring:
  config:
    activate:
      on-profile: dev
server:
  port: 9090
---
# Production Profile:
spring:
  config:
    activate:
      on-profile: prod
server:
  port: 443
```

### Profile Groups

Spring Boot allows combining fine-grained profiles into a single master profile alias:

```yaml
spring:
  profiles:
    group:
      "production": "metrics, cache, postgres, security"
```
Activating `--spring.profiles.active=production` automatically enables all four child profiles!

### Architectural Distinction: Profiles vs. Feature Flags

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │                   Spring Profiles                      │                     Feature Flags                      │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ • Configures **Infrastructure & Topologies** (DBs, URLs)│ • Toggles **Business Logic & UI capabilities**         │
  │ • **Static & Immutable** at runtime (Set at boot)      │ • **Dynamic & Mutable on-the-fly** without restarts    │
  │ • Requires container restart to change                 │ • Managed via systems like Unleash / LaunchDarkly      │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

> [!CAUTION]
> **Production Secrets Rule:** Never hardcode production database passwords, API tokens, or encryption keys in `application-prod.yml`. Inject secrets securely via Kubernetes Secrets, AWS Secrets Manager, or HashiCorp Vault.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Environment segregation mechanism for configuration properties and bean definitions.
- **Activation Order (Precedence):** CLI arguments (`--spring.profiles.active`) > JVM options (`-Dspring.profiles.active`) > OS Environment variables (`SPRING_PROFILES_ACTIVE`) > Config files.
- **`@Profile` Logic:** Supports `!`, `&`, `|` expressions (e.g. `@Profile("prod & !cloud")`).
- **Multi-Document YAML:** Activate blocks with `spring.config.activate.on-profile`.
- **Profile Groups:** Bundle multiple sub-profiles under a unified group name (`spring.profiles.group`).
- **Profiles vs. Feature Flags:** Profiles handle boot-time infrastructure; feature flags handle runtime business toggles.

**Common Follow-up Questions:**
- *"What happens if no profile is explicitly activated?"* → Spring activates the `default` profile, loading `application.yml` and beans marked with `@Profile("default")`.
- *"How do you test a specific profile in JUnit 5?"* → Annotate the test class with `@ActiveProfiles("test")`.
- *"Can you inspect the active profiles programmatically?"* → Inject Spring's `Environment` bean and call `env.getActiveProfiles()`.

**Red Flags (DO NOT Say):**
- ❌ *"You can change active profiles at runtime without restarting the application."* (Active profiles are immutable once the `ApplicationContext` is created).
- ❌ *"Feature flags and Spring profiles are identical concepts."* (Profiles configure static infrastructure; feature flags dynamically toggle features at runtime).
- ❌ *"It is good practice to store production database passwords in `application-prod.yml`."* (Production credentials should be externalized to secrets managers).
