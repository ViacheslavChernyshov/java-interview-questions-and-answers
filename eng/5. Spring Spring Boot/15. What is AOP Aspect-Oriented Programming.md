# What is AOP Aspect-Oriented Programming?

---

## 🟢 Junior Level

**Aspect-Oriented Programming (AOP)** is a programming paradigm that increases modularity by separating **Cross-Cutting Concerns** (infrastructure logic like Logging, Security, Caching, and Transactions) from the core business logic.

```
  Traditional OOP (Scattered Code):               AOP Architecture (Modularized):
  ┌───────────────────────────────┐               ┌───────────────────────────────┐
  │ [UserService.save()]          │               │ [Logging & Transaction Aspect]│
  │ • Open DB Transaction (Infra) │               └───────────────┬───────────────┘
  │ • Check Security Role (Infra) │                               │ (Weaves Cross-Cutting)
  │ • Save User Entity    (Core)  │                               ▼
  │ • Log Audit Event     (Infra) │               ┌───────────────────────────────┐
  │ • Commit Transaction  (Infra) │               │ [UserService.save()]          │
  └───────────────────────────────┘               │ • Save User Entity (100% Core)│
                                                  └───────────────────────────────┘
```

```java
// Cross-cutting concerns are extracted cleanly into an Aspect:
@Aspect
@Component
public class ExecutionTimeAspect {

    @Around("@annotation(LogExecutionTime)")
    public Object measureTime(ProceedingJoinPoint joinPoint) throws Throwable {
        long start = System.currentTimeMillis();
        Object result = joinPoint.proceed(); // Invokes the business method
        long executionTime = System.currentTimeMillis() - start;
        System.out.println(joinPoint.getSignature() + " executed in " + executionTime + "ms");
        return result;
    }
}
```

## 🟡 Middle Level

### The 4 Core Terminology Pillars of AOP

- **Aspect:** A modular Java class encapsulating cross-cutting behavior (annotated with `@Aspect`).
- **Join Point:** A specific point during program execution where an aspect can be plugged in (In Spring AOP, **always a method execution**).
- **Pointcut:** A predicate expression defining *which* Join Points should be intercepted (e.g. `execution(* com.app.service.*.*(..))`).
- **Advice:** The action taken at a Join Point.

### The 5 Types of Advice

| Advice Type | Annotation | Execution Trigger |
|---|---|---|
| **Before** | `@Before` | Runs *before* the target method execution |
| **After Returning** | `@AfterReturning` | Runs *after* successful return (captures return value) |
| **After Throwing** | `@AfterThrowing` | Runs *only if an exception is thrown* |
| **After (Finally)** | `@After` | Runs *after completion* (success or error, like a `finally` block) |
| **Around** | `@Around` | Wraps the method call entirely; **can modify arguments, catch exceptions, or skip invocation** |

## 🔴 Senior Level

### Spring AOP vs. AspectJ

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │                      Spring AOP                        │                        AspectJ                         │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ • Implemented via **Runtime Dynamic Proxies**          │ • Implemented via **Bytecode Weaving** (CTW / LTW)     │
  │ • Intercepts **`public` methods on Spring Beans only** │ • Intercepts **private, static, final methods, fields**│
  │ • Self-invocation (`this.method()`) **FAILS**          │ • Self-invocation **WORKS** (Weaved into bytecode)     │
  │ • Zero build-time compiler configuration               │ • Requires AspectJ compiler (`ajc`) or Java Agent      │
  │ • Best for: 95% of standard enterprise microservices   │ • Best for: High-frequency sub-microsecond tracing     │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

### The `ReflectiveMethodInvocation` Execution Chain

When a client calls a proxied method, Spring executes the **Advisor Chain**:

```java
// Inside Spring Framework AOP Engine:
public Object proceed() throws Throwable {
    if (this.currentInterceptorIndex == this.interceptorsAndDynamicMethodMatchers.size() - 1) {
        return invokeJoinpoint(); // All interceptors completed -> Call actual target method!
    }
    MethodInterceptor interceptor = this.interceptorsAndDynamicMethodMatchers.get(++this.currentInterceptorIndex);
    return interceptor.invoke(this); // Recursively execute the next Advice in the chain
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Modularizes cross-cutting concerns (Transactions, Security, Logging) outside business logic.
- **Key Concepts:** Aspect (module), Join Point (execution point), Pointcut (predicate matching), Advice (action).
- **5 Advice Types:** `@Before`, `@AfterReturning`, `@AfterThrowing`, `@After`, `@Around`.
- **`@Around` Invariant:** Must invoke `joinPoint.proceed()`; forgetting to call `proceed()` skips the target business logic entirely!
- **Spring AOP Limitations:** Operates strictly on `public` methods of Spring-managed beans; self-invocation bypasses the proxy.
- **Spring AOP vs. AspectJ:** Spring AOP uses runtime dynamic proxies; AspectJ uses compile-time or load-time bytecode weaving.

**Common Follow-up Questions:**
- *"Why can Spring AOP not intercept private methods?"* → Spring AOP uses runtime proxies (CGLIB subclassing / JDK interfaces); private methods cannot be overridden or accessed by subclasses or proxies.
- *"What is the difference between `@After` and `@AfterReturning`?"* → `@After` executes unconditionally (like a `finally` block); `@AfterReturning` executes strictly upon successful, exception-free method completion.
- *"How do you specify the execution order of multiple aspects?"* → Use the `@Order(int)` annotation on the `@Aspect` class (lower values execute first on the way in, and last on the way out).

**Red Flags (DO NOT Say):**
- ❌ *"Spring AOP modifies the class bytecode at compile time."* (AspectJ does bytecode weaving; Spring AOP creates runtime dynamic proxies).
- ❌ *"You can intercept method calls on objects created with `new` using Spring AOP."* (Spring AOP only manages Spring Beans; use AspectJ LTW for unmanaged objects).
- ❌ *"Forgetting to call `proceed()` in `@Around` advice will still execute the target method."* (The target method will never be invoked; `@Around` completely overrides method dispatch).
