# What is a starter in Spring Boot?

---

## 🟢 Junior Level

A **Spring Boot Starter** is an aggregated dependency descriptor that bundles a **curated set of transitive libraries** along with the auto-configuration needed to enable a specific application capability with a single dependency declaration.

```xml
<!-- One Starter pulls in Tomcat, Spring MVC, Jackson, and Hibernate Validator: -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-web</artifactId>
</dependency>
```

### Popular Standard Starters
- **`spring-boot-starter-web`:** Spring MVC, Embedded Tomcat, Jackson JSON, REST controllers.
- **`spring-boot-starter-data-jpa`:** Spring Data JPA, Hibernate ORM, HikariCP Connection Pool.
- **`spring-boot-starter-security`:** Spring Security, Servlet filter chains, BCrypt hashing.
- **`spring-boot-starter-test`:** JUnit 5, Mockito, AssertJ, Hamcrest, JSONassert, Spring Test.

## 🟡 Middle Level

### The Bill of Materials (BOM): Eliminating "JAR Hell"

Spring Boot uses **`spring-boot-dependencies`** as a **Bill of Materials (BOM)**:
- It pins harmonized, tested versions for hundreds of common third-party libraries (Jackson, Hibernate, Netty, SLF4J, Kafka).
- Developers do not need to specify `<version>` tags in application dependencies, eliminating version mismatch runtime crashes.

```xml
<parent>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-parent</artifactId>
    <version>3.2.0</version>
</parent>
```

### Official vs. Third-Party Naming Conventions

```
  Official Spring Team Starters:
  └── `spring-boot-starter-*` (e.g. `spring-boot-starter-amqp`)

  Community / Third-Party / Custom Starters:
  └── `*-spring-boot-starter` (e.g. `mybatis-spring-boot-starter`, `acme-audit-spring-boot-starter`)
```

## 🔴 Senior Level

### Standard 2-Module Architecture for Custom Starters

When developing internal enterprise starters across microservices, standard Spring Boot convention requires splitting the project into **two Maven/Gradle modules**:

```
  acme-telemetry-starter-parent/
  ├── acme-telemetry-spring-boot-autoconfigure/   <── Autoconfiguration Module
  │   ├── src/main/java/.../TelemetryAutoConfiguration.java
  │   ├── src/main/java/.../TelemetryProperties.java
  │   └── src/main/resources/META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
  │
  └── acme-telemetry-spring-boot-starter/          <── Empty Aggregator POM
      └── pom.xml (Declares dependencies on autoconfigure module + client SDK)
```

```java
// Inside Autoconfiguration module:
@AutoConfiguration
@ConditionalOnClass(TelemetryClient.class)
@EnableConfigurationProperties(TelemetryProperties.class)
public class TelemetryAutoConfiguration {

    @Bean
    @ConditionalOnMissingBean
    public TelemetryClient telemetryClient(TelemetryProperties properties) {
        return new TelemetryClient(properties.getEndpoint(), properties.getApiKey());
    }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Curated dependency bundle providing one-stop build dependencies and automatic configuration hooks.
- **BOM Management:** `spring-boot-dependencies` locks compatible versions to eliminate dependency conflicts.
- **Naming Rule:** `spring-boot-starter-*` is reserved strictly for official Spring modules; custom starters must be named `*-spring-boot-starter`.
- **2-Module Design:** Production starters split into an `autoconfigure` module (contains `@AutoConfiguration` + `.imports`) and an empty `starter` aggregator module.
- **Configuration Integration:** Bind settings via `@ConfigurationProperties` to enable IDE autocompletion via `spring-configuration-metadata.json`.

**Common Follow-up Questions:**
- *"Why is a custom starter split into two separate modules?"* → To allow other libraries to consume the auto-configuration logic without being forced to inherit the starter's transitive runtime dependency tree.
- *"How do you exclude an unwanted transitive dependency from a starter?"* → Use standard Maven `<exclusions>` (e.g. excluding default `spring-boot-starter-tomcat` to plug in `spring-boot-starter-undertow`).
- *"What file enables auto-configuration discovery in custom Spring Boot 3 starters?"* → `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`.

**Red Flags (DO NOT Say):**
- ❌ *"A Starter is just a plain JAR file with no code inside."* (Starters trigger auto-configuration classes and conditional bean creation).
- ❌ *"You should name your internal company starter `spring-boot-starter-acme`."* (Violates Spring naming conventions; must be `acme-spring-boot-starter`).
- ❌ *"Starters require you to specify versions for all dependencies manually."* (Spring Boot's BOM manages all versions automatically).
