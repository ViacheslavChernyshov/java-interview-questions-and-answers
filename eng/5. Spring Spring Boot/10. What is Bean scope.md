# What is Bean scope?

---

## 🟢 Junior Level

In Spring, **Bean Scope** defines the lifecycle boundary, visibility, and total number of instances the container creates for a specific bean definition.

### The 2 Core Scopes

| Scope | Instances Created | Lifecycle Management | Default |
|---|---|---|---|
| **`singleton`** | **Exactly 1 instance** per `ApplicationContext` | Full lifecycle managed by Spring | **YES (Default)** |
| **`prototype`** | **New instance** on every injection or `getBean()` | Instantiation & init only (No destruction) | No |

```java
// 1. Singleton Scope (Default):
@Service
public class UserService {
    // Shared across all threads in the application
}

// 2. Prototype Scope:
@Component
@Scope("prototype")
public class ReportTask {
    // Fresh independent object created every time it is requested
}
```

```java
// Verification:
UserService s1 = context.getBean(UserService.class);
UserService s2 = context.getBean(UserService.class);
System.out.println(s1 == s2); // true (Same singleton instance)

ReportTask r1 = context.getBean(ReportTask.class);
ReportTask r2 = context.getBean(ReportTask.class);
System.out.println(r1 == r2); // false (Distinct object instances)
```

## 🟡 Middle Level

### The Web Scopes (Spring MVC & WebFlux)

- **`request` (`@RequestScope`):** Creates a single bean instance per HTTP request lifecycle.
- **`session` (`@SessionScope`):** Creates a single bean instance per HTTP Session.
- **`application` (`@ApplicationScope`):** Creates a single instance bound to the lifecycle of the `ServletContext`.
- **`websocket`:** Scoped to the lifecycle of a WebSocket connection.

### The Scoping Dilemma: Injecting Short-Lived Beans into Singletons

```
  [Singleton Service] ──(Injected ONCE at startup)──> [Prototype / Request Bean]
```
- When a `prototype` or `request` scoped bean is injected directly into a `singleton`, Spring resolves the dependency **only once at startup**.
- **The Result:** The prototype or request bean becomes frozen inside the singleton, defeating the purpose of its scope!

#### Solution 1: `ObjectProvider<T>` (Programmatic)
```java
@Service
public class OrderService {
    @Autowired
    private ObjectProvider<ReportTask> reportTaskProvider;

    public void process() {
        ReportTask freshTask = reportTaskProvider.getObject(); // Fetches fresh prototype instance!
        freshTask.execute();
    }
}
```

#### Solution 2: Scoped Proxy (Transparent Architectural Standard)
```java
@Component
@Scope(value = WebApplicationContext.SCOPE_REQUEST, proxyMode = ScopedProxyMode.TARGET_CLASS)
public class UserRequestContext {
    private String jwtToken;
    private String tenantId;
}
```
- **How it Works:** Spring injects a dynamic **CGLIB proxy** into the singleton. When the singleton calls `userRequestContext.getTenantId()`, the proxy intercepts the call and dynamically delegates to the active `UserRequestContext` stored in `RequestContextHolder` (`ThreadLocal`) for the current HTTP thread.

## 🔴 Senior Level

### Under the Hood: Container Scope Storage

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ Scope                                                  │ Internal Storage Mechanism                             │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **`singleton`**                                        │ `DefaultSingletonBeanRegistry.singletonObjects` (CHM)  │
  │ **`prototype`**                                        │ Not cached; instantiated reflectively on demand        │
  │ **`request`**                                          │ `RequestContextHolder.currentRequestAttributes()`      │
  │                                                        │ (Backed by `ThreadLocal`)                              │
  │ **`session`**                                          │ `StandardSession.setAttribute()` (Servlet Session map) │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

### Implementing a Custom Scope (`Scope` SPI)

Spring allows creating custom domain scopes (e.g. `tenant`, `thread`, `flow`):

```java
public class ThreadScope implements Scope {
    private final ThreadLocal<Map<String, Object>> threadScope = ThreadLocal.withInitial(HashMap::new);

    @Override
    public Object get(String name, ObjectFactory<?> objectFactory) {
        return threadScope.get().computeIfAbsent(name, k -> objectFactory.getObject());
    }

    @Override
    public Object remove(String name) { return threadScope.get().remove(name); }

    @Override
    public void registerDestructionCallback(String name, Runnable callback) { /* ... */ }

    @Override
    public Object resolveContextualObject(String key) { return null; }

    @Override
    public String getConversationId() { return Thread.currentThread().getName(); }
}

// Registration in Configuration:
@Bean
public static CustomScopeConfigurer customScopeConfigurer() {
    CustomScopeConfigurer configurer = new CustomScopeConfigurer();
    configurer.addScope("thread", new ThreadScope());
    return configurer;
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Specifies the lifecycle and instance cardinality of a bean definition within the Spring container.
- **`singleton`:** 1 instance per `ApplicationContext` (Default); must remain strictly **stateless and thread-safe**.
- **`prototype`:** New instance on every call; `@PreDestroy` is **never** invoked by Spring.
- **Web Scopes:** `request`, `session`, `application`, `websocket`.
- **Short-in-Long Problem:** Injecting a short-lived bean into a singleton freezes the instance.
- **Scoped Proxy:** `@Scope(value = "request", proxyMode = ScopedProxyMode.TARGET_CLASS)` resolves short-lived beans dynamically via `RequestContextHolder` (`ThreadLocal`).
- **`ObjectProvider<T>`:** Programmatic on-demand factory alternative.

**Common Follow-up Questions:**
- *"Why is storing mutable state in a singleton bean dangerous?"* → Singleton beans are shared concurrently across all worker threads (e.g. Tomcat request threads). Mutable non-thread-safe fields cause race conditions and memory visibility corruptions.
- *"How does `ScopedProxyMode.TARGET_CLASS` work under the hood?"* → It creates a CGLIB proxy that routes method calls to the active thread's request attributes in `RequestContextHolder`.
- *"Can you define a custom scope in Spring?"* → Yes, by implementing `org.springframework.beans.factory.config.Scope` and registering it via `CustomScopeConfigurer`.

**Red Flags (DO NOT Say):**
- ❌ *"A Spring singleton is identical to the Gang of Four (GoF) Singleton design pattern."* (GoF singletons are 1 instance per ClassLoader; Spring singletons are 1 instance per `ApplicationContext`).
- ❌ *"Prototype beans are destroyed automatically when they are no longer in use."* (Spring does not manage prototype destruction; clients must clean them up manually).
- ❌ *"Injecting a @RequestScope bean into a Singleton works automatically without a proxy."* (Without `proxyMode = ScopedProxyMode.TARGET_CLASS` or `ObjectProvider`, it gets fixed to the first request's instance).
