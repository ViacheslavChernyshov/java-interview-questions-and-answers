# What is a proxy in Spring?

---

## 🟢 Junior Level

In Spring, a **Dynamic Proxy** is an intermediary wrapper object generated at runtime around a target bean to **intercept method calls and execute cross-cutting concerns** without modifying the original class source code.

```
  Client Call ──> [Spring Dynamic Proxy] ──> [Target Bean Instance]
                         │
                  ┌──────┴──────────────────────────┐
                  │ 1. Start Transaction            │
                  │ 2. Check Security / Permissions │
                  │ 3. Check / Evict Cache          │
                  │ 4. Execute Asynchronously       │
                  └─────────────────────────────────┘
```

```java
@Service
public class UserService {
    @Transactional // Instructs Spring to wrap this bean in a Transactional Proxy
    public void updateUser(User user) {
        // Business logic here
    }
}
```
When another component injects `UserService`, Spring supplies the **Proxy object**, not the raw `UserService` instance.

## 🟡 Middle Level

### The 2 Dynamic Proxy Mechanisms

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │                 JDK Dynamic Proxy                      │                     CGLIB Proxy                        │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ • Built into the Java runtime (`java.lang.reflect.Proxy`)│ • Third-party bytecode enhancer (ByteBuddy/CGLIB)      │
  │ • Requires the target class to **implement an interface**│ • Generates a **runtime subclass** of the target class │
  │ • Proxies **interface methods only**                   │ • Can proxy concrete classes directly                  │
  │ • Spring Framework 1.x-4.x Default                    │ • **Spring Boot 2.x / 3.x DEFAULT (`proxy-target-class`)│
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

### Why Spring Boot Defaults to CGLIB (`proxy-target-class = true`)
Historically with JDK proxies, developers had to inject interfaces (`@Autowired private OrderService orderService;`). Injecting the concrete implementation class (`SqlOrderService`) threw `BeanNotOfRequiredTypeException`. CGLIB solves this by allowing direct injection of concrete class types.

## 🔴 Senior Level

### The Interceptor Call Chain Pipeline

When a method is called on a proxied bean, Spring delegates execution through an **Advisor Chain** of `MethodInterceptor`s:

```
  Incoming Request
         │
         ▼
  [SecurityContextHolderAwareRequestFilter / SecurityInterceptor]
         │
         ▼
  [TransactionInterceptor] (Begins JDBC Connection / Starts DB Tx)
         │
         ▼
  [CacheInterceptor] (Inspects Redis / Local Cache)
         │
         ▼
  [Custom @Around Aspect]
         │
         ▼
  [Target Method Invocation] (`target.save(entity)`)
         │
         ▼
  [TransactionInterceptor] (Commits or Rolls Back on RuntimeException)
         │
         ▼
  Return Response to Caller
```

### The Self-Invocation Trap

```java
@Service
public class OrderService {

    public void processOrder(Order order) {
        // ❌ CALLS DIRECTLY VIA `this` -> Bypasses the proxy!
        saveWithAudit(order);
    }

    @Transactional
    public void saveWithAudit(Order order) {
        // Transaction is NOT initiated when called from processOrder()!
    }
}
```
Because `this.saveWithAudit(order)` executes internally on the raw target instance, **the method call never passes through the outer proxy**, rendering `@Transactional`, `@Async`, and `@Cacheable` completely non-functional!

### Inspecting Proxies Programmatically

```java
// Inspecting proxy metadata at runtime:
boolean isProxy = AopUtils.isAopProxy(service);       // true
boolean isCglib = AopUtils.isCglibProxy(service);     // true
Class<?> target = AopUtils.getTargetClass(service);   // OrderService.class
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Runtime wrapper object that intercepts method invocations to apply cross-cutting AOP concerns.
- **JDK Dynamic Proxy:** Interface-based, generated via `java.lang.reflect.Proxy`.
- **CGLIB Proxy:** Subclass-based, generated via bytecode manipulation; default in Spring Boot 2.x/3.x (`spring.aop.proxy-target-class=true`).
- **CGLIB Limitation:** Cannot proxy `final` classes or override `final` methods.
- **Self-Invocation Trap:** Calling a proxied method internally via `this.method()` bypasses the proxy and disables AOP features (`@Transactional`, `@Async`, `@Cacheable`).
- **Inspection Tools:** Use `AopUtils` (`isAopProxy`, `isCglibProxy`, `getTargetClass`).

**Common Follow-up Questions:**
- *"What happens if you mark a `@Transactional` method as `final` in Spring Boot?"* → CGLIB cannot override `final` methods in its generated subclass; the method executes without transactional management.
- *"Why does Spring Boot prefer CGLIB over JDK proxies?"* → To allow injecting concrete class types without forcing developers to extract interfaces for every single service.
- *"How does Spring chain multiple aspects (e.g. Transactions + Caching) on the same bean?"* → It constructs an ordered chain of `MethodInterceptor` instances (sorted by `@Order`) evaluated sequentially before invoking the target method.

**Red Flags (DO NOT Say):**
- ❌ *"CGLIB can proxy final methods because it works on bytecode."* (Java forbids overriding final methods, even in generated bytecode subclasses).
- ❌ *"Self-invocation works normally if you are using CGLIB."* (Self-invocation bypasses both JDK and CGLIB proxies because `this` always references the raw target instance).
- ❌ *"Spring creates dynamic proxies for every single bean in the context."* (Proxies are only created for beans that declare AOP advice, scoped proxies, or transactional/async annotations).
