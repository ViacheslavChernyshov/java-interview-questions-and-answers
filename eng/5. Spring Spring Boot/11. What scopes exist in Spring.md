# What scopes exist in Spring?

---

## 🟢 Junior Level

Spring provides several built-in scopes that determine the lifecycle and instance count of managed beans.

### Standard Scopes Overview

| Scope Name | Target Environment | Instance Cardinality |
|---|---|---|
| **`singleton`** (Default) | Universal | Exactly **1 instance per `ApplicationContext`** |
| **`prototype`** | Universal | **New instance** created on every injection or `getBean()` |
| **`request`** (`@RequestScope`) | Web / Servlet | 1 instance per individual **HTTP Request** |
| **`session`** (`@SessionScope`) | Web / Servlet | 1 instance per user **HTTP Session** |
| **`application`** (`@ApplicationScope`) | Web / Servlet | 1 instance per **`ServletContext`** |
| **`websocket`** | Web / WebSocket | 1 instance per **WebSocket connection** |

```java
@Service // Singleton (Default)
public class ProductService { }

@Component
@Scope(ConfigurableBeanFactory.SCOPE_PROTOTYPE)
public class InvoiceCalculator { }
```

## 🟡 Middle Level

### Dedicated Web Annotations (Spring 4.3+)

Instead of verbose `@Scope("request")` strings, Spring provides clean composed stereotype annotations:

```java
@Component
@RequestScope // Equivalent to @Scope(WebApplicationContext.SCOPE_REQUEST, proxyMode = TARGET_CLASS)
public class ClientIpContext {
    private String clientIp;
}

@Component
@SessionScope // Equivalent to @Scope(WebApplicationContext.SCOPE_SESSION, proxyMode = TARGET_CLASS)
public class ShoppingCart {
    private final List<Item> items = new ArrayList<>();
}
```

### Spring Cloud `@RefreshScope`

In distributed architectures with **Spring Cloud Config**:
- Annotating a bean with **`@RefreshScope`** creates a dynamic lazy proxy.
- When configuration changes in Git/Consul and `/actuator/refresh` is triggered, the proxy **invalidates the cached instance**.
- The next incoming method call transparently instantiates a new bean with the updated configuration properties!

## 🔴 Senior Level

### Distributed Microservice Pitfall: Native `@SessionScope`

```
  HTTP Request 1 (Login)   ──> [Load Balancer] ──> [Node A] (Session stored in local JVM memory)
  HTTP Request 2 (Payment) ──> [Load Balancer] ──> [Node B] (Session NOT FOUND -> Unauthorized!)
```
- **Architectural Fix:** Never use standalone in-memory `@SessionScope` in clustered production systems. Integrate **Spring Session with Redis** (`@EnableRedisHttpSession`) to externalize and replicate session state across all cluster nodes.

### Proxy Modes: `ScopedProxyMode`

```java
@Bean
@Scope(value = "request", proxyMode = ScopedProxyMode.TARGET_CLASS)
public TenantContext tenantContext() {
    return new TenantContext();
}
```

- **`TARGET_CLASS` (Default for Boot):** Generates a **CGLIB proxy** subclassing the concrete class.
- **`INTERFACES`:** Generates a **JDK Dynamic Proxy** (requires an interface).
- **`NO`:** No proxy created (breaks when injected into singletons).

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Standard Scopes:** `singleton` (1 per context), `prototype` (new instance per call).
- **Web Scopes:** `request`, `session`, `application`, `websocket`.
- **Composed Annotations:** `@RequestScope`, `@SessionScope`, `@ApplicationScope` automatically configure `ScopedProxyMode.TARGET_CLASS`.
- **Spring Cloud:** `@RefreshScope` re-instantiates beans dynamically upon configuration reload.
- **Clustered Sessions:** Native `@SessionScope` is node-local; use **Spring Session + Redis** in distributed production environments.

**Common Follow-up Questions:**
- *"What is the difference between `@ApplicationScope` and `singleton`?"* → A `singleton` is scoped to a single Spring `ApplicationContext`. `@ApplicationScope` is bound to the Servlet container's `ServletContext` (relevant in legacy deployments where multiple Spring contexts share a single ServletContext).
- *"How does `@RefreshScope` recreate beans at runtime?"* → It wraps the bean in a CGLIB proxy that queries a `RefreshScope` cache. When a refresh event occurs, the cache is cleared, forcing the proxy to instantiate a fresh bean on the next invocation.
- *"Why does Spring Boot automatically apply `ScopedProxyMode.TARGET_CLASS` on `@RequestScope`?"* → So that request-scoped beans can be safely injected into singleton-scoped controllers and services without freezing the instance at startup.

**Red Flags (DO NOT Say):**
- ❌ *"Session-scoped beans automatically synchronize across multiple microservice instances."* (They are stored in local JVM memory unless backed by Spring Session Redis).
- ❌ *"A prototype bean is destroyed when its parent singleton bean is destroyed."* (Spring does not track prototype destruction; prototype cleanup must be handled manually).
- ❌ *"You can use @RequestScope in standalone CLI or batch applications."* (Web scopes require an active Web `ApplicationContext`).
