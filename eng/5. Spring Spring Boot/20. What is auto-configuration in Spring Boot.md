# What is auto-configuration in Spring Boot?

---

## 🟢 Junior Level

**Auto-Configuration** is Spring Boot's mechanism that automatically configures and registers beans in your `ApplicationContext` based on the **libraries present on the classpath, configuration properties, and existing user beans**.

It embodies the **"Convention over Configuration"** philosophy.

```java
// Adding `spring-boot-starter-data-jpa` and `h2` to pom.xml/build.gradle
// automatically creates and configures:
// 1. HikariDataSource connection pool
// 2. Hibernate EntityManagerFactory & JpaTransactionManager
// 3. OpenEntityManagerInViewInterceptor
```

### Disabling Specific Auto-Configurations
```java
@SpringBootApplication(exclude = { DataSourceAutoConfiguration.class, SecurityAutoConfiguration.class })
public class Application {
    public static void main(String[] args) {
        SpringApplication.run(Application.class, args);
    }
}
```

## 🟡 Middle Level

### The `@Conditional` Annotation Engine

Auto-configuration classes are evaluated dynamically through a suite of `@Conditional` annotations:

```java
@AutoConfiguration
@ConditionalOnClass(ObjectMapper.class) // 1. Only runs if Jackson is on the classpath
public class JacksonAutoConfiguration {

    @Bean
    @Primary
    @ConditionalOnMissingBean // 2. Only runs if the USER has NOT defined their own ObjectMapper!
    public ObjectMapper objectMapper() {
        return new ObjectMapper();
    }
}
```

### The Most Common Conditional Annotations

- **`@ConditionalOnClass` / `@ConditionalOnMissingClass`:** Checks whether specified classes are loaded on the classpath.
- **`@ConditionalOnBean` / `@ConditionalOnMissingBean`:** Checks if a bean of that type/name already exists in the container (enables seamless developer overrides).
- **`@ConditionalOnProperty`:** Checks if an `application.properties` key matches an expected value (`havingValue = "true"`, `matchIfMissing = false`).
- **`@ConditionalOnWebApplication`:** Verifies if the context is a Servlet or Reactive (WebFlux) environment.

## 🔴 Senior Level

### Spring Boot 2.x vs. Spring Boot 3.x Discovery Engine

```
  Spring Boot 2.x:
  └── META-INF/spring.factories
      org.springframework.boot.autoconfigure.EnableAutoConfiguration=\
        com.app.config.MyAutoConfiguration

  Spring Boot 3.x (and 2.7+):
  └── META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports
      com.app.config.MyAutoConfiguration
```
- **Why the Change in Boot 3.x?**
  The `.imports` file is a flat, unkeyed list of class names parsed faster by the JVM and compatible with **GraalVM Ahead-Of-Time (AOT)** native image generation.

### Auto-Configuration Class Ordering

Because auto-configurations often depend on one another (e.g. `HibernateJpaAutoConfiguration` requires `DataSourceAutoConfiguration` to run first), use explicit ordering annotations:

```java
@AutoConfiguration(after = DataSourceAutoConfiguration.class, before = HibernateJpaAutoConfiguration.class)
@ConditionalOnClass(CustomRoutingDataSource.class)
public class RoutingDataSourceAutoConfiguration { ... }
```

### Diagnostics: The Condition Evaluation Report

Run your application with the **`--debug`** flag to inspect the **Condition Evaluation Report**:

```bash
java -jar app.jar --debug
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Automatic bean creation and configuration based on classpath dependencies, properties, and missing beans (Convention over Configuration).
- **Core Architecture:** `@SpringBootApplication` $\to$ `@EnableAutoConfiguration` $\to$ `AutoConfigurationImportSelector`.
- **Discovery Files:** Boot 2.x uses `META-INF/spring.factories`; Boot 3.x uses `META-INF/spring/org.springframework.boot.autoconfigure.AutoConfiguration.imports`.
- **Key Conditionals:** `@ConditionalOnClass`, `@ConditionalOnMissingBean` (allows developer overrides), `@ConditionalOnProperty`.
- **Ordering:** Managed via `@AutoConfiguration(after = ..., before = ...)`.
- **Disabling:** Use `@SpringBootApplication(exclude = {...})` or `spring.autoconfigure.exclude` in properties.
- **Debugging:** Start with `--debug` to view the Condition Evaluation Report.

**Common Follow-up Questions:**
- *"How do you override an auto-configured Spring Boot bean?"* → Simply declare your own `@Bean` of that type in a `@Configuration` class. The auto-configuration's `@ConditionalOnMissingBean` will detect your bean and back off.
- *"What is the difference between `@Configuration` and `@AutoConfiguration`?"* → `@AutoConfiguration` (introduced in Spring Boot 2.7) is specialized for auto-configuration classes, supporting explicit `before`, `after`, and `afterName` ordering attributes.
- *"Does auto-configuration add runtime overhead to production request processing?"* → No. Auto-configuration runs strictly once during application startup; runtime request processing incurs zero overhead.

**Red Flags (DO NOT Say):**
- ❌ *"Auto-configuration creates all beans found in starter JARs unconditionally."* (Every auto-configuration bean is guarded by `@Conditional` checks).
- ❌ *"Spring Boot 3 still relies primarily on META-INF/spring.factories for auto-configuration."* (Boot 3 uses `.imports` files located in `META-INF/spring/`).
- ❌ *"@ConditionalOnMissingBean checks whether the class exists on the classpath."* (`@ConditionalOnMissingBean` checks the `ApplicationContext` for existing bean instances; `@ConditionalOnMissingClass` checks the classpath).
