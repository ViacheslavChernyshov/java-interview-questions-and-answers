# Difference between @Component, @Service, @Repository, @Controller

---

## 🟢 Junior Level

In Spring, **Stereotype Annotations** are specialized markers used to designate classes as Spring-managed Beans across different architectural layers of an enterprise application.

All specialized stereotypes inherit directly from the foundational **`@Component`** meta-annotation.

```
                          [@Component] (Root Meta-Annotation)
                                │
        ┌───────────────────────┼───────────────────────┐
        ▼                       ▼                       ▼
   [@Service]             [@Repository]           [@Controller]
  Business Logic        Data Access (DAO)        Spring MVC Views
                                                        │
                                                        ▼
                                                [@RestController]
                                               REST APIs (JSON/XML)
```

### Stereotypes Overview

| Annotation | Target Layer | Special Spring Behavior |
|---|---|---|
| **`@Component`** | Generic Utilities | Basic container bean management |
| **`@Service`** | Business Layer | Semantic marker; target for service-layer AOP pointcuts |
| **`@Repository`** | Persistence / DAO | **Automatic Exception Translation** to `DataAccessException` |
| **`@Controller`** | Web Presentation | Returns View names (HTML templates via Thymeleaf/JSP) |
| **`@RestController`** | Web REST APIs | `@Controller` + `@ResponseBody` (Direct JSON/XML serialization) |

---

## 🟡 Middle Level

### The Unique Feature of `@Repository`: Exception Translation

The `@Repository` annotation is the **only stereotype with active framework behavior**:
- Handled by **`PersistenceExceptionTranslationPostProcessor`**.
- It creates a dynamic proxy around DAO classes to automatically intercept vendor-specific exceptions (`SQLException`, Hibernate `JDBCException`, JPA `PersistenceException`) and translate them into Spring's unified, unchecked **`DataAccessException`** hierarchy (e.g. `DataIntegrityViolationException`, `CannotAcquireLockException`).

```java
@Repository // Enables automatic SQL exception translation!
public class SqlUserRepository implements UserRepository {
    @PersistenceContext private EntityManager em;

    public User findById(Long id) {
        return em.find(User.class, id); // Native JPA exceptions become Spring DataAccessExceptions!
    }
}
```

### `@Controller` vs. `@RestController`

```java
// 1. Traditional MVC Controller (Returns HTML View name):
@Controller
public class WebPageController {
    @GetMapping("/home")
    public String renderHomePage(Model model) {
        model.addAttribute("title", "Welcome");
        return "home.html"; // Resolved by ViewResolver
    }
}

// 2. Modern REST Controller (Returns JSON response payload):
@RestController // Composed of @Controller + @ResponseBody
public class UserApiController {
    @GetMapping("/api/users/{id}")
    public UserDTO getUser(@PathVariable Long id) {
        return userService.getUserById(id); // Serialized to JSON via Jackson
    }
}
```

## 🔴 Senior Level

### Under the Hood: `PersistenceExceptionTranslationPostProcessor`

```
  Database Call Throws `org.hibernate.exception.ConstraintViolationException`
                                     │
                                     ▼
  [PersistenceExceptionTranslationInterceptor (BPP Proxy)]
                                     │
                                     ▼
  [Translates via `JpaDialect` / `PersistenceExceptionTranslator`]
                                     │
                                     ▼
  Throws Clean Spring `org.springframework.dao.DataIntegrityViolationException`
```

> [!WARNING]
> **Self-Invocation Trap on `@Repository`:** Because exception translation relies on dynamic proxies, calling a method internally within the same `@Repository` class via `this.method()` bypasses the proxy, causing raw vendor-specific exceptions to leak out untranslated.

### Targeted AOP Pointcuts with Stereotypes

Stereotypes provide clean, declarative boundaries for Aspect-Oriented pointcuts:

```java
@Aspect
@Component
public class ArchitectureMonitoringAspect {

    // Matches all public methods in classes annotated with @Service:
    @Around("within(@org.springframework.stereotype.Service *)")
    public Object profileServiceLayer(ProceedingJoinPoint pjp) throws Throwable {
        return pjp.proceed();
    }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Stereotype Hierarchy:** `@Component` is the parent; `@Service`, `@Repository`, `@Controller`, and `@RestController` are meta-annotated with `@Component`.
- **`@Repository` Exception Translation:** `PersistenceExceptionTranslationPostProcessor` translates low-level vendor SQL/Hibernate exceptions into Spring's unchecked `DataAccessException` hierarchy.
- **`@RestController` Composition:** Composed of `@Controller` + `@ResponseBody`.
- **Layering Standard:** Use `@Service` for domain logic, `@Repository` for DAOs, and `@RestController` for HTTP APIs.
- **AOP Pointcuts:** Use `@Service` and `@Repository` stereotypes to target layer-specific aspects cleanly via `within(@Service *)`.

**Common Follow-up Questions:**
- *"What happens if you replace `@Service` with `@Component` on a business class?"* → The bean is registered and functions identically for dependency injection, but loses semantic clarity, layer-targeted AOP matching, and readability.
- *"Why does Spring translate SQLExceptions into DataAccessExceptions?"* → `SQLException` is a checked exception tightly coupled to JDBC. Spring's `DataAccessException` is unchecked and provides a consistent, database-agnostic hierarchy.
- *"Can `@Repository` translate exceptions without `@EnableTransactionManagement`?"* → Yes, exception translation is governed by `PersistenceExceptionTranslationPostProcessor`, which operates independently of transaction management.

**Red Flags (DO NOT Say):**
- ❌ *"@Service automatically provides transaction management."* (Transactions require explicit `@Transactional` annotations).
- ❌ *"@RestController and @Controller are completely unrelated annotations."* (`@RestController` is a meta-annotation that includes `@Controller` and `@ResponseBody`).
- ❌ *"@Repository and @Component are 100% functionally identical."* (`@Repository` activates automatic `DataAccessException` proxy translation).
