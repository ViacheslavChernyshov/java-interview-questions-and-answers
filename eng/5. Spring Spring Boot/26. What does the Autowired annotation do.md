# What does the Autowired annotation do?

---

## 🟢 Junior Level

**`@Autowired`** is Spring's primary dependency injection annotation. It instructs the IoC container to resolve, instantiate, and inject a required collaborating bean into a class.

```java
@Service
public class OrderService {

    private final OrderRepository orderRepository;

    // In modern Spring (4.3+ / Boot 3+), @Autowired is OPTIONAL on single constructors:
    public OrderService(OrderRepository orderRepository) {
        this.orderRepository = orderRepository;
    }
}
```

### Where `@Autowired` Can Be Applied
1. **Constructors** *(Recommended & Best Practice)*.
2. **Fields** *(Field Injection via reflection)*.
3. **Setter Methods** *(Setter Injection)*.
4. **Configuration `@Bean` Methods** *(Parameter injection)*.

---

## 🟡 Middle Level

### The 4-Step Injection Resolution Algorithm

When Spring encounters an `@Autowired` injection point, `AutowiredAnnotationBeanPostProcessor` executes this resolution sequence:

```
  1. Resolution `byType`
     Finds all candidate beans in the container assignable to the target type.
             │
             ├── If exactly 1 bean found ────────> ✅ INJECTED
             ▼
  2. Filter by `@Qualifier`
     Matches candidates declaring the specified `@Qualifier("name")`.
             │
             ├── If exactly 1 match ─────────────> ✅ INJECTED
             ▼
  3. Check for `@Primary`
     Selects the candidate marked with `@Primary`.
             │
             ├── If exactly 1 @Primary ──────────> ✅ INJECTED
             ▼
  4. Fallback: Match `byName`
     Matches candidate bean name with the field/parameter variable name.
             │
             ├── If match found ─────────────────> ✅ INJECTED
             ▼
  ❌ Ambiguity Failure: Throws `NoUniqueBeanDefinitionException`
```

### Injecting Bean Collections & Maps

Spring can automatically collect all registered beans implementing a common interface:

```java
@Service
public class CheckoutService {

    // 1. Injects ALL PaymentGateway beans in @Order sequence:
    @Autowired
    private List<PaymentGateway> paymentGateways;

    // 2. Injects a Map where Key = Bean Name, Value = Bean Instance:
    @Autowired
    private Map<String, PaymentGateway> paymentGatewayMap;
}
```

## 🔴 Senior Level

### Under the Hood: `AutowiredAnnotationBeanPostProcessor`

```
  Container Lifecycle:
  Bean Instantiation (Constructor)
             │
             ▼
  [AutowiredAnnotationBeanPostProcessor.postProcessProperties()]
             │
             ├─> 1. Discovers `@Autowired` fields/setters via ASM / Reflection
             ├─> 2. Caches `InjectionMetadata`
             ├─> 3. Queries `DefaultListableBeanFactory.resolveDependency()`
             └─> 4. Injects bean instances via Field / Setter reflection
```

### Advanced Resolution: `ObjectProvider<T>`

`ObjectProvider<T>` allows on-demand, non-blocking, and streamable dependency resolution:

```java
@Service
public class ReportService {
    @Autowired
    private ObjectProvider<CustomExporter> exporterProvider;

    public void export() {
        // Safe null-checked resolution:
        CustomExporter exporter = exporterProvider.getIfAvailable(() -> new DefaultCsvExporter());

        // Process all matching beans as a Java Stream:
        exporterProvider.stream().forEach(CustomExporter::warmUpCache);
    }
}
```

> [!CAUTION]
> **The `static` Field Trap:** `@Autowired` does **NOT** work on `static` fields. Spring injects dependencies into object instances managed in the container, never into static class definitions (`@Autowired private static Repo repo;` remains `null`).

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Core Mechanism:** Processed by `AutowiredAnnotationBeanPostProcessor` during the `postProcessProperties` bean lifecycle phase.
- **Resolution Pipeline:** `byType` $\to$ `@Qualifier` $\to$ `@Primary` $\to$ `byName` $\to$ `NoUniqueBeanDefinitionException`.
- **Constructor Injection:** `@Autowired` is optional on classes with a single constructor (Spring 4.3+).
- **Collection Injection:** Injects `List<T>` (ordered by `@Order`) or `Map<String, T>` (bean name $\to$ instance).
- **`ObjectProvider<T>`:** Enables optional, lazy, and streaming resolution (`getIfAvailable()`, `stream()`).
- **Static Trap:** Cannot inject into `static` fields.

**Common Follow-up Questions:**
- *"What happens if no bean of the requested type exists?"* → Spring throws `NoSuchBeanDefinitionException` unless configured with `@Autowired(required = false)`.
- *"What is the difference between `@Autowired` and `@Resource`?"* → `@Autowired` is Spring-specific and resolves `byType` first; `@Resource` (Jakarta standard) resolves `byName` first.
- *"Why is field injection discouraged compared to constructor injection?"* → Field injection hides dependencies, breaks immutability (`final` fields cannot be used), and makes pure POJO unit testing without Spring context impossible.

**Red Flags (DO NOT Say):**
- ❌ *"Spring resolves @Autowired dependencies by bean name first."* (It always resolves `byType` first; `byName` is the last fallback).
- ❌ *"You can use @Autowired on static utility fields."* (Static fields cannot be injected by Spring).
- ❌ *"@Autowired is required on every constructor in Spring Boot 3."* (It is completely optional on single-constructor classes).
