# What is the Difference Between ConfigMap and Secret?

---

## 🟢 Junior Level

**ConfigMap** and **Secret** are Kubernetes API objects used to decouple application configuration and credentials from container images:

```
  ┌──────────────────────┬──────────────────────────────┬──────────────────────────────────────────────────┐
  │ Object               │ Storage Format               │ Primary Purpose                                  │
  ├──────────────────────┼──────────────────────────────┼──────────────────────────────────────────────────┤
  │ **`ConfigMap`**      │ Plain text (UTF-8)           │ Non-sensitive configs (URLs, ports, profiles).   │
  │ **`Secret`**         │ Base64 encoded               │ Sensitive credentials (passwords, tokens, keys). │
  └──────────────────────┴──────────────────────────────┴──────────────────────────────────────────────────┘
```

```yaml
# 1. ConfigMap: Application URLs and flags
apiVersion: v1
kind: ConfigMap
metadata:
  name: payment-config
data:
  SPRING_PROFILES_ACTIVE: "prod"
  ORDER_SERVICE_URL: "http://order-service:80"
---
# 2. Secret: Encoded credentials
apiVersion: v1
kind: Secret
metadata:
  name: payment-secret
type: Opaque
data:
  # Base64 encoded value of "super_secret_db_pass"
  DB_PASSWORD: c3VwZXJfc2VjcmV0X2RiX3Bhc3M=
```

> [!CAUTION]
> **Base64 is NOT Encryption!** Base64 is merely an encoding scheme. Anyone with read access to the namespace can decode secrets instantly (`echo '...' | base64 -d`).

## 🟡 Middle Level

### Consumption Patterns: Environment Variables vs. Mounted Volumes

```
  ┌──────────────────────┬──────────────────────────────┬──────────────────────────────────────────────────┐
  │ Injection Method     │ Manifest Configuration       │ Dynamic Update Behavior                          │
  ├──────────────────────┼──────────────────────────────┼──────────────────────────────────────────────────┤
  │ **Env Variables**    │ `env.valueFrom` / `envFrom`  │ ❌ **Static:** Requires Pod restart to pick up   │
  │                      │                              │ new values.                                      │
  │ **Volume Mounts**    │ `volumes.configMap / secret` │ ✅ **Dynamic:** Kubelet updates mounted files in │
  │                      │                              │ the background without restarting the Pod.       │
  └──────────────────────┴──────────────────────────────┴──────────────────────────────────────────────────┘
```

### Full Application Example (Volume Mount + Env Injection)

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: payment-service
spec:
  replicas: 2
  template:
    spec:
      containers:
      - name: app
        image: payment-service:1.0
        envFrom:
        - configMapRef:
            name: payment-config
        volumeMounts:
        - name: cert-volume
          mountPath: /etc/ssl/certs
          readOnly: true
      volumes:
      - name: cert-volume
        secret:
          secretName: payment-tls-secret
```

## 🔴 Senior Level

### Enterprise Security Architecture: `etcd` Encryption & External Secrets

```
                                  ┌───────────────────────────────┐
                                  │ HashiCorp Vault / AWS Secrets │
                                  └───────────────┬───────────────┘
                                                  │
                                                  ▼
                                  ┌───────────────────────────────┐
                                  │ External Secrets Operator     │
                                  └───────────────┬───────────────┘
                                                  │ (Syncs into)
                                                  ▼
  ┌───────────────────────────────────────────────────────────────────────────────────────────────┐
  │ KUBERNETES SECRETS LAYER                                                                      │
  │ • Stored encrypted in `etcd` via AWS KMS / Cloud KMS Envelope Encryption                      │
  │ • Mounted into Pods via `tmpfs` (In-Memory RAM filesystems; never written to node disk)       │
  │ • RBAC restricts `get`, `list`, `watch` permissions to security officers only                 │
  └───────────────────────────────────────────────────────────────────────────────────────────────┘
```

1. **`etcd` Encryption at Rest:** By default, Kubernetes stores Secrets unencrypted in `etcd`. Production clusters must configure an `EncryptionConfiguration` provider (AES-GCM or Cloud KMS).
2. **RAM-Backed `tmpfs` Mounting:** Mounted Secrets are written to RAM-based `tmpfs` volumes, ensuring passwords are never flushed to physical host swap or disk blocks.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Core Distinction:** ConfigMap is plaintext for configs; Secret is base64-encoded for credentials.
- **Base64 Warning:** Base64 provides zero security; encryption requires **KMS Encryption at Rest** and strict **RBAC**.
- **Injection:** Both can be consumed as Environment Variables or Mounted Files.
- **Dynamic Updates:** Volume-mounted ConfigMaps/Secrets auto-update within ~60 seconds; environment variables require a pod restart.
- **Production Standard:** Use **External Secrets Operator (ESO)** or **Vault CSI Driver** rather than committing Secrets to Git.

**Common Follow-up Questions:**
- *"What are the standard Kubernetes Secret types?"* → `Opaque` (generic), `kubernetes.io/tls` (TLS cert/key), `kubernetes.io/dockerconfigjson` (image pull registry credentials), and `kubernetes.io/service-account-token`.
- *"Why should you never commit Secrets to Git repositories?"* → Git histories are permanent; instead, commit `ExternalSecret` custom resources that pull credentials from Vault/AWS at deployment time.
- *"What is the size limit for a ConfigMap or Secret?"* → **1 MiB** (enforced by the `etcd` maximum request size limit).

**Red Flags (DO NOT Say):**
- ❌ *"Kubernetes Secrets are secure out of the box because Base64 encrypts the password."* (Base64 is plain encoding, reversible with a single command).
- ❌ *"Changing a ConfigMap automatically updates environment variables inside running containers."* (Process environment variables are immutable after OS process spawn; only volume mounts update dynamically).
- ❌ *"You can store large 500MB configuration datasets inside a ConfigMap."* (ConfigMaps are strictly limited to 1MB).
