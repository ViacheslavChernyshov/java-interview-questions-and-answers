# What is Dockerfile?

---

## 🟢 Junior Level

A **Dockerfile** is a declarative, plain-text configuration file containing a sequence of ordered instructions used by Docker to assemble an immutable **container image**:

```dockerfile
# 1. Base Image: Minimal Java 21 Runtime
FROM eclipse-temurin:21-jre-alpine

# 2. Set working directory inside container
WORKDIR /app

# 3. Copy compiled application JAR
COPY target/service.jar app.jar

# 4. Expose application port
EXPOSE 8080

# 5. Execution command when container boots
ENTRYPOINT ["java", "-jar", "app.jar"]
```

```bash
# Build the image from Dockerfile in current directory:
docker build -t my-service:1.0 .

# Run the container:
docker run -d -p 8080:8080 my-service:1.0
```

## 🟡 Middle Level

### The Build Context & Layer Caching Mechanics

When executing `docker build .`:
1. The Docker CLI packages everything in the directory into a tar stream called the **Build Context** and sends it to the Docker Daemon / BuildKit.
2. Use **`.dockerignore`** to exclude `.git`, `target/`, IDE configs, and secrets from entering the build context.

```
  Layer Invalidation Rule:
  • Each `RUN`, `COPY`, and `ADD` instruction creates a distinct, immutable filesystem layer.
  • If a layer's cache is invalidated (e.g. source file modified), ALL subsequent layers 
    must be completely rebuilt from scratch!
```

### The Dependency Layering Pattern for Maven/Gradle

```dockerfile
# ❌ ANTI-PATTERN: Re-downloads all internet dependencies on every 1-line code change:
COPY . .
RUN mvn clean package

# ✅ PRODUCTION PATTERN: Caches third-party JARs separately:
WORKDIR /build
COPY pom.xml .
RUN mvn dependency:go-offline -B  # Layer is cached until pom.xml changes!
COPY src ./src
RUN mvn package -DskipTests -B    # Fast rebuild (1-2 seconds)
```

## 🔴 Senior Level

### Production Multi-Stage Standard with Distroless / Non-Root

```dockerfile
# ==========================================
# Stage 1: Build & Compilation (Heavy JDK)
# ==========================================
FROM maven:3.9-eclipse-temurin-21-alpine AS builder
WORKDIR /workspace

COPY pom.xml .
RUN mvn dependency:go-offline -B

COPY src ./src
RUN mvn clean package -DskipTests -B

# ==========================================
# Stage 2: Production Runtime (Zero Attack Surface)
# ==========================================
FROM gcr.io/distroless/java21-debian12:nonroot
WORKDIR /app

COPY --from=builder --chown=nonroot:nonroot /workspace/target/*.jar app.jar

USER nonroot
EXPOSE 8080

# Production JVM container flags (Cgroups v2 awareness):
ENTRYPOINT ["java", \
    "-XX:+UseZGC", \
    "-XX:MaxRAMPercentage=75.0", \
    "-XX:+ExitOnOutOfMemoryError", \
    "-jar", "app.jar"]
```

### Senior Edge Cases: `musl` vs. `glibc` Compatibility

- **Alpine (`musl libc`) Trap:** Alpine Linux uses `musl` rather than GNU `glibc`. High-performance Java native libraries (e.g., Netty Epoll transport, RocksDB, Snappy compression, Profilers like Async-Profiler) can fail or trigger segmentation faults.
- **Senior Solution:** For mission-critical high-throughput services, use **Debian-Slim** (`eclipse-temurin:21-jre-jammy`) or **Google Distroless** to ensure 100% `glibc` binary compatibility.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Declarative script defining base images, file copies, build commands, and entrypoints.
- **Layer Caching:** Re-orders steps so rarely modified instructions (`pom.xml` dependency fetching) execute before frequently modified steps (`COPY src`).
- **Build Context:** The directory streamed to the daemon; must be filtered with `.dockerignore`.
- **Multi-Stage Builds:** Standard practice to isolate build tools (Maven/JDK) from minimal runtime images (JRE/Distroless).
- **Security Invariant:** Always enforce non-root execution (`USER nonroot`).

**Common Follow-up Questions:**
- *"What is the difference between `COPY` and `ADD`?"* → `COPY` copies local files directly; `ADD` can unpack local tarballs and download remote URLs (prefer `COPY` for predictability).
- *"How does Docker calculate layer cache hits?"* → For `RUN`, it compares the command string; for `COPY`/`ADD`, it computes the SHA-256 checksum of the copied files plus the parent layer's hash.
- *"Why is `-XX:MaxRAMPercentage` preferred over `-Xmx` in Docker containers?"* → It dynamically calculates the JVM heap size based on the container's Cgroup memory limit, preventing OOMKills during Kubernetes pod resizing.

**Red Flags (DO NOT Say):**
- ❌ *"Every line in a Dockerfile boots up a new virtual machine."* (Instructions run inside temporary containers on top of the host kernel).
- ❌ *"Running as root inside a Docker container is harmless because containers are completely isolated."* (Root in an unmapped container is root on the host kernel; container escapes compromise the host).
- ❌ *"Using `latest` tag is fine for production base images."* (Breaks build determinism and automated rollbacks).
