# What is Node in Kubernetes?

---

## 🟢 Junior Level

A **Node** is a worker machine (either a physical bare-metal server or a virtual machine) that provides compute, memory, and network resources to execute containerized Pods:

```
  Construction Site Analogy:
  • Control Plane ──► The Headquarters (Dispatches blueprints and schedules shifts).
  • Node          ──► The Construction Site (The physical location where work happens).
  • Pod           ──► The Work Crew (Executing tasks inside the construction site).
```

```
  3 Essential Components Running on Every Node:
  1. `kubelet`          ──► The Node Agent: Communicates with the API server, manages container lifecycles.
  2. `kube-proxy`       ──► The Network Dispatcher: Configures iptables/IPVS rules to route Service traffic.
  3. Container Runtime  ──► The Engine: OCI-compliant container runtime (`containerd` or `CRI-O`).
```

## 🟡 Middle Level

### Node Resource Allocation Math

Kubernetes prevents worker nodes from crashing due to OS starvation by partitioning capacity:

```
  ┌─────────────────────────────────────────────────────────────────────────────────┐
  │ TOTAL NODE HARDWARE CAPACITY (e.g. 16 Cores CPU, 64 GiB RAM)                    │
  ├───────────────────┬───────────────────┬───────────────────┬─────────────────────┤
  │ `kube-reserved`   │ `system-reserved` │ Eviction Threshold│ **ALLOCATABLE**     │
  │ (Kubelet/Daemon)  │ (Linux OS / sshd) │ (Buffer ~100MiB)  │ (Available to Pods) │
  │ ~1 CPU, 2 GiB     │ ~0.5 CPU, 1 GiB   │ Memory buffer     │ **~14.5 CPU, 60 GiB**│
  └───────────────────┴───────────────────┴───────────────────┴─────────────────────┘
```

$$\text{Allocatable} = \text{Capacity} - (\text{kube-reserved} + \text{system-reserved} + \text{hard-eviction-threshold})$$

### Pod Eviction & Quality of Service (QoS) Classes

When a node enters a resource pressure condition (e.g. `MemoryPressure`), `kubelet` evicts pods in strict order:

```
  ┌──────────────────┬──────────────────────────────┬──────────────────────────────────────────────────┐
  │ QoS Class        │ Resource Specification       │ Eviction Hierarchy & Risk                        │
  ├──────────────────┼──────────────────────────────┼──────────────────────────────────────────────────┤
  │ **BestEffort**   │ Zero requests & Zero limits  │ 💥 **Evicted First** (Killed immediately)        │
  │ **Burstable**    │ Requests < Limits            │ ⚠️ **Evicted Second** (If exceeding requests)    │
  │ **Guaranteed**   │ Requests == Limits (CPU+RAM) │ 🛡️ **Evicted Last** (Maximum stability)          │
  └──────────────────┴──────────────────────────────┴──────────────────────────────────────────────────┘
```

## 🔴 Senior Level

### Node Placement: Taints, Tolerations & Node Affinity

Senior architects control exactly where workloads land across specialized hardware:

```yaml
# 1. Taint placed on GPU worker nodes (Rejects standard pods):
# kubectl taint nodes gpu-node-01 accelerator=nvidia-h100:NoSchedule

# 2. Toleration + Node Affinity on specialized ML Pod:
spec:
  tolerations:
  - key: "accelerator"
    operator: "Equal"
    value: "nvidia-h100"
    effect: "NoSchedule"
  affinity:
    nodeAffinity:
      requiredDuringSchedulingIgnoredDuringExecution:
        nodeSelectorTerms:
        - matchExpressions:
          - key: topology.kubernetes.io/zone
            operator: In
            values: ["us-east-1a", "us-east-1b"]
```

### The NotReady Node Lifecycle Timeline

```
  T+0s:    Worker node loses network connectivity or suffers a kernel panic.
  T+40s:   `kube-controller-manager` flags Node condition as `NotReady` (Heartbeat grace period).
  T+5m:    `pod-eviction-timeout` expires; Control Plane begins evicting and rescheduling pods onto healthy nodes.
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Physical or virtual worker server running pods under the orchestration of the Control Plane.
- **Node Stack:** `kubelet` (agent), `kube-proxy` (network), `containerd` / `CRI-O` (runtime).
- **Allocatable Math:** Total capacity minus OS and K8s daemon reserves.
- **QoS Eviction:** `BestEffort` pods are killed first; `Guaranteed` pods are killed last.
- **Placement Controls:** **Taints & Tolerations** (repel pods) vs. **Node Affinity** (attract pods).

**Common Follow-up Questions:**
- *"What happens when a Node crashes in production?"* → The node status becomes `NotReady`; after a 5-minute eviction grace period, the controller-manager marks its pods as `Terminating` and reschedules them on healthy nodes.
- *"Why did Kubernetes remove dockershim in version 1.24?"* → Docker is an entire container suite; Kubernetes only needs the lightweight Container Runtime Interface (CRI), making direct `containerd` or `CRI-O` integrations faster and less resource-intensive.
- *"How do you safely take a worker node offline for maintenance?"* → Execute `kubectl cordon <node>` (prevents new pods) followed by `kubectl drain <node> --ignore-daemonsets` (gracefully evicts existing pods).

**Red Flags (DO NOT Say):**
- ❌ *"A Node is a Docker container inside Kubernetes."* (A Node is the underlying virtual or physical host machine running the container runtime).
- ❌ *"Pods can consume 100% of a physical server's CPU and RAM."* (Pods are restricted to `Allocatable` resources to protect the host OS).
- ❌ *"When a Node dies, Kubernetes immediately moves pods within 1 second."* (It waits for the node heartbeat timeout and eviction grace period to avoid flapping).
