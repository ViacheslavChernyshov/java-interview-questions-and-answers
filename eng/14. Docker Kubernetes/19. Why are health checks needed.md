# Why are Health Checks Needed?

---

## 🟢 Junior Level

In Kubernetes, **Health Checks** (Probes) are the sensory mechanisms that allow `kubelet` to observe the true operational status of an application container rather than merely checking if its Linux process ID (PID) exists:

```
  The Doctor Analogy:
  • Startup Probe   ──► "Is the baby born and breathing on its own?" (Initial boot check).
  • Liveness Probe  ──► "Is the patient's heart still beating?" (Deadlock / crash detection ➔ Restart).
  • Readiness Probe ──► "Is the patient ready to run a marathon?" (Traffic gatekeeper ➔ Load balance).
```

```yaml
# Complete Production Probe Triad for Spring Boot:
containers:
- name: payment-api
  image: payment-api:1.0
  # 1. Startup Probe: Disables Liveness/Readiness during cold start
  startupProbe:
    httpGet: { path: /actuator/health/liveness, port: 8080 }
    failureThreshold: 30 # 30 * 3s = 90s grace window
    periodSeconds: 3

  # 2. Liveness Probe: Recovers frozen / deadlocked processes
  livenessProbe:
    httpGet: { path: /actuator/health/liveness, port: 8080 }
    periodSeconds: 10
    failureThreshold: 3

  # 3. Readiness Probe: Prevents traffic during warmup / DB reconnects
  readinessProbe:
    httpGet: { path: /actuator/health/readiness, port: 8080 }
    periodSeconds: 5
    failureThreshold: 2
```

## 🟡 Middle Level

### The Triad Execution Lifecycle

```
  [Container Starts]
          │
          ▼
  [Startup Probe Loops] ──► (Fails 30 times? ──► Kill Container & CrashLoopBackOff)
          │
          ▼ (Passes Once!)
  ┌───────────────────────────────────────────────────────────────┐
  │ STARTUP PROBE STOPS FOREVER.                                  │
  │ LIVENESS & READINESS PROBES ACTIVATE CONCURRENTLY:            │
  ├───────────────────────────────┬───────────────────────────────┤
  │ **Liveness Probe**            │ **Readiness Probe**           │
  │ • Fails? ──► Kills container. │ • Fails? ──► Detaches from VIP│
  │ • Recovers internal deadlocks.│ • Prevents HTTP 502/503 errors│
  └───────────────────────────────┴───────────────────────────────┘
```

## 🔴 Senior Level

### Spring Boot 3.x Native Actuator Probes Architecture

When Spring Boot 3.x detects it is running inside a Kubernetes container, it automatically configures dedicated health groups:

```yaml
# application.yml
management:
  endpoint:
    health:
      probes:
        enabled: true
  health:
    livenessstate:
      enabled: true
    readinessstate:
      enabled: true
```

```
  ┌─────────────────────────────────┬─────────────────────────────────────────────────────────────────────────────────┐
  │ Actuator Endpoint               │ Health Indicators Evaluated                                                     │
  ├─────────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ `/actuator/health/liveness`     │ • `LivenessState` (Internal JVM state, fatal memory limits, active event loop). │
  │ `/actuator/health/readiness`    │ • `ReadinessState` (HikariCP DB connections, Kafka consumer groups, Disk space).│
  └─────────────────────────────────┴─────────────────────────────────────────────────────────────────────────────────┘
```

### Production Checklist for Zero-Downtime Health Checking

1. **Never check external dependencies in Liveness:** If Redis blips, you do not want 100 microservices restarting simultaneously.
2. **Always pair Startup Probes with Liveness:** Avoids setting arbitrary `initialDelaySeconds: 120` that blinds Kubernetes to real runtime deadlocks for 2 minutes.
3. **Timeout Tuning:** Set `timeoutSeconds: 2` to avoid hanging probe goroutines on sluggish threads.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **The Probe Triad:** Startup (protects boot), Liveness (kills on deadlock), Readiness (gates traffic routing).
- **The Process Reality:** A container PID can be active while the application is frozen; probes detect true health.
- **Startup Probe Advantage:** Allows slow JVM cold starts up to 90 seconds without slowing down fast deadlock detection during steady-state.
- **Zero-Downtime Enabler:** Deployments wait for Readiness Probes to pass before routing live user traffic.
- **Actuator Standard:** Use Spring Boot `/actuator/health/liveness` and `/actuator/health/readiness`.

**Common Follow-up Questions:**
- *"What happens if an application lacks any configured probes in Kubernetes?"* → Kubernetes assumes the container is always 100% healthy as long as its PID runs, routing user requests to deadlocked or uninitialized pods and causing 502/503 outages.
- *"How do probes interact during container termination?"* → When a pod is deleted, Kubernetes sets the pod phase to `Terminating`, immediately disables readiness probes, and removes the pod from Service endpoints while the container executes graceful shutdown.
- *"Why should you never use `exec: cat /tmp/healthy` for a Java REST API?"* → Because a shell command only checks if a file exists on disk, ignoring whether the Spring HTTP thread pool is deadlocked or out of memory.

**Red Flags (DO NOT Say):**
- ❌ *"Health checks are optional because Kubernetes automatically restarts containers that throw Java exceptions."* (Kubernetes only tracks process exit codes; unhandled exceptions inside running JVMs are invisible to K8s without probes).
- ❌ *"All three probes should point to the exact same `/actuator/health` URL without groups."* (This couples DB outages to full cluster container restarts).
- ❌ *"Readiness probes kill containers if database queries fail."* (Readiness probes only detach the pod from the load balancer).
