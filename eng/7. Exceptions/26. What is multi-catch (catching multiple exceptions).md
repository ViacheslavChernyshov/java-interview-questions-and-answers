# What is multi-catch (catching multiple exceptions)?

---

## 🟢 Junior Level

**Multi-Catch** is a language feature introduced in Java 7 (Project Coin) that allows a single `catch` block to handle **multiple distinct exception types** using the pipe (`|`) delimiter.

```java
// ✅ Java 7+ Multi-Catch: Eliminates duplicate catch blocks
try {
    processData();
} catch (IOException | SQLException e) {
    log.error("Resource access error: {}", e.getMessage(), e);
    throw new ServiceException("Data pipeline failed", e);
}
```

```java
// Prior to Java 7: Required copy-pasting duplicate code:
try {
    processData();
} catch (IOException e) {
    log.error("Resource access error: {}", e.getMessage(), e);
    throw new ServiceException("Data pipeline failed", e);
} catch (SQLException e) {
    log.error("Resource access error: {}", e.getMessage(), e);
    throw new ServiceException("Data pipeline failed", e);
}
```

## 🟡 Middle Level

### The 2 Strict Compiler Rules of Multi-Catch

#### 1. Alternatives Cannot Be Related by Inheritance
You cannot include two exception types where one is a subclass of the other:

```java
// ❌ COMPILATION ERROR:
// "The exception FileNotFoundException is already caught by the alternative IOException"
try {
    readFile();
} catch (FileNotFoundException | IOException e) { ... }

// ✅ CORRECT: Use only the superclass:
try {
    readFile();
} catch (IOException e) { ... }
```

#### 2. The Exception Variable is Implicitly `final`
In multi-catch, the exception parameter `e` is **implicitly `final`** and cannot be reassigned:

```java
try {
    doWork();
} catch (IOException | SQLException e) {
    // ❌ COMPILATION ERROR: The parameter e of a multi-catch clause cannot be assigned
    e = new IOException("Replacement"); 
}
```

## 🔴 Senior Level

### Precise Rethrow (Java 7+ Compiler Type Inference)

Before Java 7, catching a broad `Exception` and rethrowing it forced the method to declare `throws Exception`:

```java
// Java 7+ Precise Rethrow:
public void execute() throws IOException, SQLException { // Declares precise checked types!
    try {
        if (condition) throw new IOException("I/O error");
        else throw new SQLException("SQL error");
    } catch (Exception e) {
        log.error("Intercepted error, rethrowing...", e);
        // ✅ javac statically analyzes the `try` block and infers that `e`
        // can ONLY be IOException or SQLException!
        throw e; 
    }
}
```

### Under the Hood: Bytecode Exception Table Generation

In the compiled `.class` bytecode, multi-catch does **not** create a special synthetic compound type. Instead, the `javac` compiler generates **individual Exception Table entries** that share the exact same bytecode `target` address:

```
  Exception Table:
  from    to    target    type
     0    14        17    Class java/io/IOException
     0    14        17    Class java/sql/SQLException
```

### Reflection Code Simplification

Multi-catch dramatically improves the readability of Java Reflection code:

```java
try {
    Method method = targetClass.getDeclaredMethod("process");
    method.invoke(targetInstance);
} catch (NoSuchMethodException | IllegalAccessException | InvocationTargetException e) {
    throw new ReflectionOperationException("Failed to invoke reflective method", e);
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Java 7 syntax allowing multiple exception types in one `catch` using the pipe `|` operator.
- **Rule 1 (Inheritance):** Types in multi-catch must be disjoint; parent and child cannot be listed together (`FileNotFoundException | IOException` fails compilation).
- **Rule 2 (Finality):** The variable `e` in multi-catch is implicitly `final` and cannot be reassigned.
- **Bytecode:** Generates multiple Exception Table entries sharing the same target jump address.
- **Precise Rethrow:** `throw e` from `catch (Exception e)` preserves the precise union of checked exception types in the method signature.

**Common Follow-up Questions:**
- *"What runtime type is returned by `e.getClass()` inside a multi-catch block?"* → It returns the exact runtime class of the thrown exception (e.g. `java.io.FileNotFoundException`), not a synthetic union type.
- *"Why are subclass alternatives forbidden in multi-catch?"* → Because listing a subclass alongside its parent is redundant dead code, as the parent type already matches all instances of the child.
- *"Can you catch `InterruptedException` in a multi-catch block?"* → Yes, but if you do, you must check `if (e instanceof InterruptedException)` to restore the thread interrupt flag via `Thread.currentThread().interrupt()`.

**Red Flags (DO NOT Say):**
- ❌ *"Multi-catch creates a new compound exception object in memory."* (It is pure syntactic sugar; the original exception object is caught directly).
- ❌ *"You can reassign the variable `e` inside a multi-catch block."* (The variable `e` is strictly `final`).
- ❌ *"Multi-catch allows catching `Exception` and `IOException` together."* (Violates the inheritance exclusion rule).
