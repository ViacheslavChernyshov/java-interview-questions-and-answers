# When should you create your own exceptions?

---

## 🟢 Junior Level

Create custom exceptions when standard Java standard library exceptions cannot clearly express your application's domain logic.

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │         ✅ WHEN TO CREATE CUSTOM EXCEPTIONS            │         ❌ WHEN TO USE STANDARD JDK EXCEPTIONS         │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ • To model **specific domain business errors**         │ • Invalid method arguments (`IllegalArgumentException`)│
  │   (`InsufficientFundsException`, `OrderShippedException)│ • Invalid object state (`IllegalStateException`)       │
  │ • To attach **structured diagnostic context**          │ • Missing element in collection (`NoSuchElementException)│
  │   (`orderId`, `retryAfterSeconds`, `errorCode`)        │ • Unsupported feature (`UnsupportedOperationException`)│
  │ • To map to **distinct HTTP status codes** in REST     │ • Uninitialized pointers (`NullPointerException`)      │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

```java
// ✅ Clean Custom Domain Exception:
if (account.getBalance().compareTo(amount) < 0) {
    throw new InsufficientFundsException(account.getId(), amount, account.getBalance());
}

// ❌ Unnecessary Custom Exception (Use standard JDK exception instead):
if (age < 0) {
    throw new IllegalArgumentException("Age cannot be negative: " + age);
}
```

## 🟡 Middle Level

### The 4 Valid Architectural Scenarios for Custom Exceptions

1. **Domain Event Modeling:** In Domain-Driven Design (DDD), exceptional conditions represent significant business domain events that callers must react to explicitly.
2. **Layer Boundary Translation:** Encapsulating infrastructure-specific technologies (e.g. wrapping checked `SQLException` into unchecked `RepositoryStorageException`).
3. **Structured API Error Responses:** Providing typed payload parameters that Spring Boot's `@RestControllerAdvice` converts directly into RFC 9457 JSON fields:
   ```java
   @ExceptionHandler(RateLimitExceededException.class)
   public ResponseEntity<ProblemDetail> handleRateLimit(RateLimitExceededException ex) {
       ProblemDetail pd = ProblemDetail.forStatusAndDetail(HttpStatus.TOO_MANY_REQUESTS, ex.getMessage());
       return ResponseEntity.status(HttpStatus.TOO_MANY_REQUESTS)
           .header(HttpHeaders.RETRY_AFTER, String.valueOf(ex.getRetryAfterSeconds()))
           .body(pd);
   }
   ```
4. **Hierarchical Catch Grouping:** Organizing exceptions into an inheritance tree so callers can catch all subdomain errors in a single catch block.

## 🔴 Senior Level

### Designing a Domain Exception Hierarchy

```
                      java.lang.RuntimeException
                                  │
                       BaseDomainException (Abstract)
                         (Stores ErrorCode & Timestamp)
                                  │
             ┌────────────────────┴────────────────────┐
             ▼                                         ▼
   OrderDomainException                      PaymentDomainException
     ├── OrderNotFoundException (404)          ├── InsufficientFundsException (422)
     └── OrderAlreadyCancelledException (409)  └── PaymentGatewayTimeoutException (504)
```

```java
// Allows high-level caller to catch all order-related failures generically:
try {
    orderService.processOrder(orderId);
} catch (OrderDomainException e) {
    log.warn("Order processing rejected: {}", e.getMessage());
}
```

### The Control Flow Anti-Pattern (Benchmark Reality)

```java
// ❌ ANTI-PATTERN: Using exceptions for normal control flow
try {
    User user = userService.findUser(id); // Throws UserFoundException if user exists
} catch (UserFoundException e) {
    // Normal happy-path execution
}
```
- **Performance Benchmark:**
  - Returning `Optional<User>` takes $\approx 10\,\text{ns}$ and zero memory allocation.
  - Throwing `UserFoundException` takes $\approx 1{,}000\text{--}5{,}000\,\text{ns}$ ($100\times\text{--}500\times$ slower) because the JVM must inspect and record the native thread call stack frames.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **When to Create:** Business domain rules, custom diagnostic fields, layer boundary translation, distinct REST HTTP error mapping.
- **When to Avoid:** Standard parameter/state checks (`IllegalArgumentException`, `IllegalStateException`), or when standard exceptions describe the error completely.
- **Hierarchy Design:** Base abstract domain class (`BaseDomainException`) $\to$ Subdomain group $\to$ Specific leaf exceptions.
- **Control Flow Anti-Pattern:** Never use exceptions for normal branching; `Optional<T>` is $100\times\text{--}500\times$ faster.
- **Microservices:** Never serialize custom exception classes across REST/gRPC boundaries; translate to RFC 9457 `ProblemDetail` or gRPC status codes.

**Common Follow-up Questions:**
- *"What standard JDK exceptions should every Java developer know before creating custom ones?"* → `IllegalArgumentException`, `IllegalStateException`, `NullPointerException`, `IndexOutOfBoundsException`, `NoSuchElementException`, `UnsupportedOperationException`, `ConcurrentModificationException`.
- *"Why is having too many custom exception classes an architectural code smell?"* → It leads to "parallel class hierarchy bloat," increases Metaspace usage, and complicates maintenance without providing diagnostic value.
- *"How should error codes be associated with custom exceptions?"* → Use a strongly typed `ErrorCode` enum holding the machine-readable error string, default HTTP status code, and documentation URL.

**Red Flags (DO NOT Say):**
- ❌ *"I create a custom exception class for every single validation field in my forms."* (Use `MethodArgumentNotValidException` with field error collections).
- ❌ *"Using exceptions for control flow is fine in high-throughput systems."* (Stack trace capture creates severe CPU latency bottlenecks).
- ❌ *"Always use standard JDK exceptions and never create custom ones."* (Custom exceptions are essential for expressing domain business logic).
