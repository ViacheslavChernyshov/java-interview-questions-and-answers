# What is exception chaining?

---

## 🟢 Junior Level

**Exception Chaining** is the Java mechanism where one exception explicitly references another as its underlying cause (**`cause`**).

When an exception is chained, the Java runtime produces a linked chain of errors displayed in log outputs using the **`Caused by:`** header:

```java
try {
    // Low-level JDBC call that throws SQLException
    connection.executeQuery("SELECT * FROM accounts WHERE id = 10");
} catch (SQLException e) {
    // Chaining: Embeds the low-level SQLException into a domain runtime exception
    throw new AccountLookupException("Failed to load account 10 from database", e);
    //                                                                         ^-- Root Cause
}
```

```
com.bank.AccountLookupException: Failed to load account 10 from database
    at com.bank.AccountService.getAccount(AccountService.java:34)
Caused by: org.postgresql.util.PSQLException: Connection refused
    at org.postgresql.core.v3.ConnectionFactoryImpl.openConnection(ConnectionFactoryImpl.java:82)
```

## 🟡 Middle Level

### The Internal Mechanism of `cause` in `Throwable`

Inside `java.lang.Throwable`, the causal relationship is maintained via a private reference:

```java
private Throwable cause = this; // Self-reference sentinel indicating uninitialized cause
```
- Initialized by passing `cause` into constructors: `super(message, cause)`.
- Initialized post-construction via: `throwable.initCause(cause)`.

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ Cause (Exception Chaining)                             │ Suppressed Exceptions                                  │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ • Answers: **"Why did this operation fail?"**          │ • Answers: **"What else went wrong during cleanup?"**  │
  │ • Linked via `throwable.getCause()`                    │ • Array retrieved via `throwable.getSuppressed()`      │
  │ • Represents the **root prerequisite trigger**         │ • Represents **secondary failures in TWR `close()`**   │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

## 🔴 Senior Level

### Programmatic Root Cause Extraction

To inspect the true origin of a deeply nested exception chain (e.g. `SpringMVC -> Service -> Hibernate -> JDBC -> SocketTimeoutException`):

```java
public static Throwable findRootCause(Throwable throwable) {
    Objects.requireNonNull(throwable);
    Throwable root = throwable;
    while (root.getCause() != null && root.getCause() != root) {
        root = root.getCause();
    }
    return root;
}

// Or using Apache Commons Lang:
Throwable root = ExceptionUtils.getRootCause(throwable);
```

### Microservice Boundary Sanitization (RFC 9457)

> [!WARNING]
> Never serialize full multi-layer exception chains across remote HTTP, gRPC, or messaging boundaries.
> - Serializing deep Java exception chains across network sockets increases payload bandwidth and causes `ClassNotFoundException` if downstream clients lack internal framework classes.
> - **Production Solution:** Sanitize the causal chain at the API controller boundary and emit a clean RFC 9457 `ProblemDetail` or gRPC `Status` DTO.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Linking an underlying failure (`cause`) inside a higher-level exception; rendered as `Caused by:` in stack traces.
- **API:** Managed via `getCause()` and `initCause(Throwable)`.
- **Single Assignment:** `initCause()` can only be called once; repeated calls throw `IllegalStateException`.
- **Cause vs. Suppressed:** `cause` is the prerequisite reason for the failure; `suppressed` exceptions are parallel errors during resource cleanup.
- **Root Cause Extraction:** Traverse using `while (t.getCause() != null) t = t.getCause()`.
- **Network Boundaries:** Translate exception chains into RFC 9457 JSON DTOs rather than serializing them over network sockets.

**Common Follow-up Questions:**
- *"What happens if you attempt to create a cyclical causal loop like `A.initCause(B)` and `B.initCause(A)`?"* → The JVM detects the self-reference and throws an `IllegalArgumentException`.
- *"Why is `cause` initialized to `this` by default in `Throwable`?"* → A self-referential `this` pointer is a sentinel value indicating that no cause has been assigned yet, differentiating an uninitialized cause from a deliberately assigned `null` cause.
- *"How many levels of `cause` nesting are acceptable in enterprise code?"* → Typically 2–3 architectural layers (e.g. `DomainException -> InfrastructureException -> DriverException`); deeper chains indicate excessive wrapping without adding value.

**Red Flags (DO NOT Say):**
- ❌ *"Exception chaining is the same thing as suppressed exceptions."* (Chaining models causal root causes; suppression models parallel cleanup errors).
- ❌ *"You can call `initCause()` repeatedly to append multiple causes."* (`initCause()` can only be called once per exception).
- ❌ *"Writing `new ServiceException(e.getMessage())` correctly chains the exception."* (Passing only the message drops the cause object and its stack trace).
