# What are suppressed exceptions?

---

## 🟢 Junior Level

**Suppressed Exceptions** are a mechanism introduced in Java 7 that allows a **primary in-flight exception** to retain a list of secondary exceptions that occurred during resource cleanup or batch operations.

In standard Try-With-Resources (TWR), if both the `try` block body and the automatic `close()` method throw exceptions, the `try` block exception is thrown as the primary error, while the `close()` exception is attached as a **suppressed exception**:

```java
try (AutoCloseableResource r = new AutoCloseableResource()) {
    throw new IllegalStateException("Primary business failure");
} // r.close() also throws IOException("Resource cleanup failure")
```

```
java.lang.IllegalStateException: Primary business failure
    at com.example.Demo.run(Demo.java:12)
    Suppressed: java.io.IOException: Resource cleanup failure
        at com.example.AutoCloseableResource.close(AutoCloseableResource.java:8)
```

```java
// Inspecting suppressed exceptions programmatically:
try {
    process();
} catch (Exception e) {
    for (Throwable suppressed : e.getSuppressed()) {
        log.warn("Secondary cleanup failure: {}", suppressed.getMessage());
    }
}
```

## 🟡 Middle Level

### The `Throwable` API for Suppression

Java provides two `final` methods in `java.lang.Throwable` to manage suppression:

```java
public final void addSuppressed(Throwable exception);
public final Throwable[] getSuppressed();
```

### Invariant Rules of `addSuppressed`
1. **Self-Suppression Forbidden:** Calling `e.addSuppressed(e)` throws an **`IllegalArgumentException`** (*"Self-suppression not permitted"*).
2. **Null Forbidden:** Calling `e.addSuppressed(null)` throws a **`NullPointerException`**.
3. **Lazy Internal Allocation:** The internal `suppressedExceptions` list in `Throwable` is allocated lazily to avoid memory overhead on normal exceptions.
4. **Disabling Suppression:** Subclasses can disable suppression by passing `enableSuppression = false` into the 4-argument `Throwable` constructor.

## 🔴 Senior Level

### Pattern: Batch Error Aggregator

Suppressed exceptions are useful for collecting errors across multi-task batch pipelines without aborting after the first failure:

```java
public class BatchJobExecutor {

    public void executeAll(List<RunnableTask> tasks) {
        BatchJobException batchError = null;

        for (RunnableTask task : tasks) {
            try {
                task.execute();
            } catch (Exception e) {
                if (batchError == null) {
                    batchError = new BatchJobException("Batch execution finished with errors");
                }
                batchError.addSuppressed(e); // Aggregate every worker error
            }
        }

        if (batchError != null) {
            throw batchError;
        }
    }
}
```

### Memory & Distributed Serialization Hazards

> [!WARNING]
> Accumulating hundreds of suppressed exceptions on a long-lived singleton object creates **severe heap memory leaks** because every suppressed `Throwable` retains its full call stack frames (`StackTraceElement[]`).
> - Furthermore, serializing a `Throwable` across distributed network protocols (RMI/JMX) transmits the entire recursive tree of suppressed exceptions, causing massive network payload spikes.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Java 7 mechanism allowing an exception to hold secondary failures via `addSuppressed()` and `getSuppressed()`.
- **Try-With-Resources:** TWR automatically attaches `close()` exceptions as suppressed onto the primary `try` exception.
- **Manual try-finally:** Suppressed exceptions do **NOT** occur automatically in legacy `finally` blocks; `finally` errors shadow `try` errors.
- **Log Formatting:** Logback and Log4j2 display them indented under the `Suppressed:` header.
- **Self-Suppression:** `e.addSuppressed(e)` throws `IllegalArgumentException`.

**Common Follow-up Questions:**
- *"What happens if `try` succeeds without error, but `close()` throws an exception in Try-With-Resources?"* → The `close()` exception is thrown as a normal, unsuppressed primary exception.
- *"How does exception suppression differ from exception chaining (`cause`)?"* → `cause` represents the underlying prerequisite condition that triggered the failure; `suppressed` exceptions are parallel or subsequent secondary failures.
- *"Can custom exceptions disable the suppressed exceptions feature?"* → Yes, by calling `super(message, cause, false, writableStackTrace)` where `enableSuppression = false`.

**Red Flags (DO NOT Say):**
- ❌ *"Suppressed exceptions happen automatically in traditional try-catch-finally blocks."* (Only Try-With-Resources attaches suppressed exceptions automatically).
- ❌ *"Suppressed exceptions are lost when logging via SLF4J."* (Standard loggers render all suppressed exceptions and their full stack traces).
- ❌ *"You can pass `null` into `addSuppressed()` to clear suppressed exceptions."* (Passing `null` throws `NullPointerException`).
