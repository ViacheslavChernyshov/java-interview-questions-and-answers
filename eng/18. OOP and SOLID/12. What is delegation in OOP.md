# What is Delegation in OOP?

---

## 🟢 Junior Level

**Delegation** is an Object-Oriented design technique where an object (the **Delegator**) receives a request and passes it to another helper object (the **Delegate**) to perform the actual work:

```
  Restaurant Manager Analogy:
  • When a customer orders catering from a Restaurant Manager (Delegator), the manager does not cook 
    the meal personally.
  • The manager delegates the cooking to the Head Chef (Delegate), while maintaining the customer interface!
```

```java
// 1. The Delegate (Performs the actual heavy lifting):
public class Printer {
    public void print(String document) {
        System.out.println("Printing physical paper: " + document);
    }
}

// 2. The Delegator (Exposes public API and forwards work to delegate):
public class DocumentService {
    private final Printer printer; // Composed delegate

    public DocumentService(Printer printer) {
        this.printer = printer;
    }

    public void processAndPrint(String doc) {
        System.out.println("Validating document...");
        printer.print(doc); // 👈 DELEGATION
    }
}
```

## 🟡 Middle Level

### Delegation vs. Inheritance vs. Dynamic Proxy

```
  ┌──────────────────────────────┬──────────────────────────────────┬──────────────────────────────────────────────────┐
  │ Mechanism                    │ Coupling & Implementation        │ Performance & Flexibility                        │
  ├──────────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **Inheritance**              │ Compile-time static coupling.    │ Fast (VTable), but rigid and breaks encapsulation│
  ├──────────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **Explicit Delegation**      │ Clean composition via forwarding │ 🏆 **Fast & Flexible**: JIT inlines calls        │
  │ (Method Forwarding)          │ methods (`delegate.method()`).   │ ($< 0.5\text{ns}$); swappable at runtime.        │
  ├──────────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **Dynamic Proxy**            │ Runtime reflection / Bytecode    │ Flexible, but reflection overhead                │
  │ (`java.lang.reflect.Proxy`)  │ generation (`InvocationHandler`).│ (~100–500ns per invocation).                     │
  └──────────────────────────────┴──────────────────────────────────┴──────────────────────────────────────────────────┘
```

### Delegation in the Java Standard Library

The JDK uses explicit delegation throughout `java.util.Collections` and `java.io`:

```java
// SynchronizedList wraps an underlying ArrayList and delegates with synchronization:
List<String> threadSafeList = Collections.synchronizedList(new ArrayList<>());

// How SynchronizedCollection implements delegation:
static class SynchronizedCollection<E> implements Collection<E> {
    final Collection<E> c; // The Delegate
    final Object mutex;

    public int size() {
        synchronized (mutex) { return c.size(); } // Delegated call inside lock!
    }

    public boolean add(E e) {
        synchronized (mutex) { return c.add(e); }  // Delegated call inside lock!
    }
}
```

## 🔴 Senior Level

### Design Patterns Powered by Delegation

Delegation is the architectural engine powering the majority of Gang of Four (GoF) structural and behavioral patterns:

```
  ┌──────────────────────────────┬─────────────────────────────────────────────────────────────────────────────────┐
  │ Design Pattern               │ How Delegation is Applied                                                       │
  ├──────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ **Decorator Pattern**        │ Wraps a delegate to add behavior (e.g. `BufferedInputStream` buffering reads). │
  │ **Adapter Pattern**          │ Translates calls from target interface to an incompatible delegate interface.   │
  │ **Strategy Pattern**         │ Delegates an algorithmic calculation to a swappable strategy object.            │
  │ **State Pattern**            │ Delegates state-dependent behavior to an internal state delegate object.        │
  │ **Proxy Pattern**            │ Intercepts access to a delegate to add lazy loading, caching, or security.      │
  └──────────────────────────────┴─────────────────────────────────────────────────────────────────────────────────┘
```

### Boilerplate Reduction & Modern Language Evolution

One common critique of delegation in Java is the boilerplate code required to forward 20 interface methods. Modern solutions include:

1. **Lombok `@Delegate` in Java:**
   ```java
   public class CustomListWrapper<T> {
       @Delegate // Lombok automatically generates forwarding methods for all List<T> methods!
       private final List<T> internalList = new ArrayList<>();
   }
   ```
2. **First-Class Native Delegation in Kotlin:**
   ```kotlin
   // Kotlin native class delegation:
   class CustomList<T>(private val inner: List<T>) : List<T> by inner
   ```

### JVM Performance: Inlining & Escape Analysis

When dependencies are composed as `private final` fields:
- The HotSpot JIT compiler detects **Monomorphic Call Sites** (a single concrete delegate class).
- The JIT compiler completely eliminates the delegation method call overhead through **Method Inlining**, compiling `documentService.processAndPrint()` directly into the delegate's raw assembly instructions!

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** An object passes execution to a composed helper object rather than inheriting from it.
- **Core Benefit:** Provides code reuse without the tight coupling and fragile base class hazards of inheritance.
- **JDK Examples:** `Collections.synchronizedList()`, `Collections.unmodifiableList()`, `FilterInputStream`.
- **Patterns Powered:** Decorator, Adapter, Strategy, State, and Proxy patterns.
- **JVM Optimization:** JIT compiler inlines monomorphic delegated calls to near-zero ($0\text{ns}$) overhead.

**Common Follow-up Questions:**
- *"What is Circular Delegation and how do you prevent it?"* → Circular delegation occurs when Object A delegates to Object B, which delegates back to Object A, causing a fatal `StackOverflowError`. Prevent it by enforcing strict directional dependency flow (A depends on B, never B on A).
- *"How does Delegation relate to the Dependency Inversion Principle (DIP)?"* → When the delegator delegates to an **interface** (`private final PaymentGateway gateway`) rather than a concrete class, it fulfills both Delegation and DIP.
- *"What is the difference between Delegation and Forwarding?"* → In strict theoretical OOP, *Delegation* passes the original caller's `this` context to the helper; in Java, what is commonly called delegation is technically *Method Forwarding* (explicitly calling methods on an internal reference).

**Red Flags (DO NOT Say):**
- ❌ *"Delegation and inheritance are the same thing because both reuse code."* (Inheritance creates compile-time coupling; delegation uses runtime composition).
- ❌ *"Delegation is always too slow for high-performance applications."* (JIT compiler inlines final delegate calls directly into machine code).
- ❌ *"You should use reflection-based dynamic proxies instead of explicit delegation for simple wrappers."* (Dynamic proxies carry reflection overhead; use explicit method forwarding for standard wrappers).
