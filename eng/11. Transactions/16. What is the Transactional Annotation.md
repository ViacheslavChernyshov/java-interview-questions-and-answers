# What is the @Transactional Annotation?

---

## 🟢 Junior Level

**`@Transactional`** is Spring Framework's declarative transaction management annotation.

Instead of writing manual boilerplate (`connection.setAutoCommit(false)`, `commit()`, `rollback()`), annotating a method with `@Transactional` instructs Spring to automatically manage transaction boundaries:

```java
@Service
public class UserService {

    @Autowired private UserRepository userRepository;
    @Autowired private NotificationService notificationService;

    @Transactional
    public void registerUser(User user) {
        userRepository.save(user);
        notificationService.sendWelcomeEmail(user);
        // Automatically COMMITS if method exits successfully.
        // Automatically ROLLS BACK if a RuntimeException or Error is thrown.
    }
}
```

### Core Annotation Attributes

```
  ┌──────────────────┬──────────────────────────────────────┬──────────────────────────────────────────────────┐
  │ Attribute        │ Description                          │ Default Value                                    │
  ├──────────────────┼──────────────────────────────────────┼──────────────────────────────────────────────────┤
  │ `propagation`    │ Transaction boundary behavior        │ `Propagation.REQUIRED`                           │
  │ `isolation`      │ Database isolation level             │ `Isolation.DEFAULT` (Database engine default)    │
  │ `readOnly`       │ Read-only performance optimization   │ `false`                                          │
  │ `rollbackFor`    │ Exceptions that trigger rollback     │ `RuntimeException.class`, `Error.class`          │
  │ `noRollbackFor`  │ Exceptions that should NOT rollback  │ `{}`                                             │
  │ `timeout`        │ Maximum execution time in seconds    │ `-1` (No timeout)                                │
  └──────────────────┴──────────────────────────────────────┴──────────────────────────────────────────────────┘
```

## 🟡 Middle Level

### Spring AOP Proxy Mechanics

```
  Client Call ──► Spring AOP Proxy ──► TransactionInterceptor ──► PlatformTransactionManager
                                                                           │
                                                    ┌──────────────────────┴──────────────────────┐
                                                    ▼                                             ▼
                                      Acquires JDBC Connection                      Executes Target Method
                                      Binds to ThreadLocal                          COMMITS or ROLLS BACK
```

1. **Proxy Creation:** Spring creates a dynamic proxy wrapper (CGLIB subclass by default in Spring Boot) around the `@Service` bean.
2. **Interception:** When an external client calls the method, `TransactionInterceptor` intercepts the call.
3. **Transaction Demarcation:** It queries `PlatformTransactionManager` (e.g. `JpaTransactionManager`), opens a transaction, and binds the connection to `TransactionSynchronizationManager` (`ThreadLocal`).
4. **Execution:** It invokes the target method. If an unchecked exception occurs, it triggers `rollback()`; otherwise, it executes `commit()`.

## 🔴 Senior Level

### Common Production Traps & Anti-Patterns

```
  ┌───┬──────────────────────────────────┬─────────────────────────────────────────────────────────────────────────────┐
  │ # │ Anti-Pattern / Bug               │ Root Cause & Correction                                                     │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────────────────┤
  │ 1 │ **Self-Invocation Proxy Bypass** │ Calling `this.innerMethod()` bypasses the proxy; `@Transactional` is ignored│
  │ 2 │ **Checked Exception Trap**       │ Checked exceptions (`Exception`) DO NOT trigger rollback by default!        │
  │   │                                  │ Fix: Always specify `@Transactional(rollbackFor = Exception.class)`.        │
  │ 3 │ **Private / Final Methods**      │ CGLIB cannot override `private` or `final` methods; silently ignored.       │
  │ 4 │ **Long Remote HTTP Calls**       │ Network I/O inside `@Transactional` holds JDBC connections open for seconds,│
  │   │                                  │ rapidly causing HikariCP connection pool starvation.                        │
  └───┴──────────────────────────────────┴─────────────────────────────────────────────────────────────────────────────┘
```

```java
// ✅ Production Standard for Transactional Service Methods:
@Transactional(
    propagation = Propagation.REQUIRED,
    isolation = Isolation.READ_COMMITTED,
    timeout = 10,
    rollbackFor = Exception.class // Ensures rollback for checked business exceptions!
)
public void executeFinancialSettlement(Order order) {
    orderRepository.updateStatus(order.getId(), OrderStatus.SETTLED);
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Purpose:** Declarative transaction management using Spring AOP proxies.
- **Rollback Default:** Automatically rolls back on **`RuntimeException` and `Error`**, but **NOT** on checked `Exception`.
- **Public Only:** Only works on **`public`** methods when called from outside the class.
- **Self-Invocation:** Calling `@Transactional` methods internally via `this` bypasses the AOP proxy and disables transactions.
- **ThreadLocal:** Transaction context is bound to `ThreadLocal`; spawning child threads (`@Async` or `CompletableFuture`) loses the transaction context.
- **HikariCP Protection:** Never perform slow external REST API calls or heavy file I/O inside `@Transactional`.

**Common Follow-up Questions:**
- *"Why does `@Transactional` fail on private methods?"* → Spring AOP proxies use inheritance (CGLIB) or interfaces (JDK Proxy); private methods cannot be overridden or intercepted by the proxy wrapper.
- *"How can you execute programmatic transactions when declarative `@Transactional` is too rigid?"* → Inject and use `TransactionTemplate` or `PlatformTransactionManager` directly.
- *"What happens if a `@Transactional` method calls an `@Async` method?"* → The `@Async` method executes on a separate worker thread with its own independent transaction context (or no transaction).

**Red Flags (DO NOT Say):**
- ❌ *"Checked exceptions automatically roll back Spring transactions by default."* (Checked exceptions do NOT trigger rollback unless `rollbackFor = Exception.class` is set).
- ❌ *"Calling `this.helperMethod()` inside the same class triggers transaction interception."* (Internal `this` calls bypass the Spring AOP proxy completely).
- ❌ *"Putting `@Transactional` on a Controller class is best practice."* (It holds database connections open during JSON serialization and HTTP response rendering).
