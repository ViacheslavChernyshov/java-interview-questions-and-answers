# What does RANK() and DENSE_RANK() do?

---

## 🟢 Junior Level

Both **`RANK()`** and **`DENSE_RANK()`** are SQL window functions that assign a ranking order (position) to rows based on values specified in an `ORDER BY` clause. Crucially, **duplicate values receive identical ranks**, but they handle subsequent numbers differently:

- **`RANK()` (Olympic Podium System):** Leaves **gaps** in rank sequence after ties. If two rows tie for 1st place, the next row receives 3rd place (`1, 1, 3`).
- **`DENSE_RANK()` (Consecutive Tier System):** Leaves **no gaps** after ties. If two rows tie for 1st place, the next row receives 2nd place (`1, 1, 2`).

**Simple Example:**
```sql
-- Exam scores: 100, 100, 85, 70
SELECT 
    student_name,
    score,
    ROW_NUMBER() OVER (ORDER BY score DESC) AS row_num,
    RANK() OVER (ORDER BY score DESC) AS rnk,
    DENSE_RANK() OVER (ORDER BY score DESC) AS dense_rnk
FROM exam_results;

-- Output:
-- student_name | score | row_num | rnk | dense_rnk
-- Alice        | 100   | 1       | 1   | 1
-- Bob          | 100   | 2       | 1   | 1         <-- Tied for 1st
-- Charlie      | 85    | 3       | 3   | 2         <-- RANK skips to 3; DENSE_RANK continues to 2
-- David        | 70    | 4       | 4   | 3
```

## 🟡 Middle Level

### Complete Ranking Comparison Matrix

| Function | Sequence for Tied Values `(100, 100, 85, 70)` | Sequence Gaps | Primary Use Case |
|---|---|---|---|
| **`ROW_NUMBER()`** | `1, 2, 3, 4` | No | Strict unique numbering, pagination |
| **`RANK()`** | `1, 1, 3, 4` | **Yes** | Competitions, leaderboards where position count matters |
| **`DENSE_RANK()`** | `1, 1, 2, 3` | **No** | Pay grades, price brackets, multi-tiered groupings |

### Analytical Distribution Functions

#### 1. `PERCENT_RANK()` (Relative Rank from 0.0 to 1.0)
Calculates relative percentile position across a partition using the formula:
$$\text{PERCENT\_RANK} = \frac{\text{RANK} - 1}{\text{Total Partition Rows} - 1}$$
```sql
-- Identify employees in the top 10% salary bracket
SELECT name, salary,
       ROUND(PERCENT_RANK() OVER (ORDER BY salary DESC)::numeric, 3) AS pct_rank
FROM employees;
-- 0.000 = Top Earner, 1.000 = Lowest Earner
```

#### 2. `NTILE(n)` (Bucket Segmentation)
Divides the partition as equally as possible into $N$ ordered buckets (e.g., quartiles, deciles):
```sql
-- Segment customers into 4 revenue quartiles (Top 25%, Upper-Mid, Lower-Mid, Bottom 25%)
SELECT customer_id, annual_spend,
       NTILE(4) OVER (ORDER BY annual_spend DESC) AS spend_quartile
FROM customer_analytics;
```

#### 3. `CUME_DIST()` (Cumulative Distribution)
Calculates the proportion of partition rows with values less than or equal to the current row value:
$$\text{CUME\_DIST} = \frac{\text{Count of preceding or peer rows}}{\text{Total Partition Rows}}$$

### Handling `NULL` Values in Ranking

By default in PostgreSQL:
- `ORDER BY col DESC` places `NULL` values **FIRST**. Unhandled `NULL` values will accidentally receive `rank = 1`!
- **Best Practice:** Always explicitly specify `NULLS LAST` or `NULLS FIRST`:

```sql
-- ✅ Ensure NULL scores do not claim 1st place!
SELECT name, score,
       RANK() OVER (ORDER BY score DESC NULLS LAST) AS contest_rank
FROM players;
```

## 🔴 Senior Level

### "Fair" Top-N Leaderboards: `RANK()` vs `LIMIT`

A common business bug in gaming, e-commerce, and financial applications is using `LIMIT` to select top performers:

```sql
-- ❌ UNFAIR TRUNCATION: Discards tied winners arbitrarily
SELECT player_id, score 
FROM leaderboard 
ORDER BY score DESC 
LIMIT 10;
-- If players in 10th, 11th, and 12th place all scored 950 points, 2 players are discarded at random!

-- ✅ FAIR COMPETITION SELECTION: Returns all tied winners
WITH ranked_leaderboard AS (
    SELECT player_id, score,
           RANK() OVER (ORDER BY score DESC) AS position
    FROM leaderboard
)
SELECT player_id, score, position
FROM ranked_leaderboard
WHERE position <= 10;
-- Emits 12 rows if there is a 3-way tie for 10th place.
```

### Physical Execution Internals

Inside PostgreSQL's `WindowAgg` engine:
- **`ROW_NUMBER()`** executes with minimal overhead ($O(N)$), simply incrementing an integer counter as tuples stream past.
- **`RANK()` and `DENSE_RANK()`** must maintain a **peer check buffer**. For every row, the engine compares the current tuple's sort attributes against the previous tuple. If identical, the current rank value is retained; if distinct, `RANK()` adds the accumulated tie counter while `DENSE_RANK()` increments by 1.

```sql
-- Optimizing WindowAgg by eliminating Sort nodes:
CREATE INDEX idx_leaderboard_score ON leaderboard(score DESC);

EXPLAIN (ANALYZE, BUFFERS)
SELECT player_id, score, RANK() OVER (ORDER BY score DESC)
FROM leaderboard;
-- WindowAgg (cost=... actual rows=1000000)
--   -> Index Only Scan using idx_leaderboard_score on leaderboard  <-- Zero Sort overhead!
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`RANK()`:** Ties receive the same rank; creates subsequent sequence gaps (`1, 1, 3`).
- **`DENSE_RANK()`:** Ties receive the same rank; no sequence gaps (`1, 1, 2`).
- **`ROW_NUMBER()`:** Strictly unique incrementing integers (`1, 2, 3`).
- **`NTILE(k)`:** Splits partition into $K$ equal-sized buckets (quartiles, deciles).
- **`PERCENT_RANK()`:** Normalized relative rank from `0.0` (top) to `1.0` (bottom).
- **`NULLS LAST`:** Crucial in `DESC` orderings so `NULL` values do not usurp rank 1.
- **Fair Leaderboard Pattern:** Use `RANK() ... WHERE position <= 10` instead of `LIMIT 10` to include all tied contestants.

**Common Follow-up Questions:**
- *"When would you choose DENSE_RANK() over RANK()?"* → When ranking tiers or salary bands where you need continuous grade numbers without missing steps (e.g. 1st tier, 2nd tier, 3rd tier).
- *"How do you calculate quartiles in SQL?"* → Using `NTILE(4) OVER (ORDER BY metric ASC)`.
- *"Why is `ROW_NUMBER()` slightly faster than `RANK()`?"* → `ROW_NUMBER()` increments a simple memory counter without running peer comparison checks against the previous row's sort keys.

**Red Flags (DO NOT Say):**
- ❌ *"RANK() and DENSE_RANK() produce identical output."* (RANK skips numbers after ties; DENSE_RANK never skips).
- ❌ *"LIMIT 10 is the standard way to award prizes in a tournament."* (LIMIT arbitrarily truncates tied contestants).
- ❌ *"NULL values are automatically placed at the end during descending sort."* (Postgres places NULLs FIRST in `DESC` by default unless `NULLS LAST` is specified).
