## 🔗 Key Connections Between Topics

### Topic: Indexes

```
Q1 (Why needed) → Q2 (B-tree) → Q3 (Composite) → Q4 (When) → Q5 (Disadvantages) → Q6 (Cardinality)
                                              ↓
                                    Q21 (Query Optimization)
```

**Key connections:**
- Q1 ↔ Q17 (MVCC): HOT updates are impossible on indexed columns
- Q2 ↔ Q18 (VACUUM): B-tree bloat → `REINDEX CONCURRENTLY`
- Q3 ↔ Q6 (Cardinality): Column ordering determined by selectivity and query predicates
- Q4 ↔ Q19 (ANALYZE): Table statistics determine whether the planner chooses an index
- Q5 ↔ Q21 (Optimization): Write amplification and balancing index overhead

### Topic: JOINs and Subqueries

```
Q7 (JOIN types) → Q8 (INNER vs LEFT) → Q9 (JOIN vs subquery) → Q10 (Correlated)
                                                    ↓
                                          Q20 (EXPLAIN: check for SubPlan)
```

**Key connections:**
- Q7 ↔ Q20 (EXPLAIN): Physical execution strategies (Nested Loop, Hash, Merge)
- Q8 ↔ Q11 (WHERE vs HAVING): Filtering right-side outer tables in `ON` vs `WHERE`
- Q9 ↔ Q10: Semi-Join transformations, decorrelation, SubPlan vs InitPlan
- Q10 ↔ Q14 (Window Functions): Window functions as an optimized replacement for correlated subqueries

### Topic: GROUP BY and Window Functions

```
Q11 (WHERE vs HAVING) → Q12 (GROUP BY) → Q13 (When HAVING)
                                                ↓
                                    Q14 (Window Functions) → Q15 (ROW_NUMBER) → Q16 (RANK)
```

**Key connections:**
- Q11 ↔ Q12: `WHERE` filters before `GROUP BY`, `HAVING` filters after aggregation
- Q12 ↔ Q14: Window functions retain individual rows (unlike `GROUP BY`)
- Q13 ↔ Q14: Window functions evaluate after `HAVING` → wrapping in a subquery/CTE is required to filter
- Q14 ↔ Q15, Q16: `ROW_NUMBER`, `RANK`, `DENSE_RANK`, `NTILE`, `PERCENT_RANK`

### Topic: MVCC and Engine Maintenance

```
Q17 (MVCC) → Q18 (VACUUM) → Q19 (ANALYZE) → Q20 (EXPLAIN) → Q21 (Optimization)
```

**Key connections:**
- Q17 ↔ Q18: MVCC generates dead tuples upon `UPDATE`/`DELETE` → `VACUUM` reclaims them
- Q18 ↔ Q19: Autovacuum daemon triggers `ANALYZE` when update thresholds are reached
- Q19 ↔ Q20: Stale catalog statistics lead to suboptimal execution plans
- Q20 ↔ Q21: `EXPLAIN (ANALYZE, BUFFERS)` is the primary tool for query bottleneck diagnosis

## 🎓 Cheat Sheet: What to Know for Each Level

### 🟢 Junior
- What an index is and why it speeds up reads while penalizing writes
- Logical JOIN types (INNER, LEFT, RIGHT, FULL, CROSS)
- `WHERE` vs `HAVING`: when to filter individual rows vs aggregated groups
- `GROUP BY` and standard aggregate functions (`COUNT`, `SUM`, `AVG`, `MIN`, `MAX`)
- MVCC core principle: readers never block writers, writers never block readers
- `VACUUM`: dead tuples cleanup, difference between standard non-blocking VACUUM and `VACUUM FULL`
- `EXPLAIN`: how to identify Seq Scan vs Index Scan

### 🟡 Middle
- B-tree page hierarchy, composite indexes, and the leftmost prefix rule
- Physical JOIN algorithms: Nested Loop (index-driven), Hash Join (in-memory hash table), Merge Join (sorted inputs)
- `EXISTS` vs `IN` vs `JOIN`, SubPlan vs InitPlan execution
- Window functions: `ROW_NUMBER`, `RANK`, `DENSE_RANK`, `LAG`/`LEAD`, window framing (`ROWS` vs `RANGE`)
- Autovacuum configuration: thresholds, scale factors, and cost-based throttling
- `ANALYZE`: `pg_statistic`, `n_distinct`, Most Common Values (MCV) lists, histogram bounds
- `EXPLAIN (ANALYZE, BUFFERS)`: reading actual execution time, shared buffer hits/reads, filter loss

### 🔴 Senior
- Lehman-Yao B-tree concurrency, High Key routing, deduplication (PG 13+), Skip Scan emulation via recursive CTEs
- Join order search (Genetic Query Optimizer - GEQO), outer join removal, `Memoize` node (PG 14+)
- MVCC internals: `xmin`/`xmax`/`ctid`, Hint Bits, Heap-Only Tuples (HOT), SSI (Serializable Snapshot Isolation), XID Wraparound freeze
- Maintenance engineering: Visibility Map, index-only scans, parallel vacuuming, zero-downtime table packing (`pg_repack`)
- Extended statistics (`CREATE STATISTICS`) for correlated multi-column distributions
- Plan caching: Generic vs Custom plans, `plan_cache_mode`, JIT compilation overhead, WAL write amplification
- System-level architecture: connection poolers (pgBouncer), declarative table partitioning, selective denormalization
