# How to Configure the Second-Level Cache?

---

## 🟢 Junior Level

Setting up Hibernate's **Second-Level Cache (L2 Cache)** in a modern Spring Boot 3.x application requires three essential steps: adding the cache provider dependency, configuring cache properties in `application.yml`, and annotating target entities:

```
  Step 1: Add JCache / Ehcache Dependency (pom.xml)
  Step 2: Enable L2 Cache & RegionFactory in application.yml
  Step 3: Annotate Entity with @Cacheable & @Cache(usage = ...)
```

```xml
<!-- 1. pom.xml: JCache & Ehcache 3.x -->
<dependency>
    <groupId>org.hibernate.orm</groupId>
    <artifactId>hibernate-jcache</artifactId>
</dependency>
<dependency>
    <groupId>org.ehcache</groupId>
    <artifactId>ehcache</artifactId>
    <classifier>jakarta</classifier>
</dependency>
```

```yaml
# 2. application.yml (Spring Boot 3.x / Jakarta Persistence)
spring:
  jpa:
    properties:
      hibernate:
        cache:
          use_second_level_cache: true
          use_query_cache: true # Optional: Enables Query Cache
          region.factory_class: org.hibernate.cache.jcache.JCacheRegionFactory
        javax.cache.provider: org.ehcache.jsr107.EhcacheCachingProvider
        javax.cache.uri: classpath:ehcache.xml
      jakarta.persistence.sharedCache.mode: ENABLE_SELECTIVE # Only cache @Cacheable entities
```

```java
// 3. Entity Annotation:
@Entity
@Table(name = "products")
@Cacheable
@org.hibernate.annotations.Cache(usage = CacheConcurrencyStrategy.READ_WRITE, region = "productCache")
public class Product {
    @Id
    private Long id;
    private String name;
    private BigDecimal price;
}
```

## 🟡 Middle Level

### JPA Shared Cache Modes (`sharedCache.mode`)

Configured via `jakarta.persistence.sharedCache.mode`:

```
  ┌──────────────────────────────┬─────────────────────────────────────────────────────────────────────────────────┐
  │ Shared Cache Mode            │ Caching Policy & Behavior                                                       │
  ├──────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ **`ENABLE_SELECTIVE`**       │ 🏆 **Recommended Standard**: Caches **ONLY** entities marked with `@Cacheable`. │
  │ **`DISABLE_SELECTIVE`**      │ Caches ALL entities EXCEPT those marked with `@Cacheable(false)`.               │
  │ **`ALL`**                    │ Blindly caches 100% of all entities across the entire application model.        │
  │ **`NONE`** (Default)         │ Second-Level Cache is completely disabled.                                      │
  │ **`UNSPECIFIED`**            │ Uses provider-specific defaults.                                                │
  └──────────────────────────────┴─────────────────────────────────────────────────────────────────────────────────┘
```

### Cache Configuration File (`ehcache.xml`)

```xml
<config xmlns:xsi='http://www.w3.org/2001/XMLSchema-instance'
        xmlns='http://www.ehcache.org/v3'
        xsi:schemaLocation="http://www.ehcache.org/v3 http://www.ehcache.org/schema/ehcache-core-3.0.xsd">

    <!-- Configured cache region for Products -->
    <cache alias="productCache">
        <key-type>java.lang.Long</key-type>
        <value-type>java.lang.Object</value-type>
        <expiry>
            <ttl unit="hours">12</ttl> <!-- Time-to-live: 12 hours -->
        </expiry>
        <resources>
            <heap unit="entries">2000</heap> <!-- Max 2,000 entities in JVM RAM -->
            <offheap unit="MB">50</offheap>  <!-- 50 MB in off-heap memory -->
        </resources>
    </cache>
</config>
```

## 🔴 Senior Level

### Configuring the Query Cache

The **Query Cache** does not store raw table rows; it stores **Query Hash Signatures mapped to Entity IDs**:

```java
public interface ProductRepository extends JpaRepository<Product, Long> {

    // 1. Must explicitly mark query as cacheable:
    @QueryHints(@QueryHint(name = AvailableHints.HINT_CACHEABLE, value = "true"))
    @Query("SELECT p FROM Product p WHERE p.category = :category")
    List<Product> findByCategoryCached(@Param("category") String category);
}
```

```
  ⚠️ The Query Cache Invalidation Hazard:
  • If ANY `Product` row is inserted, updated, or deleted anywhere in the database:
  • Hibernate INVALIDATES 100% OF ALL QUERY CACHE ENTRIES for the entire `Product` space!
  • High-frequency write tables cause near-zero Query Cache hit rates and wasted CPU!
```

### Programmatic Cache Invalidation API

```java
@Service
@RequiredArgsConstructor
public class CacheManagementService {

    private final EntityManagerFactory entityManagerFactory;

    public void evictProductFromL2(Long productId) {
        Cache cache = entityManagerFactory.getCache();
        
        // Evict a single entity instance:
        cache.evict(Product.class, productId);
        log.info("Evicted Product #{} from L2 cache", productId);
    }

    public void evictEntireProductRegion() {
        // Evict all instances of Product:
        entityManagerFactory.getCache().evict(Product.class);
    }

    public void flushAllCaches() {
        // Nuclear option: Evicts ALL entities across ALL regions:
        entityManagerFactory.getCache().evictAll();
    }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **3 Setup Steps:** JCache provider dependency + `application.yml` properties + `@Cacheable` entity annotation.
- **Shared Cache Mode:** Always use `ENABLE_SELECTIVE` to cache only intended reference entities.
- **Provider Role:** Hibernate delegates storage and TTL eviction to a JCache provider (Ehcache, Hazelcast, Infinispan).
- **Query Cache Requirement:** The Query Cache only caches IDs and requires the underlying entities to be in L2 cache.
- **Manual Eviction:** `entityManagerFactory.getCache().evict(...)` allows programmatically purging stale entities.

**Common Follow-up Questions:**
- *"What happens if you enable Query Cache without enabling Second-Level Cache?"* → The Query Cache will fetch the list of entity IDs from memory, but must fire individual SQL queries (`WHERE id = ?`) to load every entity from the database, creating an instant N+1 problem!
- *"How do you configure L2 Caching for a clustered, multi-node cloud environment?"* → Use a distributed cache provider like **Hazelcast** or **Infinispan**; they synchronize cache invalidation events across multiple Kubernetes pods over the network.
- *"Why is `jakarta.persistence.sharedCache.mode` used instead of `javax.` in Spring Boot 3?"* → Spring Boot 3 uses Jakarta EE 9/10 specifications where package namespaces migrated from `javax.persistence` to `jakarta.persistence`.

**Red Flags (DO NOT Say):**
- ❌ *"Setting `use_second_level_cache=true` automatically caches all entities without annotations."* (Requires `@Cacheable` when using `ENABLE_SELECTIVE`).
- ❌ *"Query Cache stores the entire JSON response of database tables."* (It stores the query hash key and a list of primary key IDs).
- ❌ *"L2 Cache automatically detects changes made by external Python scripts directly in Postgres."* (External writes bypass Hibernate and corrupt L2 cache with stale data).
