# What is the Difference Between Lazy and Eager Loading?

---

## 🟢 Junior Level

The **FetchType** in JPA/Hibernate defines **when** related entities or collections are loaded from the database into Java memory:

```
  ┌─────────────────────────────────────────────────────────┬─────────────────────────────────────────────────────────┐
  │ ⏳ LAZY LOADING (`FetchType.LAZY`)                      │ ⚡ EAGER LOADING (`FetchType.EAGER`)                    │
  ├─────────────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ • Data is loaded **on demand** only when first accessed │ • Data is loaded **immediately** alongside the parent   │
  │   via a getter method (`order.getItems()`).             │   entity.                                               │
  │ • Uses lightweight **ByteBuddy Proxies**.               │ • Executes SQL joins or secondary queries upfront.      │
  │ • 🛡️ **Prevents unnecessary memory & DB load.**        │ • ⚠️ **Risks massive N+1 query and memory blowups!**    │
  └─────────────────────────────────────────────────────────┴─────────────────────────────────────────────────────────┘
```

```java
@Entity
public class Order {
    @Id
    private Long id;

    // LAZY: items are NOT fetched until `order.getItems().size()` is called:
    @OneToMany(mappedBy = "order", fetch = FetchType.LAZY)
    private List<OrderItem> items;

    // EAGER: customer is ALWAYS fetched immediately on `em.find(Order.class, 1L)`:
    @ManyToOne(fetch = FetchType.EAGER)
    private Customer customer;
}
```

## 🟡 Middle Level

### JPA Default FetchType Matrix (The Single-Valued Trap)

```
  ┌──────────────────────┬──────────────────────────────┬──────────────────────────────────────────────────┐
  │ Relationship Mapping │ JPA Default FetchType        │ Production Architecture Standard                 │
  ├──────────────────────┼──────────────────────────────┼──────────────────────────────────────────────────┤
  │ **`@OneToMany`**     │ 🟢 **`LAZY`**                │ Keep `LAZY` (Default)                            │
  │ **`@ManyToMany`**    │ 🟢 **`LAZY`**                │ Keep `LAZY` (Default)                            │
  │ **`@ManyToOne`**     │ 🔴 **`EAGER` (⚠️ Trap!)**     │ 🚨 **Always explicitly override to `LAZY`!**      │
  │ **`@OneToOne`**      │ 🔴 **`EAGER` (⚠️ Trap!)**     │ 🚨 **Always explicitly override to `LAZY`!**      │
  └──────────────────────┴──────────────────────────────┴──────────────────────────────────────────────────┘
```

```java
// 🏆 SENIOR BEST PRACTICE: Always explicitly declare LAZY on *ToOne relations:
@ManyToOne(fetch = FetchType.LAZY, optional = false)
@JoinColumn(name = "customer_id")
private Customer customer;
```

## 🔴 Senior Level

### Under the Hood: ByteBuddy Proxies & `PersistentCollection`

When Hibernate loads an entity with lazy associations, it does not inject `null` or raw database values:

```
  Entity in Java Memory:
  Order (id: 1, totalAmount: $250.00)
    ├── customer ──► [Customer$ByteBuddy$Proxy: {target: null, id: 42, initialized: false}]
    └── items    ──► [org.hibernate.collection.spi.PersistentBag: {elements: null, initialized: false}]
```

1. **Proxy Interception:** When you invoke `order.getCustomer().getName()`, the ByteBuddy proxy intercepts the call.
2. **Session Verification:** The proxy checks if the underlying `Session` is still open.
   - If **OPEN**: Fires SQL `SELECT * FROM customers WHERE id = 42`, initializes target object, and returns name.
   - If **CLOSED**: 💥 Throws `org.hibernate.LazyInitializationException: could not initialize proxy - no Session`!

### Inspection and Manual Initialization Utilities

```java
// Check if an association proxy is initialized without triggering SQL:
boolean isCustomerLoaded = Hibernate.isInitialized(order.getCustomer());

// Force-load a lazy proxy explicitly within an open transaction:
if (!Hibernate.isInitialized(order.getItems())) {
    Hibernate.initialize(order.getItems()); // Triggers SQL query immediately
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **LAZY:** Deferred loading on first method access using ByteBuddy proxies.
- **EAGER:** Immediate loading at parent query time.
- **JPA Defaults:** Collection mappings (`@OneToMany`, `@ManyToMany`) default to `LAZY`; single-entity mappings (`@ManyToOne`, `@OneToOne`) default to `EAGER`.
- **The Golden Rule:** Always explicitly set `fetch = FetchType.LAZY` on `@ManyToOne` and `@OneToOne`.
- **`LazyInitializationException`:** Occurs when accessing an uninitialized lazy proxy after the `EntityManager` / `Session` is closed.

**Common Follow-up Questions:**
- *"Why does `@OneToOne` sometimes ignore `fetch = FetchType.LAZY`?"* → When `@OneToOne` is mapped on the non-owning side without `optional = false`, Hibernate cannot know if the child exists without querying the database, forcing an immediate query.
- *"How do you fetch a lazy association without triggering N+1 queries?"* → Use `JOIN FETCH` in JPQL or an `@EntityGraph` at the repository query layer.
- *"What is the difference between `em.find()` and `em.getReference()`?"* → `find()` executes an immediate SQL SELECT and returns an initialized entity; `getReference()` returns an uninitialized ByteBuddy proxy without querying the database until a property is accessed.

**Red Flags (DO NOT Say):**
- ❌ *"All JPA mappings default to Lazy loading."* (`@ManyToOne` and `@OneToOne` default to EAGER).
- ❌ *"Eager loading is faster because it saves CPU cycles from creating proxies."* (Eager loading creates massive unintended joins and fetches entire database graphs into memory).
- ❌ *"Lazy associations contain `null` until they are loaded."* (They contain non-null dynamic proxies or `PersistentCollection` wrappers).
