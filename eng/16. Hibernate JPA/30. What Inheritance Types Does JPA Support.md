# What Inheritance Types Does JPA Support?

---

## 🟢 Junior Level

JPA supports **3 primary Inheritance Strategies** (`@Inheritance(strategy = ...)`) to map object-oriented class hierarchies into relational database tables, along with **`@MappedSuperclass`** for base property inheritance:

```
  ┌──────────────────────────────┬─────────────────────────────────────────────────────────────────────────────────┐
  │ Inheritance Strategy         │ Database Physical Table Structure                                               │
  ├──────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ **1. `SINGLE_TABLE`** (Def)  │ 🏆 **1 Single Table**: All hierarchy fields in 1 table + Discriminator column.   │
  │ **2. `JOINED`**              │ 🔗 **Normalized Tables**: Base table + separate subclass tables joined via FKs. │
  │ **3. `TABLE_PER_CLASS`**     │ 📦 **Independent Tables**: Each concrete subclass has its own standalone table.  │
  │ **4. `@MappedSuperclass`**   │ 📋 **Code Inheritance Only**: Base class is not an entity; fields mapped in child│
  └──────────────────────────────┴─────────────────────────────────────────────────────────────────────────────────┘
```

```java
// Example: SINGLE_TABLE Hierarchy:
@Entity
@Inheritance(strategy = InheritanceType.SINGLE_TABLE)
@DiscriminatorColumn(name = "payment_type", discriminatorType = DiscriminatorType.STRING)
public abstract class Payment {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    private BigDecimal amount;
}

@Entity
@DiscriminatorValue("CARD")
public class CreditCardPayment extends Payment {
    private String cardNumber;
}

@Entity
@DiscriminatorValue("CRYPTO")
public class CryptoPayment extends Payment {
    private String walletAddress;
}
```

## 🔴 Senior Level

### `@MappedSuperclass` (The Domain Model Common Base)

When you want to share common properties (`id`, `createdAt`, `updatedAt`, `version`) across multiple entities **without** creating an inheritance relationship for polymorphic querying, use **`@MappedSuperclass`**:

```java
@MappedSuperclass
@Getter
@Setter
public abstract class BaseEntity {

    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    @Version
    private Long version;

    @CreationTimestamp
    @Column(updatable = false)
    private Instant createdAt;

    @UpdateTimestamp
    private Instant updatedAt;
}
```

```java
@Entity
@Table(name = "users")
public class User extends BaseEntity {
    private String username;
    private String email;
}

@Entity
@Table(name = "products")
public class Product extends BaseEntity {
    private String name;
    private BigDecimal price;
}
```

```
  Key Invariants of @MappedSuperclass:
  • Base class is NOT an entity (`@Entity` is omitted).
  • Base class cannot be queried directly in JPQL (`SELECT b FROM BaseEntity b` is ILLEGAL!).
  • Each child entity gets physical columns for `id`, `version`, `created_at`, `updated_at` 
    in its own independent database table.
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **3 Strategies:** `SINGLE_TABLE` (default/fastest), `JOINED` (normalized/joins), `TABLE_PER_CLASS` (independent/unions).
- **`SINGLE_TABLE` Trade-off:** Maximum query speed, but subclass columns cannot have database `NOT NULL` constraints.
- **`JOINED` Trade-off:** Clean normalized relational tables with `NOT NULL` support, but requires SQL joins on polymorphic queries.
- **`TABLE_PER_CLASS` Penalty:** Polymorphic queries execute massive SQL `UNION` operations.
- **`@MappedSuperclass`:** For sharing common entity properties (audit fields/IDs) without polymorphic query capabilities.

**Common Follow-up Questions:**
- *"What is a Discriminator Column?"* → An auxiliary database column (default `DTYPE` varchar) used in `SINGLE_TABLE` and optionally `JOINED` strategies to identify which Java subclass to instantiate for a given row.
- *"Why is `GenerationType.IDENTITY` prohibited with `TABLE_PER_CLASS`?"* → Subclasses have separate tables; identity auto-increment IDs could produce duplicate IDs across subclass tables, breaking unique identification on polymorphic queries (requires `GenerationType.SEQUENCE` or `TABLE`).
- *"When should you choose `@MappedSuperclass` over `SINGLE_TABLE` or `JOINED`?"* → Choose `@MappedSuperclass` when child classes have zero polymorphic domain relationship (e.g. `User` and `Product` both have `createdAt`, but you never query "all items with createdAt > 2024" as a polymorphic collection).

**Red Flags (DO NOT Say):**
- ❌ *"`@MappedSuperclass` creates a shared database table named `base_entity`."* (`@MappedSuperclass` creates zero database tables).
- ❌ *"You can execute `em.createQuery("SELECT b FROM BaseEntity b")` on a `@MappedSuperclass`."* (MappedSuperclasses cannot be queried directly in JPQL).
- ❌ *"`SINGLE_TABLE` supports database-level `NOT NULL` constraints on subclass-specific columns."* (Subclass columns must be nullable because rows for other subclasses will leave those columns empty).
