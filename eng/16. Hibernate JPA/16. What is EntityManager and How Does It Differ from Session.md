# What is EntityManager and How Does It Differ from Session?

---

## 🟢 Junior Level

**`EntityManager`** and **`Session`** represent the primary client interfaces for managing persistence contexts, but they originate from two different standards:

```
  ┌─────────────────────────────────────────────────────────┬─────────────────────────────────────────────────────────┐
  │ 🌐 `EntityManager` (JPA Standard)                       │ 🦅 `Session` (Hibernate Native)                         │
  ├─────────────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ • The official **Jakarta Persistence (JPA)** standard.   │ • The proprietary native **Hibernate** interface.       │
  │ • Vendor-neutral (Hibernate, EclipseLink, OpenJPA).     │ • Existed before JPA; implements `EntityManager`.       │
  │ • Methods: `persist`, `merge`, `remove`, `find`, `detach`.│ • Methods: `save`, `update`, `delete`, `get`, `evict`.  │
  └─────────────────────────────────────────────────────────┴─────────────────────────────────────────────────────────┘
```

```java
// Standard JPA EntityManager (Recommended):
@PersistenceContext
private EntityManager entityManager;

public void createCustomer(Customer customer) {
    entityManager.persist(customer);
}

// Unwrapping the underlying native Hibernate Session:
public void advancedHibernateOperation() {
    Session session = entityManager.unwrap(Session.class);
    session.setReadOnly(Customer.class, true);
}
```

## 🟡 Middle Level

### Method Equivalency Matrix

```
  ┌──────────────────────────────┬──────────────────────────────┬──────────────────────────────────────────────────┐
  │ Operation                    │ JPA `EntityManager`          │ Native Hibernate `Session`                       │
  ├──────────────────────────────┼──────────────────────────────┼──────────────────────────────────────────────────┤
  │ **Insert New Entity**        │ `persist(entity)`            │ `save(entity)` / `persist(entity)`               │
  │ **Update Detached Entity**   │ `merge(entity)`              │ `update(entity)` / `saveOrUpdate(entity)`        │
  │ **Delete Entity**            │ `remove(entity)`             │ `delete(entity)` / `remove(entity)`              │
  │ **Lookup by Primary Key**    │ `find(Class, id)`            │ `get(Class, id)` / `load(Class, id)`             │
  │ **Evict from L1 Cache**      │ `detach(entity)`             │ `evict(entity)` / `detach(entity)`               │
  │ **Factory Interface**        │ `EntityManagerFactory`       │ `SessionFactory`                                 │
  └──────────────────────────────┴──────────────────────────────────────────────────────────────────────────────────┘
```

## 🔴 Senior Level

### Advanced Features Exclusive to Native Hibernate `Session`

When standard JPA `EntityManager` APIs are insufficient, unwrapping the native `Session` provides access to advanced enterprise features:

```java
Session session = entityManager.unwrap(Session.class);
```

#### 1. Dynamic Tenant / Soft-Delete Filters
```java
// Enable a global Hibernate filter across all queries in this session:
session.enableFilter("tenantFilter")
       .setParameter("tenantId", "TENANT_US_EAST");

session.enableFilter("deletedFilter")
       .setParameter("isDeleted", false);
```

#### 2. Native Identifier Lookups (`NaturalId`)
```java
// Lookup by natural business key (e.g. unique email or tax ID) with L2 cache support:
User user = session.byNaturalId(User.class)
                   .using("email", "alice@example.com")
                   .load();
```

#### 3. Direct JDBC Connection Access (`doWork`)
```java
// Execute raw low-level JDBC batch commands safely using the active connection:
session.doWork(connection -> {
    try (PreparedStatement ps = connection.prepareStatement("COPY audit_log FROM STDIN")) {
        // High-speed PostgreSQL streaming copy...
    }
});
```

#### 4. High-Throughput `StatelessSession`
```java
// Open a command-oriented StatelessSession that completely bypasses L1 cache and Dirty Checking:
SessionFactory sessionFactory = entityManager.getEntityManagerFactory().unwrap(SessionFactory.class);
try (StatelessSession stateless = sessionFactory.openStatelessSession()) {
    stateless.insert(new LargeBatchPayload());
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **EntityManager:** The vendor-neutral JPA specification standard (`jakarta.persistence.EntityManager`).
- **Session:** The native core interface of Hibernate (`org.hibernate.Session`), implementing `EntityManager`.
- **Unwrapping:** Access native Session features via `em.unwrap(Session.class)`.
- **Method Naming:** JPA uses `persist/merge/remove/detach`; native Hibernate historically used `save/update/delete/evict`.
- **Best Practice:** Use standard `EntityManager` for repository business logic to keep code portable; unwrap `Session` only for advanced features (filters, natural IDs, stateless sessions).

**Common Follow-up Questions:**
- *"What is the difference between `session.get()` and `session.load()` in native Hibernate?"* → `get()` queries the database immediately and returns `null` if not found (equivalent to `em.find()`); `load()` returns a lazy ByteBuddy proxy without querying the database, throwing `ObjectNotFoundException` on access if the row doesn't exist (equivalent to `em.getReference()`).
- *"Is `EntityManager` thread-safe?"* → No; `EntityManager` is **NOT thread-safe** and must not be shared across concurrent threads. Spring injects a transactional proxy (`SharedEntityManagerCreator`) that routes calls to the thread-bound instance.
- *"What is the relationship between `SessionFactory` and `EntityManagerFactory`?"* → In Hibernate, `SessionFactory` implements `EntityManagerFactory`.

**Red Flags (DO NOT Say):**
- ❌ *"`EntityManager` and `Session` are completely unrelated competitor libraries."* (Hibernate's `Session` implements `EntityManager`).
- ❌ *"`EntityManager` is thread-safe and can be stored in a static global singleton."* (It is not thread-safe and is bound to a single transaction/thread).
- ❌ *"You must never use `Session` in modern applications."* (Unwrapping `Session` is standard when you need specialized features like filters or stateless sessions).
