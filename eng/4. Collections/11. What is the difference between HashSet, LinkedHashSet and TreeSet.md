# What is the difference between HashSet, LinkedHashSet and TreeSet?

---

## 🟢 Junior Level

**`HashSet`**, **`LinkedHashSet`**, and **`TreeSet`** are the three core implementations of the `java.util.Set` interface in Java, each enforcing **element uniqueness** through distinct underlying data structures and ordering behaviors.

### Comparison Matrix

| Set Implementation | Internal Structure | Element Ordering | Time Complexity | `null` Allowed? |
|---|---|---|---|---|
| **`HashSet`** | Hash Table (`HashMap`) | **No guaranteed order** | **$O(1)$** | **Yes** (One `null`) |
| **`LinkedHashSet`** | Hash Table + Doubly-Linked List | **Preserves insertion order** | **$O(1)$** | **Yes** (One `null`) |
| **`TreeSet`** | Red-Black Tree (`TreeMap`) | **Sorted order** (Natural/Comparator) | **$O(\log n)$** | **No** (Throws NPE) |

```java
// 1. HashSet: Unordered (Order changes across JVM versions and resizes)
Set<String> hs = new HashSet<>(List.of("Z", "A", "M")); // e.g. [A, Z, M]

// 2. LinkedHashSet: Deterministic insertion order
Set<String> lhs = new LinkedHashSet<>(List.of("Z", "A", "M")); // [Z, A, M]

// 3. TreeSet: Alphabetical / Natural sorted order
Set<String> ts = new TreeSet<>(List.of("Z", "A", "M")); // [A, M, Z]
```

## 🟡 Middle Level

### Architectural Mechanics & Iteration Differences

#### 1. `HashSet` Iteration Complexity: $O(\text{capacity} + \text{size})$
- When iterating through a `HashSet`, the iterator must linearly scan **every single bucket in the hash table**, including empty buckets.
- *Pitfall:* If you initialize `new HashSet<>(1_000_000)` and add only 10 elements, iterating over the set still requires scanning all 1,000,000 table slots!

#### 2. `LinkedHashSet` Iteration Complexity: Strictly $O(\text{size})$
- `LinkedHashSet` maintains a doubly-linked list (`before` and `after` pointers) linking all `Entry` nodes across the hash table.
- Iteration traverses **only active nodes directly**, executing significantly faster than `HashSet` when the table is sparsely populated.

#### 3. `TreeSet` Navigable Range Queries
`TreeSet` implements `NavigableSet`, exposing closest-match and sub-range lookups:
```java
NavigableSet<Integer> scores = new TreeSet<>(List.of(10, 25, 50, 80, 95));

Integer floor   = scores.floor(75);   // 50 (Greatest element <= 75)
Integer ceiling = scores.ceiling(75); // 80 (Smallest element >= 75)
Set<Integer> mid = scores.subSet(20, true, 90, false); // [25, 50, 80]
```

## 🔴 Senior Level

### The Critical `TreeSet` Trap: `compareTo()` vs. `equals()`

> [!WARNING]
> While `HashSet` uses `equals()` and `hashCode()` to evaluate uniqueness, **`TreeSet` relies EXCLUSIVELY on `Comparable.compareTo()` or `Comparator.compare()`**:

```java
class Customer implements Comparable<Customer> {
    int id;
    String email;

    @Override
    public int compareTo(Customer o) {
        return Integer.compare(this.id, o.id); // Compares ID only!
    }

    @Override
    public boolean equals(Object o) {
        // Logically distinct if emails differ
        return o instanceof Customer c && this.id == c.id && this.email.equals(c.email);
    }
}

// In application code:
Set<Customer> treeSet = new TreeSet<>();
treeSet.add(new Customer(1, "alice@work.com"));
boolean added = treeSet.add(new Customer(1, "alice@personal.com")); 
// ❌ REJECTED! compareTo() returned 0, so TreeSet considers it a duplicate,
// even though equals() returns false!
```
**Rule:** Ensure `compareTo()` is **strictly consistent with `equals()`** (`(x.compareTo(y) == 0) == x.equals(y)`).

### The Mutable Element "Lost Object" Bug

```java
Set<User> set = new HashSet<>();
User user = new User("Alice");
set.add(user);

// ❌ DANGEROUS: Mutating a field used in hashCode() calculation!
user.setName("Alicia"); 

boolean found = set.contains(user); // Returns FALSE! Object is permanently orphaned in the wrong bucket!
```
**Best Practice:** Always use **immutable objects (`record`s)** as elements in Sets and keys in Maps.

### Java 21 `SequencedSet` Integration

Both `LinkedHashSet` and `TreeSet` implement **`SequencedSet`** in Java 21:
```java
SequencedSet<String> seq = new LinkedHashSet<>();
seq.addFirst("Alpha");
seq.addLast("Omega");
String first = seq.getFirst();
SequencedSet<String> reversed = seq.reversed(); // Live reverse view!
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`HashSet`:** Unordered, $O(1)$ operations, iteration $O(\text{capacity} + \text{size})$, backed by `HashMap`.
- **`LinkedHashSet`:** Preserves insertion order via doubly-linked bucket nodes, iteration $O(\text{size})$, backed by `LinkedHashMap`.
- **`TreeSet`:** Sorted $O(\log n)$ operations, range queries (`floor`, `ceiling`, `subSet`), backed by Red-Black Tree `TreeMap`.
- **`TreeSet` Equality:** Enforced strictly via `compareTo() == 0`, **not `equals()`**.
- **Mutable Elements:** Never mutate an object's fields after adding it to `HashSet` (alters `hashCode()` and loses the element).
- **`null` Handling:** `HashSet` and `LinkedHashSet` permit one `null`; `TreeSet` throws `NullPointerException`.

**Common Follow-up Questions:**
- *"Why is iteration over a sparsely populated `LinkedHashSet` faster than over a `HashSet`?"* → `HashSet` must inspect every allocated table bucket (including empty ones); `LinkedHashSet` traverses a contiguous linked list connecting only populated entries.
- *"What happens if you add an object that doesn't implement `Comparable` to a `TreeSet` without providing a `Comparator`?"* → Throws `ClassCastException` on the first insertion.
- *"How does `LinkedHashMap` implement an LRU cache?"* → Override `removeEldestEntry(entry)` and configure `accessOrder = true` in the constructor.

**Red Flags (DO NOT Say):**
- ❌ *"TreeSet uses equals() to check whether an element already exists."* (`TreeSet` uses `compareTo()` or `Comparator.compare()`).
- ❌ *"HashSet always returns elements in the exact order they were inserted."* (Only `LinkedHashSet` preserves insertion order).
- ❌ *"LinkedHashSet is slower than HashSet for contains() lookups."* (Both are $O(1)$ hash lookups).
