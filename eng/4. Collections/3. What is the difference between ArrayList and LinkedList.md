# What is the difference between ArrayList and LinkedList?

---

## 🟢 Junior Level

**`ArrayList`** and **`LinkedList`** are the two standard implementations of the `java.util.List` interface in Java.

### High-Level Comparison

| Feature | `ArrayList` | `LinkedList` |
|---|---|---|
| **Underlying Data Structure** | Resizable dynamic array (`Object[]`) | Doubly-linked list (`Node<E>`) |
| **Random Index Access (`get(i)`)** | **$O(1)$ Instant** | **$O(n)$ Slow** (traverses pointer chain) |
| **Insertion at Head (`add(0, e)`)** | $O(n)$ (shifts entire array) | $O(1)$ (updates head pointer) |
| **Memory Footprint** | Extremely compact (4–8 bytes per pointer) | Heavy ($24-32$ bytes per node object) |
| **Production Recommendation** | **Default choice (99% of use cases)** | **Avoid in modern Java** |

```java
// ArrayList: Blazing fast indexed lookups
List<String> arrayList = new ArrayList<>();
arrayList.add("Alpha");
String first = arrayList.get(0); // O(1) Instant lookup

// LinkedList: Pointer-based traversal
List<String> linkedList = new LinkedList<>();
linkedList.add("Alpha");
String slow = linkedList.get(0); // O(n) Traverses node chain
```

> [!TIP]
> If you need a FIFO queue or LIFO stack, **use `ArrayDeque` instead of `LinkedList`**. `ArrayDeque` is $3-10\times$ faster to iterate and consumes a fraction of the memory.

## 🟡 Middle Level

### Internal Architecture & Algorithmic Complexities

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │                 ArrayList (Dynamic Array)              │               LinkedList (Doubly-Linked Nodes)         │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ [ A ] [ B ] [ C ] [ D ] [ E ] ...                      │ [Node A] <---> [Node B] <---> [Node C]                 │
  │ • Contiguous physical memory block                     │ • Dispersed heap nodes connected via `prev` and `next` │
  │ • Indexed arithmetic: `array[index]`                   │ • Must traverse from head/tail to reach index          │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

| Operation | `ArrayList` | `LinkedList` |
|---|---|---|
| **`get(int index)`** | **$O(1)$** | $O(n)$ (traverses $n/2$ nodes) |
| **`add(E e)` (Append)** | **Amortized $O(1)$** | $O(1)$ |
| **`add(0, E e)` (Prepend)** | $O(n)$ | **$O(1)$** |
| **`remove(0)`** | $O(n)$ | **$O(1)$** |
| **`contains(Object o)`** | $O(n)$ | $O(n)$ |
| **`iterator.remove()`** | $O(n)$ | **$O(1)$** |
| **Memory per Element** | **4 bytes** (with Compressed OOPs) | **24–32 bytes** |

## 🔴 Senior Level

### Hardware Cache Locality & CPU Cache Lines

The true performance gap between `ArrayList` and `LinkedList` is dictated by **modern CPU architecture**:

```
  CPU L1/L2 Cache Line (64 Bytes):
  ┌────────────────────────────────────────────────────────┐
  │ ArrayList: [Ref 0][Ref 1][Ref 2][Ref 3][Ref 4]...      │ -> All 8-16 references loaded in ONE cache hit!
  └────────────────────────────────────────────────────────┘

  LinkedList Heap Memory:
  ┌──────────────┐      ┌──────────────┐      ┌──────────────┐
  │ Node A (0x10)│ ---> │ Node B (0x9F)│ ---> │ Node C (0x3A)│ -> Random addresses: Cache Miss on EVERY step!
  └──────────────┘      └──────────────┘      └──────────────┘
```

- **`ArrayList` Cache Hits:** Because array memory is contiguous, the CPU hardware prefetcher loads adjacent elements into **L1/L2 CPU caches**, executing iterations up to **$50\times$ faster**.
- **`LinkedList` Pointer Chasing:** Nodes are scattered across the JVM Heap. Following `node.next` triggers a CPU pipeline stall and a main RAM fetch (~50–100ns penalty per node).

### The "Big-O Illusion" of Head Insertions

While `LinkedList.add(0, e)` is theoretically $O(1)$ and `ArrayList.add(0, e)` is $O(n)$:
- `ArrayList` executes array shifts using **`System.arraycopy()`**, a JVM intrinsic compiled down to **SIMD vector instructions** (e.g. AVX-512) that shift memory blocks in parallel in nanoseconds.
- `LinkedList` must allocate a new `Node` object on the heap (`new Node()`), initialize 3 references, and adjust pointers.
- **Result:** `ArrayList.add(0, e)` is frequently **faster than `LinkedList` for lists with up to 10,000 elements!**

### GC Allocation Pressure & Memory Bloat

```
  LinkedList Node Overhead (64-bit JVM with Compressed OOPs):
  ┌─────────────────────────────────────────┐
  │ Object Header (Mark + Klass)    12 Bytes│
  │ item Pointer                     4 Bytes│
  │ next Pointer                     4 Bytes│
  │ prev Pointer                     4 Bytes│
  │ Alignment Padding                8 Bytes│
  ├─────────────────────────────────────────┤
  │ Total Footprint per Element:   32 Bytes │
  └─────────────────────────────────────────┘
```
Inserting and deleting 10 million elements in `LinkedList` creates and discards **10 million `Node` heap instances**, triggering violent **Minor GC thrashing** and Stop-The-World pause spikes. `ArrayList` simply zeroes out array slots with zero GC allocation.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`ArrayList`:** Contiguous `Object[]`, $O(1)$ random index access, cache-friendly, default choice in 99% of applications.
- **`LinkedList`:** Doubly-linked `Node` objects, $O(n)$ index traversal, heavy memory overhead ($32\text{ bytes/node}$ vs $4\text{ bytes}$ in `ArrayList`).
- **Cache Locality:** `ArrayList` leverages 64-byte CPU cache lines and SIMD intrinsics; `LinkedList` suffers cache misses on every node lookup.
- **GC Impact:** `LinkedList` creates millions of transient `Node` objects causing GC pressure; `ArrayList` creates zero object overhead during mutation.
- **Stack/Queue Replacement:** Always use **`ArrayDeque`** instead of `LinkedList` for stacks and queues.

**Common Follow-up Questions:**
- *"Is there any scenario where LinkedList is genuinely better than ArrayList?"* → Only in rare legacy codebases where an enormous list ($>100{,}000$ elements) undergoes frequent element deletions *during active iterator traversal* (`iterator.remove()`) and cannot be refactored to `list.removeIf()`.
- *"Why does `ArrayList` implement `RandomAccess` while `LinkedList` does not?"* → `RandomAccess` is a marker interface signaling $O(1)$ indexed access, allowing algorithms like `Collections.binarySearch()` to execute binary search instead of linear iteration.
- *"How does `ArrayList` grow when its capacity is exceeded?"* → It grows by $50\%$ ($1.5\times$ original capacity: `newCapacity = oldCapacity + (oldCapacity >> 1)`), copying elements to the new array via `Arrays.copyOf()`.

**Red Flags (DO NOT Say):**
- ❌ *"LinkedList is faster than ArrayList for iterating through elements."* (ArrayList is $10-50\times$ faster due to CPU cache line prefetching).
- ❌ *"LinkedList saves memory because it only allocates what it needs."* (LinkedList consumes $\sim 8\times$ more memory per element due to node object headers and pointers).
- ❌ *"LinkedList is the best implementation for a Stack or FIFO Queue."* (`ArrayDeque` is significantly faster, cache-friendly, and uses less memory).
