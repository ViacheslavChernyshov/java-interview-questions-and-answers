# What is the difference between Iterator and ListIterator?

---

## 🟢 Junior Level

**`Iterator`** and **`ListIterator`** are standard interfaces in `java.util` used to traverse elements in collections.

| Feature | `Iterator` | `ListIterator` |
|---|---|---|
| **Supported Collections** | **All Collections** (`List`, `Set`, `Queue`) | **`List` Implementations Only** |
| **Traversal Direction** | **Forward Only** (`next()`) | **Bidirectional** (`next()` and `previous()`) |
| **Index Tracking** | No index awareness | **`nextIndex()`**, **`previousIndex()`** |
| **Mutator Operations** | **`remove()`** only | **`remove()`**, **`set(e)`**, **`add(e)`** |
| **Starting Position** | Always begins at Head (Index 0) | Can start at any index (`list.listIterator(n)`) |

```java
List<String> list = new ArrayList<>(List.of("A", "B", "C"));

// 1. Standard Iterator: Forward only
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    System.out.print(it.next() + " "); // A B C
}

// 2. ListIterator: Bidirectional traversal
ListIterator<String> listIt = list.listIterator();
while (listIt.hasNext()) {
    String current = listIt.next();
    if (current.equals("B")) {
        listIt.set("Beta"); // Modifies last returned element!
    }
}
```

## 🟡 Middle Level

### The Virtual Cursor Model

In `ListIterator`, the cursor position is conceptualized as sitting **between elements**:

```
  Element Positions:      [ Index 0: A ]    [ Index 1: B ]    [ Index 2: C ]
  Cursor Positions:    ^                  ^                 ^                 ^
                    Index 0            Index 1           Index 2           Index 3
```

- **`next()`:** Returns the element to the right of the cursor and advances the cursor one position right.
- **`previous()`:** Returns the element to the left of the cursor and advances the cursor one position left.
- **`add(E e)`:** Inserts the element immediately **before the cursor**. A subsequent call to `previous()` will return the newly inserted element.
- **`set(E e)`:** Replaces the element returned by the **last call to `next()` or `previous()`**. Throws `IllegalStateException` if `next()` or `previous()` has not been called, or if `remove()` / `add()` was called immediately prior.

## 🔴 Senior Level

### Algorithmic Optimization: Rescuing `LinkedList` from $O(n^2)$ Traversal

Iterating through a `LinkedList` via indexed loop incurs severe quadratic overhead:

```java
// ❌ DISASTER: O(n^2) Quadratic Traversal!
for (int i = 0; i < linkedList.size(); i++) {
    process(linkedList.get(i)); // get(i) traverses from head on every single iteration!
}

// ✅ PROPER OPTIMIZATION: O(n) Linear Traversal via ListIterator
ListIterator<String> it = linkedList.listIterator();
while (it.hasNext()) {
    String item = it.next(); // O(1) step: follows node.next reference directly!
    if (needsReplacement(item)) {
        it.set("NewValue");   // O(1) in-place node value assignment!
    }
}
```

### Modern Functional Traversal: `forEachRemaining()`

Java 8 introduced `forEachRemaining(Consumer<? super E>)` on `Iterator`, enabling clean functional consumption of remaining items:

```java
Iterator<String> it = list.iterator();
String header = it.next(); // Consume first element

// Process all remaining elements cleanly:
it.forEachRemaining(item -> processBody(item));
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Scope:** `Iterator` works across all `Collection` types (forward-only); `ListIterator` is exclusive to `List` (bidirectional).
- **Mutations:** `Iterator` supports only `remove()`; `ListIterator` supports `remove()`, `set(e)`, and `add(e)`.
- **Cursor Mechanics:** Sits between elements; `add()` inserts before the cursor, `set()` mutates the last returned element.
- **Index Methods:** `nextIndex()` and `previousIndex()` expose positional offsets.
- **`LinkedList` Traversal:** `ListIterator` maintains an active pointer to the current `Node`, turning $O(n^2)$ indexed loops into $O(n)$ linear traversal.

**Common Follow-up Questions:**
- *"What happens if you invoke `listIterator.set(e)` immediately after `listIterator.add(e)`?"* → Throws `IllegalStateException` because `set()` requires a preceding `next()` or `previous()` call without intervening modifications.
- *"How can you traverse a List in reverse order using `ListIterator`?"* → Obtain an iterator positioned at the end (`list.listIterator(list.size())`) and loop while `hasPrevious()` calling `previous()`.
- *"Why does `Set` not support `ListIterator`?"* → Mathematical Sets do not have a concept of positional index order (`get(i)` or indexed insertion).

**Red Flags (DO NOT Say):**
- ❌ *"Iterator and ListIterator both support bidirectional traversal."* (Only `ListIterator` has `hasPrevious()` and `previous()`).
- ❌ *"You can use ListIterator on a HashSet."* (Only `List` implementations provide `listIterator()`).
- ❌ *"ListIterator.set() replaces the next element in the list."* (It replaces the last element returned by `next()` or `previous()`).
