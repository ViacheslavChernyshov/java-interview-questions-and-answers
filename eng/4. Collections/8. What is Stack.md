# What is Stack?

---

## 🟢 Junior Level

A **Stack** is an abstract data structure that operates strictly on the **LIFO (Last-In, First-Out)** principle: the last element added to the stack is always the first element removed.

**Core Operations:**
- **`push(e)`:** Pushes an item onto the top of the stack ($O(1)$).
- **`pop()`:** Removes and returns the top item ($O(1)$).
- **`peek()`:** Inspects the top item without removing it ($O(1)$).

```java
// ❌ OBSOLETE ANTI-PATTERN:
Stack<String> stack = new Stack<>();

// ✅ MODERN PRODUCTION STANDARD:
Deque<String> stack = new ArrayDeque<>();
stack.push("Base");
stack.push("Top");
String item = stack.pop(); // Returns "Top" (LIFO)
```

## 🟡 Middle Level

### Why `java.util.Stack` is an Architectural Anti-Pattern

```java
// Definition in JDK:
public class Stack<E> extends Vector<E> { ... }
```

1. **Liskov Substitution Principle (LSP) Violation:**
   - Because `Stack` extends `Vector`, it illegally inherits random-access index methods:
     ```java
     Stack<String> stack = new Stack<>();
     stack.push("A");
     stack.push("B");
     stack.add(0, "Corrupted"); // ❌ Breaks LIFO encapsulation!
     ```
2. **Unnecessary Synchronization Overhead:**
   - Inherits `synchronized` on every method from `Vector`, killing throughput even in single-threaded algorithms.
3. **Inconsistent Exception Contract:**
   - Calling `pop()` on an empty `java.util.Stack` throws `EmptyStackException` (an unchecked legacy exception), whereas `ArrayDeque.pop()` throws the standard `NoSuchElementException`.

### Implementation Comparison

| Dimension | `java.util.Stack` | `ArrayDeque` (Modern Stack) | `LinkedList` |
|---|---|---|---|
| **Underlying Storage** | Synchronized resizable array | Resizable circular array | Doubly-linked node chain |
| **Thread Synchronization** | Synchronized (Slow) | **Unsynchronized (Fast)** | Unsynchronized |
| **Memory Footprint** | Moderate | **Lowest (Compact)** | High ($32\text{ bytes/node}$) |
| **LIFO Encapsulation** | **Violated** (Allows `get(i)`) | **Strictly Enforced** | **Strictly Enforced** |
| **Empty `pop()` Exception** | `EmptyStackException` | `NoSuchElementException` | `NoSuchElementException` |

## 🔴 Senior Level

### Modern High-Performance Stack Idioms

```java
// 1. Single-Threaded Algorithms (DFS, Parsing, Expression Evaluation):
Deque<Node> dfsStack = new ArrayDeque<>();

// 2. Lock-Free Thread-Safe Stack (Concurrent Environments):
Deque<Task> concurrentStack = new ConcurrentLinkedDeque<>();
```

### Classic Stack Use Cases

1. **Grammar & Expression Parsers:** Tracking parenthesis balancing and reverse Polish notation (RPN).
2. **Undo / Redo Buffers:** Reverting historical state snapshots in UI editors.
3. **Depth-First Search (DFS):** Managing graph and tree traversal frontiers iteratively to prevent call stack recursion overflows.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **LIFO Concept:** Last-In, First-Out; primary methods are `push()`, `pop()`, and `peek()`.
- **Why `java.util.Stack` is Deprecated:** Extends `Vector` (LSP violation allowing arbitrary indexed insertions) and incurs obsolete per-method synchronization.
- **Recommended Standard:** **`ArrayDeque`** is the standard modern stack implementation in Java.
- **Exceptions:** `java.util.Stack` throws `EmptyStackException`; `ArrayDeque` throws `NoSuchElementException`.
- **Concurrency Alternative:** Use `ConcurrentLinkedDeque` for lock-free multi-threaded stack processing.

**Common Follow-up Questions:**
- *"Why does `ArrayDeque` make a better stack than `LinkedList`?"* → `ArrayDeque` stores elements contiguously in a circular array, maximizing CPU cache line prefetching and creating zero object allocation garbage during `push()` and `pop()`.
- *"How does `ArrayDeque` enforce LIFO when used as a stack?"* → When declared as `Deque<T> stack = new ArrayDeque<>()`, it exposes `push()` (inserts at head) and `pop()` (removes from head) while hiding random-access array index methods.
- *"What is the time complexity of `ArrayDeque.push()`?"* → Amortized $O(1)$; when the circular array buffer fills up, it doubles capacity in $O(n)$ time.

**Red Flags (DO NOT Say):**
- ❌ *"Using `java.util.Stack` is fine because it is thread-safe."* (Its coarse-grained locking causes severe lock contention, and its inheritance from `Vector` breaks LIFO invariants).
- ❌ *"A Stack allows random element retrieval by index in constant time."* (A true stack only permits access to the top element; `Stack.get(i)` is an inheritance bug).
- ❌ *"LinkedList is faster than ArrayDeque for a stack."* (`ArrayDeque` is significantly faster due to cache locality and zero heap node allocations).
