# When to use ArrayList vs LinkedList?

---

## 🟢 Junior Level

**Short Answer:** In virtually all enterprise applications, **always use `ArrayList`**.

```java
// ✅ RECOMMENDED (Default in 99% of use cases):
List<String> list = new ArrayList<>();

// ❌ ANTI-PATTERN in modern Java:
List<String> list = new LinkedList<>();
```

**Why `LinkedList` is rarely the right choice:**
1. **CPU Cache Locality:** `ArrayList` stores data in contiguous memory lines, allowing the CPU to iterate up to **$50\times$ faster**.
2. **Memory Bloat:** `LinkedList` consumes **$8\times$ more memory** per element to store object headers and pointer handles.
3. **Better Alternatives Exist:** If you need a FIFO Queue or LIFO Stack, **use `ArrayDeque`**, which outperforms `LinkedList` in both speed and memory efficiency.

## 🟡 Middle Level

### Production Selection Matrix

| Workload Scenario | Recommended Collection | Rationale |
|---|---|---|
| **Frequent Index Lookups (`get(i)`)** | **`ArrayList`** | Direct $O(1)$ pointer arithmetic |
| **High-Throughput Iteration / Streams** | **`ArrayList`** | 64-byte CPU cache line prefetching |
| **Appending Elements (`add(e)`)** | **`ArrayList`** | Amortized $O(1)$ with SIMD array resizing |
| **FIFO Queue or LIFO Stack** | **`ArrayDeque`** | Ring-buffer dynamic array without node allocations |
| **Mass Batch Removals** | **`ArrayList` (`removeIf`)** | Optimized two-pointer sweep in $O(n)$ time |
| **Insertion at Head ($>100{,}000$ items)** | **`ArrayDeque`** | $O(1)$ ring buffer head insertion |

### Why `removeIf()` Eliminated LinkedList's Last Advantage

Historically, the only theoretical advantage of `LinkedList` was removing elements during iteration (`iterator.remove()` in $O(1)$ time vs $O(n)$ array shift in `ArrayList`).

With Java 8+, **`list.removeIf()`** changed the paradigm:
```java
// In ArrayList: Two-pointer BitSet scan + ONE consolidated arraycopy -> O(n) total!
usersList.removeIf(user -> user.isInactive());
```
Because `ArrayList.removeIf()` executes in $O(n)$ linear time without garbage creation, it outpaces `LinkedList` even during mass element deletions.

## 🔴 Senior Level

### Hardware Reality: SIMD Vectorization vs. Pointer Chasing

```
  1,000 Element Shift in ArrayList:
  ┌────────────────────────────────────────────────────────┐
  │ `System.arraycopy()` executed via CPU AVX/SIMD vector  │
  │ instructions -> Shifts 1,000 reference pointers in ~1μs│
  └────────────────────────────────────────────────────────┘

  1,000 Element Node Insertion in LinkedList:
  ┌────────────────────────────────────────────────────────┐
  │ 1,000 `new Node()` allocations in Heap + 3,000 pointer │
  │ writes -> Incurs GC allocations and stalls in ~5-10μs  │
  └────────────────────────────────────────────────────────┘
```
**Conclusion:** `ArrayList.add(0, e)` is empirically **faster than `LinkedList` for lists up to $\sim 10{,}000-20{,}000$ elements**, debunking the theoretical "Big-O" assumption that linked lists are always faster for head insertion.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Default Choice:** `ArrayList` is the standard for 99% of all collections.
- **Cache Locality:** Contiguous memory array allows CPU hardware prefetchers to load entire 64-byte cache lines.
- **Queue/Stack Standard:** Always use **`ArrayDeque`** instead of `LinkedList` or legacy `Stack`.
- **`removeIf()` Advantage:** Java 8+ `removeIf()` executes a single $O(n)$ compacting pass on `ArrayList`, eliminating the need for `LinkedList` pointer manipulation.
- **Capacity Pre-Sizing:** Call `new ArrayList<>(expectedSize)` or `ensureCapacity()` to eliminate array resizing allocations.

**Common Follow-up Questions:**
- *"When would you ever use `LinkedList` in production?"* → Only in rare legacy APIs that explicitly expect `LinkedList` parameters or when maintaining specialized internal LRU double-linked node structures where node references are held externally.
- *"Why is `ArrayDeque` superior to `LinkedList` for a Queue?"* → `ArrayDeque` uses a circular array buffer that avoids allocating `Node` objects on the heap, eliminating GC pressure and maximizing cache hits.
- *"What happens when `ArrayList` runs out of capacity?"* → It allocates a new array $1.5\times$ larger (`oldCapacity + (oldCapacity >> 1)`) and transfers elements using native `System.arraycopy()`.

**Red Flags (DO NOT Say):**
- ❌ *"LinkedList is better for frequently adding items to a list."* (`ArrayList` is faster due to SIMD memory copying and lack of object allocation overhead).
- ❌ *"LinkedList uses less memory than ArrayList because it doesn't allocate empty array slots."* (`LinkedList` wastes $24-32\text{ bytes}$ per element on node headers and pointers).
- ❌ *"Use LinkedList to implement a FIFO processing queue."* (Use `ArrayDeque` or `ConcurrentLinkedQueue`).
