# What are the main Collection Framework interfaces?

---

## 🟢 Junior Level

The **Java Collections Framework (JCF)** is a unified architecture in `java.util` for representing, storing, and manipulating groups of objects.

### The 4 Primary Interfaces

| Interface | Structural Concept | Duplicate Elements? | Core Implementations |
|---|---|---|---|
| **`List<E>`** | Ordered sequence with positional index access | **Allowed** | `ArrayList`, `LinkedList` |
| **`Set<E>`** | Collection guaranteeing uniqueness | **Forbidden** | `HashSet`, `LinkedHashSet`, `TreeSet` |
| **`Queue<E>`** | Ordered buffer for processing (FIFO) | **Allowed** | `ArrayDeque`, `PriorityQueue` |
| **`Map<K, V>`** | Key-Value mappings (Key uniqueness) | Keys: **No**, Values: **Yes** | `HashMap`, `LinkedHashMap`, `TreeMap` |

> [!NOTE]
> **`Map` does NOT extend `Collection`!** It represents a parallel hierarchy because it operates on key-value pairs (`Map.Entry<K, V>`) rather than discrete single elements.

```java
// List: Preserves insertion order, allows duplicates
List<String> list = new ArrayList<>(List.of("A", "B", "A"));

// Set: Drops duplicates based on equals() and hashCode()
Set<String> set = new HashSet<>(list); // Contains only ["A", "B"]

// Map: Associates unique keys with values
Map<String, Integer> map = new HashMap<>();
map.put("A", 1);
map.put("B", 2);
```

## 🟡 Middle Level

### Complete Interface Hierarchy (Including Java 21)

```
  java.lang.Iterable<E>
    │
    └── java.util.Collection<E>
          ├── java.util.SequencedCollection<E> (Java 21+)
          │     ├── java.util.List<E>           (ArrayList, LinkedList)
          │     ├── java.util.Deque<E>          (ArrayDeque, LinkedList)
          │     └── java.util.SequencedSet<E>   (LinkedHashSet, TreeSet)
          ├── java.util.Set<E>                  (HashSet)
          └── java.util.Queue<E>                (PriorityQueue)

  java.util.Map<K, V> (Parallel Hierarchy)
    ├── java.util.SequencedMap<K, V> (Java 21+: LinkedHashMap, TreeMap)
    └── java.util.concurrent.ConcurrentMap<K, V> (ConcurrentHashMap)
```

### Marker Interfaces & Algorithm Optimization

1. **`RandomAccess` (Marker Interface):**
   - Implemented by `ArrayList` and `Vector`, but **not** by `LinkedList`.
   - Informs algorithms (e.g. `Collections.binarySearch()`) that index lookups execute in $O(1)$ time. If present, the algorithm uses fast index loops (`for-i`); otherwise, it falls back to iterative pointer traversal (`ListIterator`).

2. **`NavigableSet<E>` & `NavigableMap<K, V>`:**
   - Extended by `TreeSet` and `TreeMap` to provide closest-match search methods: `lower()`, `floor()`, `ceiling()`, `higher()`, and descending views.

### Fail-Fast vs. Fail-Safe Iteration Mechanics

- **Fail-Fast (`ArrayList`, `HashMap`, `HashSet`):** Tracks internal mutations via a `modCount` field. If modified structurally during active iteration without using `Iterator.remove()`, it throws `ConcurrentModificationException` immediately.
- **Fail-Safe / Weakly Consistent (`CopyOnWriteArrayList`, `ConcurrentHashMap`):** Iterates over an immutable snapshot or tolerates concurrent updates without throwing exceptions.

## 🔴 Senior Level

### Java 21: Sequenced Collections (JEP 431)

Historically, accessing the first or last element in Java collections lacked a unified contract (`list.get(0)`, `deque.getFirst()`, `sortedSet.first()`, `linkedHashSet.iterator().next()`).

**Java 21 introduces `SequencedCollection<E>`**, establishing uniform end-to-end access across all ordered collections:

```java
// Unified API across Lists, Deques, and Ordered Sets:
SequencedCollection<String> seq = new ArrayList<>(List.of("Alpha", "Beta", "Gamma"));

String first = seq.getFirst(); // "Alpha"
String last  = seq.getLast();  // "Gamma"
seq.addFirst("Zero");
seq.addLast("Omega");

// Returns a reverse-ordered live view:
SequencedCollection<String> reversed = seq.reversed();
```

### Stream Engine Foundation: `Spliterator<E>` (Java 8+)

`Spliterator` ("splitable iterator") powers parallel partitioning in the Java Stream API. It exposes internal collection characteristics via bitmasks:

```java
Spliterator<String> split = list.spliterator();
// Bitmask Characteristics:
// SIZED      -> Exact element count known (O(1) size())
// DISTINCT   -> Guarantees element uniqueness (Set implementations)
// SORTED     -> Pre-sorted according to natural or custom Comparator
// ORDERED    -> Guarantees deterministic traversal sequence
// CONCURRENT -> Safe for concurrent modifications without external locking
```

### The "Optional Operation" Architectural Design

Methods defined in `Collection` (such as `add()`, `remove()`, and `clear()`) are defined as **Optional Operations** in the Java specification:
- Unmodifiable collections (`Collections.unmodifiableList()` or `List.of()`) throw **`UnsupportedOperationException`** when mutators are called.
- This design allowed the JDK architects to preserve a single unified interface hierarchy without creating separate `MutableCollection` and `ImmutableCollection` hierarchies.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Framework Core:** `Iterable` $\to$ `Collection` $\to$ (`List`, `Set`, `Queue`), alongside parallel `Map`.
- **Why Map is separate:** Operates on Key-Value pairs (`Map.Entry`), requiring 2-dimensional access (`keySet()`, `values()`, `entrySet()`).
- **`RandomAccess`:** Marker interface indicating $O(1)$ indexed access, used by JDK utilities to choose optimal algorithms.
- **Fail-Fast:** Detects concurrent modifications via `modCount` and aborts with `ConcurrentModificationException`.
- **Java 21 Sequenced Collections:** Standardizes `addFirst()`, `addLast()`, `getFirst()`, `getLast()`, and `reversed()` across `List`, `Deque`, `LinkedHashSet`, and `SortedSet`.
- **`Spliterator`:** Foundation of Stream API, splitting data chunks for `parallelStream()`.

**Common Follow-up Questions:**
- *"Why does `LinkedList` not implement `RandomAccess`?"* → Because accessing an element by index in a linked list requires $O(n)$ pointer traversal from the head or tail node.
- *"What is the difference between `Fail-Fast` and `Fail-Safe`?"* → Fail-Fast checks `modCount` and throws `ConcurrentModificationException` on mutation; Fail-Safe works on a memory snapshot (e.g. `CopyOnWriteArrayList`) and never throws.
- *"Why are collection mutation methods like `add()` called 'Optional Operations'?"* → To allow unmodifiable and immutable collections (`List.of()`) to adhere to the `List` interface while throwing `UnsupportedOperationException` on write.

**Red Flags (DO NOT Say):**
- ❌ *"Map extends Collection in Java."* (Map is a separate root interface in the framework).
- ❌ *"Vector and Stack are the standard modern choices for thread-safe lists."* (They are legacy synchronized classes; use `CopyOnWriteArrayList` or `ConcurrentHashMap`).
- ❌ *"Fail-Fast iterators guarantee thread-safety in concurrent environments."* (Fail-Fast is a best-effort single-threaded bug detector, not a concurrency mechanism).
