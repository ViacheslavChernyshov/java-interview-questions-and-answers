# What is the difference between HashMap, LinkedHashMap and TreeMap?

---

## 🟢 Junior Level

**`HashMap`**, **`LinkedHashMap`**, and **`TreeMap`** represent the primary implementations of the `java.util.Map` interface in Java.

### Comparison Matrix

| Feature | `HashMap` | `LinkedHashMap` | `TreeMap` |
|---|---|---|---|
| **Key Ordering** | **Unordered** (Nondeterministic) | **Preserves Insertion or Access Order** | **Sorted by Key** (Natural/Comparator) |
| **Internal Structure** | Hash Table (Buckets + Treeification) | Hash Table + Doubly-Linked List | Red-Black Tree (`NavigableMap`) |
| **Time Complexity** | **$O(1)$ Amortized** | **$O(1)$ Amortized** | **$O(\log n)$** |
| **`null` Keys** | **Allowed** (One `null` key) | **Allowed** (One `null` key) | **Prohibited** (Throws NPE) |
| **Default Use Case** | General-purpose dictionary lookup | Predictable order / LRU Caching | Range lookups & sorted reporting |

```java
// 1. HashMap: No guaranteed order
Map<String, Integer> hm = new HashMap<>(Map.of("Z", 26, "A", 1, "M", 13)); // e.g. {A=1, Z=26, M=13}

// 2. LinkedHashMap: Preserves insertion sequence
Map<String, Integer> lhm = new LinkedHashMap<>();
lhm.put("Z", 26); lhm.put("A", 1); lhm.put("M", 13); // {Z=26, A=1, M=13}

// 3. TreeMap: Sorted alphabetically by key
Map<String, Integer> tm = new TreeMap<>(lhm); // {A=1, M=13, Z=26}
```

## 🟡 Middle Level

### High-Performance LRU Cache with `LinkedHashMap`

By enabling **`accessOrder = true`**, `LinkedHashMap` moves any entry touched by `get()` or `put()` to the tail of the internal doubly-linked list, turning it into a turnkey **LRU (Least Recently Used) Cache**:

```java
public class SimpleLruCache<K, V> extends LinkedHashMap<K, V> {
    private final int maxEntries;

    public SimpleLruCache(int maxEntries) {
        // initialCapacity, loadFactor, accessOrder = true
        super(maxEntries, 0.75f, true);
        this.maxEntries = maxEntries;
    }

    @Override
    protected boolean removeEldestEntry(Map.Entry<K, V> eldest) {
        // Automatically evicts the oldest untouched entry when capacity exceeds limit
        return size() > maxEntries;
    }
}
```

### The `TreeMap` Invariant: `compareTo()` over `equals()`

`TreeMap` searches for matching keys exclusively using **`Comparable.compareTo()` or `Comparator.compare()`**:
- It never calls `equals()` or `hashCode()`.
- If `compareTo()` returns `0`, the existing key's value is overwritten, even if `equals()` returns `false`.

### Java 21: `SequencedMap` Standard (JEP 431)

Both `LinkedHashMap` and `TreeMap` implement **`SequencedMap`**:

```java
SequencedMap<String, Integer> map = new LinkedHashMap<>();
map.putFirst("FirstKey", 1);
map.putLast("LastKey", 100);

Map.Entry<String, Integer> first = map.firstEntry(); // ("FirstKey", 1)
SequencedMap<String, Integer> reversed = map.reversed(); // Live reverse-ordered view!
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`HashMap`:** Unordered, $O(1)$ amortized lookups, Java 8+ treeification at bucket length $\ge 8$.
- **`LinkedHashMap`:** $O(1)$ amortized lookups, preserves insertion or access order (LRU) via internal doubly-linked list.
- **`TreeMap`:** $O(\log n)$ sorted tree lookups (`NavigableMap`), range navigation (`subMap`, `floorKey`, `ceilingKey`).
- **`null` Keys:** `HashMap` and `LinkedHashMap` allow one `null` key (mapped to bucket 0); `TreeMap` throws `NullPointerException`.
- **LRU Implementation:** `new LinkedHashMap<>(cap, 0.75f, true)` with `removeEldestEntry()`.
- **Memory Footprint:** `HashMap` (~32B) $<$ `TreeMap` (~48B) $\approx$ `LinkedHashMap` (~48B).
- **Java 21:** `LinkedHashMap` and `TreeMap` implement `SequencedMap`.

**Common Follow-up Questions:**
- *"Why is `LinkedHashMap.get()` slightly slower than `HashMap.get()` when `accessOrder` is true?"* → In access-order mode, every `get()` must unlink the node from its current position in the doubly-linked list and re-attach it to the tail.
- *"How does `HashMap` handle null keys?"* → Null keys are always placed at array index 0 with a fixed hash of 0.
- *"Why does `TreeMap` not require `equals()` and `hashCode()`?"* → It navigates nodes by comparing keys via `Comparable.compareTo()` or `Comparator.compare()`.

**Red Flags (DO NOT Say):**
- ❌ *"TreeMap uses hashCode() to locate the root node."* (`TreeMap` uses binary search tree comparison, completely ignoring hash codes).
- ❌ *"HashMap preserves the order in which keys were inserted."* (Only `LinkedHashMap` preserves insertion order).
- ❌ *"LinkedHashMap has O(n) get() complexity because of its linked list."* (It maintains the exact same $O(1)$ hash table as `HashMap`; the linked list is only used for ordering).
