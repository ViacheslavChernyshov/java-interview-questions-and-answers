# What is Deque?

---

## 🟢 Junior Level

A **`Deque` (Double-Ended Queue)** is a linear collection that supports element insertion, removal, and inspection at **both ends** (Head and Tail).

**The Universal Structure:** `Deque` can act simultaneously as a **FIFO Queue** and a **LIFO Stack**:

```java
Deque<String> deque = new ArrayDeque<>();

// 1. Used as a LIFO Stack:
deque.push("Bottom");
deque.push("Top");
String popped = deque.pop(); // "Top"

// 2. Used as a FIFO Queue:
deque.offer("First");
deque.offer("Second");
String served = deque.poll(); // "First"

// 3. Explicit Head / Tail Operations:
deque.addFirst("Front");
deque.addLast("Back");
deque.removeFirst();
deque.removeLast();
```

## 🟡 Middle Level

### `ArrayDeque`: The Premier Implementation

`ArrayDeque` is the recommended default implementation of `Deque` in Java, outperforming `LinkedList` across every metric:

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │                        ArrayDeque                      │                       LinkedList                       │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ • Backed by a resizable **circular array buffer**      │ • Backed by doubly-linked `Node` objects               │
  │ • Continuous memory block (High CPU cache hits)        │ • Dispersed heap nodes (Cache misses on every jump)    │
  │ • Zero object allocation on `push()` / `poll()`        │ • Allocates new `Node` object on every single `add()`  │
  │ • **$3-10\times$ faster iteration**                    │ • Heavy memory footprint ($32\text{ bytes/node}$)      │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

### Method Summary Matrix

| Position | Throws Exception | Returns Special Value (`null` / `false`) |
|---|---|---|
| **Insert at Head** | `addFirst(e)` | `offerFirst(e)` |
| **Insert at Tail** | `addLast(e)` | `offerLast(e)` |

| **Examine Tail** | `getLast()` | `peekLast()` |

## 🔴 Senior Level

### Circular Array Buffer & Bitwise Power-of-Two Indexing

`ArrayDeque` ensures that its backing `Object[] elements` array length is **always a power of two ($2^n$)**:
- Instead of using slow CPU integer modulo arithmetic (`index = (index + 1) % capacity`), `ArrayDeque` wraps circular indices using a single high-speed **bitwise AND mask**:

$$\text{head} = (\text{head} - 1) \ \& \ (\text{elements.length} - 1)$$
$$\text{tail} = (\text{tail} + 1) \ \& \ (\text{elements.length} - 1)$$

```
  Circular Array Wrapping (Capacity = 8, Mask = 0111_2 = 7):
  Head advances from 0 -> (0 - 1) & 7 = -1 & 7 = 7 (Instantly wraps to end of array in 1 CPU cycle!)
```

### Concurrency: Work-Stealing in `ForkJoinPool`

In multi-threaded scheduling frameworks (such as `ForkJoinPool` and virtual thread schedulers), worker threads use **Double-Ended Queues (Work-Stealing Algorithm)**:
- A worker thread processes its own tasks in **LIFO order from the Head** (maximizing cache warmth).
- When a worker thread runs out of tasks, it **steals tasks from the Tail of a peer thread's deque in FIFO order**, minimizing lock contention between owners and thieves.

### Java 21 `SequencedCollection` Integration

In Java 21 (JEP 431), `Deque` extends `SequencedCollection`:
```java
Deque<String> deque = new ArrayDeque<>(List.of("A", "B", "C"));

String first = deque.getFirst(); // "A"
String last  = deque.getLast();  // "C"

// Produces a reverse-ordered live view without copying data:
SequencedCollection<String> reversed = deque.reversed();
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Double-Ended Queue allowing $O(1)$ amortized operations at both Head and Tail.
- **Dual Role:** Replaces `java.util.Stack` for LIFO operations and `LinkedList` for FIFO queues.
- **`ArrayDeque` Performance:** Resizable circular array, $3-10\times$ faster than `LinkedList` with zero node allocation garbage.
- **Power-of-Two Masking:** Sized to $2^n$ to replace `%` division with bitwise `& (length - 1)` wrapping.
- **Prohibits `null`:** Throws `NullPointerException` on `offer(null)` to eliminate ambiguity with `poll() == null`.
- **Work-Stealing:** Foundation of `ForkJoinPool` task scheduling (`LinkedBlockingDeque`).

**Common Follow-up Questions:**
- *"Why is `ArrayDeque` sized to powers of two?"* → To allow instantaneous circular index wrapping using a bitwise AND instruction (`& length - 1`), avoiding CPU division latency.
- *"Why should you never use `LinkedList` to implement a queue or stack?"* → `LinkedList` allocates an independent 32-byte `Node` object on the heap for every element, creating severe memory fragmentation and GC pressure.
- *"What happens when `ArrayDeque` circular array fills up?"* → It doubles its capacity, copying elements into the new array with `head` reset to 0.

**Red Flags (DO NOT Say):**
- ❌ *"LinkedList is better than ArrayDeque because it doesn't need to resize."* (`ArrayDeque`'s amortized resizing cost is negligible compared to `LinkedList`'s continuous node allocation overhead).
- ❌ *"ArrayDeque allows storing null elements."* (`ArrayDeque` strictly throws `NullPointerException`).
- ❌ *"Stack should be used instead of Deque for LIFO algorithms."* (`Stack` is obsolete and flawed; `Deque` is the official modern replacement).
