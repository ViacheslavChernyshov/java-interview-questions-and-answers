# What is TreeSet and how does it work?

---

## 🟢 Junior Level

**`TreeSet`** is a sorted, navigable collection of unique elements that implements the `NavigableSet` interface and maintains its elements in strictly sorted order (either by natural `Comparable` order or via an explicit `Comparator`).

```java
TreeSet<Integer> numbers = new TreeSet<>();
numbers.add(42);
numbers.add(10);
numbers.add(99);
numbers.add(10); // Duplicate ignored

System.out.println(numbers); // [10, 42, 99] (Guaranteed sorted!)
```

### Key Differences from `HashSet`

| Feature | `TreeSet` | `HashSet` |
|---|---|---|
| **Element Order** | **Strictly Sorted** | Unordered |
| **Internal Structure** | **Red-Black Tree** (`TreeMap`) | Hash Table (`HashMap`) |
| **Time Complexity** | **$O(\log n)$** | **$O(1)$** |
| **`null` Elements** | **Prohibited** (Throws NPE) | Allows 1 `null` |

## 🟡 Middle Level

### Internal Architecture: Red-Black Tree (`TreeMap`)

`TreeSet` is an adapter wrapper around `TreeMap<E, Object>`, storing elements as keys and binding them to the constant `PRESENT` dummy object:

```java
private transient NavigableMap<E,Object> m;
private static final Object PRESENT = new Object();
```

```
  Self-Balancing Red-Black Binary Search Tree:
                    ┌───────────┐
                    │   20 (B)  │  <- Root is always BLACK
                    └─────┬─────┘
               ┌──────────┴──────────┐
         ┌─────▼─────┐         ┌─────▼─────┐
         │   10 (R)  │         │   30 (R)  │
         └─────┬─────┘         └─────┬─────┘
            ┌──┴──┐               ┌──┴──┐
         ┌──▼─┐ ┌─▼──┐         ┌──▼─┐ ┌─▼──┐
         │5(B)│ │15(B)         │25(B) │35(B)
         └────┘ └────┘         └────┘ └────┘
```

**Red-Black Invariants Guarantees:**
1. Every node is either **Red** or **Black**.
2. The root is always **Black**.
3. No two consecutive Red nodes can appear on any path (Red parents have Black children).
4. Every path from the root to a leaf contains the exact same count of Black nodes (Black-Height invariant).
5. **Guarantee:** Tree height is strictly bounded by $\le 2 \log_2(n + 1)$, ensuring **$O(\log n)$ worst-case time complexity**.

### Navigable Query Operations

```java
TreeSet<Integer> scores = new TreeSet<>(List.of(10, 20, 30, 40, 50));

scores.floor(25);   // 20 (Greatest element <= 25)
scores.ceiling(25); // 30 (Smallest element >= 25)
scores.lower(20);   // 10 (Strictly < 20)
scores.higher(20);  // 30 (Strictly > 20)

// Sub-range Live Views:
NavigableSet<Integer> range = scores.subSet(20, true, 40, true); // [20, 30, 40]
```

## 🔴 Senior Level

### Live View Range Semantics & Memory Isolation

Range views returned by `subSet()`, `headSet()`, and `tailSet()` are **zero-copy live window views** mapped over the backing tree:
- Adding or removing elements in the view directly mutates the underlying `TreeSet`.
- Attempting to insert an element outside the bounded range throws `IllegalArgumentException`:

```java
NavigableSet<Integer> sub = scores.subSet(10, true, 30, true);
sub.add(25); // ✅ OK: Reflected in parent 'scores'

sub.add(50); // ❌ Throws IllegalArgumentException (50 is outside [10, 30] window!)
```

### The `compareTo()` vs. `equals()` Contract

`TreeSet` checks for duplicates using **`compareTo() == 0`**, ignoring `equals()`:
- If `compareTo()` returns `0`, the element is rejected as a duplicate even if `equals()` returns `false`.
- Always ensure `compareTo()` is **strictly consistent with `equals()`**:
  $$\forall a, b: (a.\text{compareTo}(b) == 0) \iff a.\text{equals}(b)$$

### Java 21 `SequencedSet` & Positional Operations

In Java 21, `TreeSet` implements `SequencedSet`:
```java
TreeSet<String> set = new TreeSet<>(List.of("A", "B", "C"));

String min = set.getFirst(); // "A" (Lowest sorted element)
String max = set.getLast();  // "C" (Highest sorted element)
SequencedSet<String> desc = set.reversed(); // Descending view

// Positional Mutators are FORBIDDEN:
set.addFirst("Z"); // ❌ Throws UnsupportedOperationException!
// (Sorted sets determine element placement strictly by sort key, not insertion position)
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Sorted, navigable set backed by a self-balancing Red-Black Tree (`TreeMap`).
- **Complexity:** $O(\log n)$ for `add()`, `remove()`, and `contains()`.
- **`NavigableSet` Methods:** `floor()`, `ceiling()`, `lower()`, `higher()`, `subSet()`.
- **Live Views:** `subSet()` creates an $O(1)$ live window view; mutations out of bounds throw `IllegalArgumentException`.
- **Equality:** Governed exclusively by `compareTo() == 0`, ignoring `equals()`.
- **`null` Restriction:** Throws `NullPointerException` (unless an explicit null-handling `Comparator` like `Comparator.nullsFirst()` is provided).
- **Java 21:** Implements `SequencedSet`, but `addFirst()` / `addLast()` throw `UnsupportedOperationException`.

**Common Follow-up Questions:**
- *"Why does `TreeSet` throw `UnsupportedOperationException` on `addFirst()` in Java 21?"* → Because a `TreeSet` is ordered by its sorting key; allowing callers to force an element to the front would violate the Red-Black sorting invariants.
- *"How does `TreeSet` balance itself during insertions?"* → By performing tree rotations (left/right turns) and node recoloring to preserve the Black-Height invariant.
- *"When should you choose `TreeSet` over `HashSet`?"* → When you require ascending/descending iteration order or need closest-match range lookups (`floor`, `ceiling`, `subSet`).

**Red Flags (DO NOT Say):**
- ❌ *"TreeSet uses equals() to check for duplicate elements."* (It uses `Comparable.compareTo()` or `Comparator.compare()`).
- ❌ *"TreeSet is faster than HashSet."* (TreeSet is $O(\log n)$ and suffers CPU cache misses; `HashSet` is $O(1)$).
- ❌ *"TreeSet.subSet() returns an independent copy of elements."* (It returns a live backed view).
