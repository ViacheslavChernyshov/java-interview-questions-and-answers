# What is the time complexity of operations in ArrayList?

---

## 🟢 Junior Level

**`ArrayList`** is backed by a contiguous, resizable dynamic array (`Object[] elementData`). Its algorithmic complexity reflects direct pointer offset arithmetic and array shifts.

### Time Complexity Summary

| Method / Operation | Complexity | Description |
|---|---|---|
| **`get(int index)`** | **$O(1)$** | Direct index lookup via pointer arithmetic (`array[i]`) |
| **`set(int index, E e)`** | **$O(1)$** | Replaces value at designated array slot |
| **`add(E e)` (Append)** | **Amortized $O(1)$** | Instant slot assignment; triggers $O(n)$ resize rarely |
| **`add(int index, E e)`** | **$O(n)$** | Shifts $n - \text{index}$ elements right via `System.arraycopy()` |
| **`remove(int index)`** | **$O(n)$** | Shifts $n - \text{index} - 1$ elements left |
| **`contains(Object o)`** | **$O(n)$** | Performs linear scan (`equals()`) through all elements |
| **`size()` / `isEmpty()`** | **$O(1)$** | Returns cached primitive `int size` field |

```java
ArrayList<String> list = new ArrayList<>();
list.add("A");      // Amortized O(1)
list.get(0);        // O(1) Instant
list.add(0, "B");   // O(n) Shifts elements
list.remove(0);     // O(n) Shifts elements
```

## 🟡 Middle Level

### The Mathematics of Amortized $O(1)$ Appends

When the internal buffer fills up, `ArrayList` allocates a new array $1.5\times$ larger and copies all elements:

```java
// Java ArrayList Growth Formula (Bitwise Shift):
int newCapacity = oldCapacity + (oldCapacity >> 1); // 1.5x scaling
```

**Why it is mathematically Amortized $O(1)$:**
- To insert $N$ items, the JVM resizes the array at sizes: $10, 15, 22, 33, \dots, N$.
- The total number of element copies across all resizes forms a geometric series summing to $\le 3N$.
- The average cost per insertion is:
  $$\text{Amortized Cost} = \frac{\text{Total Work}}{\text{Total Insertions}} = \frac{3N}{N} = \mathbf{O(1)}$$

### Bulk Operations & Optimization

```java
// 1. removeIf(predicate): O(n)
// Two-pointer BitSet scan + ONE consolidated arraycopy (replaces O(n^2) iterator loops)
list.removeIf(String::isEmpty);

// 2. ensureCapacity(int minCapacity):
// Pre-allocates buffer, eliminating all intermediate resize copies entirely
list.ensureCapacity(1_000_000);

// 3. binarySearch: O(log n) (Sorted lists only)
int idx = Collections.binarySearch(sortedList, "target");
```

## 🔴 Senior Level

### Memory Allocator Mechanics: Why $1.5\times$ Growth Instead of $2.0\times$?

In modern systems programming (and HotSpot's internal memory management), exponential array growth factor $k$ determines whether previously deallocated memory blocks can be reused:

```
  If Growth Factor = 2.0x:
  Allocation 1: [ 10 ]
  Allocation 2: [ 20 ] (Sum of previous = 10 -> Cannot fit in freed block 1)
  Allocation 3: [ 40 ] (Sum of previous = 30 -> Cannot fit in freed blocks 1 + 2)
  -> Every reallocation MUST allocate a new chunk at the end of the heap (Fragmentation!)

  If Growth Factor = 1.5x (k < 1.618 Golden Ratio):
  Allocation 1: [ 10 ]
  Allocation 2: [ 15 ]
  Allocation 3: [ 22 ]
  Allocation 4: [ 33 ] (Sum of freed blocks 10 + 15 + 22 = 47 -> FITS inside freed blocks!)
  -> Reuses previously reclaimed heap blocks, minimizing memory fragmentation.
```

### JIT SIMD Vectorization & `System.arraycopy()`

When `ArrayList` shifts elements during `add(index, e)` or `remove(index)`:
- `System.arraycopy()` is not a standard C `for` loop; it is a **JVM intrinsic** compiled down to hardware **SIMD vector instructions** (AVX2 / AVX-512).
- The CPU transfers **64 bytes (8–16 reference pointers) per clock cycle**.
- *Empirical Impact:* Shifting 1,000 pointers takes **$<1\text{ microsecond}$**, making $O(n)$ array shifts faster in practice than pointer allocation chains in $O(1)$ linked lists.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Key Operations:** `get(i)` is $O(1)$; append `add(e)` is amortized $O(1)$; positional `add(i, e)` and `remove(i)` are $O(n)$.
- **Amortized $O(1)$:** Resizing is infrequent ($1.5\times$ expansion); $N$ appends cost $\le 3N$ operations $\implies O(1)$ average.
- **Growth Factor:** $1.5\times$ expansion (`oldCapacity + (oldCapacity >> 1)`) allows OS and JVM memory allocators to reuse previously freed memory chunks ($k < 1.618$).
- **SIMD Acceleration:** `System.arraycopy()` utilizes hardware vector instructions to shift memory blocks in bulk.
- **Optimizations:** Use `ensureCapacity()` to eliminate resizing overhead; use `removeIf()` for single-pass $O(n)$ deletions.

**Common Follow-up Questions:**
- *"What is the difference in complexity between `list.contains(e)` and `Collections.binarySearch(list, e)`?"* → `contains()` performs an $O(n)$ linear scan; `binarySearch()` executes in $O(\log n)$ logarithmic time, requiring the list to be pre-sorted.
- *"Why is `remove(0)` on an ArrayList of 500 items faster than `LinkedList.remove(0)`?"* → Because `System.arraycopy()` moves 500 contiguous pointer addresses in a single SIMD burst, whereas `LinkedList` must dereference heap pointers and trigger GC cleanup.
- *"What happens to the internal `Object[]` capacity when elements are removed?"* → Removing elements does **not** shrink the internal array capacity; call `trimToSize()` to release unused array slots.

**Red Flags (DO NOT Say):**
- ❌ *"ArrayList.add(e) is always O(1) in the worst case."* (During array resizing, the individual operation is $O(n)$; it is *amortized* $O(1)$).
- ❌ *"A growth factor of 2.0x is always superior to 1.5x."* ($2.0\times$ growth prevents memory block reuse and causes heap fragmentation).
- ❌ *"Calling `remove(index)` frees the backing array memory."* (It only sets the slot to `null` for GC and shifts pointers; the array length remains unchanged).
