# What is Map and what implementations exist?

---

## 🟢 Junior Level

A **`Map<K, V>`** is an object that maps unique **Keys** to **Values**. Each key can map to at most one value.

> [!NOTE]
> **`Map` is NOT a `Collection`!**
> `Collection` represents a container of discrete single elements (`E`). `Map` defines a 2-dimensional key-value mapping model (`Map.Entry<K, V>`) exposing collection views: `keySet()`, `values()`, and `entrySet()`.

### The Core 4 Implementations

| Implementation | Internal Structure | Key Ordering | Best Use Case |
|---|---|---|---|
| **`HashMap`** | Hash Table (Buckets + Treeification) | **Unordered** | **Default choice (High-speed $O(1)$)** |
| **`LinkedHashMap`** | Hash Table + Doubly-Linked List | **Insertion / Access Order** | Deterministic traversal / LRU caches |
| **`TreeMap`** | Red-Black Tree (`NavigableMap`) | **Sorted by Key** | Range lookups & sorted reporting |
| **`ConcurrentHashMap`** | Concurrent Hash Table | **Unordered** | High-throughput multi-threaded code |

```java
Map<String, Integer> map = new HashMap<>();
map.put("Alice", 30);
map.put("Bob", 25);

int age = map.getOrDefault("Alice", 0); // 30
boolean exists = map.containsKey("Bob"); // true
```

## 🟡 Middle Level

### Specialized High-Performance Map Implementations

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │                   Specialized Map Class                │             Architecture & Ideal Application           │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **`EnumMap<K, V>`**                                    │ Backed by a flat `Object[]` array. Index is determined │
  │                                                        │ by `enum.ordinal()`. Zero hashing or collisions!       │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **`IdentityHashMap<K, V>`**                            │ Compares keys using **`==` reference equality** and    │
  │                                                        │ `System.identityHashCode()`. Used in serializers/graph │
  │                                                        │ cycle detection.                                       │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **`WeakHashMap<K, V>`**                                │ Keys are wrapped in `WeakReference`. Entries are       │
  │                                                        │ automatically purged when keys become weakly reachable.│
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

```java
// 1. EnumMap: The fastest Map implementation in the JVM
enum Priority { LOW, MEDIUM, HIGH }
Map<Priority, TaskHandler> handlers = new EnumMap<>(Priority.class);
handlers.put(Priority.HIGH, new HighPriorityHandler()); // Direct array index write!

// 2. IdentityHashMap: Tracking visited nodes in cyclic object graphs
Map<Object, Boolean> visitedNodes = new IdentityHashMap<>();
```

### Functional Mutations (Java 8+)

```java
// 1. Atomic computeIfAbsent: Initializes collection value if missing
map.computeIfAbsent("errors", k -> new ArrayList<>()).add("Connection timed out");

// 2. Atomic merge: Ideal for word counting and aggregations
map.merge("hitCount", 1, Integer::sum);
```

## 🔴 Senior Level

### Immutable Compact Maps (Java 9+)

```java
// Compact unmodifiable map (prohibits nulls, randomized iteration order):
Map<String, Integer> staticConfig = Map.of("timeout", 5000, "retries", 3);

// For more than 10 entries:
Map<String, Integer> largeMap = Map.ofEntries(
    Map.entry("k1", 1),
    Map.entry("k2", 2)
);
```
- Internally uses a compact linear probing array instead of allocating `HashMap.Node` objects, reducing memory consumption by over **$50\%$**.

### Java 21: SequencedMap (JEP 431)

`LinkedHashMap` and `TreeMap` implement **`SequencedMap`**, standardizing first/last entry access across ordered maps:

```java
SequencedMap<String, String> seqMap = new LinkedHashMap<>();
seqMap.putFirst("Root", "0");
seqMap.putLast("Leaf", "99");

Map.Entry<String, String> first = seqMap.firstEntry(); // ("Root", "0")
SequencedMap<String, String> reversed = seqMap.reversed(); // Live reverse view!
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`Map` vs `Collection`:** `Map` is a distinct hierarchy operating on Key-Value pairs (`Map.Entry`), exposing collection views via `keySet()`, `values()`, and `entrySet()`.
- **`HashMap`:** Default $O(1)$ hash table with Java 8+ treeification at bucket length $\ge 8$.
- **`EnumMap`:** Fastest map in the JVM; uses flat arrays indexed by `ordinal()`, bypassing hashing and collision resolution completely.
- **`IdentityHashMap`:** Compares keys using `==` reference identity instead of `equals()`.
- **`WeakHashMap`:** Automatically purges entries when keys lose strong reachability.
- **Java 8 Atomic Helpers:** `computeIfAbsent()`, `computeIfPresent()`, `merge()`, `putIfAbsent()`.
- **Java 21 `SequencedMap`:** Standardizes `firstEntry()`, `lastEntry()`, `putFirst()`, `putLast()`, and `reversed()`.

**Common Follow-up Questions:**
- *"Why is `EnumMap` significantly faster than `HashMap`?"* → Because enum ordinals are dense integers, `EnumMap` stores values in a flat `Object[]` array. A `get(key)` is a single primitive array lookup (`vals[key.ordinal()]`) without hashing or collision branching.
- *"Why is `WeakHashMap` dangerous when used as an application cache?"* → Because entries are cleared during Minor GC as soon as keys are dereferenced elsewhere. Use dedicated cache libraries (e.g. Caffeine) instead.
- *"What happens if you insert duplicate keys into a Map?"* → The existing value is overwritten, and `put()` returns the previous value.

**Red Flags (DO NOT Say):**
- ❌ *"Map extends Collection in Java."* (Map is a separate root interface).
- ❌ *"IdentityHashMap uses equals() and hashCode() to match keys."* (It uses `==` and `System.identityHashCode()`).
- ❌ *"WeakHashMap keys stay in memory as long as values have strong references."* (Reachability depends solely on the *Keys*; strong value references can create memory leaks if values point back to keys).
