# What is the difference between List, Set and Queue?

---

## 🟢 Junior Level

**`List`**, **`Set`**, and **`Queue`** represent the three fundamental sub-interfaces of `java.util.Collection`.

### Core Architectural Differences

| Interface | Ordering Guarantee | Duplicate Elements? | Positional Index Access? | Real-World Analogy |
|---|---|---|---|---|
| **`List`** | Preserves insertion sequence | **Allowed** | **Yes** (`list.get(index)`) | Grocery shopping checklist |
| **`Set`** | Unordered (except `LinkedHashSet`/`TreeSet`) | **Forbidden** (Unique only) | **No** (Iteration only) | Unique keychain |
| **`Queue`** | FIFO / Priority order | **Allowed** | **No** (Head access only) | Supermarket checkout line |

```java
// 1. List: Maintains order and allows duplicates
List<String> list = new ArrayList<>(List.of("B", "A", "B")); // [B, A, B]

// 2. Set: Rejects duplicate entries
Set<String> set = new HashSet<>(list); // [A, B] (Unordered)

// 3. Queue: Processes elements in FIFO order
Queue<String> queue = new ArrayDeque<>();
queue.offer("Task 1");
queue.offer("Task 2");
String next = queue.poll(); // "Task 1"
```

## 🟡 Middle Level

### Big-O Algorithmic Comparison

| Operation | `ArrayList` (List) | `HashSet` (Set) | `TreeSet` (Set) | `ArrayDeque` (Queue) |
|---|---|---|---|---|
| **Insertion** | Amortized $O(1)$ | $O(1)$ | $O(\log n)$ | $O(1)$ |
| **Lookup / Contains** | $O(n)$ (Linear scan) | **$O(1)$** | $O(\log n)$ | $O(n)$ |
| **Deletion** | $O(n)$ (Array shift) | **$O(1)$** | $O(\log n)$ | **$O(1)$** (Head/Tail) |
| **Index Access (`get(i)`)** | **$O(1)$** | Not Supported | Not Supported | Not Supported |

### Queue Method Dual Contracts

The `Queue` interface defines two parallel sets of methods for handling capacity limits and empty states:

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │                 Throws Exception on Failure            │               Returns Special Value (null / false)     │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ • `add(e)`: Throws `IllegalStateException` if full     │ • `offer(e)`: Returns `false` if full                  │
  │ • `remove()`: Throws `NoSuchElementException` if empty │ • `poll()`: Returns `null` if empty                    │
  │ • `element()`: Throws `NoSuchElementException` if empty│ • `peek()`: Returns `null` if empty                    │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```
> [!TIP]
> In production code, **always prefer `offer()`, `poll()`, and `peek()`** to avoid unexpected runtime exceptions in high-throughput pipelines.

## 🔴 Senior Level

### Memory Footprint & Cache Locality Breakdown

```
  Memory Layout Comparison:
  ┌─────────────────────────────────────────────────────────────────────────────────────────┐
  │ 1. ArrayList: Contiguous `Object[]` buffer -> 4-8 bytes per reference pointer           │
  │    (Maximum CPU L1/L2 cache prefetching efficiency; 10-50x faster iteration!)           │
  ├─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 2. HashSet: Wraps `HashMap<E, Object>` -> Allocates `Node<K, V>` per element            │
  │    (32-48 bytes per element; scattered heap nodes causing cache misses during iteration)│
  ├─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 3. TreeSet: Wraps `TreeMap<E, Object>` (Red-Black Tree) -> Allocates `Entry<K, V>`      │
  │    (48-64 bytes per node: `left`, `right`, `parent`, `color` pointers)                  │
  └─────────────────────────────────────────────────────────────────────────────────────────┘
```

### High-Performance Concurrent Alternatives

When thread safety is required, avoid legacy `Collections.synchronized*` wrappers:

```java
// Concurrent List (Optimized for heavy reads, rare mutations):
List<String> threadSafeList = new CopyOnWriteArrayList<>();

// Concurrent Set (Highest throughput concurrent set backed by ConcurrentHashMap):
Set<String> threadSafeSet = ConcurrentHashMap.newKeySet();

// Concurrent Queue (Lock-free non-blocking FIFO queue):
Queue<Task> threadSafeQueue = new ConcurrentLinkedQueue<>();
```

### Huge Sets: Bloom Filters vs. `HashSet`

When tracking **hundreds of millions of unique keys** (e.g. tracking visited URLs in a web crawler or cache-aside checks), storing standard `HashSet` instances consumes tens of gigabytes of RAM.

Use an off-heap or bitset **Bloom Filter**:
- Consumes **megabytes instead of gigabytes**.
- Delivers $O(1)$ membership checks.
- *Trade-off:* Zero false negatives ("definitely not in set"), but slight configurable false positive rate ("probably in set").

## 🎯 Interview Cheat Sheet

**Must Know:**
- **List:** Ordered sequence, duplicates permitted, $O(1)$ random index access (`ArrayList`).
- **Set:** Uniqueness guaranteed via `equals()` & `hashCode()`, $O(1)$ search (`HashSet`), $O(\log n)$ sorting (`TreeSet`).
- **Queue:** FIFO buffer, $O(1)$ head/tail operations (`ArrayDeque`), safe methods (`offer`, `poll`, `peek`).
- **Memory Efficiency:** `ArrayList` (contiguous array, CPU cache hits) $\gg$ `HashSet` ($\sim 2\times$ memory, `Node` wrappers) $\gg$ `TreeSet` ($\sim 4\times$ memory, Red-Black nodes).
- **Concurrency Best Practice:** Use `ConcurrentHashMap.newKeySet()` for thread-safe sets and `ConcurrentLinkedQueue` for lock-free queues.

**Common Follow-up Questions:**
- *"Why does `HashSet` consume significantly more memory than `ArrayList`?"* → `HashSet` is internally backed by a `HashMap`, wrapping every element inside a `HashMap.Node` object (containing hash, key, value, and next pointer).
- *"When should you choose `TreeSet` over `HashSet`?"* → When you require automatic sorted ordering or range queries (`subSet`, `headSet`, `tailSet`), accepting $O(\log n)$ search cost.
- *"Why is `ArrayDeque` superior to `Stack` and `LinkedList` for queue/stack operations?"* → `ArrayDeque` uses a circular array buffer, eliminating node allocation overhead and maximizing CPU cache locality.

**Red Flags (DO NOT Say):**
- ❌ *"HashSet preserves the order in which elements were added."* (`HashSet` is unordered; use `LinkedHashSet` to preserve insertion order).
- ❌ *"Checking `contains()` in an `ArrayList` is just as fast as in a `HashSet`."* (`ArrayList.contains()` is $O(n)$; `HashSet.contains()` is $O(1)$).
- ❌ *"LinkedList is faster than ArrayList for iteration because it uses pointers."* (Pointers cause random memory lookups and CPU cache misses, making `LinkedList` up to $50\times$ slower to iterate).
