# What is Collections.unmodifiableList()?

---

## 🟢 Junior Level

**`Collections.unmodifiableList()`** returns an **unmodifiable view wrapper** around a backing `List`.

Any attempt to modify the returned list directly via mutator methods (`add()`, `set()`, `remove()`, `clear()`) will throw an **`UnsupportedOperationException`**.

```java
List<String> mutableList = new ArrayList<>(List.of("A", "B"));
List<String> unmodifiableView = Collections.unmodifiableList(mutableList);

unmodifiableView.get(0);    // ✅ OK -> Returns "A"
unmodifiableView.add("C");  // ❌ Throws UnsupportedOperationException!
```

> [!WARNING]
> **It is a VIEW, not a copy!**
> If the underlying `mutableList` is modified elsewhere, **those changes are immediately visible through the unmodifiable view**:
> ```java
> mutableList.add("C");
> System.out.println(unmodifiableView.size()); // 3 (Shows "C"!)
> ```

## 🟡 Middle Level

### Unmodifiable View vs. True Immutability (`List.of` / `List.copyOf`)

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │         Unmodifiable View (Collections.unmodifiableList)│             Truly Immutable List (List.copyOf / List.of)│
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ • $O(1)$ lightweight wrapper decorator                 │ • $O(n)$ independent defensive memory snapshot         │
  │ • Reflects subsequent mutations made to the backing list│ • 100% decoupled from the source collection            │
  │ • Allows `null` elements (if backing list does)        │ • Strictly prohibits `null` elements                   │
  │ • Retains backing collection in memory                 │ • Compact memory footprint                             │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

```java
// 1. Unmodifiable View: Linked to backing list
List<String> view = Collections.unmodifiableList(originalList);

// 2. Truly Immutable List (Java 10+): Decoupled defensive copy
List<String> immutable = List.copyOf(originalList);
```

### Shallow vs. Deep Immutability

`unmodifiableList` provides **shallow structural protection only**:
```java
List<User> users = Collections.unmodifiableList(userList);

// ❌ Structural mutation blocked:
users.add(new User("Hacker")); // Throws UnsupportedOperationException!

// ⚠️ Internal object mutation PERMITTED:
users.get(0).setName("Compromised"); // Modifies mutable object state!
```
**Best Practice:** Store **immutable objects (`record`s)** inside unmodifiable collections to guarantee deep immutability.

## 🔴 Senior Level

### Preservation of `RandomAccess`

To ensure optimal algorithmic efficiency in utilities like `Collections.binarySearch()`, the factory method inspects the backing list's capabilities:

```java
public static <T> List<T> unmodifiableList(List<? extends T> list) {
    return (list instanceof RandomAccess ?
            new UnmodifiableRandomAccessList<>(list) :
            new UnmodifiableList<>(list));
}
```
If the source list implements `RandomAccess` (e.g. `ArrayList`), the returned wrapper also implements `RandomAccess`, allowing binary search algorithms to execute via $O(1)$ index lookups instead of falling back to iterator traversal.

### Defensive Encapsulation in Domain Services

```java
public class OrderService {
    private final List<OrderItem> items = new ArrayList<>();

    // ✅ PROPER ENCAPSULATION:
    public List<OrderItem> getItems() {
        // Option A: Zero-allocation live view (Clients cannot modify, but observe internal updates)
        return Collections.unmodifiableList(items);

        // Option B: Snapshot isolation (Clients receive decoupled immutable copy)
        // return List.copyOf(items);
    }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Returns an $O(1)$ unmodifiable view wrapper around a backing list; mutators throw `UnsupportedOperationException`.
- **View vs Copy:** It is a view; modifications to the original backing list are immediately reflected in the unmodifiable wrapper.
- **True Immutability:** Use `List.copyOf()` (Java 10+) or `List.of()` (Java 9+) for fully decoupled immutable snapshots.
- **Shallow Immutability:** Protects list structure (add/remove), but does not prevent mutations to internal object fields.
- **Marker Preservation:** Implements `RandomAccess` if the backing list does (`UnmodifiableRandomAccessList`).

**Common Follow-up Questions:**
- *"What is the performance difference between `Collections.unmodifiableList(list)` and `List.copyOf(list)`?"* → `unmodifiableList()` is an instant $O(1)$ decorator allocation; `List.copyOf()` is an $O(n)$ array allocation that copies all element references.
- *"Can you pass `null` to `Collections.unmodifiableList()`?"* → If the backing list contains `null`, `unmodifiableList` allows it; `List.copyOf()` and `List.of()` will throw a `NullPointerException`.
- *"Why is `Collections.unmodifiableList()` useful in getters?"* → It prevents callers from altering private internal list state without the overhead of making a full defensive copy.

**Red Flags (DO NOT Say):**
- ❌ *"Collections.unmodifiableList creates an independent immutable copy of the list."* (It is an $O(1)$ view of the original list).
- ❌ *"Collections.unmodifiableList makes all objects inside the list immutable."* (It only prevents structural list mutations; objects inside can still be modified).
- ❌ *"List.copyOf and Collections.unmodifiableList are identical in Java."* (`List.copyOf` creates an immutable copy; `unmodifiableList` creates a live view).
