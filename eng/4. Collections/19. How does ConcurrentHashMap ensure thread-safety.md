# How does ConcurrentHashMap ensure thread-safety?

---

## 🟢 Junior Level

**`ConcurrentHashMap`** delivers high-concurrency thread safety through **three cooperative mechanisms**:

```
  ┌─────────────────────────────────────────────────────────────────────────────────────────┐
  │ 1. Lock-Free CAS: Inserts elements into empty buckets without acquiring any locks       │
  ├─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 2. Volatile Visibility: All bucket arrays and node fields are `volatile`                │
  ├─────────────────────────────────────────────────────────────────────────────────────────┤
  │ 3. Per-Bucket `synchronized`: Locks ONLY the individual bucket experiencing a collision │
  └─────────────────────────────────────────────────────────────────────────────────────────┘
```

```java
ConcurrentHashMap<String, Integer> map = new ConcurrentHashMap<>();

// Thread 1 writes to Bucket A -> Uses CAS or locks Bucket A only
map.put("KeyA", 100);

// Thread 2 writes to Bucket B simultaneously -> Runs concurrently without waiting!
map.put("KeyB", 200);

// Thread 3 reads from Bucket A -> Lock-free volatile read!
Integer val = map.get("KeyA");
```

## 🟡 Middle Level

### The 3 Core Concurrency Pillars

#### 1. Lock-Free CAS on Empty Buckets
When a bucket slot is empty (`table[i] == null`), `ConcurrentHashMap` attempts an atomic **Compare-And-Swap (CAS)** instruction:
```java
// Conceptual JDK implementation:
if (casTabAt(tab, i, null, new Node<K,V>(hash, key, value))) {
    // Insertion succeeded with ZERO lock acquisition!
}
```
If two threads attempt to insert into the same empty slot simultaneously, one CAS succeeds immediately and the losing thread loops to synchronize on the newly installed head node.

#### 2. Fine-Grained `synchronized` on Bucket Heads
When a collision occurs (`table[i] != null`), `ConcurrentHashMap` locks **strictly the first node (head) of that specific bucket**:

```java
// Synchronizes ONLY on the head node of bucket i:
Node<K, V> f = tabAt(tab, i);
synchronized (f) {
    // Traverses linked list or Red-Black Tree to insert or update
}
```
Threads writing to any of the thousands of other buckets continue executing in parallel.

#### 3. Volatile JMM Visibility
The internal table array and node references are declared **`volatile`**:
```java
transient volatile Node<K, V>[] table;

static class Node<K, V> implements Map.Entry<K, V> {
    final int hash;
    final K key;
    volatile V val;        // Volatile write visibility
    volatile Node<K, V> next; // Volatile link visibility
}
```
Under the Java Memory Model (JMM), reading a volatile reference forms a **Happens-Before** edge, allowing `get()` to read data safely with zero locks.

## 🔴 Senior Level

### Distributed Multi-Threaded Resizing (`ForwardingNode`)

```
  Table Transfer Mechanics:
  [Old Table Bucket i] ──> Replaced by `ForwardingNode` (hash = -1 / MOVED)
                                │
  Thread arrives to write ──────┘
  Detects ForwardingNode -> Calls `helpTransfer()` -> Migrates a chunk of buckets in parallel!
```

- When the table capacity threshold is crossed, the resizing thread allocates a `nextTable` twice the size.
- Migrated buckets are replaced with a **`ForwardingNode`** pointing to the new table.
- Concurrent writer threads that encounter a `ForwardingNode` do not block; they cooperate to assist the migration via **`helpTransfer()`**, finishing large resizes in parallel.

### Scalable Counter: `CounterCell` Array (LongAdder Pattern)

Instead of forcing all threads to contend on a single volatile `size` variable, `ConcurrentHashMap` stripes modifications across a **`CounterCell[]` array**:
- Each thread hashes its thread probe ID to increment an independent `CounterCell`.
- `mappingCount()` computes the transient sum across all cells:

$$\text{Total Count} = \text{baseCount} + \sum \text{CounterCell}[i].\text{value}$$

### Atomic Synchronization with `ReservationNode`

During **`computeIfAbsent()`**, if the target bucket is empty:
1. `ConcurrentHashMap` inserts a lightweight **`ReservationNode`** (hash `-3`) via CAS.
2. It locks the `ReservationNode` while the user's mapping function executes.
3. This prevents other threads from computing duplicate values for the same key while keeping all other table buckets completely unlocked.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **3 Pillars:** Lock-free CAS for empty buckets, fine-grained `synchronized` on bucket head nodes for collisions, and `volatile` for lock-free `get()` reads.
- **Lock-Free Reads:** `get()` never acquires a lock, relying on `volatile Node.val` and `volatile Node.next`.
- **Parallel Resizing:** `ForwardingNode` (hash `-1`) routes threads to `helpTransfer()` to migrate table segments cooperatively.
- **Size Scalability:** `CounterCell[]` array (striped like `LongAdder`) prevents CAS contention on size tracking.
- **`ReservationNode`:** Locks empty bucket slots during `computeIfAbsent()` to prevent duplicate computations.
- **TreeBins:** Converts bucket lists with $\ge 8$ entries into Red-Black trees using internal read-write state bits.

**Common Follow-up Questions:**
- *"Why did Java 8 replace `ReentrantLock` segments with `synchronized` on bucket heads?"* → `synchronized` in modern JVMs is heavily optimized by HotSpot (biased locking, lock coarsening, adaptive spinning) and consumes zero object header memory compared to allocating 16 discrete `Segment` objects.
- *"What happens if a custom key class has a broken `hashCode()` returning a constant?"* → All keys collide in a single bucket. While TreeBin conversion maintains $O(\log n)$ algorithmic complexity, all multi-threaded writes serialize on the single bucket head lock, reducing concurrency to zero.
- *"How does `ConcurrentHashMap` prevent deadlock during `computeIfAbsent()`?"* → Never call nested mutations or blocking methods on the same map inside the lambda, as holding the bucket head lock will deadlock concurrent operations.

**Red Flags (DO NOT Say):**
- ❌ *"ConcurrentHashMap acquires a read lock during get()."* (`get()` is 100% lock-free).
- ❌ *"ConcurrentHashMap uses Segment locking in modern Java."* (Segments were eliminated in Java 8 in favor of node-level synchronization).
- ❌ *"ConcurrentHashMap allows null keys if synchronized externally."* (Null keys and values are strictly prohibited).
