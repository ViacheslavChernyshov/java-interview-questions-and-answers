# What is Queue and what implementations exist?

---

## 🟢 Junior Level

A **`Queue`** is a collection designed for holding elements prior to processing, typically ordering elements in a **FIFO (First-In, First-Out)** sequence.

### The Two Parallel Method Contracts

The `Queue` interface provides two distinct sets of methods for handling boundary conditions (full buffers or empty queues):

| Operation Type | Throws Exception on Failure | Returns Special Value (`false` / `null`) |
|---|---|---|
| **Insert** | `add(e)` (Throws `IllegalStateException`) | **`offer(e)`** (Returns `false`) |
| **Remove** | `remove()` (Throws `NoSuchElementException`) | **`poll()`** (Returns `null`) |
| **Examine** | `element()` (Throws `NoSuchElementException`) | **`peek()`** (Returns `null`) |

```java
// ✅ RECOMMENDED: Use offer/poll/peek to avoid runtime exceptions
Queue<String> queue = new ArrayDeque<>();
queue.offer("Order 1");
queue.offer("Order 2");

String processed = queue.poll(); // "Order 1" (First-In, First-Out)
String next      = queue.peek(); // "Order 2" (Inspects head without removal)
```

## 🟡 Middle Level

### Comprehensive Taxonomy of Queue Implementations

```
  java.util.Queue<E>
    ├── java.util.Deque<E> (Double-ended queue)
    │     ├── java.util.ArrayDeque<E>                (Fastest single-threaded FIFO/LIFO)
    │     └── java.util.LinkedList<E>                (Doubly-linked list)
    ├── java.util.PriorityQueue<E>                   (Min-Heap priority ordering)
    └── java.util.concurrent.BlockingQueue<E>        (Thread-safe Producer-Consumer)
          ├── java.util.concurrent.ArrayBlockingQueue<E>   (Bounded circular array)
          ├── java.util.concurrent.LinkedBlockingQueue<E>  (Optionally bounded two-lock queue)
          ├── java.util.concurrent.ConcurrentLinkedQueue<E>(Lock-free CAS queue)
          ├── java.util.concurrent.SynchronousQueue<E>     (Zero-capacity rendezvous)
          └── java.util.concurrent.DelayQueue<E>           (Time-delayed release)
```

### Why Most Queues Strictly Prohibit `null`

Unlike `List`, nearly all modern `Queue` implementations (including `ArrayDeque`, `PriorityQueue`, and all `BlockingQueue` classes) **throw `NullPointerException` on `offer(null)`**:
- `poll()` and `peek()` return `null` as a sentinel value indicating that the queue is empty.
- If `null` were allowed as a valid element, `poll()` returning `null` would be fatally ambiguous (is the queue empty, or was the head element a literal `null`?).

## 🔴 Senior Level

### High-Throughput Concurrency Patterns & Backpressure

```java
// 1. Production Producer-Consumer Pattern with Backpressure:
BlockingQueue<OrderEvent> boundedQueue = new ArrayBlockingQueue<>(10_000);

// Producer Thread:
boundedQueue.put(event); // Blocks when buffer hits 10,000, throttling producers!

// Consumer Thread:
OrderEvent event = boundedQueue.take(); // Blocks when buffer is empty
```

> [!IMPORTANT]
> **Backpressure & OOM Defense:** Always use a **bounded** queue in production. An unbounded queue (`new LinkedBlockingQueue<>()` default size is $2^{31}-1$) allows fast producers to swamp slow consumers, accumulating gigabytes of unconsumed events until an `OutOfMemoryError` crashes the JVM.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **FIFO Concept:** First-In, First-Out; use `offer()`, `poll()`, and `peek()` for graceful non-throwing execution.
- **`ArrayDeque`:** The fastest single-threaded queue and stack in Java (circular array, $O(1)$ amortized).
- **`PriorityQueue`:** Dynamic min-heap array extracting the smallest element ($O(\log n)$ enqueue/dequeue).
- **Backpressure via Bounded Queues:** Protects systems from OOM crashes by forcing fast producers to block (`put()`).
- **`LinkedBlockingQueue` Two-Lock Design:** Uses separate `putLock` and `takeLock` to allow simultaneous producer-consumer throughput.
- **`null` Prohibition:** Queues forbid `null` to eliminate ambiguity with `poll() == null` on empty queues.

**Common Follow-up Questions:**
- *"What is the difference between `ArrayBlockingQueue` and `LinkedBlockingQueue`?"* → `ArrayBlockingQueue` uses a pre-allocated fixed circular array and a single lock; `LinkedBlockingQueue` uses dynamically allocated nodes and two separate locks (`putLock` and `takeLock`) for higher concurrency.
- *"Why does `PriorityQueue` extract the minimum element by default?"* → It is a standard Min-Heap based on natural `Comparable` ordering. To make it a Max-Heap, supply a reverse comparator (`Comparator.reverseOrder()`).
- *"Where is `SynchronousQueue` used in the JDK?"* → Inside `Executors.newCachedThreadPool()`, allowing worker threads to hand off incoming tasks directly without queuing them in memory.

**Red Flags (DO NOT Say):**
- ❌ *"Queue allows storing null elements."* (Almost all implementations throw `NullPointerException`).
- ❌ *"Use LinkedList whenever you need a FIFO Queue."* (`ArrayDeque` is significantly faster, uses less memory, and creates no GC pressure).
- ❌ *"PriorityQueue is sorted in memory."* (It only guarantees that the head element is the minimum element according to the binary heap property; the underlying array is not fully sorted).
