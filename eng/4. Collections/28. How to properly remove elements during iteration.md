# How to properly remove elements during iteration?

---

## 🟢 Junior Level

Attempting to remove elements directly from a collection using `list.remove()` inside an enhanced `for-each` loop throws **`ConcurrentModificationException`**.

### The 2 Correct Ways to Remove Elements

```java
List<String> list = new ArrayList<>(List.of("Alpha", "Beta", "Gamma"));

// ✅ METHOD 1: Collection.removeIf() (Java 8+ Modern Standard):
list.removeIf(item -> item.startsWith("A"));

// ✅ METHOD 2: Explicit Iterator.remove() (Legacy & Specialized):
Iterator<String> it = list.iterator();
while (it.hasNext()) {
    if (it.next().startsWith("B")) {
        it.remove(); // Safely removes element and updates iterator state!
    }
}
```

## 🟡 Middle Level

### Strategy Comparison Matrix

| Removal Technique | `ArrayList` Complexity | `LinkedList` Complexity | Thread Safety | Safe from CME? |
|---|---|---|---|---|
| **`for-each` + `list.remove()`** | ❌ Fails | ❌ Fails | None | **NO (Throws CME)** |
| **`Iterator.remove()`** | **$O(n^2)$** (Repeated array shifts) | **$O(n)$** ($O(1)$ pointer rewiring) | None | **YES** |
| **`Collection.removeIf()`** | **$O(n)$** (Single consolidated sweep) | **$O(n)$** | None | **YES** |
| **Reverse `for-i` Loop** | **$O(n^2)$** | **$O(n^2)$** (Traverses from head) | None | **YES** |
| **`Stream.filter().toList()`** | **$O(n)$** (Allocates new list) | **$O(n)$** | None | **YES** |

## 🔴 Senior Level

### Why `removeIf()` is $20{,}000\times$ Faster than `Iterator.remove()`

```
  Iterator.remove() on ArrayList of 1,000,000 Elements (Removing 500,000 items):
  ┌─────────────────────────────────────────────────────────────────────────────────────────┐
  │ Remove item 1  -> Shifts 999,999 elements via `System.arraycopy()`                      │
  │ Remove item 2  -> Shifts 999,998 elements via `System.arraycopy()`                      │
  │ ...                                                                                     │
  │ Remove item 500,000 -> Shifts 500,000 elements                                          │
  │ -> Total Work: ~375,000,000,000 memory copies -> Runs in ~10 MINUTES! (O(n^2))          │
  └─────────────────────────────────────────────────────────────────────────────────────────┘

  ArrayList.removeIf() (Java 9+ Engine):
  ┌─────────────────────────────────────────────────────────────────────────────────────────┐
  │ Pass 1: Scans array and marks removal indices in a bitmask without altering memory       │
  │ Pass 2: Executes a single consolidated two-pointer sweep, compacting survivors in-place  │
  │ -> Total Work: Exactly 1,000,000 element reads and surviving writes -> Runs in ~30ms!   │
  └─────────────────────────────────────────────────────────────────────────────────────────┘
```

### The Reverse Indexed Loop ($O(n^2)$ Fallacy)

A common interview trick is iterating backward to avoid `ConcurrentModificationException`:
```java
// Avoids CME, but still suffers O(n^2) arraycopy latency on ArrayList:
for (int i = list.size() - 1; i >= 0; i--) {
    if (shouldRemove(list.get(i))) {
        list.remove(i); // Triggers arraycopy on every match!
    }
}
```
While this avoids CME and index misalignment, it is still asymptotically inferior to **`removeIf()`**.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Never Use:** `list.remove()` inside an enhanced `for-each` loop (triggers `ConcurrentModificationException`).
- **Standard Choice:** **`list.removeIf(predicate)`** is the production standard (linear $O(n)$ time).
- **`Iterator.remove()`:** Safe from CME, but degrades to $O(n^2)$ on `ArrayList` due to repeated `System.arraycopy` shifts.
- **`LinkedList` Nuance:** `Iterator.remove()` is $O(1)$ per node because the iterator already holds the reference to the target node.
- **Stream Alternative:** `list.stream().filter(predicate).toList()` creates a new unmodifiable collection instead of mutating in place.

**Common Follow-up Questions:**
- *"Why does `Iterator.remove()` not cause a `ConcurrentModificationException`?"* → `Iterator.remove()` updates the iterator's `expectedModCount` to match the list's newly incremented `modCount`.
- *"How does `ArrayList.removeIf()` achieve $O(n)$ time?"* → It uses a two-pointer BitSet sweep to compact all non-matching elements in a single sequential pass across the backing array.
- *"How do you safely remove elements from a `ConcurrentHashMap` during iteration?"* → Calling `it.remove()` on a `ConcurrentHashMap` iterator is fully thread-safe and weakly consistent.

**Red Flags (DO NOT Say):**
- ❌ *"Calling list.remove() inside a for-each loop is safe if you break immediately."* (Even if breaking avoids CME on the first match, it fails for multiple removals and is dangerous code).
- ❌ *"Iterator.remove() is just as fast as removeIf() for ArrayLists."* (`Iterator.remove()` causes $O(n^2)$ array copying; `removeIf()` executes in $O(n)$).
- ❌ *"Stream.filter() mutates the original list in-place."* (`Stream.filter()` produces a brand-new stream/collection).
