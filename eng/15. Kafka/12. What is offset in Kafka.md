# What is Offset in Kafka?

---

## 🟢 Junior Level

An **Offset** in Apache Kafka is a 64-bit sequential, monotonically increasing integer assigned to each message as it is appended to a partition log. It acts as the unique sequential address (index) of a record within that specific partition:

```
  Book Bookmark Analogy:
  • Partition = A book with numbered pages (Page 0, 1, 2, 3... 100).
  • Offset = The page number of each paragraph.
  • Consumer Position = Your physical bookmark indicating which page you are currently reading.
  • Committed Offset = Marking your reading progress in a reading journal (Saving progress).
```

```
  Partition 0:
  ┌──────────┬──────────┬──────────┬──────────┬──────────┐
  │ Offset 0 │ Offset 1 │ Offset 2 │ Offset 3 │ Offset 4 │ ──► (Append Only)
  └──────────┴──────────┴──────────┴──────────┴──────────┘
```

```
  3 Fundamental Properties of Offsets:
  1. Monotonic: Always increments (`0, 1, 2, 3...`); never resets or decreases under normal operation.
  2. Partition-Local: Offset 100 in Partition 0 has zero relation to Offset 100 in Partition 1.
  3. Immutable: Once assigned and written, a record's offset can never be changed.
```

## 🟡 Middle Level

### The 4 Core Offset Landmarks

```
  PARTITION LOG:
  [Offset 0] ... [Offset 95] ... [Offset 100] ... [Offset 105] ──► (Next Write: 106)
                     ▲               ▲                ▲
                     │               │                │
            [Committed Offset]  [High Watermark]    [Log End Offset - LEO]
```

```
  ┌──────────────────────────────┬─────────────────────────────────────────────────────────────────────────────────┐
  │ Offset Landmark              │ Technical Definition & Role                                                     │
  ├──────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ **Current Position**         │ The next offset the consumer will fetch on its next `poll()` call.              │
  │ **Committed Offset**         │ The last offset successfully saved into `__consumer_offsets` for this group.    │
  │ **High Watermark (HW)**      │ The highest offset replicated across all **In-Sync Replicas (ISR)**.           │
  │                              │ Consumers are restricted to reading only up to the High Watermark!              │
  │ **Log End Offset (LEO)**     │ The offset of the next record to be written by a producer.                      │
  │ **Consumer Lag**             │ $\text{Lag} = \text{HW} - \text{Committed Offset}$ (Backlog of unread messages).│
  └──────────────────────────────┴─────────────────────────────────────────────────────────────────────────────────┘
```

## 🔴 Senior Level

### Offset Repositioning & Time-Travel Operations (`seek`)

Consumers can programmatically reposition their reading bookmark to any valid historical offset:

```java
TopicPartition partition = new TopicPartition("order-events", 0);

// 1. Reset consumer to the very beginning of the partition log:
consumer.seekToBeginning(List.of(partition));

// 2. Jump forward to the very latest end of the log (Skip backlog):
consumer.seekToEnd(List.of(partition));

// 3. Precise point-in-time seek (e.g. replay from 2 hours ago):
long twoHoursAgo = System.currentTimeMillis() - TimeUnit.HOURS.toMillis(2);
Map<TopicPartition, Long> timestampsToSearch = Map.of(partition, twoHoursAgo);

// Queries broker index files (.timeindex) for matching offsets:
Map<TopicPartition, OffsetAndTimestamp> foundOffsets = consumer.offsetsForTimes(timestampsToSearch);
OffsetAndTimestamp target = foundOffsets.get(partition);

if (target != null) {
    consumer.seek(partition, target.offset());
    log.info("Repositioned partition 0 to offset: {}", target.offset());
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Monotonically increasing 64-bit integer identifier assigned to each record in a partition.
- **Scope:** Offsets are strictly unique **only within their individual partition**.
- **High Watermark:** Consumers can only read messages up to the High Watermark (data confirmed by all ISR replicas).
- **Consumer Lag:** The delta between the partition High Watermark and the Consumer Group's Committed Offset.
- **Time-Travel:** `consumer.seek()` and `offsetsForTimes()` allow replaying historical events.

**Common Follow-up Questions:**
- *"What happens if a consumer queries an offset that was already deleted by the retention policy?"* → The broker returns `OffsetOutOfRangeException`; the consumer then applies its `auto.offset.reset` policy (`earliest` or `latest`).
- *"Where are consumer offsets stored in modern Kafka?"* → In the internal Kafka topic `__consumer_offsets` (stored with 50 partitions and log compaction enabled).
- *"Can a consumer commit an offset that is higher than the High Watermark?"* → No; consumers cannot read or commit offsets beyond the High Watermark.

**Red Flags (DO NOT Say):**
- ❌ *"Offsets are globally sequential across the entire topic."* (Offsets are strictly local to each individual partition).
- ❌ *"Kafka deletes a record as soon as its offset is committed by all consumers."* (Records persist according to time/size retention policies).
- ❌ *"Consumers can read uncommitted messages beyond the High Watermark."* (The High Watermark enforces safety against reading un-replicated records).
