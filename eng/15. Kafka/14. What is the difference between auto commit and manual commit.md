# What is the Difference Between Auto Commit and Manual Commit?

---

## 🟢 Junior Level

The core difference between **Auto Commit** and **Manual Commit** is who decides *when* a consumer's read position is saved to the Kafka cluster:

```
  ┌─────────────────────────────────────────────────────────┬─────────────────────────────────────────────────────────┐
  │ ⏰ AUTO COMMIT (`enable.auto.commit=true`)              │ ✋ MANUAL COMMIT (`enable.auto.commit=false`)           │
  ├─────────────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ • The Kafka client automatically commits offsets on a   │ • The developer explicitly calls `commitSync()` or      │
  │   background timer (`auto.commit.interval.ms=5000`).    │   `commitAsync()` in application code.                  │
  │ • Simple, zero boilerplate.                             │ • Requires custom error handling & commit logic.        │
  │ • ⚠️ **High risk of message loss or duplicate spikes!** │ • 🛡️ **Guarantees reliable At-Least-Once processing.** │
  └─────────────────────────────────────────────────────────┴─────────────────────────────────────────────────────────┘
```

```java
// ❌ ANTI-PATTERN: Auto-commit in production:
props.put("enable.auto.commit", "true");
props.put("auto.commit.interval.ms", "5000");

// ✅ PRODUCTION STANDARD: Explicit manual commit:
props.put("enable.auto.commit", "false");
while (running) {
    ConsumerRecords<String, String> records = consumer.poll(Duration.ofMillis(100));
    for (ConsumerRecord<String, String> record : records) {
        processOrder(record.value());
    }
    consumer.commitSync(); // Commit ONLY after all database writes succeed!
}
```

## 🟡 Middle Level

### The Two Dangerous Traps of Auto-Commit

Under the hood, auto-commit does **not** run on an independent daemon thread; it evaluates the timer inside the `poll()` call:

```
  TRAP 1: SILENT MESSAGE LOSS (At-Most-Once Hazard)
  1. `consumer.poll()` fetches a batch of 100 messages (Offsets 1..100).
  2. 5 seconds elapse while your app processes messages 1..10.
  3. Consumer invokes `poll()` again ──► Auto-commit immediately commits Offset 101 to Kafka!
  4. The application suffers an unhandled NullPointerException or OOMKill on message 15.
  5. The pod restarts and reads from Offset 101 ──► 💥 Messages 15..100 are PERMANENTLY LOST!

  TRAP 2: MASSIVE DUPLICATE BURSTS (At-Least-Once Hazard)
  1. `consumer.poll()` fetches 500 records.
  2. Application writes 450 records into PostgreSQL in 4.8 seconds.
  3. The pod crashes at 4.9 seconds (Before the 5.0-second auto-commit timer fires).
  4. The pod restarts and reads from Offset 0 ──► 💥 All 450 orders are DUPLICATED in the database!
```

## 🔴 Senior Level

### Spring Kafka `ContainerProperties.AckMode` Options

In Spring Boot, setting `spring.kafka.consumer.enable-auto-commit=false` delegates offset management to Spring's `MessageListenerContainer`:

```
  ┌──────────────────────────────┬─────────────────────────────────────────────────────────────────────────────────┐
  │ Spring AckMode               │ Commit Trigger Timing                                                           │
  ├──────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ **`BATCH`** (Default)        │ Commits the entire batch after all records returned by `poll()` are processed.  │
  │ **`RECORD`**                 │ Commits the offset immediately after each individual `@KafkaListener` call.    │
  │ **`MANUAL`**                 │ App calls `Acknowledgment.acknowledge()`; committed on next poll loop.          │
  │ **`MANUAL_IMMEDIATE`**       │ Executes synchronous/async commit immediately when `acknowledge()` is called.   │
  │ **`TIME`** / **`COUNT`**     │ Commits when $N$ records are processed or $T$ milliseconds elapse.              │
  └──────────────────────────────┴─────────────────────────────────────────────────────────────────────────────────┘
```

```java
@Component
public class AcknowledgingOrderListener {

    @KafkaListener(topics = "orders-topic", groupId = "order-group", 
                   containerFactory = "manualAckContainerFactory")
    public void onMessage(ConsumerRecord<String, OrderEvent> record, Acknowledgment ack) {
        try {
            saveOrderToDatabase(record.value());
            // Explicitly commit offset only upon successful persistence:
            ack.acknowledge();
        } catch (Exception e) {
            log.error("Failed to process order: {}. Offset NOT committed!", record.key(), e);
            throw e; // Triggers Dead Letter Queue / ErrorHandler
        }
    }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Auto-Commit:** Client commits highest fetched offset periodically on a timer (`auto.commit.interval.ms`).
- **Manual Commit:** Application controls commit timing via `commitSync()` / `commitAsync()` or Spring `Acknowledgment`.
- **Auto-Commit Danger:** Can trigger both **unintended message loss** (if committed before processing) and **massive duplicate replays** (if crashed before timer).
- **Production Standard:** Always disable auto-commit in enterprise applications (`enable.auto.commit=false`).
- **Spring AckMode:** Use `AckMode.MANUAL_IMMEDIATE` or `AckMode.RECORD` for mission-critical transactional pipelines.

**Common Follow-up Questions:**
- *"When does the auto-commit actually occur in the Java client?"* → It executes during subsequent calls to `poll()` (or during `consumer.close()`), NOT on an independent background thread.
- *"What is the performance trade-off of `AckMode.RECORD` versus `AckMode.BATCH`?"* → `RECORD` makes a commit request per message (slower throughput, minimum duplicate blast radius); `BATCH` commits once per poll batch (higher throughput, duplicates up to `max.poll.records` on crash).
- *"How do you avoid rebalance timeouts when using manual commit?"* → Ensure the total processing time for the records returned by `poll()` is strictly less than `max.poll.interval.ms` (default 300,000ms / 5 minutes).

**Red Flags (DO NOT Say):**
- ❌ *"Auto-commit runs on an independent background thread every 5 seconds regardless of what the main thread is doing."* (It is executed synchronously inside the `poll()` invocation).
- ❌ *"Auto-commit is safe for banking and billing systems if you set `interval.ms` to 100ms."* (Still vulnerable to message loss if processing fails).
- ❌ *"Manual commit requires writing raw TCP packets to the Kafka broker."* (You simply invoke `consumer.commitSync()` or Spring's `ack.acknowledge()`).
