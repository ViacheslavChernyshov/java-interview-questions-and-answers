# How to Protect a Collection from Modification?

---

## 🟢 Junior Level

Java provides three primary approaches to protect collections from unwanted modifications:

```java
// 1. `List.copyOf()` (Java 10+ Recommended Standard):
List<String> immutableList = List.copyOf(sourceList); // Creates an independent unmodifiable snapshot

// 2. `List.of()` (Java 9+ Literal Creation):
List<String> staticList = List.of("A", "B", "C"); // Built-in unmodifiable collection

// 3. `Collections.unmodifiableList()` (Java 8 Legacy Wrapper):
List<String> wrapperList = Collections.unmodifiableList(sourceList); // Live view wrapper
```

```
  Attempting to call `.add()`, `.remove()`, or `.clear()` on any of these collections 
  throws an `UnsupportedOperationException`!
```

## 🟡 Middle Level

### Architectural Comparison of Collection Protection Mechanisms

```
  ┌──────────────────────────────┬────────────┬──────────────┬────────────────┬────────────────────────────────────────┐
  │ Mechanism                    │ Added In   │ Data Copy?   │ Null Allowed?  │ Modification Behavior                  │
  ├──────────────────────────────┼────────────┼──────────────┼────────────────┼────────────────────────────────────────┤
  │ `Collections.unmodifiable*`  │ Java 2     │ ❌ No (View) │ ✅ Yes         │ ⚠️ **Reflects mutations in source!**   │
  │ `List.of(...)`               │ Java 9     │ ✅ New array │ ❌ Throws NPE  │ 🛡️ Completely static and unmodifiable │
  │ `List.copyOf(...)`           │ Java 10    │ ✅ Snapshot  │ ❌ Throws NPE  │ 🛡️ Independent immutable snapshot     │
  └──────────────────────────────┴────────────┴──────────────┴────────────────┴────────────────────────────────────────┘
```

### The Unmodifiable Wrapper Trap

```java
// ⚠️ THE LIVE VIEW TRAP:
List<String> mutable = new ArrayList<>(List.of("Alice"));
List<String> unmodifiable = Collections.unmodifiableList(mutable);

mutable.add("Bob"); // Mutates the underlying list!

System.out.println(unmodifiable); // Prints [Alice, Bob]! (View mutated silently!)
```

## 🔴 Senior Level

### Shallow Container Protection vs. Deep Object Immutability

All standard JDK methods (`List.of`, `List.copyOf`, `unmodifiableList`) provide **Shallow Immutability**:
- The collection structure cannot be modified (cannot add/remove elements).
- However, if the collection holds mutable objects, callers can still mutate the internal fields of those elements!

```java
// Shallow list of mutable objects:
List<User> users = List.copyOf(inputUsers);

// 💥 EXPLOIT: Modifying internal state of element 0:
users.get(0).setName("Hacked"); // Allowed! Element 0 was mutated!

// 🛡️ DEEP IMMUTABILITY SOLUTION (Clone each element):
List<User> deepCopy = inputUsers.stream()
    .map(u -> new User(u.getName()))
    .toList(); // Java 16 unmodifiable list
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Primary Methods:** `List.copyOf()` (Java 10+ snapshot), `List.of()` (Java 9+ static factory), `Collections.unmodifiableList()` (Legacy live wrapper).
- **Wrapper Hazard:** `Collections.unmodifiableList()` is a live view; changes to the source list mutate the wrapper.
- **Null Policy:** `List.of()` and `List.copyOf()` reject `null` elements with `NullPointerException`.
- **Shallow by Default:** JDK unmodifiable collections only protect the container; contained mutable objects must be cloned for deep immutability.
- **Persistent Alternative:** Use Vavr (`io.vavr.collection.*`) for collections that require immutable structural sharing.

**Common Follow-up Questions:**
- *"What happens if you pass an already immutable list into `List.copyOf()`?"* → The JDK optimizes the call and returns the exact same list instance without allocating a new object ($O(1)$ fast-path).
- *"How does `List.of()` differ from `Arrays.asList()`?"* → `List.of()` returns a truly unmodifiable list; `Arrays.asList()` returns a fixed-size mutable list wrapper that allows `.set(index, value)`.
- *"Why do modern factory methods reject null values?"* → To prevent ambiguity between missing entries and null values, following modern Java clean-code practices.

**Red Flags (DO NOT Say):**
- ❌ *"`Collections.unmodifiableList()` creates an isolated, independent copy of the list."* (It is a live wrapper around the original list).
- ❌ *"`Arrays.asList()` produces an unmodifiable list."* (`Arrays.asList()` allows modifying elements via `.set()`).
- ❌ *"`List.copyOf()` deeply clones all objects contained within the list."* (It only copies references, creating a shallowly protected container).
