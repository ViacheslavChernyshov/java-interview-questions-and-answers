# Difference Between Shallow Copy and Deep Copy

---

## 🟢 Junior Level

When copying objects in Java, the distinction between **Shallow Copy** and **Deep Copy** determines whether nested child objects are shared or cloned:

```
  ┌────────────────────────┬──────────────────────────────────────────┬────────────────────────────────────────────────┐
  │ Copy Type              │ What is Cloned                           │ What Happens to Nested Objects                 │
  ├────────────────────────┼──────────────────────────────────────────┼────────────────────────────────────────────────┤
  │ **Shallow Copy**       │ Container / Parent object only           │ **Shared memory references** (aliases)         │
  │ **Deep Copy**          │ Container **AND all nested objects**     │ **Recursively cloned independent objects**     │
  └────────────────────────┴──────────────────────────────────────────┴────────────────────────────────────────────────┘
```

```java
class User {
    String name;
    User(String name) { this.name = name; }
}

List<User> original = new ArrayList<>(List.of(new User("Alice")));

// 1. SHALLOW COPY (Shares the same User instance):
List<User> shallow = new ArrayList<>(original);
shallow.get(0).name = "Bob"; 
System.out.println(original.get(0).name); // 💥 Prints "Bob"! (Mutated original!)

// 2. DEEP COPY (Clones the User instance):
List<User> deep = original.stream().map(u -> new User(u.name)).toList();
deep.get(0).name = "Charlie";
System.out.println(original.get(0).name); // 🛡️ Prints "Bob" (Original is untouched!)
```

## 🟡 Middle Level

### Implementation Techniques

```
  ┌──────────────────────────────┬────────────┬────────────┬───────────────────────────────────────────────────────────┐
  │ Mechanism                    │ Depth      │ Speed      │ Notes & Hazards                                           │
  ├──────────────────────────────┼────────────┼────────────┼───────────────────────────────────────────────────────────┤
  │ `new ArrayList<>(list)`      │ **Shallow**│ Fast       │ Safe only for collections of immutable items (`String`).  │
  │ `List.copyOf(list)`          │ **Shallow**│ Fast       │ Container is unmodifiable, but nested objects are shared. │
  │ `Object.clone()`             │ **Shallow**│ Fast       │ Flawed design (*Effective Java Item 13*); avoid.          │
  │ **Copy Constructors**        │ **Deep**   │ Fast       │ Best practice: `new User(existingUser)`                   │
  │ **JSON Serialization**       │ **Deep**   │ Medium     │ Jackson / Gson; requires default constructors.            │
  │ **Java Binary Serialization**│ **Deep**   │ Slow       │ `SerializationUtils.clone()`; high CPU/GC overhead.       │
  └──────────────────────────────┴────────────┴────────────┴───────────────────────────────────────────────────────────┘
```

## 🔴 Senior Level

### Deep Copy Performance: $O(N \times D)$ vs. Persistent Structural Sharing

In large enterprise systems, deep copying deep object graphs introduces severe performance penalties:
- **Complexity:** $O(N \times D)$ where $N$ is element count and $D$ is graph depth.
- **GC Overhead:** Allocates thousands of transient heap objects, triggering Minor GC pauses.

```
  Alternative: Persistent Data Structures (Vavr / Structural Sharing)
  Instead of cloning all N elements, persistent trees share unchanged branches:
  
         [Root V1]                       [Root V2 (Updated)]
          /      \                         /            \
     [Node A]   [Node B] ───► Shared ───► [Node A]    [Node B' (New)]
       /   \                                /   \            \
     [1]   [2]                            [1]   [2]          [3] (Added)
     
  • Update Complexity: O(log N) instead of O(N)
  • Memory Overhead: Allocates only the modified path!
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Shallow Copy:** Clones only the parent container; nested objects share the exact same memory references.
- **Deep Copy:** Recursively clones the container and all nested objects, creating complete memory isolation.
- **When Shallow is Enough:** When collection elements are intrinsically immutable (`String`, `Integer`, `LocalDate`).
- **When Deep is Required:** When collection elements are mutable domain models.
- **Best Deep Copy Practice:** Use explicit **Copy Constructors** (`new User(user)`) or factory methods; avoid `Object.clone()`.
- **High-Performance Immutability:** Use **Persistent Data Structures** (Vavr) for $O(\log N)$ structural sharing.

**Common Follow-up Questions:**
- *"Does `Object.clone()` perform a shallow or deep copy by default?"* → `Object.clone()` performs a shallow field-by-field bitwise copy of references.
- *"Why is Java binary serialization discouraged for deep copying?"* → It relies on slow reflection, bypasses constructors, requires `Serializable` markers, and creates security vulnerabilities.
- *"Is `List.copyOf()` sufficient for deep immutability?"* → No; `List.copyOf()` is shallow; if items in the list have setter methods, callers can still mutate them.

**Red Flags (DO NOT Say):**
- ❌ *"`new ArrayList<>(list)` creates a deep copy of all elements."* (It is a shallow copy; element references are identical).
- ❌ *"`Object.clone()` automatically clones all nested objects recursively."* (It only copies top-level fields).
- ❌ *"Deep copying via JSON serialization is the fastest approach in Java."* (Copy constructors are orders of magnitude faster and avoid serialization reflection overhead).
