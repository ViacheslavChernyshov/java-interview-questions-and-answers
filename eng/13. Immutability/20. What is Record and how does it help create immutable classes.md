# What is Record and How Does It Help Create Immutable Classes?

---

## 🟢 Junior Level

A **`record`** (introduced in Java 14, finalized in Java 16 via JEP 395) is a special class declaration designed to model **immutable data carriers** with zero boilerplate:

```java
// Traditional Immutable Class (25+ lines):
public final class Point {
    private final int x;
    private final int y;

    public Point(int x, int y) { this.x = x; this.y = y; }
    public int x() { return x; }
    public int y() { return y; }
    @Override public boolean equals(Object o) { ... }
    @Override public int hashCode() { ... }
    @Override public String toString() { ... }
}

// Java 16+ Record Equivalent (1 single line):
public record Point(int x, int y) {}
```

```
  What `record` Generates Automatically:
  1. `final class extends java.lang.Record`
  2. `private final` component fields
  3. Canonical constructor
  4. Public accessors (`x()`, `y()` — without the `get` prefix)
  5. Deterministic `equals()`, `hashCode()`, and `toString()`
```

## 🟡 Middle Level

### The Shallow Immutability Caveat in Records

A record guarantees that **references cannot be reassigned**, but it does **not** make contained mutable objects immutable:

```java
// ⚠️ SHALLOW IMMUTABILITY HAZARD:
public record Order(Long id, List<String> items) {}

Order order = new Order(1L, new ArrayList<>(List.of("Shoes")));
order.items().add("Hat"); // 💥 ALLOWED! Mutates the underlying list!
```

### The Solution: Compact Constructor Defensive Copying

```java
public record Order(Long id, List<String> items) {
    // Compact constructor (No parameter list needed):
    public Order {
        Objects.requireNonNull(id, "ID must not be null");
        // Defensive copy turns mutable list into an unmodifiable snapshot:
        items = (items == null) ? List.of() : List.copyOf(items);
    }
}
```

## 🔴 Senior Level

### Language Constraints & Architectural Rules

```
  ┌──────────────────────────────────┬─────────────────────────────────────────────────────────────────────────────────┐
  │ Rule                             │ Architectural Reason                                                            │
  ├──────────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ **No Class Inheritance**         │ All records implicitly extend `java.lang.Record`; Java lacks multiple           │
  │                                  │ class inheritance.                                                              │
  │ **Implicitly `final`**           │ Cannot be extended by subclasses; preserves immutable invariants.               │
  │ **No Extra Instance Fields**     │ All instance state must be declared in the record header. (Static fields        │
  │                                  │ and constants are allowed).                                                     │
  │ **Interface Implementation**     │ Records **can** implement interfaces (`implements Serializable, Comparable<T>`). │
  └──────────────────────────────────┴─────────────────────────────────────────────────────────────────────────────────┘
```

### Architectural Comparison: Record vs. Lombok `@Value` vs. `final` Class

```
  ┌──────────────────────────────┬──────────────────┬──────────────────────────┬───────────────────────────────────────┐
  │ Feature                      │ Java `record`    │ Lombok `@Value`          │ Standard `final class`                │
  ├──────────────────────────────┼──────────────────┼──────────────────────────┼───────────────────────────────────────┤
  │ **Boilerplate**              │ Zero             │ Minimal (Annotation)     │ High (Manual methods)                 │
  │ **Dependency Requirement**   │ **Built-in JDK** │ External library (Lombok)│ None                                  │
  │ **Pattern Matching (JEP 440)│ **Full Support** │ None (Requires deconstr) │ None                                  │
  │ **Extra Instance Fields**    │ ❌ Forbidden     │ ✅ Allowed               │ ✅ Allowed                            │

```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** First-class language construct (Java 16+) for modeling immutable data carriers.
- **Auto-Generated:** `final class`, `private final` fields, canonical constructor, accessors (`x()`), equals, hashCode, toString.
- **Accessor Naming:** Accessor methods match component names (`name()`), not JavaBean getters (`getName()`).
- **Shallow by Default:** Must use compact constructors with `List.copyOf()` to protect mutable collections.
- **Constraints:** Cannot extend classes, cannot be subclassed, cannot declare extra instance fields.
- **Modern Superpower:** Fully integrated with Java 21+ **Record Patterns** and exhaustive pattern matching in `switch`.

**Common Follow-up Questions:**
- *"How does a Compact Constructor differ from a Canonical Constructor?"* → A compact constructor omits the argument list and `this.x = x` assignments; you only write validation logic and defensive copies before assignment occurs implicitly.
- *"Can you override `equals()` or `hashCode()` in a record?"* → Yes; you can provide custom implementations if specific caching or field-exclusion logic is required.
- *"Can a record implement multiple interfaces?"* → Yes; records can implement any number of interfaces (e.g., `Comparable`, `Serializable`).

**Red Flags (DO NOT Say):**
- ❌ *"Records automatically make all collection items deeply immutable."* (Records are shallowly immutable; you must manually invoke `List.copyOf()`).
- ❌ *"Record getter methods are named `getX()` and `getY()`."* (They are named `x()` and `y()`).
- ❌ *"You can declare additional private instance variables inside the record body."* (Only static fields are permitted).
