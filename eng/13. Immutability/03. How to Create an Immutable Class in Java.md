# How to Create an Immutable Class in Java

---

## 🟢 Junior Level

To construct a robust immutable class in Java, follow these 4 core steps:

```java
// 1. Declare the class as final (Prevents subclassing)
public final class Person {

    // 2. Make all fields private and final
    private final String name;
    private final int age;

    // 3. Initialize all fields completely in the constructor
    public Person(String name, int age) {
        this.name = name;
        this.age = age;
    }

    // 4. Provide only getter accessors (No setters!)
    public String getName() { return name; }
    public int getAge() { return age; }
}
```

```
  Core Rules for Junior Developers:
  • Mark the class `final`.
  • Mark all fields `private final`.
  • Do not provide any `setX()` mutator methods.
```

## 🟡 Middle Level

### Joshua Bloch's 5 Rules for Immutable Classes (*Effective Java*)

```
  ┌───┬──────────────────────────────────┬─────────────────────────────────────────────────────────────────────────────┐
  │ # │ Rule                             │ Implementation Mechanism                                                    │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────────────────┤
  │ 1 │ **No Mutators**                  │ Omit all `set*`, `add*`, `remove*`, and in-place mutating methods.          │
  │ 2 │ **Prevent Subclassing**          │ Mark the class `final`, or make constructors private with static factories. │
  │ 3 │ **Make All Fields `final`**      │ Enforces single assignment and JMM safe publication memory barriers.       │
  │ 4 │ **Make All Fields `private`**    │ Restricts direct access to internal state.                                  │
  │ 5 │ **Exclusive Access to Mutables** │ Perform defensive copies in constructors and getters on mutable fields.     │
  └───┴──────────────────────────────────┴─────────────────────────────────────────────────────────────────────────────┘
```

### Handling Mutable Collections & Java 16+ Records

```java
// Traditional Class with Defensive Copying:
public final class OrderReport {
    private final String reportId;
    private final List<String> tags;

    public OrderReport(String reportId, List<String> tags) {
        this.reportId = reportId;
        // Defensive copy: creates an independent, unmodifiable list snapshot:
        this.tags = (tags == null) ? List.of() : List.copyOf(tags);
    }

    public String getReportId() { return reportId; }
    public List<String> getTags() { return tags; } // Safe: List.copyOf is unmodifiable
}

// Modern Java 16+ Record Equivalent:
public record OrderReportRecord(String reportId, List<String> tags) {
    public OrderReportRecord {
        tags = (tags == null) ? List.of() : List.copyOf(tags);
    }
}
```

## 🔴 Senior Level

### Deep Immutability vs. Shallow Immutability

`List.copyOf(items)` creates an unmodifiable collection, but it does **not** clone the elements themselves:

```java
// ⚠️ SHALLOW IMMUTABILITY HAZARD:
public record Order(Long id, List<MutableItem> items) {
    public Order {
        items = List.copyOf(items); // Collection cannot be resized, but items[0].setPrice(0) still works!
    }
}

// 🛡️ TRUE DEEP IMMUTABILITY (Copy Constructors):
public record DeepOrder(Long id, List<MutableItem> items) {
    public DeepOrder {
        items = (items == null) ? List.of() : items.stream()
            .map(MutableItem::new) // Clones each element via copy constructor
            .toList();
    }
}
```

### Preventing the Constructor Escape Anti-Pattern

```java
public final class VulnerablePublication {
    private final String status;

    public VulnerablePublication(String status) {
        this.status = status;
        // 💥 DISASTER: `this` escapes to another thread before constructor finishes!
        GlobalRegistry.register(this);
    }
}
```

> [!CAUTION]
> If `this` is passed to another thread or event bus inside the constructor, concurrent threads may access the object before the JMM freeze barrier executes, seeing `null` or uninitialized field values.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Bloch's 5 Rules:** `final` class, `private final` fields, no mutators, defensive copy mutable fields, no constructor escape.
- **Defensive Copying:** Always wrap incoming collections with `List.copyOf()` or `Map.copyOf()`.
- **Deep Copying:** If collections contain mutable domain objects, clone every individual element.
- **Constructor Escape:** Never publish `this` to external listeners or threads inside a constructor.
- **Modern Java:** Use Java 16+ **`record`** components for clean, boilerplate-free immutable data carriers.
- **When NOT to use:** JPA Entities (require no-arg constructors and setters) and high-frequency in-memory graphics buffers.

**Common Follow-up Questions:**
- *"Why is `clone()` discouraged for defensive copying?"* → Effective Java Item 13 notes that `clone()` can be overridden by malicious subclasses and does not call constructors; use copy constructors or static copy factories (`new Item(item)`).
- *"How can you make a class immutable without using the `final` class keyword?"* → Make all constructors `private` or package-private, and provide `public static` factory methods (e.g. `public static Person of(...)`).
- *"Is `Collections.unmodifiableList(list)` safe for constructors?"* → No; `unmodifiableList()` is a live view of the underlying list. If the caller retains a reference to the original mutable list, mutating it will mutate your class's state. Use `List.copyOf()`.

**Red Flags (DO NOT Say):**
- ❌ *"Making fields `final` is sufficient to make any class immutable."* (If a `final` field references a mutable collection, its contents can still be modified).
- ❌ *"Records are deeply immutable automatically."* (Records are shallowly immutable; mutable objects inside records must still be cloned manually).
- ❌ *"It is safe to call `this.register()` in the constructor of an immutable class."* (This is a Constructor Escape bug that causes data races).
