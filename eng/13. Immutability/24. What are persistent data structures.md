# What Are Persistent Data Structures?

---

## 🟢 Junior Level

> [!NOTE]
> In Computer Science, a **"Persistent Data Structure"** does **NOT** mean writing data to a hard drive or database (which is *Data Persistence*).
> 
> A Persistent Data Structure is an **in-memory immutable data structure** that **always preserves its previous versions** whenever it is modified.

When you add or remove an item, a **new version** of the data structure is created while the old version remains completely intact and accessible:

```java
// Example using the Vavr persistent library:
io.vavr.collection.List<String> v1 = io.vavr.collection.List.of("A", "B");
io.vavr.collection.List<String> v2 = v1.prepend("Z"); // Adds to head

System.out.println(v1); // List("A", "B")     <-- Version 1 is UNCHANGED!
System.out.println(v2); // List("Z", "A", "B") <-- Version 2 shares v1's tail
```

```
  Git Analogy:
  • When you make a Git commit, Git does not copy your entire 10GB project from scratch.
  • Git creates a new commit pointer and reuses all existing unchanged tree blobs.
```

## 🟡 Middle Level

### The Principle of Structural Sharing

Naive immutability (like `List.copyOf()` in the JDK) must copy the entire underlying array ($O(N)$ memory and time) whenever a new element is added.

Persistent data structures solve this via **Structural Sharing**:

#### 1. Persistent Singly Linked List ($O(1)$ Prepend)
```
  Version 1 (v1):                    [Node "A"] ──► [Node "B"] ──► [Node "C"] ──► null
                                         ▲
                                         │ (Shared Tail)
  Version 2 (v2 = v1.prepend("Z")):   [Node "Z"] ──┘
```
- Prepending an element costs **$O(1)$ time** and allocates exactly **one single node** (`Node "Z"`).
- Both `v1` and `v2` share the exact same tail nodes in memory without risk of mutation.

#### 2. Persistent Trees & Path Copying ($O(\log N)$ Updates)
When updating a node in a persistent binary or trie tree, only the nodes along the direct path from the root to the target element are cloned ($O(\log N)$); all other subtrees are shared.

```
  ┌──────────────────────────────────┬──────────────────────────┬──────────────────────────┬───────────────────────────┐
  │ Collection                       │ Immutable?               │ Persistent?              │ Modification Cost         │
  ├──────────────────────────────────┼──────────────────────────┼──────────────────────────┼───────────────────────────┤
  │ `Collections.unmodifiableList()` │ ❌ (Wrapper)             │ ❌ No                    │ Throws exception          │
  │ `List.of("A", "B")` (JDK 9+)     │ ✅ Yes                   │ ❌ **No** (Array backed) │ $O(N)$ full array copy    │
  │ `io.vavr.collection.List` (Vavr) │ ✅ Yes                   │ ✅ **Yes**               │ **$O(1)$** (Tail sharing) │
  │ `io.vavr.collection.HashMap`     │ ✅ Yes                   │ ✅ **Yes** (HAMT)        │ **$O(\log_{32} N)$**      │
  └──────────────────────────────────┴──────────────────────────┴──────────────────────────┴───────────────────────────┘
```

## 🔴 Senior Level

### HAMT (Hash Array Mapped Trie) Architecture

The foundational data structure behind production persistent sets and maps (in Vavr, Scala, and Clojure) is the **Hash Array Mapped Trie (HAMT)**:

```
  1. 32-Way Branching (5-Bit Hash Chunks):
     • The 32-bit `hashCode()` of a key is partitioned into 5-bit slices (2^5 = 32).
     • Each tree level inspects a single 5-bit chunk.
     • Maximum tree depth for 4 billion elements is at most ⌈32 / 5⌉ = 7 levels!

  2. Bitmap Indexing & Hardware POPCNT:
     • Instead of allocating 32 child pointers per node, nodes store a 32-bit `bitmap` mask 
       and a compact array containing ONLY populated children.
     • Child index is computed in 1 CPU clock cycle via the hardware `POPCNT` instruction:
       int index = Integer.bitCount(bitmap & ((1 << bitPos) - 1));

  3. Complexity:
     • Reads/Writes: O(log32 N) ≤ 7 hops ≈ O(1) in practice.
     • Snapshot Creation: Exactly O(1) (Copying a single Root reference)!
```

### Highload Architecture: Lock-Free State Snapshots

```java
public class GlobalStateManager {
    // Lock-Free state container:
    private final AtomicReference<io.vavr.collection.Map<String, UserSession>> state = 
        new AtomicReference<>(io.vavr.collection.HashMap.empty());

    public void registerUser(UserSession session) {
        // Atomic lock-free CAS update:
        state.updateAndGet(currentMap -> currentMap.put(session.id(), session));
    }

    public io.vavr.collection.Map<String, UserSession> getSnapshot() {
        return state.get(); // O(1) instantaneous immutable snapshot!
    }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Immutable data structures that preserve all previous versions across modifications.
- **Structural Sharing:** New versions share unchanged nodes and subtrees with previous versions.
- **JDK Distinction:** JDK `List.of()` is immutable, but **not persistent** (it lacks structural sharing).
- **Popular Java Library:** **Vavr** (`io.vavr.collection.*`).
- **HAMT:** Hash Array Mapped Trie provides $O(\log_{32} N) \approx O(1)$ persistent maps using hardware `POPCNT`.
- **Primary Use Cases:** Lock-free state management via `AtomicReference`, Undo/Redo buffers, and event sourcing.

**Common Follow-up Questions:**
- *"How does prepending to a persistent list achieve $O(1)$ time complexity?"* → The new node is created as the head, and its `next` pointer references the entire existing list as its shared tail.
- *"How does the Garbage Collector handle old versions in a persistent tree?"* → When an application drops references to older root nodes, the GC automatically reclaims unreferenced nodes while leaving nodes shared with newer roots untouched.
- *"Why is HAMT faster than standard TreeMap?"* → `TreeMap` uses 2-way branching ($O(\log_2 N)$); HAMT uses 32-way branching ($O(\log_{32} N)$), needing at most 7 pointer hops for 4 billion elements.

**Red Flags (DO NOT Say):**
- ❌ *"Persistent data structures are database tables managed by Hibernate."* (It is an in-memory Computer Science data structure pattern).
- ❌ *"Modifying a persistent data structure clones the entire collection via deep copying."* (It uses structural sharing to clone only the affected path).
- ❌ *"`List.copyOf()` in Java 17 is a persistent data structure."* (It is a flat array-backed immutable list without structural sharing).
