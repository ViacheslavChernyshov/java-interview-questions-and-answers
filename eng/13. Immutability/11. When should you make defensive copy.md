# When Should You Make Defensive Copy?

---

## 🟢 Junior Level

You must make a **Defensive Copy** whenever an immutable class receives or returns a **mutable object**:

```java
// 1. Mandatory Ingress Copy (Constructor receives mutable collection):
public UserGroup(String name, List<String> members) {
    this.name = name;
    this.members = List.copyOf(members); // 🛡️ Mandatory defensive snapshot
}

// 2. Mandatory Egress Copy (Returning mutable array):
public byte[] getEncryptionKey() {
    return this.key.clone(); // 🛡️ Mandatory defensive copy
}
```

```
  Decision Rule:
  • Mutable Parameter (List, Set, Map, Array, Date) ──► MANDATORY Defensive Copy
  • Immutable Parameter (String, Integer, LocalDate) ──► NEVER Copy (Return direct reference)
```

## 🟡 Middle Level

### Mandatory Scenarios Matrix

```
  ┌──────────────────────────────────┬─────────────────────────────────────────────────────────────────────────────────┐
  │ Scenario                         │ Required Action & Rationale                                                     │
  ├──────────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ **Mutable Collections**          │ Construct with `List.copyOf()`, `Set.copyOf()`, or `Map.copyOf()`.              │
  │ **Raw Arrays (`byte[]`, `T[]`)** │ Arrays in Java are always mutable! Use `array.clone()` in constructor & getter. │
  │ **Legacy Date (`Date`, `Cal`)**  │ Use `new Date(date.getTime())` or refactor to modern `java.time.Instant`.       │
  │ **Custom Mutable Objects**       │ Use Copy Constructors (`new Address(addr)`) or Static Factory Methods.          │
  └──────────────────────────────────┴─────────────────────────────────────────────────────────────────────────────────┘
```

### When Defensive Copying is an Anti-Pattern (Wasteful)

1. **Immutable Types:** `String`, `UUID`, `BigDecimal`, `BigInteger`, `java.time.*` classes.
2. **Java Records with Immutable Components:** Component accessors are already safe.
3. **Private Internal Methods:** When objects are strictly confined within a single class.

## 🔴 Senior Level

### Zero-Copy Optimizations in Modern JDK

1. **`List.copyOf` Fast-Path (JDK 10+):**
   ```java
   // If source is already an immutable JDK collection, copyOf skips allocation:
   List<String> list1 = List.of("A", "B");
   List<String> list2 = List.copyOf(list1);
   System.out.println(list1 == list2); // true (Zero allocation fast-path!)
   ```
2. **Persistent Structural Sharing (Vavr):**
   Avoids $O(N)$ copies by sharing tree branches ($O(\log N)$).
3. **Project Valhalla Value Types:**
   Flat value classes eliminate identity references entirely.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Mandatory When:** Receiving or exposing mutable collections, raw arrays, legacy dates, or mutable domain entities.
- **Forbidden/Wasteful When:** Working with primitive wrappers, `String`, `LocalDate`, or records composed of immutable fields.
- **Array Rule:** Java arrays can **never** be made unmodifiable; always `.clone()`.
- **Collection Rule:** Use `List.copyOf()` on ingress; return directly if already unmodifiable.
- **Fast-Path:** `List.copyOf()` short-circuits to $O(1)$ zero-allocation if input is already immutable.

**Common Follow-up Questions:**
- *"Why must arrays always be defensively copied?"* → Java does not support read-only or unmodifiable arrays; any caller with a reference to `arr` can execute `arr[0] = null`.
- *"How do you avoid defensive copies for date fields?"* → Replace legacy `java.util.Date` with modern immutable `java.time.LocalDate` or `java.time.Instant`.
- *"Is defensive copying required inside private helper methods?"* → No; if the method is private and arguments are trusted internal references, copying is unnecessary overhead.

**Red Flags (DO NOT Say):**
- ❌ *"You should defensively copy Strings and Integers just to be safe."* (Strings and Integers are immutable; copying wastes CPU and memory).
- ❌ *"Arrays can be protected with `Collections.unmodifiableList()` without copying."* (Converting an array to a list view still leaves the backing array vulnerable to modification).
- ❌ *"Defensive copies are only needed in getters, not constructors."* (Constructors without defensive copies allow callers to mutate internal state via retained references).
