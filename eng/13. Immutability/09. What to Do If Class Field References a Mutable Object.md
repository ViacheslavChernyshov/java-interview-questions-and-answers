# What to Do If Class Field References a Mutable Object?

---

## 🟢 Junior Level

If an immutable class contains a field pointing to a mutable object (such as a `java.util.Date`, array, or `ArrayList`), you must apply the **Two-Point Defensive Copying Rule**:

```java
public final class EmployeeRecord {
    private final String name;
    private final Date hireDate; // Date is mutable!

    // 1. INGRESS DEFENSIVE COPY (Constructor):
    public EmployeeRecord(String name, Date hireDate) {
        this.name = name;
        // Copy the date so external callers cannot mutate internal state:
        this.hireDate = (hireDate == null) ? null : new Date(hireDate.getTime());
    }

    public String getName() { return name; }

    // 2. EGRESS DEFENSIVE COPY (Getter):
    public Date getHireDate() {
        // Return a fresh clone so callers cannot mutate internal state:
        return (hireDate == null) ? null : new Date(hireDate.getTime());
    }
}
```

```
  The Two-Point Rule:
  • On Ingress (Constructor): Clone incoming parameters before assignment.
  • On Egress (Getter): Return a new clone or unmodifiable view to callers.
```

## 🟡 Middle Level

### Strategy Matrix by Data Type

```
  ┌────────────────────────┬──────────────────────────────────────────┬────────────────────────────────────────────────┐
  │ Field Type             │ Defensive Copy on Ingress (Constructor)  │ Defensive Copy on Egress (Getter)              │
  ├────────────────────────┼──────────────────────────────────────────┼────────────────────────────────────────────────┤
  │ **Collections**        │ `this.items = List.copyOf(items);`       │ `return items;` (Already unmodifiable!)        │
  │ (`List`, `Set`, `Map`) │                                          │                                                │
  │ **Arrays**             │ `this.arr = Arrays.copyOf(arr, arr.len);`│ `return Arrays.copyOf(arr, arr.length);`       │
  │ (`byte[]`, `int[]`)    │                                          │                                                │
  │ **Legacy `Date`**      │ `this.d = new Date(d.getTime());`        │ `return new Date(d.getTime());`                │
  │ **Mutable Domain Obj** │ `this.u = new User(u);` (Copy Ctor)      │ `return new User(u);` (Copy Ctor)              │
  └────────────────────────┴──────────────────────────────────────────┴────────────────────────────────────────────────┘
```

> [!TIP]
> Modernize legacy code by replacing mutable `java.util.Date` with immutable **`java.time.Instant`** or **`java.time.LocalDate`**, eliminating the need for defensive date cloning!

## 🔴 Senior Level

### TOCTOU Attack Defense: Copy BEFORE Validation

In multi-threaded systems, a malicious or buggy concurrent thread can mutate an incoming object during constructor validation:

```java
// ❌ VULNERABLE TO TOCTOU ATTACK (Validates BEFORE copying):
public Period(Date start, Date end) {
    if (start.after(end)) { // 1. Time-of-Check (Validation)
        throw new IllegalArgumentException("Start after end");
    }
    // A concurrent thread could call start.setTime(future) right here!
    this.start = new Date(start.getTime()); // 2. Time-of-Use
    this.end = new Date(end.getTime());
}

// 🛡️ SECURE DEFENSIVE COPYING (Copies BEFORE validation):
public Period(Date start, Date end) {
    this.start = new Date(start.getTime()); // 1. Freeze snapshot immediately!
    this.end = new Date(end.getTime());
    
    if (this.start.after(this.end)) {        // 2. Validate the private snapshot!
        throw new IllegalArgumentException("Start after end");
    }
}
```

### Deep Defensive Copying for Mutable Collections

```java
public record Order(Long id, List<MutableLineItem> items) {
    public Order {
        // Deep copy: Clones every individual element to prevent item-level mutation!
        items = (items == null) ? List.of() : items.stream()
            .map(MutableLineItem::new) // Uses copy constructor
            .toList();
    }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Two-Point Rule:** Defensive copy on ingress (constructor) and defensive copy on egress (getter).
- **Collections:** Use `List.copyOf()` / `Set.copyOf()` / `Map.copyOf()` (Java 10+ unmodifiable snapshots).
- **Arrays:** Use `Arrays.copyOf()`; arrays are always mutable in Java.
- **Legacy Dates:** Use `new Date(date.getTime())` or migrate to `java.time.Instant` / `LocalDate`.
- **TOCTOU Principle:** Always make the defensive copy **before** executing parameter validation checks.
- **Deep Copying:** If collection items are mutable, clone each element individually.

**Common Follow-up Questions:**
- *"Why should you NOT use `clone()` for defensive copying of parameters in constructors?"* → `clone()` can be overridden by a malicious subclass to return a mutable subclass or leak references; use copy constructors or static copy methods instead (Effective Java Item 50).
- *"Is `List.copyOf()` a shallow or deep copy?"* → `List.copyOf()` is a **shallow copy**; it makes the list structure unmodifiable, but contained mutable objects can still have their internal fields modified.
- *"What is the performance cost of defensive copying?"* → $O(N)$ allocation and memory copy overhead; for high-frequency low-latency paths, design upstream APIs to pass immutable types (`List.of()`, records) directly.

**Red Flags (DO NOT Say):**
- ❌ *"Returning `Collections.unmodifiableList(this.items)` in a constructor protects against external mutation."* (`unmodifiableList()` is a live wrapper; if the caller mutates the original list, the class's state changes).
- ❌ *"Validating parameters before making defensive copies is completely safe."* (Leaves the constructor vulnerable to multi-threaded TOCTOU race conditions).
- ❌ *"Calling `clone()` on an incoming argument is the best way to make a defensive copy."* (Subclasses can override `clone()` maliciously; use copy constructors).
