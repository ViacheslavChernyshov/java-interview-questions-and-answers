# What is HATEOAS?

---

## 🟢 Junior Level

**HATEOAS** (Hypermedia As The Engine Of Application State) is the defining constraint of **Level 3 REST** (Richardson Maturity Model).

Under HATEOAS, a server returns **both data and dynamic navigation links (`_links`)** in its response payload, informing the client what actions can be taken next.

```json
// GET /api/v1/orders/101
{
  "orderId": 101,
  "totalAmount": 99.50,
  "status": "AWAITING_PAYMENT",
  "_links": {
    "self": { "href": "/api/v1/orders/101" },
    "payment": { "href": "/api/v1/orders/101/payments" },
    "cancel": { "href": "/api/v1/orders/101/cancellations" }
  }
}
```

### Core Value Proposition
- **Decoupled Clients:** Clients do not hardcode complex URI paths; they follow hypermedia link relations (`rel="payment"`).
- **Self-Descriptive State Navigation:** The API behaves like a web browser: users don't memorize URLs; they navigate by clicking hyperlinks.

---

## 🟡 Middle Level

### The Concept of Dynamic Affordances

In HATEOAS, links represent **Affordances (Actionable Capabilities)**:
- If a user lacks permission to delete an order, or if the order is already in a `SHIPPED` state, the server **omits the `cancel` link entirely**.
- **Client Logic Becomes Trivial:**
  ```javascript
  // Frontend does not duplicate backend business logic:
  if (response._links.cancel) {
      renderCancelButton(response._links.cancel.href);
  }
  ```

### The HAL Standard (`application/hal+json`)

Hypertext Application Language (HAL) is the industry standard format for hypermedia APIs:

```json
{
  "page": { "size": 20, "totalElements": 100, "totalPages": 5, "number": 1 },
  "_embedded": {
    "orders": [
      {
        "id": 101,
        "amount": 50.00,
        "_links": { "self": { "href": "/api/v1/orders/101" } }
      }
    ]
  },
  "_links": {
    "self": { "href": "/api/v1/orders?page=1" },
    "next": { "href": "/api/v1/orders?page=2" },
    "prev": { "href": "/api/v1/orders?page=0" }
  }
}
```

## 🔴 Senior Level

### Spring HATEOAS Implementation

Spring Boot provides first-class support via **`spring-boot-starter-hateoas`**:

```java
@RestController
@RequestMapping("/api/v1/orders")
public class OrderController {

    @GetMapping("/{id}")
    public EntityModel<OrderDTO> getOrder(@PathVariable Long id) {
        OrderDTO order = orderService.findById(id);
        
        EntityModel<OrderDTO> model = EntityModel.of(order);
        model.add(linkTo(methodOn(OrderController.class).getOrder(id)).withSelfRel());
        
        if (order.getStatus() == OrderStatus.AWAITING_PAYMENT) {
            model.add(linkTo(methodOn(PaymentController.class).payOrder(id)).withRel("payment"));
            model.add(linkTo(methodOn(OrderController.class).cancelOrder(id)).withRel("cancel"));
        }
        return model;
    }
}
```

### The API Gateway Proxy Link Bug & Fix

When running behind Nginx or an AWS API Gateway, Spring's `WebMvcLinkBuilder` builds links using internal container network IPs (`http://10.0.12.4:8080/orders/101`) instead of the public domain.
- **Production Solution:** Enable **`ForwardedHeaderFilter`** in Spring Boot to parse `X-Forwarded-Host`, `X-Forwarded-Proto`, and `X-Forwarded-Port` headers passed by reverse proxies.

### When NOT to Use HATEOAS
1. **Highload Microservices:** Adds 30–50% JSON payload bloat (2–3x on large collections) and CPU reflection overhead.
2. **Single-Team Fullstack Apps:** Frontend and backend evolve synchronously, making hypermedia link discovery redundant.
3. **Fixed-Layout Mobile Apps:** Native mobile screens have static navigation trees that do not adapt dynamically to hypermedia links.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Level 3 REST constraint where servers return hypermedia links (`_links`) alongside entity data.
- **Affordances:** Server dynamically controls client capabilities by including or omitting action links based on business state and permissions.
- **HAL Standard:** `application/hal+json` using `_links` (relations) and `_embedded` (nested collections).
- **Spring HATEOAS:** Uses `EntityModel<T>`, `CollectionModel<T>`, and `WebMvcLinkBuilder`.
- **Proxy Fix:** Use `ForwardedHeaderFilter` to generate public domain links from `X-Forwarded-Host`.
- **Trade-off:** High payload overhead (30–50% larger responses); rarely used in private microservices.

**Common Follow-up Questions:**
- *"What is the main benefit of HATEOAS for API versioning?"* → Clients follow dynamic link relations (`rel="payment"`) rather than hardcoded URLs, allowing backend teams to alter URI structures without breaking clients.
- *"Why is HATEOAS rarely implemented in internal microservices?"* → The payload serialization overhead and CPU cost of building link graphs offer little value when services communicate via strict RPC/OpenAPI contracts.
- *"How should HATEOAS responses be cached in CDNs?"* → If links depend on user permissions, include `Vary: Authorization` in response headers to prevent CDNs from serving cached administrative links to regular users.

**Red Flags (DO NOT Say):**
- ❌ *"HATEOAS is mandatory for an API to be useful."* (Level 2 REST is the global standard; Level 3 HATEOAS is optional and situational).
- ❌ *"HATEOAS reduces network bandwidth."* (It increases payload size by 30–50% due to link structures).
- ❌ *"Clients must parse URI strings manually in HATEOAS."* (Clients query link relations by key, such as `links.payment.href`).
