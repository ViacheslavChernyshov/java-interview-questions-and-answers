## 🎯 Recommended Learning Path

### 🟢 Junior Level (Weeks 1–2)
1. **REST Core:** [What is REST](01.%20What%20is%20REST.md), [What does Stateless mean in REST context](02.%20What%20does%20Stateless%20mean%20in%20REST%20context.md).
2. **HTTP Verbs:** [What are the main HTTP methods used in REST](03.%20What%20are%20the%20main%20HTTP%20methods%20used%20in%20REST.md).
3. **Status Codes:** [What HTTP status codes do you know](09.%20What%20HTTP%20status%20codes%20do%20you%20know.md), [What is the difference between 401 and 403](10.%20What%20is%20the%20difference%20between%20401%20and%20403.md).
4. **Header Basics:** [What is Content-Type header](16.%20What%20is%20Content%20Type%20header.md), [What is Accept header](17.%20What%20is%20Accept%20header.md).

### 🟡 Middle Level (Weeks 3–4)
1. **Idempotency & Safety:** [What is idempotency](05.%20What%20is%20idempotency.md), [Which HTTP methods are idempotent](06.%20Which%20HTTP%20methods%20are%20idempotent.md), [Why GET and DELETE are idempotent](07.%20Why%20GET%20and%20DELETE%20are%20idempotent.md), [Is POST idempotent](08.%20Is%20POST%20idempotent.md).
2. **Resource Mutation:** [What is the difference between PUT and PATCH](04.%20What%20is%20the%20difference%20between%20PUT%20and%20PATCH.md).
3. **Resource Modeling:** [What is RESTful API design](11.%20What%20is%20RESTful%20API%20design.md), [How to properly name REST endpoints](12.%20How%20to%20properly%20name%20REST%20endpoints.md), [Should you use verbs in URL](13.%20Should%20you%20use%20verbs%20in%20URL.md).
4. **Evolution & Discoverability:** [What is HATEOAS](14.%20What%20is%20HATEOAS.md), [How to organize REST API versioning](15.%20How%20to%20organize%20REST%20API%20versioning.md).

### 🔴 Senior Level (Weeks 5–6)
1. **Richardson Maturity Model:** Levels 0–3, Hypermedia Affordances, RPC vs. REST tradeoffs.
2. **Distributed Idempotency:** Distributed `Idempotency-Key` tracking via Redis/PostgreSQL to ensure at-most-once semantics.
3. **Content Negotiation:** Server-driven negotiation with `q`-values, binary Protobuf vs JSON benchmarking.
4. **Evolutionary Architecture:** Non-breaking Expand & Contract API schema migrations, sunsetting headers (`Sunset`, `Deprecation`).
