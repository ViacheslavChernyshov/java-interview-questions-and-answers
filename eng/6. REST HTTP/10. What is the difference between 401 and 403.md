# What is the difference between 401 and 403?

---

## 🟢 Junior Level

The fundamental difference between **`401 Unauthorized`** and **`403 Forbidden`** boils down to **Authentication ("Who are you?")** versus **Authorization ("What are you allowed to do?")**:

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │                 401 Unauthorized                       │                  403 Forbidden                         │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ • **Authentication Failure** ("Identity Unknown")      │ • **Authorization Failure** ("Access Denied")         │
  │ • Client has **not provided valid credentials**        │ • Server **knows who you are**, but you lack permission│
  │ • Re-authenticating (logging in) will help             │ • Re-authenticating with the same user will NOT help   │
  │ • Example: Arriving at office security without a badge │ • Example: Having a badge, but attempting to enter the │
  │                                                        │   server room without admin clearance                  │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

```http
// 401 Response (Triggers Client Login Flow):
GET /api/v1/profile
<-- 401 Unauthorized
<-- WWW-Authenticate: Bearer realm="api"

// 403 Response (Triggers Access Denied Banner):
GET /api/v1/admin/audit-logs
Authorization: Bearer <valid_user_jwt_without_admin_role>
<-- 403 Forbidden
```

## 🟡 Middle Level

### Client Flow Handling

```
                 Incoming Request to Protected Resource
                                   │
                                   ▼
                  Is Authentication Token Present & Valid?
                                   │
                  ┌────────────────┴────────────────┐
                  ▼ NO                              ▼ YES
           [401 Unauthorized]               Are Required Roles/Scopes Present?
                  │                                 │
                  ▼                                 ┌────────────────┴────────────────┐
        • Trigger Refresh Token Flow                ▼ NO                              ▼ YES
        • OR Redirect to Login Page          [403 Forbidden]                     [200 OK]
                                                    │
                                                    ▼
                                            Show "Access Denied"
```

### Spring Security 6.x Architectural Handlers

In Spring Security, these two status codes are managed by distinct framework interfaces:

1. **`AuthenticationEntryPoint`:** Executed when an unauthenticated/anonymous user attempts to access a secured resource (issues **`401`**).
2. **`AccessDeniedHandler`:** Executed when an authenticated user lacks the required `GrantedAuthority` or role (issues **`403`**).

```java
@Bean
public SecurityFilterChain securityFilterChain(HttpSecurity http) throws Exception {
    return http
        .exceptionHandling(ex -> ex
            .authenticationEntryPoint((req, res, e) -> res.sendError(HttpServletResponse.SC_UNAUTHORIZED))
            .accessDeniedHandler((req, res, e) -> res.sendError(HttpServletResponse.SC_FORBIDDEN))
        )
        .build();
}
```

## 🔴 Senior Level

### Security by Obscurity: Masking with `404 Not Found`

Returning `403 Forbidden` confirms to an attacker that a sensitive resource **actually exists** at that URI (Information Disclosure).

```
  Attacker Probes: GET /api/v1/tenants/acme-corp/financials
  ├── Returning 403 ──> "Resource exists, but you are not authorized" (Leaks tenant presence!)
  └── Returning 404 ──> "Resource not found" (Prevents tenant enumeration!)
```
- **Enterprise Rule:** For multi-tenant and classified endpoints, mask authorization failures with `404 Not Found`.

### JWT Expiration & OAuth2 Scopes

- **Expired JWT Token:** Must return **`401 Unauthorized`** (NOT `403`). Mobile and Single-Page Applications rely strictly on `401` to trigger silent background OAuth2 Refresh Token exchange flows.
- **Scope Insufficiency:** A client with valid user login but missing OAuth2 scope (e.g. token has `read:profile`, but endpoint requires `write:orders`) must receive **`403 Forbidden`**.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`401 Unauthorized`:** Authentication issue (Identity unknown; missing/expired token); requires `WWW-Authenticate` header; triggers login/refresh flow.
- **`403 Forbidden`:** Authorization issue (Identity verified, but lacking role/scope); re-login does not fix it.
- **Spring Security:** `AuthenticationEntryPoint` generates `401`; `AccessDeniedHandler` generates `403`.
- **Expired Tokens:** Return `401` to enable automatic refresh token flows.
- **Security by Obscurity:** Return `404` instead of `403` on sensitive multi-tenant endpoints to prevent URI enumeration.
- **Rate Limiting:** Must return `429 Too Many Requests`, never `403`.

**Common Follow-up Questions:**
- *"What should a single-page application (React/Vue) do upon receiving a 401 vs. a 403?"* → On `401`, attempt to refresh the JWT via refresh token or redirect to `/login`; on `403`, display an "Access Denied / Insufficient Permissions" notification without logging the user out.
- *"Why does RFC 9110 mandate the `WWW-Authenticate` header on 401 responses?"* → To inform the client which authentication scheme (e.g. `Bearer`, `Basic`, `Digest`) and realm are accepted by the server.
- *"Why is CSRF failure mapped to 403 in Spring Security?"* → Because the user is authenticated, but the request fails the security token validation check.

**Red Flags (DO NOT Say):**
- ❌ *"401 and 403 are interchangeable error codes."* (`401` is authentication identity failure; `403` is authorization permission failure).
- ❌ *"Expired JWT tokens should return 403 Forbidden."* (Expired credentials mean identity cannot be verified; it must return `401 Unauthorized`).
- ❌ *"Logging in again will fix a 403 Forbidden error."* (The user lacks the required role; logging in with the same credentials will produce another `403`).
