# What is REST?

---

## 🟢 Junior Level

**REST (Representational State Transfer)** is an architectural style for designing networked web services, introduced by Roy Fielding in his 2000 doctoral dissertation.

It is **not a protocol or library**, but a set of architectural constraints. A service is strictly considered **RESTful** only when it adheres to all core constraints.

### Core Architectural Pillars
- **Resources:** Every business entity is treated as a resource identified by a unique Uniform Resource Identifier (URI) (e.g. `/api/v1/orders/42`).
- **Standard HTTP Verbs:** Standardized operations performed on resources:
  - `GET` — Retrieve resource state.
  - `POST` — Create a new subordinate resource.
  - `PUT` — Replace an existing resource entirely.
  - `PATCH` — Partially update specific resource fields.
  - `DELETE` — Remove a resource.
- **Stateless:** The server retains zero client session state between requests. Every incoming request must contain all credentials and context needed for processing.
- **Representations:** Resources are decoupled from their serialization format (commonly JSON, XML, or Protocol Buffers).

```
  Standard Resource CRUD Mapping:
  GET    /api/v1/users        ──> Retrieve list of users
  GET    /api/v1/users/101    ──> Retrieve user 101
  POST   /api/v1/users        ──> Create a new user
  PUT    /api/v1/users/101    ──> Replace user 101
  PATCH  /api/v1/users/101    ──> Update user 101 email
  DELETE /api/v1/users/101    ──> Delete user 101
```

### The Richardson Maturity Model

```
  Level 3: HATEOAS (Hypermedia As The Engine Of Application State)
           Server supplies discoverable hypermedia links (`_links`) in response bodies.
           ▲
  Level 2: HTTP Verbs & Status Codes (⭐ Modern Industry Standard for Web APIs)
           Uses GET, POST, PUT, DELETE properly alongside status codes (200, 201, 400, 404).
           ▲
  Level 1: Resources (Discrete URIs)
           Introduces individual URIs for entities (`/orders/1`, `/customers/5`), but single verb (e.g. POST).
           ▲
  Level 0: The Swamp of POX (Plain Old XML / RPC over HTTP)
           Single URI endpoint (e.g. `/endpoint`) handling all operations via POST RPC envelopes.
```

## 🔴 Senior Level

### Modern Java 21 & Spring Boot 3.3 REST Architecture

1. **RFC 9457 Problem Details (`ProblemDetail`):**
   Spring Boot 3 natively formats REST API errors into RFC 9457 standard JSON:
   ```json
   {
     "type": "https://api.example.com/errors/insufficient-funds",
     "title": "Insufficient Funds",
     "status": 422,
     "detail": "Account balance is $12.00, transfer requires $50.00",
     "instance": "/transfers/txn-9841"
   }
   ```
2. **Spring 6 Declarative HTTP Interfaces (`@HttpExchange`):**
   ```java
   @HttpExchange("/api/v1/users")
   public interface UserClient {
       @GetExchange("/{id}")
       UserDTO getUserById(@PathVariable Long id);
   }
   ```
3. **High-Throughput Concurrency with Virtual Threads:**
   Enabling `spring.threads.virtual.enabled=true` in Java 21 allows standard blocking Spring MVC `@RestController` endpoints to handle $50{,}000+$ concurrent I/O connections without requiring complex reactive WebFlux programming.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Architectural style for networked systems introduced by Roy Fielding in 2000; not a protocol.
- **6 Constraints:** Client-Server, Stateless, Cacheable, Layered System, Uniform Interface, Code on Demand (optional).
- **Richardson Maturity Model:** Level 0 (RPC over HTTP) $\to$ Level 1 (URIs) $\to$ Level 2 (HTTP Verbs & Status Codes - Industry Standard) $\to$ Level 3 (HATEOAS).
- **REST vs. HTTP API:** True REST requires Level 3 HATEOAS; most real-world APIs operate at Level 2 (Pragmatic HTTP APIs).
- **When NOT to Use REST:** Real-time bi-directional streaming (use WebSockets/gRPC), ultra-low-latency inter-microservice IPC (use gRPC/Protobuf), complex graph queries (use GraphQL).

**Common Follow-up Questions:**
- *"What is Uniform Interface in REST?"* → It requires identification of resources via URIs, manipulation through representations, self-descriptive messages (`Content-Type`), and HATEOAS links.
- *"Why is REST considered stateless?"* → Each request contains complete authentication and operational metadata; the server does not hold session state between requests.
- *"What is RFC 9457 Problem Details?"* → An IETF standard defining a structured JSON format for returning HTTP API error responses.

**Red Flags (DO NOT Say):**
- ❌ *"REST is an official W3C or IETF protocol."* (It is an architectural style defined in a PhD dissertation).
- ❌ *"Any API using JSON over HTTP is a REST API."* (It must adhere to REST architectural constraints).
- ❌ *"GET requests can be used to mutate database records if needed."* (GET must remain strictly Safe and Idempotent).
