# What is Accept header?

---

## 🟢 Junior Level

The **`Accept`** request HTTP header informs the server **what data format (MIME type) the client expects and is able to process in the response body**.

```http
GET /api/v1/users/42 HTTP/1.1
Accept: application/json
```

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │                   Content-Type                         │                        Accept                          │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ • Tells the recipient what format **is being SENT**     │ • Tells the server what format **is WANTED in return** │
  │ • Example: `Content-Type: application/json`            │ • Example: `Accept: application/json`                  │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

### The 406 Not Acceptable Error
If a client requests a format the backend cannot produce (e.g. `Accept: application/pdf` on a user data endpoint), the server rejects the request with **`406 Not Acceptable`**.

---

## 🟡 Middle Level

### Quality Values (`q`-values) & Graceful Degradation

The `Accept` header supports priority weights called **`q`-values** (ranging from `0.0` to `1.0`, default `1.0`):

```http
Accept: application/json;q=1.0, application/xml;q=0.8, text/plain;q=0.5, */*;q=0.1
```

- **Graceful Fallback:** The server returns JSON if possible; if JSON serialization is unavailable for that entity, it falls back to XML, then plain text.

### The `Vary: Accept` Caching Invariant

```
  Client 1 (Requests XML)  ──> GET /reports/42 (Accept: application/xml)  ──> [CDN Cache] (Stores XML)
  Client 2 (Requests JSON) ──> GET /reports/42 (Accept: application/json) ──> [CDN Cache] (BUG: Returns XML!)
```

> [!IMPORTANT]
> Whenever a server serves different representations from the same URI based on the `Accept` header, it **MUST return `Vary: Accept`**. This instructs CDNs and reverse proxies to key their cache entries by both the **URI and the `Accept` header**.

## 🔴 Senior Level

### Spring MVC Content Negotiation Architecture

Spring's **`ContentNegotiationManager`** resolves the response format:

```
  Incoming Request (`Accept: application/json`)
                         │
                         ▼
  [ContentNegotiationManager] ──> Extracts MediaTypes from `Accept` header
                         │
                         ▼
  [HandlerMethod: @GetMapping(produces = "application/json")]
                         │
                         ▼
  [HttpMessageConverter Pipeline]
  ├── MappingJackson2HttpMessageConverter.canWrite() ──> ✅ Writes JSON body!
  └── If no converter matches ──> Throws `HttpMediaTypeNotAcceptableException` (406)
```

```java
// Controller-level content negotiation:
@GetMapping(value = "/reports/{id}", produces = {
    MediaType.APPLICATION_JSON_VALUE,
    MediaType.APPLICATION_XML_VALUE
})
public ReportDTO getReport(@PathVariable Long id) {
    return reportService.findById(id);
}
```

### Content Negotiation Header Family

- **`Accept`:** Target data format (`application/json`, `application/xml`).
- **`Accept-Encoding`:** Supported compression algorithms (`gzip`, `br` [Brotli], `zstd`).
- **`Accept-Language`:** Preferred human locale (`en-US`, `de;q=0.8`).

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Request header driving Content Negotiation, specifying acceptable response MIME types.
- **`Content-Type` vs `Accept`:** `Content-Type` describes the sent request payload; `Accept` dictates the desired response payload.
- **Error Code:** Unsupported format returns **`406 Not Acceptable`**.
- **Quality Values:** `q=0.0` to `q=1.0` weights facilitate client-side graceful degradation.
- **CDN Caching Rule:** Any multi-format endpoint must return **`Vary: Accept`** to avoid serving mismatched cached formats.
- **Spring Architecture:** Managed by `ContentNegotiationManager` and `HttpMessageConverter.canWrite()`.

**Common Follow-up Questions:**
- *"What happens if a client sends `Accept: */*`?"* → The server chooses its default registered format (in Spring Boot, typically `application/json`).
- *"Why is `Vary: Accept` critical for performance?"* → It tells intermediate caching layers (Cloudflare, Nginx) that cached responses cannot be shared across clients requesting different MIME types.
- *"How does Media Type versioning use the `Accept` header?"* → Clients pass vendor MIME types like `Accept: application/vnd.company.v2+json`, enabling entity versioning without modifying URI paths.

**Red Flags (DO NOT Say):**
- ❌ *"Content-Type and Accept are synonyms."* (`Content-Type` describes the payload sent; `Accept` requests the format received).
- ❌ *"406 Not Acceptable is an internal server error."* (It is a client error indicating the client requested an unsupported media format).
- ❌ *"Quality values (q-values) specify the image resolution."* (`q`-values represent preference weights between 0.0 and 1.0).
