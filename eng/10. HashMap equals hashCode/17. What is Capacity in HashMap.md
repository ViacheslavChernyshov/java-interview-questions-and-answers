# What is Capacity in HashMap?

---

## 🟢 Junior Level

**Capacity** is the total number of bucket slots in a `HashMap`'s internal array (`Node<K,V>[] table`):

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ Default Initial Capacity                               │ **16** buckets (`1 << 4`)                              │
  │ Maximum Permitted Capacity                             │ **$2^{30} = 1,073,741,824$** (`1 << 30`)               │
  │ Capacity Sizing Invariant                              │ **Strictly a power of two** ($2^n$)                    │
  │ Array Allocation                                       │ **Lazy** (Allocated on first `put()` invocation)       │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

```java
// Allocates array of size 16 (default):
Map<String, Integer> map1 = new HashMap<>(); 

// Requested 10 -> Automatically rounded up to 16:
Map<String, Integer> map2 = new HashMap<>(10); 

// Requested 33 -> Automatically rounded up to 64:
Map<String, Integer> map3 = new HashMap<>(33); 
```

## 🟡 Middle Level

### The Bitwise Rounding Algorithm: `tableSizeFor()`

When a developer requests an arbitrary initial capacity, `HashMap` calculates the next highest power of two using `tableSizeFor()`:

```java
// OpenJDK HashMap.java source:
static final int tableSizeFor(int cap) {
    int n = cap - 1;
    n |= n >>> 1;
    n |= n >>> 2;
    n |= n >>> 4;
    n |= n >>> 8;
    n |= n >>> 16;
    return (n < 0) ? 1 : (n >= MAXIMUM_CAPACITY) ? MAXIMUM_CAPACITY : n + 1;
}
```

```
  How tableSizeFor(10) Works:
  1. cap = 10 -> n = 9 (Binary: 0000 1001)
  2. n |= n >>> 1  ->  0000 1001 | 0000 0100 = 0000 1101
  3. n |= n >>> 2  ->  0000 1101 | 0000 0011 = 0000 1111 (All bits below MSB become 1s)
  4. Return n + 1  ->  15 + 1 = 16 (Exact power of 2!)
```

### The Cost of Oversizing: Iteration Overhead

```
  Full Map Iteration Complexity: O(Capacity + Size)
```
- If a map has **1,000,000 capacity** but only **5 elements**, `map.entrySet()` must iterate through all 1,000,000 null slots in memory to find the 5 entries.
- Never allocate huge initial capacities unless you intend to populate them with a proportional volume of data!

## 🔴 Senior Level

### Memory Footprint of the Internal Array

An empty bucket array still consumes heap memory for pointer references:

```
  ┌──────────────────────────────┬──────────────────────────────────┬──────────────────────────────────────────────────┐
  │ Array Capacity               │ 64-bit JVM (Compressed OOPs)     │ 64-bit JVM (No Compressed OOPs)                  │
  ├──────────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **16 buckets**               │ ~64 bytes array payload          │ ~128 bytes array payload                         │
  │ **65,536 buckets**           │ ~256 KB array payload            │ ~512 KB array payload                            │
  │ **1,048,576 buckets**        │ ~4.19 MB array payload           │ ~8.38 MB array payload                           │
  └──────────────────────────────┴──────────────────────────────────┴──────────────────────────────────────────────────┘
```

> [!NOTE]
> Under `-XX:+UseCompressedOops` (default for heaps $<32\text{GB}$), array object references are compressed from 8 bytes down to 4 bytes.

### Maximum Capacity Limit Behavior

When capacity reaches `MAXIMUM_CAPACITY` ($2^{30}$):
- Resizing is disabled.
- `threshold` is set to `Integer.MAX_VALUE` ($2^{31} - 1$).
- Subsequent insertions continue to populate existing buckets, degrading collision chains without allocating larger arrays.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** The length of the internal `table` array.
- **Default:** 16; **Maximum:** $2^{30}$ ($1,073,741,824$).
- **Power of Two Rule:** Enforces efficient bitmask indexing `(capacity - 1) & hash`.
- **`tableSizeFor()`:** Bit-shifts fill all lower bits with 1s before adding 1 to round up to the next power of two.
- **Iteration Penalty:** Iterating over `keySet()` or `entrySet()` costs $O(\text{Capacity} + \text{Size})$.
- **Lazy Initialization:** The array is not allocated in heap memory until the first `put()` call.

**Common Follow-up Questions:**
- *"What happens if you pass initial capacity 0 to the constructor?"* → `tableSizeFor(0)` evaluates `n = -1`, resulting in capacity 1 upon first insertion.
- *"Why does Hashtable not require powers of two for its capacity?"* → `Hashtable` uses modulo arithmetic `(hash & 0x7FFFFFFF) % tab.length`, which works on arbitrary integers but requires slow CPU division.
- *"How do you calculate initial capacity for 600 items with 0.75 load factor?"* → $\lceil 600 / 0.75 \rceil = 800 \to$ `tableSizeFor(800)` allocates capacity **1024**.

**Red Flags (DO NOT Say):**
- ❌ *"Capacity is the current number of elements in the map."* (That is `size`; capacity is the number of bucket slots).
- ❌ *"New HashMap(10) creates an array of length 10."* (It rounds up to 16).
- ❌ *"Allocating 10 million capacity for 10 elements is harmless."* (It consumes ~40MB of RAM and severely slows down map iterations).
