# Can HashMap Store a null Value?

---

## 🟢 Junior Level

**YES.** `HashMap` allows an **unlimited number of `null` values**:

```java
Map<String, String> userProfiles = new HashMap<>();

userProfiles.put("user_1", null);
userProfiles.put("user_2", null);
userProfiles.put("user_3", "Active");

System.out.println(userProfiles.size()); // 3 (All entries are stored successfully)
```

```
  The Ambiguity Dilemma:
  String val = userProfiles.get("user_1");   // Returns null
  String missing = userProfiles.get("user_99"); // Returns null

  Question: How do you differentiate a missing key from a key mapped to null?
  Solution: Use map.containsKey(key)!
```

---

## 🟡 Middle Level

### Resolving Retrieval Ambiguity

```java
// Method 1: containsKey() Disambiguation
if (map.containsKey("user_1")) {
    String value = map.get("user_1");
    // Guaranteed that the key exists, even if value == null
}

// Method 2: Modern Java getOrDefault()
String status = map.getOrDefault("user_99", "DEFAULT_FALLBACK");
```

### Map Implementation Comparison: `null` Values

```
  ┌──────────────────────────┬──────────────────────────┬──────────────────────────────────────────────────┐
  │ Map Implementation       │ `null` Value Permitted?  │ Behavior / Exception                             │
  ├──────────────────────────┼──────────────────────────┼──────────────────────────────────────────────────┤
  │ **`HashMap`**            │ ✅ **Yes (Unlimited)**   │ Stored directly in `Node.value`                  │
  │ **`LinkedHashMap`**      │ ✅ **Yes (Unlimited)**   │ Stored directly in `Node.value`                  │
  │ **`TreeMap`**            │ ✅ **Yes (Unlimited)**   │ Permitted (only keys require `Comparable`)       │
  │ **`ConcurrentHashMap`**  │ ❌ **No**                │ Throws `NullPointerException`                    │
  │ **`Hashtable`**          │ ❌ **No**                │ Throws `NullPointerException`                    │
  └──────────────────────────┴─────────────────────────────────────────────────────────────────────────────┘
```

## 🔴 Senior Level

### The Concurrent Race Hazard with `null` Values

Why `ConcurrentHashMap` and modern concurrent maps strictly reject `null` values:

```java
// 💥 Hypothetical Concurrent Code if null were allowed:
String val = concurrentMap.get(key); // Thread 1: gets null
if (val == null) {
    // Thread 2 mutates the map right here!
    if (!concurrentMap.containsKey(key)) {
        // TOCTOU Race Condition: Thread 1 acts on outdated state, 
        // leading to corrupted updates and broken synchronization!
    }
}
```

> [!NOTE]
> In `ConcurrentHashMap`, `map.get(key) == null` is an atomic, unambiguous guarantee that the key **does not exist**.

### Recommended Architecture: The Null Object Pattern

```java
// ✅ Zero heap overhead, type-safe, eliminates null ambiguity:
public record UserPreferences(String theme, boolean notifications) {
    public static final UserPreferences DEFAULT = new UserPreferences("DARK", true);
}

Map<String, UserPreferences> configMap = new ConcurrentHashMap<>();
configMap.put("user_1", UserPreferences.DEFAULT); // Never null!
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Permission:** `HashMap` allows any number of `null` values.
- **The Ambiguity:** `map.get(k) == null` cannot tell whether the key is missing or mapped to `null`.
- **The Solution:** Use `map.containsKey(k)` to check key existence explicitly.
- **Allowed in:** `HashMap`, `LinkedHashMap`, `TreeMap`.
- **Forbidden in:** `ConcurrentHashMap` and `Hashtable` (both throw `NullPointerException`).
- **Best Practice:** Prefer Sentinel constants or the Null Object Pattern over storing raw `null` references.

**Common Follow-up Questions:**
- *"Why does TreeMap allow null values if it forbids null keys?"* → `TreeMap` only compares keys using `Comparable`/`Comparator` to construct its binary tree; values are stored passively in tree nodes without comparison.
- *"Does storing a null value save heap memory?"* → A `null` value reference points to nothing (0 bytes object payload), but the full `Node<K,V>` object wrapper (~32 bytes) is still allocated in heap memory.
- *"How do Java 8+ functional methods handle null values?"* → Methods like `computeIfAbsent()` treat `null` values as if the key were absent, executing the mapping function.

**Red Flags (DO NOT Say):**
- ❌ *"HashMap allows only one null value, just like null keys."* (Keys are limited to 1 null; values can have unlimited nulls).
- ❌ *"ConcurrentHashMap allows null values as long as the key is non-null."* (ConcurrentHashMap strictly forbids null values).
- ❌ *"Checking `map.get(key) != null` is identical to `map.containsKey(key)`."* (If the value is stored as `null`, `get()` returns `null` while `containsKey()` returns `true`).
