# How HashMap Works Internally

---

## 🟢 Junior Level

**`HashMap`** is a key-value associative data structure implementing the `Map` interface. It provides average **$O(1)$ constant time complexity** for `get()`, `put()`, `containsKey()`, and `remove()` operations:

```
  ┌──────────────────────────┬────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ Property                 │ Standard `HashMap`                                     │ `TreeMap`                                              │
  ├──────────────────────────┼────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **Underlying Structure** │ Hash table: Array of buckets + Linked Lists / RB-Trees │ Red-Black Self-Balancing Binary Search Tree            │
  │ **Average Time Comp.**   │ **$O(1)$**                                             │ **$O(\log N)$**                                        │
  │ **Ordering**             │ **Unordered & non-deterministic**                      │ **Sorted by key natural order or Comparator**          │
  │ **Null Support**         │ Allows **one `null` key** and multiple `null` values   │ Forbids `null` keys (Throws `NullPointerException`)    │
  └──────────────────────────┴────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

```java
Map<String, Integer> inventory = new HashMap<>();

// 1. put() computes the hash of "Apple", finds its bucket index, and stores the Node:
inventory.put("Apple", 50);

// 2. get() recalculates the hash, jumps directly to the bucket, and checks key equality:
Integer stock = inventory.get("Apple"); // 50
```

## 🟡 Middle Level

### Internal State & Field Architecture

A `HashMap` instance manages its state using four primary internal fields:

```java
transient Node<K,V>[] table;  // Internal bucket array (lazily initialized on first put())
transient int size;           // Total count of key-value mappings in the map
int threshold;                // Next size threshold at which to resize (capacity * loadFactor)
final float loadFactor;       // Fill ratio determining capacity growth (default: 0.75f)
```

```
  HashMap Step-by-Step put(K, V) Algorithm:
  1. Lazy Initialization: If 'table' is null or empty, allocate table array (default capacity = 16).
  2. Hash Spread Computation: Compute perturbed hash = (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16).
  3. Bucket Indexing: Calculate target array slot index = (n - 1) & hash.
  4. Empty Bucket: If table[index] == null, instantiate a new Node<K,V> at table[index].
  5. Collision Encountered:
     a. If existing node has identical hash and (key == k || (key != null && key.equals(k))), overwrite value.
     b. If node is a 'TreeNode', insert into the Red-Black Tree.
     c. Otherwise, traverse the linked list. If key found, overwrite value; else append new Node to tail.
  6. Treeification Check: If bucket list length reaches 8:
     - If total capacity >= 64, convert bucket list into a Red-Black Tree ('TreeNode').
     - If total capacity < 64, trigger resize() instead of treeifying.
  7. Resize Evaluation: Increment 'size'. If size > threshold, invoke resize() to double capacity.
```

## 🔴 Senior Level

### Bitwise Hash Spread & Power-of-Two Masking

```java
// Java JDK HashMap hash spread function:
static final int hash(Object key) {
    int h;
    return (key == null) ? 0 : (h = key.hashCode()) ^ (h >>> 16);
}
```

```
  Why the High-Bit XOR Shift (>>> 16) is Crucial:
  • In small arrays (e.g. n = 16), index mask (n - 1) = 15 (binary 0000...1111).
  • Without bit-shifting, only the lowest 4 bits of key.hashCode() determine the bucket slot!
  • Shifting the top 16 bits down and XOR-ing folds higher-bit entropy into the lower bits,
    drastically reducing collisions for hashes that only differ in higher bits.
```

```java
// Lightning-fast bitwise index calculation (equivalent to hash % capacity, but 10x faster):
int index = (table.length - 1) & hash;
```

### Treeification Thresholds & Hysteresis

To mitigate **Hash Flooding Denial-of-Service (DoS) attacks** (where adversaries craft thousands of keys that hash to the exact same bucket), Java 8+ dynamically replaces long linked lists with **Red-Black Balanced Trees**:

```
  ┌──────────────────────────────┬──────────────────┬──────────────────────────────────────────────────┐
  │ Parameter                    │ Value            │ Architectural Purpose                            │
  ├──────────────────────────────┼──────────────────┼──────────────────────────────────────────────────┤
  │ **`TREEIFY_THRESHOLD`**      │ **8** elements   │ Transforms linked list into Red-Black Tree       │
  │ **`MIN_TREEIFY_CAPACITY`**   │ **64** capacity  │ Table capacity required before treeifying        │
  │ **`UNTREEIFY_THRESHOLD`**    │ **6** elements   │ Reverts Red-Black Tree back to linked list       │
  └──────────────────────────────┴──────────────────┴──────────────────────────────────────────────────┘
```

> [!NOTE]
> **Hysteresis Gap (8 vs 6):** The threshold difference between treeifying (8) and untreeifying (6) prevents **structure thrashing** (rapidly converting back and forth between lists and trees under frequent add/remove operations).

### Highload Resize Optimization: Lo/Hi Bit Split

During table resizing (`resize()`), capacity doubles from $N$ to $2N$. Because capacity is always a power of two, elements do not require hash recalculations. Instead, the JVM inspects the single newly exposed high bit:

```java
// If the bit matching oldCap is 0, element stays at current index; if 1, moves to index + oldCap:
if ((e.hash & oldCap) == 0) {
    // Low Head / Tail: Retains index 'i' in new table
} else {
    // High Head / Tail: Relocates to index 'i + oldCap' in new table
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Structure:** Array of buckets (`Node<K,V>[] table`), chaining collisions via linked lists and Red-Black Trees (Java 8+).
- **Time Complexity:** Average $O(1)$ for get/put/remove; worst-case $O(\log N)$ with treeification (or $O(N)$ if keys are non-comparable).
- **Lazy Initialization:** Table array is allocated upon the first `put()` call, defaulting to capacity 16.
- **Spread Function:** `(h = key.hashCode()) ^ (h >>> 16)` prevents lower-bit collision clustering.
- **Index Formula:** `index = (capacity - 1) & hash` (relies on power-of-two capacity).
- **Treeification Rules:** Triggers when bucket length reaches 8 **AND** table capacity $\ge 64$; reverts to list at 6.

**Common Follow-up Questions:**
- *"Why is the default load factor 0.75?"* → Under Poisson distribution statistics with $\lambda = 0.5$, the probability of any single bucket reaching 8 elements is less than one in ten million ($0.00000006$).
- *"What happens if you use HashMap across concurrent threads?"* → Concurrent mutations cause race conditions, lost updates, corrupted tree structures, and null-pointer exceptions (use `ConcurrentHashMap`).
- *"Why does `null` key always go to bucket index 0?"* → Because `hash(null)` explicitly returns 0, and `0 & (n - 1)` always resolves to index 0.

**Red Flags (DO NOT Say):**
- ❌ *"HashMap uses modulo division `%` to compute bucket indices."* (It uses bitwise AND `(n - 1) & hash`).
- ❌ *"A bucket always turns into a tree as soon as it gets 8 elements."* (Only if total table capacity is at least 64; otherwise it resizes).
- ❌ *"HashMap is thread-safe for reads."* (Concurrent writes during reads can result in memory visibility bugs or corrupted traversals).
