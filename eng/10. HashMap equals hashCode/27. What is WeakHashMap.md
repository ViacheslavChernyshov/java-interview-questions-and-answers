# What is WeakHashMap?

---

## 🟢 Junior Level

**`WeakHashMap`** is a specialized `Map` implementation where keys are stored using **Weak References (`WeakReference`)**.

When an object used as a key **loses all external strong references**, the JVM Garbage Collector automatically reclaims the key, and the corresponding entry is subsequently removed from the map:

```java
Map<Object, String> weakMap = new WeakHashMap<>();
Object sessionToken = new Object(); // 1. Strong reference exists

weakMap.put(sessionToken, "User Session Data");
System.out.println(weakMap.size()); // 1

sessionToken = null; // 2. Release strong reference!

System.gc(); // Suggest Garbage Collection

// 3. After GC runs, the entry is automatically evicted:
System.out.println(weakMap.size()); // 0
```

## 🟡 Middle Level

### The Internal Eviction Lifecycle: `ReferenceQueue`

```
  1. Key Invalidation:
     Object has zero strong references remaining -> GC reclaims key object in Heap.

  2. ReferenceQueue Notification:
     JVM enqueues the cleared WeakReference into WeakHashMap's internal ReferenceQueue.

  3. Lazy Expunging (expungeStaleEntries):
     Upon the next call to map.get(), put(), size(), or containsKey(),
     WeakHashMap polls the queue and unlinks all dead Entry nodes from table[].
```

```java
// OpenJDK WeakHashMap.java lazy cleanup loop:
private void expungeStaleEntries() {
    for (Object x; (x = queue.poll()) != null; ) {
        synchronized (queue) {
            Entry<K,V> e = (Entry<K,V>) x;
            int i = indexFor(e.hash, table.length);
            // Unlink entry 'e' from bucket linked list 'i'
        }
    }
}
```

### The Value-to-Key Memory Leak Hazard

> [!WARNING]
> In `WeakHashMap`, **KEYS are weakly referenced, but VALUES are strongly referenced!**
> If a value contains a reference pointing back to its key (e.g. `value.setOwnerKey(key)`), a **circular strong reference** is formed, completely preventing the Garbage Collector from reclaiming the key!

## 🔴 Senior Level

### Why `WeakHashMap` is NOT an Application Cache

```
  ┌──────────────────────────────┬──────────────────────────┬──────────────────────────────────────────────────┐
  │ Cache Capability             │ `WeakHashMap`            │ Production Cache (e.g. Caffeine / Guava)         │
  ├──────────────────────────────┼──────────────────────────┼──────────────────────────────────────────────────┤
  │ **Eviction Basis**           │ GC GC-sweep timing only  │ **LRU / LFU / TinyLFU / W-TinyLFU**              │
  │ **Time-to-Live (TTL)**       │ ❌ No                    │ ✅ Configurable (e.g. `expireAfterWrite`)         │
  │ **Maximum Size Bounds**      │ ❌ Unbounded             │ ✅ Strictly bounded (e.g. `maximumSize(10_000)`) │
  │ **Thread Safety**            │ ❌ Non-thread-safe       │ ✅ Fully concurrent & lock-free reads            │
  └──────────────────────────────┴──────────────────────────┴──────────────────────────────────────────────────┘
```

### Common Traps: String Pool & Integer Cache

```java
// ❌ TRAP 1: String Literals are never collected (held permanently in the String Pool)
weakMap.put("constant_key", "data"); // Strong reference held by JVM ClassLoader!

// ❌ TRAP 2: Boxed primitive caches (-128 to 127) are never collected
weakMap.put(Integer.valueOf(42), "data"); // Strong reference held in IntegerCache!
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Mechanism:** Keys are wrapped in `WeakReference`; entries are auto-evicted when the key loses external strong references.
- **Lazy Cleanup:** Orphaned nodes are cleaned via `expungeStaleEntries()` during subsequent map operations (`get()`, `put()`, `size()`).
- **Strong Values Trap:** Values are held via strong references; if a value points back to its key, memory leaks permanently.
- **Not a Production Cache:** Lacks LRU/LFU, TTL, size bounding, and thread safety (use **Caffeine**).
- **String Pool Trap:** String literals and cached primitive wrappers (`Integer.valueOf(10)`) will never be collected by GC.

**Common Follow-up Questions:**
- *"When is WeakHashMap useful in practice?"* → For associating metadata with transient external objects without preventing them from being garbage collected (e.g. ClassLoader metadata or Lapsed Listener registries).
- *"Is WeakHashMap thread-safe?"* → No. It must be wrapped with `Collections.synchronizedMap(new WeakHashMap<>())` for multi-threaded environments.
- *"What is the difference between SoftReference and WeakReference?"* → `SoftReference` is collected only when the JVM is low on memory (out-of-memory avoidance); `WeakReference` is collected eagerly on the very next GC cycle regardless of available RAM.

**Red Flags (DO NOT Say):**
- ❌ *"WeakHashMap is the best choice for implementing an in-memory HTTP cache."* (It lacks size bounds, TTL, and cache eviction policies; use Caffeine).
- ❌ *"Values in WeakHashMap are automatically cleared by GC when memory is low."* (Only keys are weakly referenced; values are strongly referenced).
- ❌ *"Calling `key = null` instantly removes the entry from the map."* (Removal happens only after the GC runs and a subsequent map method invokes `expungeStaleEntries()`).
