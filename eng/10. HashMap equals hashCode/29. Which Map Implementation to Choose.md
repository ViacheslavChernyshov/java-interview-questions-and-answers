# Which Map Implementation to Choose? (Comparison)

---

## 🟢 Junior Level

Java provides several specialized implementations of the `Map` interface. Use this quick selection guide:

```
  ┌──────────────────────────┬──────────────────────────────┬──────────────────────────────────────────────────┐
  │ Map Implementation       │ Primary Use Case             │ Time Complexity & Ordering                       │
  ├──────────────────────────┼──────────────────────────────┼──────────────────────────────────────────────────┤
  │ **`HashMap`**            │ **General-Purpose Default**  │ $O(1)$ constant time; **Unordered**              │
  │ **`LinkedHashMap`**      │ **Insertion Order / LRU**    │ $O(1)$ constant time; **Predictable order**      │
  │ **`TreeMap`**            │ **Sorted Keys / Range Query**│ $O(\log N)$ tree search; **Natural/Sorted order** │
  │ **`ConcurrentHashMap`**  │ **Multi-Threaded Concurrent**│ $O(1)$ thread-safe; **Unordered**                │
  │ **`EnumMap`**            │ **Enum Keys**                │ $O(1)$ fastest possible; **Enum ordinal order**  │
  │ **`WeakHashMap`**        │ **Transient Metadata / GC**  │ $O(1)$ auto-evicting keys; **Unordered**         │
  │ **`IdentityHashMap`**    │ **Reference Identity (`==`)**│ $O(1)$ open addressing; **Unordered**            │
  └──────────────────────────┴──────────────────────────────┴──────────────────────────────────────────────────┘
```

```java
// Rule of Thumb: Default to HashMap unless specific requirements arise:
Map<String, User> defaultMap = new HashMap<>();
```

## 🟡 Middle Level

### Architectural Feature Matrix

```
  ┌──────────────────────┬──────────────────────┬──────────────────────┬──────────────────────┬──────────────────────┐
  │ Implementation       │ Thread Safety        │ `null` Keys Allowed  │ Search Complexity    │ Internal Structure   │
  ├──────────────────────┼──────────────────────┼──────────────────────┼──────────────────────┼──────────────────────┤
  │ **`HashMap`**        │ ❌ No                │ ✅ Yes (1 key)       │ **$O(1)$**           │ Array + List/Tree    │
  │ **`LinkedHashMap`**  │ ❌ No                │ ✅ Yes (1 key)       │ **$O(1)$**           │ HashMap + Doubly-List│
  │ **`TreeMap`**        │ ❌ No                │ ❌ No (NPE)          │ **$O(\log N)$**      │ Red-Black Tree       │
  │ **`ConcurrentHashMap`│ ✅ **Yes**           │ ❌ No (NPE)          │ **$O(1)$**           │ Array + CAS + Locks  │
  │ **`EnumMap`**        │ ❌ No                │ ❌ No (NPE)          │ **$O(1)$**           │ Flat Array (Ordinal) │
  │ **`WeakHashMap`**    │ ❌ No                │ ✅ Yes (1 key)       │ **$O(1)$**           │ `WeakReference` Array│
  │ **`IdentityHashMap`**│ ❌ No                │ ✅ Yes               │ **$O(1)$**           │ Open Addressing Array│
  └──────────────────────┴──────────────────────┴──────────────────────┴──────────────────────┴──────────────────────┘
```

### Specialized Implementations in Action

```java
// 1. LinkedHashMap as an LRU (Least-Recently Used) Cache:
Map<String, String> lruCache = new LinkedHashMap<>(16, 0.75f, true /* accessOrder */) {
    @Override
    protected boolean removeEldestEntry(Map.Entry<String, String> eldest) {
        return size() > 100; // Evicts oldest accessed entry when size exceeds 100
    }
};

// 2. TreeMap Range Queries:
TreeMap<Integer, String> tree = new TreeMap<>();
tree.put(10, "A"); tree.put(20, "B"); tree.put(30, "C");
NavigableMap<Integer, String> range = tree.subMap(10, true, 25, false); // [10, 20]

// 3. EnumMap for Maximum Performance (Zero hashing overhead):
enum Priority { LOW, MEDIUM, HIGH }
Map<Priority, String> priorityMap = new EnumMap<>(Priority.class); // Indexed by ordinal()
```

## 🔴 Senior Level

### Production Decision Flowchart

```
  Do you need a Map data structure?
  │
  ├── Multiple threads mutating concurrently?
  │   └── YES ──► ConcurrentHashMap
  │
  ├── Are all keys Enums?
  │   └── YES ──► EnumMap (Zero hashing, minimal RAM footprint)
  │
  ├── Do you need sorted keys or range queries (subMap/headMap)?
  │   └── YES ──► TreeMap (Red-Black Binary Search Tree)
  │
  ├── Do you need predictable insertion order or a simple LRU cache?
  │   └── YES ──► LinkedHashMap
  │
  ├── Do you require strict Reference Identity (==) comparison?
  │   └── YES ──► IdentityHashMap (Open addressing)
  │
  ├── Is it an unmodifiable configuration map?
  │   └── YES ──► Map.of() / Map.copyOf() (Java 9+ compact immutable maps)
  │
  └── Default general-purpose workload?
      └── YES ──► HashMap
```

```
  ┌──────────────────────────────┬──────────────────────────┬──────────────────────────────────────────────────┐
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`HashMap`:** Default choice; $O(1)$ average; unordered; allows 1 `null` key.
- **`ConcurrentHashMap`:** Thread-safe default; lock-free reads + CAS + bucket locks; forbids `null`.
- **`LinkedHashMap`:** Preserves insertion order; supports LRU caching via `accessOrder = true`.
- **`TreeMap`:** $O(\log N)$ sorted map based on Red-Black Trees; supports range queries; forbids `null` keys.
- **`EnumMap`:** Extremely fast and compact; indexed directly by `enum.ordinal()`.
- **`Map.of()` / `Map.copyOf()`:** Immutable, space-optimized collections (Java 9+).

**Common Follow-up Questions:**
- *"Why is EnumMap faster than HashMap?"* → `EnumMap` internally uses a simple `Object[]` array indexed by `enum.ordinal()`, completely skipping hash calculations and collision resolution.
- *"How do you construct an unmodifiable Map in modern Java?"* → Use `Map.of("k1", "v1", "k2", "v2")` or `Map.copyOf(existingMap)`.
- *"Why should you not use WeakHashMap for an application cache?"* → It lacks LRU/LFU eviction policies, TTL expiration, size limits, and thread safety; use **Caffeine** instead.

**Red Flags (DO NOT Say):**
- ❌ *"TreeMap provides O(1) constant time lookups."* (TreeMap is strictly $O(\log N)$).
- ❌ *"Hashtable is the preferred thread-safe map."* (Hashtable is obsolete; use `ConcurrentHashMap`).
- ❌ *"LinkedHashMap has identical memory footprint to HashMap."* (LinkedHashMap allocates two extra pointer references per entry for the doubly-linked list).
