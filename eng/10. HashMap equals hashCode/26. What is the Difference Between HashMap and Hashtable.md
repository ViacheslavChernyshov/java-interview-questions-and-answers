# What is the Difference Between HashMap and Hashtable?

---

## 🟢 Junior Level

**`HashMap`** and **`Hashtable`** are both key-value hash table data structures, but `Hashtable` is an **obsolete legacy class from Java 1.0**, whereas `HashMap` is the modern standard collection introduced in Java 1.2:

```
  ┌──────────────────────────┬─────────────────────────────────────────────┬───────────────────────────────────────────────┐
  │ Architectural Property   │ `HashMap` (Modern)                          │ `Hashtable` (Legacy Obsolete)                 │
  ├──────────────────────────┼─────────────────────────────────────────────┼───────────────────────────────────────────────┤
  │ **Thread Safety**        │ ❌ **No** (Unsynchronized, ultra-fast)      │ ✅ **Yes** (Every method `synchronized`)      │
  │ **Null Support**         │ Allows **1 `null` key** & any `null` values │ ❌ **Throws `NullPointerException`**          │
  │ **Inheritance Base**     │ Extends `AbstractMap<K,V>`                  │ Extends obsolete `Dictionary<K,V>`            │
  │ **Index Calculation**    │ Bitwise AND: **`(n - 1) & hash`**           │ Integer Modulo: **`(hash & 0x7FFFFFFF) % n`** │
  │ **Treeification (8+)**   │ ✅ **Converts to Red-Black Trees**          │ ❌ **Singly-Linked Lists only ($O(N)$)**      │
  └──────────────────────────┴─────────────────────────────────────────────┴───────────────────────────────────────────────┘
```

> [!IMPORTANT]
> **Production Rule:** Never use `Hashtable` in modern Java applications. For single-threaded workloads use `HashMap`; for multi-threaded concurrency use `ConcurrentHashMap`.

## 🟡 Middle Level

### The Performance Overhead of `Hashtable`

In `Hashtable`, every single method is wrapped with a coarse-grained method-level monitor lock (`synchronized`):

```java
// OpenJDK Hashtable.java source:
public synchronized V get(Object key) { ... }
public synchronized V put(K key, V value) { ... }
```

```
  Why Hashtable Crushes Concurrency:
  • Even concurrent READ operations must acquire the single global object monitor lock!
  • Multi-threaded threads form an OS parking queue, destroying CPU throughput.
  • ConcurrentHashMap replaces this with lock-free volatile reads and fine-grained bucket locks.
```

### Index Math: Bitmask vs. Integer Modulo

```
  HashMap (Bitwise AND):
  int index = (capacity - 1) & hash;  // ~1 CPU clock cycle

  Hashtable (Modulo Division):
  int index = (hash & 0x7FFFFFFF) % table.length;  // ~10-50 CPU clock cycles (Hardware division)
```

## 🔴 Senior Level

### Benchmarks: Multi-Threaded Contention

Under 8 concurrent reading and writing threads:

```
  ┌──────────────────────────────┬──────────────────────────┬──────────────────────────────────────────────────┐
  │ Operation Under Contention   │ `Hashtable` Latency      │ `ConcurrentHashMap` Latency                      │
  ├──────────────────────────────┼──────────────────────────┼──────────────────────────────────────────────────┤
  │ **Concurrent Reads**         │ $\sim 500\text{ ns}$     │ **$\sim 60\text{ ns}$ ($\mathbf{8\times}$ faster)**│
  │ **Concurrent Writes**        │ $\sim 2000\text{ ns}$    │ **$\sim 120\text{ ns}$ ($\mathbf{16\times}$ faster)**│
  └──────────────────────────────┴──────────────────────────┴──────────────────────────────────────────────────┘
```

### Historical Context: Why `Hashtable` Persists in the JDK

`Hashtable` was created in 1995 for JDK 1.0 before the Java Collections Framework existed. When Java 1.2 introduced `Map`, `Hashtable` was retrofitted with the `Map` interface for backward compatibility. It remains in the JDK solely to prevent breaking legacy enterprise systems and third-party libraries.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Status:** `Hashtable` is legacy/obsolete (Java 1.0); `HashMap` is modern (Java 1.2).
- **Synchronization:** `Hashtable` synchronizes every method; `HashMap` is unsynchronized.
- **Nulls:** `HashMap` allows 1 `null` key and multiple `null` values; `Hashtable` throws NPE.
- **Index Math:** `HashMap` uses `(n - 1) & hash`; `Hashtable` uses modulo `(hash & 0x7FFFFFFF) % n`.
- **Treeification:** `HashMap` treeifies long collision chains; `Hashtable` stays as slow linked lists ($O(N)$).
- **Modern Replacements:** Single-threaded: `HashMap`; Multi-threaded: `ConcurrentHashMap`.

**Common Follow-up Questions:**
- *"What is the difference between `Enumeration` and `Iterator` in Hashtable?"* → `Hashtable.elements()` returns `Enumeration` (legacy, lacks `remove()`, not fail-fast); `Hashtable.keySet().iterator()` returns a modern fail-fast `Iterator`.
- *"Why does Hashtable use `& 0x7FFFFFFF` in its index calculation?"* → To mask out the sign bit (ensuring the integer is positive) before executing modulo arithmetic.
- *"Why is `Hashtable` slower than `ConcurrentHashMap`?"* → `Hashtable` locks the entire collection monitor for every operation; `ConcurrentHashMap` performs lock-free reads and locks only the individual bucket modified.

**Red Flags (DO NOT Say):**
- ❌ *"Hashtable is the recommended thread-safe Map in modern Java."* (It is an obsolete anti-pattern; use `ConcurrentHashMap`).
- ❌ *"HashMap uses modulo division for index calculation."* (It uses bitwise AND with power-of-two capacity).
- ❌ *"Hashtable supports treeification in Java 8+."* (Treeification was added to `HashMap` and `ConcurrentHashMap`, but never to `Hashtable`).
