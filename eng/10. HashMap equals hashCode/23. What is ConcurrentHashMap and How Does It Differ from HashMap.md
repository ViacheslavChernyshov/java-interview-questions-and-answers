# What is ConcurrentHashMap and How Does It Differ from HashMap?

---

## 🟢 Junior Level

**`ConcurrentHashMap`** is a high-throughput, thread-safe implementation of the `ConcurrentMap` interface:

```
  ┌──────────────────────────┬─────────────────────────────────────────────┬───────────────────────────────────────────────┐
  │ Feature                  │ `HashMap`                                   │ `ConcurrentHashMap`                           │
  ├──────────────────────────┼─────────────────────────────────────────────┼───────────────────────────────────────────────┤
  │ **Thread Safety**        │ ❌ **No** (Causes data races & corruption)  │ ✅ **Yes** (Thread-safe across all threads)   │
  │ **Null Support**         │ Allows **1 `null` key** & multiple values   │ ❌ **Throws `NullPointerException`**          │
  │ **Iterator Type**        │ **Fail-Fast** (`modCount` triggers CME)     │ **Weakly-Consistent** (Never throws CME)      │
  │ **Locking Strategy**     │ None                                        │ **Lock-Free Reads + CAS + Bucket-Level Locks**│
  │ **Atomic Operations**    │ None (Vulnerable to TOCTOU race conditions) │ `computeIfAbsent()`, `putIfAbsent()`, `merge()`│
  └──────────────────────────┴─────────────────────────────────────────────┴───────────────────────────────────────────────┘
```

```java
// Thread-safe map with atomic compound update:
ConcurrentMap<String, LongAdder> metrics = new ConcurrentHashMap<>();

// Atomic compute-if-absent:
metrics.computeIfAbsent("HTTP_200", k -> new LongAdder()).increment();
```

## 🟡 Middle Level

### Concurrency Architecture (Java 8+)

```
  ConcurrentHashMap Step-by-Step put(K, V) Algorithm:
  1. Reject Nulls: If key == null || value == null, throw NullPointerException.
  2. Spread Hash: Compute perturbed spread hash code.
  3. Bucket Resolution:
     a. Empty Bucket: Use CAS (Unsafe.compareAndSetReference / casTabAt) to insert new Node lock-free!
     b. Resizing in Progress: If bucket holds a ForwardingNode (hash == -1), calling thread helps resize.
     c. Occupied Bucket (Collision): Lock ONLY the head Node via synchronized(headNode) and insert.
  4. Treeification: If bucket length >= 8, convert to TreeBin (Red-Black Tree).
  5. Sharded Size Increment: Increment size via high-performance CounterCell[] array.
```

### Why `null` Keys and Values are Strictly Forbidden

According to designer **Doug Lea**, allowing `null` in a concurrent map introduces the **Unresolvable Ambiguity Hazard**:

```java
// 💥 If null were allowed in ConcurrentHashMap:
if (map.get(key) == null) {
    // Problem: Does the key NOT exist, or is it mapped to the value NULL?
    if (map.containsKey(key)) {
        // TOCTOU Race Condition: Another thread could have removed the key 
        // between the get() and containsKey() invocations!
    }
}
```

## 🔴 Senior Level

### Evolution: Java 7 Segment Locks vs. Java 8+ Node Locking

```
  ┌──────────────────────────────┬──────────────────────────────────┬──────────────────────────────────────────────────┐
  │ Architectural Parameter      │ Java 7 `ConcurrentHashMap`       │ Java 8+ `ConcurrentHashMap`                      │
  ├──────────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **Lock Granularity**         │ **Segment-level** (16 `ReentrantLock`s)│ **Bucket-level** (`synchronized` on head `Node`)│
  │ **Max Concurrent Writers**   │ 16 threads (fixed concurrency level)│ Capacity threads ($N$ buckets locked individually)│
  │ **Memory Footprint**         │ Heavy (`Segment` object wrappers)│ Lightweight (No wrapper objects per bucket)      │
  │ **Bucket Treeification**     │ Unsupported ($O(N)$ worst case)  │ Supported ($O(\log N)$ via `TreeBin`)            │
  └──────────────────────────────┴──────────────────────────────────┴──────────────────────────────────────────────────┘
```

### High-Throughput Size Calculation: `CounterCell[]`

Standard atomic integers (`AtomicLong`) suffer from severe **CPU cache line bouncing** under high thread contention.

`ConcurrentHashMap` adopts the **`LongAdder` sharding pattern**:
- Maintains a base counter (`baseCount`) and an array of sharded cells (`CounterCell[]`).
- When CAS contention on `baseCount` fails, threads hash to independent `CounterCell` slots.
- `size()` sums `baseCount` with all active `CounterCell` values in $O(\text{cells})$ without global locks.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Thread Safety:** `ConcurrentHashMap` provides full thread safety without coarse global locks.
- **Java 8+ Locking:** Lock-free reads via `volatile`, CAS for empty buckets, and `synchronized` on the head node for collisions.
- **No Nulls Allowed:** Throws `NullPointerException` on `null` keys and values to eliminate concurrent state ambiguity.
- **Weakly Consistent Iterators:** Iterators never throw `ConcurrentModificationException` and reflect map state at or after iterator creation.
- **Atomic Operations:** Use `computeIfAbsent()`, `putIfAbsent()`, and `merge()` instead of manual check-then-act blocks.
- **`size()` Scalability:** Uses `CounterCell[]` sharded cell arrays to eliminate CAS contention bottlenecks.

**Common Follow-up Questions:**
- *"Why is `ConcurrentHashMap.get()` completely lock-free?"* → Table entries and node references are declared `volatile`, guaranteeing visibility across CPU cores without locking.
- *"How does multi-threaded resizing work in ConcurrentHashMap?"* → Threads encountering a `ForwardingNode` actively assist in migrating bucket chunks coordinated via `transferIndex`.
- *"Why should you avoid `Collections.synchronizedMap()`?"* → `synchronizedMap` locks the entire collection on every operation, whereas `ConcurrentHashMap` allows hundreds of threads to write to distinct buckets concurrently.

**Red Flags (DO NOT Say):**
- ❌ *"ConcurrentHashMap uses 16 Segments in Java 17."* (Segments were replaced in Java 8 by fine-grained bucket-level locks and CAS).
- ❌ *"ConcurrentHashMap uses fail-safe iterators that copy the entire array."* (It uses Weakly-Consistent iterators that traverse the active array without cloning).
- ❌ *"Null keys go to bucket 0 in ConcurrentHashMap."* (Null keys throw `NullPointerException` immediately).
