# Can HashMap Store a null Key?

---

## 🟢 Junior Level

**YES.** `HashMap` allows **exactly ONE `null` key**:

```java
Map<String, String> map = new HashMap<>();

map.put(null, "Initial Value");
map.put(null, "Updated Value"); // Overwrites previous entry!

System.out.println(map.get(null)); // "Updated Value"
System.out.println(map.size());    // 1 (Only one null key can exist)
```

```
  How null Keys are Handled:
  • The spread function hash(null) explicitly returns 0.
  • The bucket index calculation (capacity - 1) & 0 strictly resolves to table[0].
  • A null key always resides in bucket index 0.
```

## 🟡 Middle Level

### Map Hierarchy: `null` Key Support Matrix

```
  ┌──────────────────────────┬──────────────────────────┬──────────────────────────────────────────────────┐
  │ Map Implementation       │ `null` Key Permitted?    │ Behavior / Exception                             │
  ├──────────────────────────┼──────────────────────────┼──────────────────────────────────────────────────┤
  │ **`HashMap`**            │ ✅ **Yes (1 key)**       │ Placed in `table[0]`                             │
  │ **`LinkedHashMap`**      │ ✅ **Yes (1 key)**       │ Placed in `table[0]`, ordered in iteration link  │
  │ **`TreeMap`**            │ ❌ **No**                │ Throws `NullPointerException` (`compareTo(null)`)│
  │ **`ConcurrentHashMap`**  │ ❌ **No**                │ Throws `NullPointerException` (Doug Lea rule)    │
  │ **`Hashtable`**          │ ❌ **No**                │ Throws `NullPointerException` (Legacy code)      │
  └──────────────────────────┴─────────────────────────────────────────────────────────────────────────────┘
```

### Equality Evaluation Inside `table[0]`

When checking for a `null` key inside bucket 0:

```java
// OpenJDK node comparison check:
if (p.hash == 0 && ((k = p.key) == null || (key != null && key.equals(k))))
```
- Because `key == null`, `key.equals(k)` is **never invoked**.
- Match evaluation succeeds instantly via reference equality `p.key == null`.

## 🔴 Senior Level

### Production Pitfalls & Migration Bugs

```java
// ❌ HIDDEN MIGRATION HAZARD:
Map<String, UserProfile> userCache = new HashMap<>();
userCache.put(null, guestProfile); // Works fine in single-threaded tests

// 💥 Production Refactoring to Concurrency:
Map<String, UserProfile> concurrentCache = new ConcurrentHashMap<>(userCache); 
// Instant runtime crash: java.lang.NullPointerException!
```

### Architectural Alternative: The Null Object Pattern

Rather than using raw `null` literals as map keys:

```java
// ✅ Safe, type-explicit sentinel key:
public enum SystemUserKey {
    ANONYMOUS_GUEST,
    SYSTEM_DAEMON
}

Map<Object, UserProfile> secureMap = new ConcurrentHashMap<>();
secureMap.put(SystemUserKey.ANONYMOUS_GUEST, guestProfile); // Safe across all Map implementations!
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Permission:** `HashMap` allows exactly one `null` key.
- **Overwriting:** Repeated `put(null, val)` updates the value and keeps `size` unchanged.
- **Location:** Always stored in `table[0]` because `hash(null) == 0` and `(n - 1) & 0 == 0`.
- **No Equals Call:** Evaluated strictly using reference equality `p.key == null`.
- **Forbidden in:** `ConcurrentHashMap`, `TreeMap`, and `Hashtable` (all throw `NullPointerException`).
- **Sentinel Alternative:** Use the Null Object Pattern or Enums rather than raw `null` keys.

**Common Follow-up Questions:**
- *"Why does TreeMap reject `null` keys?"* → `TreeMap` relies on `Comparable.compareTo()` or a custom `Comparator` to sort keys; invoking `compareTo(null)` or `null.compareTo()` throws `NullPointerException`.
- *"Can a HashMap have a collision in bucket 0 with non-null keys?"* → Yes! If a non-null key has a hash code that evaluates to `(n - 1) & hash == 0` (e.g. hash = 16 or 32 on capacity 16), it will share bucket 0 with the `null` key.
- *"What happens if you iterate over a map containing a `null` key?"* → `entry.getKey()` returns `null`; unboxing or invoking methods without a null check will throw `NullPointerException`.

**Red Flags (DO NOT Say):**
- ❌ *"HashMap does not allow null keys."* (It allows exactly one).
- ❌ *"Every null key is inserted as a new entry into bucket 0."* (It overwrites the previous `null` key's value).
- ❌ *"ConcurrentHashMap supports null keys in Java 21."* (ConcurrentHashMap strictly forbids null keys and null values in all Java versions).
