# What is the equals() and hashCode() Contract?

---

## 🟢 Junior Level

The **`equals()` and `hashCode()` contract** is a foundational set of rules defined in `java.lang.Object` that governs how Java objects determine equality and compute hash bucket locations:

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ Rule                                                   │ Mathematical & Architectural Contract                  │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **If `a.equals(b) == true`**                           │ `a.hashCode() == b.hashCode()` **MUST BE TRUE**        │
  │ **If `a.hashCode() == b.hashCode()`**                  │ `a.equals(b)` **MAY BE TRUE OR FALSE** (Collision)    │
  │ **If `a.equals(b) == false`**                          │ Hash codes do not need to be distinct (Collisions OK)  │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

```java
public class User {
    private final String email;
    private final int age;

    public User(String email, int age) { this.email = email; this.age = age; }

    @Override
    public boolean equals(Object o) {
        if (this == o) return true;
        if (!(o instanceof User user)) return false;
        return age == user.age && Objects.equals(email, user.email);
    }

    @Override
    public int hashCode() {
        return Objects.hash(email, age); // Standard multi-field hash calculation
    }
}
```

## 🟡 Middle Level

### The 5 Formal Axioms of `equals()`

```
  ┌───┬──────────────────────────┬─────────────────────────────────────────────────────────────────────────────┐
  │ # │ Axiom                    │ Contract Specification                                                      │
  ├───┼──────────────────────────┼─────────────────────────────────────────────────────────────────────────────┤
  │ 1 │ **Reflexivity**          │ For any non-null `x`, `x.equals(x)` must return `true`.                     │
  │ 2 │ **Symmetry**             │ For any non-null `x` and `y`, `x.equals(y) == y.equals(x)`.                 │
  │ 3 │ **Transitivity**         │ If `x.equals(y)` and `y.equals(z)` are true, `x.equals(z)` must be `true`.  │
  │ 4 │ **Consistency**          │ Multiple invocations must return identical results if fields do not change. │
  │ 5 │ **Non-Nullity**          │ For any non-null `x`, `x.equals(null)` must return `false`.                 │
  └───┴──────────────────────────┴─────────────────────────────────────────────────────────────────────────────┘
```

### Why the Prime Multiplier 31 is Standard

Joshua Bloch's classic hash computation:

$$\text{hash} = 31 \times \text{hash} + \text{field.hashCode()}$$

```
  Why 31?
  1. Prime Number: Minimizes clustering and arithmetic modulo overlaps.
  2. Bit-Shift Optimization: Modern JIT compilers replace 31 * i with a single CPU instruction:
     31 * i == (i << 5) - i
  3. Integer Wrap-Around: 32-bit integer overflow wraps silently in Java without throwing exceptions.
```

## 🔴 Senior Level

### Inheritance & Symmetry Violations in the JDK

A famous symmetry bug exists within Java's own standard library between `java.util.Date` and `java.sql.Timestamp`:

```java
java.util.Date date = new java.util.Date(1000);
java.sql.Timestamp ts = new java.sql.Timestamp(1000);
ts.setNanos(500); // Additional nanosecond precision

System.out.println(date.equals(ts)); // true  (Date ignores nanoseconds and checks milliseconds)
System.out.println(ts.equals(date)); // false (Timestamp checks nanoseconds -> Symmetry Broken!)
```

> [!CAUTION]
> Avoid extending instantiable classes and adding new value components while preserving `equals()` symmetry. Prefer **Composition over Inheritance**.

### Dangerous Edge Cases: `java.net.URL`

```java
// ❌ CRITICAL PRODUCTION FLAW: URL.equals() performs blocking DNS lookups!
Map<URL, String> urlMap = new HashMap<>();
urlMap.put(new URL("https://example.com"), "Site Data");
```
> [!WARNING]
> `URL.equals()` and `URL.hashCode()` trigger **synchronous network DNS resolutions** to determine if two hostnames resolve to the same IP address. If DNS is slow or offline, `map.get()` blocks the thread. Always use `java.net.URI` instead of `java.net.URL` for map keys!

### Modern Java Records (Java 14+)

Java `record`s eliminate manual boilerplate by automatically generating canonical, mathematically compliant `equals()` and `hashCode()` methods based on all declared components:

```java
// Automatically satisfies all 5 equals axioms and the hashCode contract:
public record CustomerAccount(UUID accountId, String email, BigDecimal balance) {}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Golden Rule:** If `a.equals(b)` is true, `a.hashCode() == b.hashCode()` MUST be true.
- **5 `equals()` Axioms:** Reflexive, Symmetric, Transitive, Consistent, Non-Null.
- **Multiplier 31:** Prime number optimized by JIT into `(i << 5) - i`.
- **Inheritance Trap:** Subclassing with additional state often breaks symmetry (use Composition).
- **`java.net.URL` Warning:** Never use `URL` as a key because `equals()` triggers blocking DNS network queries (use `URI`).
- **Records:** Java `record` types automatically implement safe contracts.

**Common Follow-up Questions:**
- *"What happens if you override `equals()` but not `hashCode()`?"* → Two equal objects will produce different hash codes, placing them in different buckets; `map.get()` will return `null` and `HashSet` will store duplicate elements.
- *"Why is `getClass() != o.getClass()` safer than `instanceof` for inheritance?"* → `getClass()` strictly enforces that both objects belong to the exact same class, preventing symmetry violations between superclasses and subclasses.
- *"What happens if `hashCode()` throws an exception?"* → `HashMap` will propagate the runtime exception immediately on `put()` or `get()`.

**Red Flags (DO NOT Say):**
- ❌ *"Two objects with the same hashCode must always be equal."* (Equal hashes mean only that they collided in the same bucket; `equals()` must still be checked).
- ❌ *"Overriding equals() without hashCode() only causes minor performance degradation."* (It fundamentally breaks collection correctness, causing silent data loss and duplicate keys).
- ❌ *"URL is a great immutable key for caching web responses."* (URL triggers blocking network DNS lookups on every equals/hashCode call).
