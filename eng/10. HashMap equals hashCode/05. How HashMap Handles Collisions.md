# How HashMap Handles Collisions

---

## 🟢 Junior Level

`HashMap` handles collisions using **Separate Chaining**: when multiple keys map to the same bucket index, they are chained together within that bucket as a **Singly-Linked List** or a **Red-Black Tree** (Java 8+):

```
  Bucket table[index] Collision Chain:
  [table[index]] ──► [Node: "Aa"=10] ──► [Node: "BB"=20] ──► [Node: "CC"=30] ──► null
```

```java
Map<String, String> map = new HashMap<>();

// Both keys have identical hashCode (2112) and map to bucket index 2:
map.put("Aa", "First Value");
map.put("BB", "Second Value");

// HashMap traverses the bucket chain and uses .equals() to return the exact match:
System.out.println(map.get("Aa")); // "First Value"
System.out.println(map.get("BB")); // "Second Value"
```

## 🟡 Middle Level

### Java 7 vs. Java 8+ Separate Chaining Architecture

```
  ┌──────────────────────────┬──────────────────────────────────┬──────────────────────────────────────────────────┐
  │ Architectural Aspect     │ Java 7                           │ Java 8+                                          │
  ├──────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **Insertion Strategy**   │ **Head Insertion** (Prepended)   │ **Tail Insertion** (Appended to end)             │
  │ **Collision Structure**  │ Purely Singly-Linked List        │ **Linked List $\to$ Red-Black Tree** (`TreeNode`)│
  │ **Worst-Case Search**    │ **$O(N)$** linear degradation    │ **$O(\log N)$** logarithmic bound                │
  │ **Multi-Threaded Bug**   │ Reversed list order caused loops │ Preserves element order; eliminates cyclic loops │
  └──────────────────────────┴──────────────────────────────────┴──────────────────────────────────────────────────┘
```

### Complete `put()` Traversal Algorithm Under Collision

```
  1. Calculate bucket index: index = (capacity - 1) & hash.
  2. If table[index] is occupied:
     a. Check Root/Head node: If (p.hash == hash && (p.key == key || key.equals(p.key))), update value.
     b. If node is a TreeNode: Delegate insertion to Red-Black Tree algorithm.
     c. If node is a standard Node (Linked List):
        - Traverse chain with a counter 'binCount'.
        - If matching key found, update value and break.
        - If tail reached (p.next == null), append new Node to tail.
        - If binCount >= 7 (8 elements in bucket): invoke treeifyBin().
```

## 🔴 Senior Level

### Under the Hood: JDK Source Traversal

```java
// OpenJDK HashMap.java bucket chain traversal:
for (int binCount = 0; ; ++binCount) {
    if ((e = p.next) == null) {
        p.next = newNode(hash, key, value, null); // 🚀 Tail Insertion!
        if (binCount >= TREEIFY_THRESHOLD - 1) // binCount >= 7 (8th element)
            treeifyBin(tab, hash);
        break;
    }
    // Fast integer hash check followed by identity/equals check:
    if (e.hash == hash && ((k = e.key) == key || (key != null && key.equals(k))))
        break; // Key exists: break out to overwrite value
    p = e;
}
```

### Tree Balancing & `Comparable` Keys

When converting a bucket list to a Red-Black Tree (`treeifyBin`), `HashMap` needs to order nodes across tree branches:
1. **Primary Ordering:** Compares 32-bit `hash` integers.
2. **Secondary Ordering (`Comparable`):** If hashes are identical, `HashMap` checks if the key implements `Comparable<K>` and calls `k1.compareTo(k2)`.
3. **Fallback Tie-Breaker (`tieBreakOrder`):** If keys are non-comparable or produce `compareTo == 0`, `HashMap` compares `System.identityHashCode(k1)` vs `System.identityHashCode(k2)` to break ties consistently.

> [!TIP]
> Always implement `Comparable<K>` on custom classes used as `HashMap` keys if you anticipate high collision volumes; it speeds up tree branch traversals significantly!

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Technique:** Separate Chaining (Linked Lists + Red-Black Trees).
- **Java 8+ Evolution:** Tail insertion (prevents circular loops) + Treeification at 8 elements.
- **Search Complexity:** Average $O(1)$; worst-case $O(\log N)$ with balanced trees.
- **Two-Step Node Match:** `p.hash == hash && (p.key == key || key.equals(p.key))`.
- **Tree Ordering:** Uses `Comparable.compareTo()` when available; falls back to `tieBreakOrder()`.
- **Untreeify:** Reverts from tree to linked list when node count drops to 6.

**Common Follow-up Questions:**
- *"Why did Java 8 switch from Head-insertion to Tail-insertion?"* → In Java 7, head-insertion inverted the order of list elements during concurrent resizing, leading to cyclic node references (`A.next = B; B.next = A`) that caused 100% CPU infinite loops during `get()`.
- *"Why does treeification require capacity $\ge 64$?"* → If total capacity is small ($<64$), collisions are caused by a cramped table rather than a compromised hash function; resizing the table is cheaper and spreads elements more effectively than allocating heavy tree nodes.
- *"What happens if two collided keys have the same hash and are not Comparable?"* → `HashMap` resolves node ordering using `System.identityHashCode()` via the internal `tieBreakOrder()` helper method.

**Red Flags (DO NOT Say):**
- ❌ *"HashMap uses Open Addressing (linear probing) to handle collisions."* (Open addressing is used in `ThreadLocalMap` and `IdentityHashMap`, NOT `HashMap`).
- ❌ *"Collided elements overwrite each other."* (Values are only overwritten if `key.equals(existingKey)` evaluates to true).
- ❌ *"Java 8 completely eliminates all performance impacts of collisions."* (Tree nodes consume 2x more memory and require balancing rotations on insertion).
