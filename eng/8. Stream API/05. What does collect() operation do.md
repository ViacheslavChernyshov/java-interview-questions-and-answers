# What does collect() operation do?

---

## 🟢 Junior Level

The **`collect()`** operation is an **eager terminal operation** that triggers execution of the stream pipeline and performs a **mutable reduction**, packaging stream elements into a target data structure (such as a `List`, `Set`, `Map`, `String`, or summary metric).

```java
// 1. Collect into List (Java 16+ .toList() is preferred for unmodifiable lists)
List<String> list = stream.collect(Collectors.toList());
List<String> unmodifiable = stream.toList(); // Modern Java 16+ standard

// 2. Collect into Set (Deduplicates elements)
Set<String> unique = stream.collect(Collectors.toSet());

// 3. Join strings with delimiter, prefix, and suffix
String csv = names.stream().collect(Collectors.joining(", ", "[", "]"));

// 4. Summarizing numeric metrics
IntSummaryStatistics stats = numbers.stream().collect(Collectors.summarizingInt(n -> n));
```

## 🟡 Middle Level

### The 4 Pillars of `Collector<T, A, R>`

A `Collector` parameterizes the reduction process using four functional building blocks:

```
  ┌──────────────────┬──────────────────────────────────────────┬──────────────────────────────────────────────────┐
  │ Component        │ Signature                                │ Role in Reduction                                │
  ├──────────────────┼──────────────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **`supplier`**   │ `Supplier<A>`                            │ Instantiates the mutable container (`List::new`)  │
  │ **`accumulator`**│ `BiConsumer<A, T>`                       │ Folds a stream element into container (`List::add`)│
  │ **`combiner`**   │ `BinaryOperator<A>`                      │ Merges two containers in parallel executions     │
  │ **`finisher`**   │ `Function<A, R>`                         │ Final transformation (`A -> R` or identity)      │
  └──────────────────┴──────────────────────────────────────────┴──────────────────────────────────────────────────┘
```

### Mutable Reduction vs. Immutable `reduce()`

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ `collect()` (Mutable Reduction)                        │ `reduce()` (Immutable Reduction)                       │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ • Mutates a single accumulator in place ($O(N)$)       │ • Produces a **new result object on every step**       │
  │ • Highly optimized for collections (`List`, `Map`)    │ • Ideal for mathematical folding (`+`, `*`, `min`)     │
  │ • Parallel threads accumulate into separate containers │ • Using `reduce` for collections incurs $O(N^2)$ copies│
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

## 🔴 Senior Level

### Advanced Grouping & Downstream Reductions

`Collectors.groupingBy()` provides expressive, SQL-like aggregation in memory:

```java
// Multi-Level Aggregation: Group orders by Customer ID, calculating total spending
Map<Long, BigDecimal> customerSpending = orders.stream()
    .collect(Collectors.groupingBy(
        Order::getCustomerId,
        Collectors.mapping(Order::getAmount, Collectors.reducing(BigDecimal.ZERO, BigDecimal::add))
    ));
```

### Collector Characteristics & Concurrent Optimization

A `Collector` exposes an immutable set of **`Characteristics`** that allow the JVM runtime to skip pipeline overhead:
- **`IDENTITY_FINISH`:** The intermediate accumulator `A` is cast directly to result type `R` without invoking `finisher()`.
- **`UNORDERED`:** Indicates that collection operations do not depend on stream encounter order.
- **`CONCURRENT`:** Accumulator can be shared concurrently across multiple worker threads into a single thread-safe container (e.g. `ConcurrentHashMap`), **bypassing the `combiner()` entirely in parallel streams**.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Eager terminal operation performing mutable reduction into a target container.
- **4 Functions:** `supplier` (creator), `accumulator` (folder), `combiner` (merger), `finisher` (converter).
- **collect vs. reduce:** `collect` mutates an existing container ($O(N)$); `reduce` creates new immutable objects.
- **Java 16+:** Prefer `.toList()` for unmodifiable lists instead of `.collect(Collectors.toList())`.
- **Key Collisions:** When using `Collectors.toMap()`, always provide a merge function to prevent `IllegalStateException`.

**Common Follow-up Questions:**
- *"What happens if you invoke `collect()` on an infinite stream?"* → The operation will hang in an infinite loop and eventually throw an `OutOfMemoryError` (unless short-circuited via `.limit()`).
- *"Why is a combiner required even in single-threaded streams?"* → The collector API is generic; writing a custom collector without a valid combiner breaks contract if callers invoke `.parallelStream()`.
- *"What is a downstream collector?"* → A secondary collector passed into grouping/partitioning collectors (e.g. `Collectors.groupingBy(User::getRole, Collectors.counting())`) to aggregate sub-groups.

**Red Flags (DO NOT Say):**
- ❌ *"collect() is an intermediate operation."* (It is an eager terminal operation).
- ❌ *"Using `reduce(new ArrayList<>(), (l, e) -> { l.add(e); return l; })` is just as fast as `collect()`."* (It violates purity, breaks parallel execution, and causes race conditions).
- ❌ *"Collectors.toMap() silently overwrites duplicate keys by default."* (It throws `IllegalStateException` on duplicate keys unless a merge function is supplied).
