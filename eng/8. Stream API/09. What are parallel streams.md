# What are parallel streams?

---

## 🟢 Junior Level

A **Parallel Stream** is a multi-threaded stream pipeline that partitions a collection's elements and executes operations across multiple CPU cores simultaneously using Java's **Fork/Join framework**.

```java
List<String> items = getLargeDataSet();

// 1. Created directly from Collection:
items.parallelStream()
    .map(String::toUpperCase)
    .forEach(System.out::println); // ⚠️ Non-deterministic execution order!

// 2. Converted from an existing sequential stream:
items.stream()
    .parallel()
    .map(String::toUpperCase)
    .toList();
```

> [!IMPORTANT]
> **Encounter Order vs. Parallelism:**
> - `forEach()` processes elements in **arbitrary, non-deterministic order** across threads.
> - `forEachOrdered()` forces strict encounter order, but introduces thread synchronization barriers that diminish parallel speedups.

## 🟡 Middle Level

### The Core Mechanism: `Spliterator` & `ForkJoinPool`

```
                                  [Source Collection (ArrayList)]
                                                │
                                    Spliterator.trySplit()
                                   ┌────────────┴────────────┐
                                   ▼                         ▼
                            [Sub-Chunk 1]              [Sub-Chunk 2]
                                   │                         │
                               trySplit()                trySplit()
                              ┌────┴────┐               ┌────┴────┐
                              ▼         ▼               ▼         ▼
                            [Task1]   [Task2]         [Task3]   [Task4]
                              │         │               │         │
                   Worker 1 ──┘         └── Worker 2    └── Worker 3
                              │                         │
                              └─────────── Combiner ────┘
                                               │
                                       [Final Result]
```

### Splitting Efficiency by Data Structure

```
  ┌──────────────────┬──────────────────┬────────────────────────────────────────────────────────┐
  │ Data Structure   │ Splitting Cost   │ Parallel Performance Rating                            │
  ├──────────────────┼──────────────────┼────────────────────────────────────────────────────────┤
  │ `ArrayList`, `[]`│ $O(1)$ (Direct)  │ ⭐⭐⭐⭐⭐ **Optimal:** Array bounds split instantly      │
  │ `IntStream.range`│ $O(1)$ (Direct)  │ ⭐⭐⭐⭐⭐ **Optimal:** Arithmetic range subdivision     │
  │ `HashSet`, `TreeSet`│ $O(\log N)$    │ ⭐⭐⭐ **Good:** Balanced trees / bucket splits        │
  │ `LinkedList`     │ $O(N)$ (Walk)    │ ❌ **Terrible:** Must traverse $N/2$ pointers to split │
  │ `Stream.iterate` │ $O(N)$ (Serial)  │ ❌ **Broken:** Cannot split sequential dependencies    │
  └──────────────────┴──────────────────┴────────────────────────────────────────────────────────┘
```

## 🔴 Senior Level

### The $N \times Q > 10{,}000$ Rule of Thumb

Parallelism introduces substantial CPU overhead (task splitting, context switching, queue coordination, memory barriers, container merging). Parallel streams only outperform sequential streams when:

$$\mathbf{N \times Q > 10{,}000}$$

- $N$: Number of stream elements.
- $Q$: Computational cost (CPU clock cycles/instructions) per element.

### Global JVM `commonPool()` Contention Hazard

By default, all parallel streams across the entire JVM execute on the globally shared **`ForkJoinPool.commonPool()`**:
- **Default Worker Count:** `Runtime.getRuntime().availableProcessors() - 1`.
- **The Pitfall:** If one developer runs blocking network/database I/O inside a parallel stream, **all worker threads in the common pool become blocked**, starving unrelated parallel streams throughout the microservice.

### Isolating Workloads with Custom `ForkJoinPool`

```java
// Isolating heavy CPU tasks from the global commonPool:
ForkJoinPool customPool = new ForkJoinPool(4);
try {
    List<Result> results = customPool.submit(() ->
        heavyDataList.parallelStream()
            .map(this::computeHeavyCpuHash)
            .toList()
    ).get(); // Runs parallel tasks exclusively inside customPool workers
} finally {
    customPool.shutdown();
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Multi-threaded stream execution leveraging `ForkJoinPool.commonPool()` and `Spliterator.trySplit()`.
- **Default Thread Pool:** Uses `Runtime.getRuntime().availableProcessors() - 1` worker threads in the common pool.
- **Data Source Matters:** `ArrayList` and primitive arrays split with $O(1)$ efficiency; `LinkedList` performs terribly.
- **$N \times Q$ Heuristic:** Parallelize only when $N \times Q > 10{,}000$; never use for small arrays ($N < 1{,}000$).
- **Avoid Blocking I/O:** Blocking operations in parallel streams saturate the JVM-wide `commonPool`.

**Common Follow-up Questions:**
- *"What is the difference between `forEach()` and `forEachOrdered()` on a parallel stream?"* → `forEach()` executes whenever any worker thread finishes, emitting items out-of-order; `forEachOrdered()` enforces upstream encounter order at the cost of thread synchronization.
- *"Why is `ThreadLocal` dangerous inside parallel stream operations?"* → Because operations run across arbitrary pooled worker threads (`ForkJoinPool.commonPool-worker-N`), leading to thread-local state leakage and race conditions.
- *"Can you change the number of threads in the common pool?"* → Yes, using the JVM system property `-Djava.util.concurrent.ForkJoinPool.common.parallelism=N`.

**Red Flags (DO NOT Say):**
- ❌ *"Adding `.parallel()` always makes every stream faster."* (For small datasets or cheap computations, parallelism is significantly slower due to coordination overhead).
- ❌ *"Parallel streams spawn a brand new thread for every element in the collection."* (They divide tasks among a fixed worker thread pool in `ForkJoinPool`).
- ❌ *"Parallel streams are recommended for making REST API calls."* (Blocking HTTP calls starve `ForkJoinPool.commonPool()`).
