# What to do about key collisions when collecting into Map?

---

## 🟢 Junior Level

A **Key Collision** occurs when two or more stream elements produce the identical key when mapped to a `Map`.

By default, the 2-argument `Collectors.toMap()` throws a runtime exception:

```java
// ❌ THROWS EXCEPTION if any users share the same department!
Map<String, User> deptUsers = users.stream()
    .collect(Collectors.toMap(User::getDepartment, Function.identity()));
```

```
Exception in thread "main" java.lang.IllegalStateException: Duplicate key Engineering (attempted merging values User[1] and User[2])
```

### The Solution: Supply a Merge Function

Supply a **`BinaryOperator` merge function** as the 3rd argument to define how duplicate values should be resolved:

```java
Map<String, User> deptUsers = users.stream()
    .collect(Collectors.toMap(
        User::getDepartment,
        Function.identity(),
        (existing, replacement) -> existing // ✅ Keep the FIRST encountered user on duplicate
    ));
```

## 🟡 Middle Level

### The 4 Core Collision Resolution Strategies

```
  ┌──────────────────────────┬──────────────────────────────────────────┬──────────────────────────────────────────────────┐
  │ Strategy                 │ Lambda Signature                         │ Use Case                                         │
  ├──────────────────────────┼──────────────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **1. Keep First**        │ `(oldVal, newVal) -> oldVal`             │ Deduplication (Retain first encounter)           │
  │ **2. Keep Last**         │ `(oldVal, newVal) -> newVal`             │ Latest-state updates (Overwrite with freshest)   │
  │ **3. Numerical Max/Min** │ `(v1, v2) -> v1 > v2 ? v1 : v2`          │ Keeping the highest/lowest attribute             │
  │ **4. String Concatenation│ `(s1, s2) -> s1 + ", " + s2`             │ Merging text descriptions                        │
  └──────────────────────────┴──────────────────────────────────────────┴──────────────────────────────────────────────────┘
```

```java
// Example: Keeping employee with highest salary per department:
Map<String, Employee> highestPaidByDept = employees.stream()
    .collect(Collectors.toMap(
        Employee::getDepartment,
        Function.identity(),
        (emp1, emp2) -> emp1.getSalary() >= emp2.getSalary() ? emp1 : emp2
    ));
```

## 🔴 Senior Level

### Associativity Requirement in Parallel Streams

When using parallel streams (`.parallelStream()`), the `mergeFunction` is invoked by the `combiner` when merging thread-local map partitions:

> [!IMPORTANT]
> The `mergeFunction` **must be strictly associative**:
> $$(v_1 \oplus v_2) \oplus v_3 = v_1 \oplus (v_2 \oplus v_3)$$
> If the merge function is non-associative (e.g. string formatting without commutative order), parallel execution yields non-deterministic results.

### When `toMap()` is the Wrong Tool: `groupingBy()`

If duplicate keys are a legitimate business characteristic representing 1-to-Many relationships, **do not force resolution inside `toMap()`—use `Collectors.groupingBy()`**:

```java
// ✅ IDIOMATIC 1-TO-MANY ASSOCIATION:
Map<Department, List<User>> usersByDept = users.stream()
    .collect(Collectors.groupingBy(User::getDepartment));
```

### Static Code Analysis Rules (SonarQube & Error Prone)

In enterprise CI/CD pipelines, static analyzers (Google Error Prone & SonarQube Rule `java:S2001`) flag 2-argument `Collectors.toMap()` as high-risk code, enforcing the 3-argument version with explicit merge functions across production codebases.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Key Collision:** Multiple elements mapping to the same map key.
- **Default Failure:** 2-argument `toMap()` throws `IllegalStateException: Duplicate key`.
- **Solution:** 3-argument `toMap(keyMapper, valueMapper, mergeFunction)` resolves collisions.
- **Common Merge Rules:** `(oldVal, newVal) -> oldVal` (keep first) or `(oldVal, newVal) -> newVal` (keep last).
- **Alternative:** Use `Collectors.groupingBy()` when multiple values should be preserved per key.
- **Parallel Rule:** In `parallelStream()`, the merge function must be associative.

**Common Follow-up Questions:**
- *"When is the merge function executed?"* → It is invoked strictly when a duplicate key is detected during map insertion or when combining partial maps in parallel streams.
- *"Why does Google Error Prone flag `Collectors.toMap(k, v)` without a merge function?"* → Because any unexpected duplicate data in production causes an immediate unhandled `IllegalStateException` crash.
- *"Can the merge function return `null`?"* → No, returning `null` from a merge function inside `Map.merge()` removes the key entry, and passing `null` values throws a `NullPointerException`.

**Red Flags (DO NOT Say):**
- ❌ *"toMap() silently overrides old values with new values by default."* (It throws `IllegalStateException`).
- ❌ *"The merge function runs for every single element in the stream."* (It executes only when two elements share the same key).
- ❌ *"You should use `toMap()` with string concatenation instead of `groupingBy()`."* (`groupingBy()` is designed for multi-value mapping).
