# What does map() operation do?

---

## 🟢 Junior Level

The **`map()`** operation is an **intermediate, stateless** operation that applies a **1-to-1 transformation** to each element in a stream.

It accepts a `Function<? super T, ? extends R>` and produces a new `Stream<R>` containing the transformed values:

```java
List<String> words = List.of("apple", "banana", "cherry");

// 1-to-1 transformation: String -> Integer (Length)
List<Integer> lengths = words.stream()
    .map(String::length) // Function<String, Integer>
    .toList(); // [5, 6, 6]

// 1-to-1 transformation: DTO to Domain Entity
List<UserResponse> responses = users.stream()
    .map(user -> new UserResponse(user.getId(), user.getName()))
    .toList();
```

> [!IMPORTANT]
> **1-to-1 Cardinality Guarantee:** Unlike `filter()` (which decreases element count) or `flatMap()` (which can produce $0 \dots N$ items per element), `map()` emits **exactly one output element for every input element**.

## 🟡 Middle Level

### The Primitive Boxing Trap (`map` vs. `mapToInt`)

Mapping objects to primitive properties using standard `map()` forces the JVM to box each primitive value into a heap wrapper object:

```java
// ❌ MEMORY WASTE: Generates 1,000,000 Integer objects on the Heap (~24 MB)
int totalLength = words.stream()
    .map(String::length) // Produces Stream<Integer> (Autoboxing!)
    .reduce(0, Integer::sum);

// ✅ HIGH PERFORMANCE: Specialized primitive stream uses zero heap allocations (~4 MB)
int totalLength = words.stream()
    .mapToInt(String::length) // Produces IntStream (Raw primitives!)
    .sum();
```

### Primitive Stream Mappers

| Operation | Input Type | Output Type |
|---|---|---|
| `mapToInt(ToIntFunction)` | `Stream<T>` | `IntStream` |
| `mapToLong(ToLongFunction)` | `Stream<T>` | `LongStream` |
| `mapToDouble(ToDoubleFunction)` | `Stream<T>` | `DoubleStream` |
| `mapToObj(IntFunction)` | `IntStream` | `Stream<R>` |

## 🔴 Senior Level

### Null Propagation Hazard

If a mapper function returns `null`, the stream propagates a `null` element downstream, creating silent `NullPointerException` bugs in subsequent operations:

```java
// ❌ DANGEROUS: If getAddress() or getCity() is null, subsequent stages crash
List<String> cities = users.stream()
    .map(User::getAddress)  // Might return null!
    .map(Address::getCity)  // 💥 Throws NullPointerException if address was null!
    .toList();

// ✅ ROBUST: Explicit null sanitization
List<String> cities = users.stream()
    .map(User::getAddress)
    .filter(Objects::nonNull)
    .map(Address::getCity)
    .filter(Objects::nonNull)
    .toList();
```

### Checked Exceptions Friction

Java functional interfaces (`Function<T, R>`) do not declare checked exceptions in their method contracts. Calling methods that throw checked exceptions inside `map()` requires handling or wrapping:

```java
// Idiomatic handling for checked exceptions in map:
List<URI> uris = urlStrings.stream()
    .map(str -> {
        try {
            return new URI(str);
        } catch (URISyntaxException e) {
            throw new IllegalArgumentException("Invalid URI syntax: " + str, e);
        }
    })
    .toList();
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Intermediate stateless 1-to-1 transformation taking `Function<T, R>` and returning `Stream<R>`.
- **Cardinality Invariant:** Always produces exactly one output element for every input element.
- **Primitive Streams:** Use `mapToInt`, `mapToLong`, `mapToDouble` to avoid boxing and heap allocations.
- **Null Safety:** If the mapper returns `null`, the stream contains `null`; sanitize with `.filter(Objects::nonNull)`.
- **Method References:** Prefer `String::length` over `s -> s.length()` for cleaner code and optimal `invokedynamic` JIT inlining.

**Common Follow-up Questions:**
- *"What is the primary difference between `map()` and `flatMap()`?"* → `map()` performs a 1-to-1 transformation returning a single value; `flatMap()` performs a 1-to-N transformation returning a `Stream` that is flattened into the parent pipeline.
- *"Can a `map()` operation perform side-effects like writing to a database?"* → It can syntactically, but doing so violates functional purity and breaks parallel stream execution. Use `.forEach()` for terminal side-effects.
- *"Does `map()` preserve element encounter order?"* → Yes. If the source stream has `ORDERED` characteristics, the transformed elements maintain the exact same relative order.

**Red Flags (DO NOT Say):**
- ❌ *"map() can be used to filter out elements by returning null."* (Returning `null` passes a `null` reference downstream; use `filter()` instead).
- ❌ *"map() and mapToInt() have identical memory performance."* (`mapToInt()` avoids millions of boxed heap allocations).
- ❌ *"map() executes immediately when called."* (It is an intermediate operation and executes lazily).
