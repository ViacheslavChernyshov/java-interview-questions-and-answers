# How to create a parallel stream?

---

## 🟢 Junior Level

In Java, there are two primary idioms for creating a parallel stream:

```java
List<String> data = List.of("apple", "banana", "cherry");

// Idiom 1: Direct creation from a Collection
Stream<String> parallel1 = data.parallelStream();

// Idiom 2: Transitioning an existing stream via .parallel()
Stream<String> parallel2 = data.stream().parallel();

// Verification:
boolean isMultiThreaded = parallel1.isParallel(); // true
```

Both methods produce identical execution behavior by configuring the underlying pipeline to execute with `parallel = true`.

## 🟡 Middle Level

### The 4 Ways to Instantiate a Parallel Stream

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ Approach                                               │ Implementation Details                                 │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **`Collection.parallelStream()`**                      │ Invokes `StreamSupport.stream(spliterator(), true)`    │
  │ **`Stream.parallel()`**                                │ Sets the internal pipeline mode flag to parallel       │
  │ **`Arrays.stream(array).parallel()`**                  │ Constructs a fixed-size `ArraySpliterator` with flags  │
  │ **`StreamSupport.stream(spliterator, true)`**          │ Low-level constructor for custom data structures       │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

### The All-or-Nothing Invariant: Last Call Wins

> [!WARNING]
> **A stream cannot be partially parallel.** A stream pipeline is either **100% sequential** or **100% parallel**.
> - If both `.parallel()` and `.sequential()` are called on the same pipeline, **the last call before the terminal operation determines the execution mode for the entire pipeline**:

```java
// ❌ Misconception: Filter runs parallel, Map runs sequentially
list.stream()
    .parallel()
    .filter(this::heavyCheck)
    .sequential() // ⚠️ OVERRIDES the entire pipeline: filter AND map run SEQUENTIALLY!
    .map(this::transform)
    .toList();
```

## 🔴 Senior Level

### Performance Optimization: Stripping Order with `.unordered()`

When a stream source possesses the `ORDERED` characteristic (like an `ArrayList` or `List`), parallel workers must synchronize during buffer consolidation to preserve original sequence order.
- If your business logic does not require ordered outputs, inserting **`.unordered()`** significantly improves parallel throughput:

```java
// Eliminates synchronization contention across ForkJoin worker threads:
List<String> distinctValues = bigList.parallelStream()
    .unordered() // 🚀 Informs Spliterator to skip encounter order preservation
    .distinct()
    .toList();
```

### Custom `ForkJoinPool` Encapsulation

```java
// Dedicated worker pool prevents starvation of ForkJoinPool.commonPool:
ForkJoinPool cpuPool = new ForkJoinPool(8);
try {
    List<ProcessedItem> results = cpuPool.submit(() ->
        rawItems.parallelStream()
            .map(this::processHeavyCompute)
            .toList()
    ).get();
} finally {
    cpuPool.shutdown();
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Creation:** `collection.parallelStream()` or `stream.parallel()`.
- **Underlying Engine:** Executes via `ForkJoinPool.commonPool()` by default.
- **Last Call Wins:** Chaining `.parallel()` and `.sequential()` applies the final configuration across the entire pipeline.
- **Order Optimization:** Use `.unordered().parallel()` to remove ordering bottlenecks in stateful operations.
- **IntStream Optimization:** `IntStream.range(0, N).parallel()` creates perfectly balanced arithmetic spliterators.

**Common Follow-up Questions:**
- *"How can you determine programmatically if a stream is running in parallel?"* → Call `stream.isParallel()`, which returns a boolean.
- *"Why is `Arrays.stream(array).parallel()` faster than `list.parallelStream()`?"* → Arrays feature direct memory indexing and fixed bounds (`SIZED | SUBSIZED`), allowing `ArraySpliterator` to divide chunks instantaneously with zero iterator overhead.
- *"Can you switch back to sequential execution mid-stream?"* → No, invoking `.sequential()` switches the entire pipeline to sequential mode from source to terminal operation.

**Red Flags (DO NOT Say):**
- ❌ *"You can run `.filter()` in parallel and `.map()` sequentially within the same stream pipeline."* (Pipelines are strictly all-or-nothing).
- ❌ *"parallelStream() creates an operating system thread for each element in the collection."* (It distributes work across a fixed pool of `ForkJoinWorkerThread` instances).
- ❌ *"parallel() modifies the original collection."* (Streams never mutate their underlying source collections).
