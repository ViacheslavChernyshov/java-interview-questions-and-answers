# What does flatMap() operation do?

---

## 🟢 Junior Level

The **`flatMap()`** operation is an **intermediate operation** that transforms each element of a stream into an individual nested stream and **flattens all resulting sub-streams into a single unified stream**.

```java
// 1. Flattening Nested Collections:
List<List<String>> nested = List.of(
    List.of("alpha", "beta"),
    List.of("gamma", "delta")
);

List<String> flatList = nested.stream()
    .flatMap(Collection::stream) // Flattens List<List<String>> -> Stream<String>
    .toList(); // ["alpha", "beta", "gamma", "delta"]

// 2. Extracting One-to-Many Relationships (e.g. Order -> Items):
List<LineItem> allItems = orders.stream()
    .flatMap(order -> order.getItems().stream())
    .toList();
```

> [!IMPORTANT]
> **Cardinality Rule:**
> - `map()` is strictly **1-to-1** ($1 \to 1$).
> - `flatMap()` is **1-to-Many** ($1 \to 0 \dots N$).

## 🟡 Middle Level

### The Monadic Difference: `map` vs. `flatMap`

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ `map(order -> order.getItems())`                       │ `flatMap(order -> order.getItems().stream())`          │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ Output: `Stream<List<LineItem>>` (Nested collections)  │ Output: `Stream<LineItem>` (Flattened elements)        │
  │ Retains original 2D dimension                          │ Collapses dimension into 1D stream                     │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

### Flattening Optionals: `Optional.flatMap()`

In `java.util.Optional`, `flatMap` prevents deeply nested wrappers:

```java
// ❌ WRONG with map: Produces Optional<Optional<String>>
Optional<Optional<String>> zip = userOpt.map(User::getAddress).map(Address::getZipCode);

// ✅ CORRECT with flatMap: Monadic unwrapping
Optional<String> zip = userOpt
    .flatMap(User::getAddress)   // Returns Optional<Address>
    .flatMap(Address::getZipCode); // Returns Optional<String>
```

### Primitive `flatMap` Specializations
Always use specialized primitive mappers to prevent GC boxing allocations:
- `flatMapToInt(Function<T, IntStream>)`
- `flatMapToLong(Function<T, LongStream>)`
- `flatMapToDouble(Function<T, DoubleStream>)`

## 🔴 Senior Level

### Automatic Resource Management in `flatMap`

When `flatMap` produces I/O streams (such as `Files.lines()`), closing the parent stream inside a Try-With-Resources block **automatically closes all child streams created by `flatMap`**:

```java
// Automatic cascading close for I/O streams:
try (Stream<Path> filePaths = Files.list(directoryPath)) {
    List<String> allLines = filePaths
        .filter(Files::isRegularFile)
        .flatMap(path -> {
            try {
                return Files.lines(path); // AutoCloseable inner stream
            } catch (IOException e) {
                return Stream.empty(); // Discard unreadable files
            }
        })
        .toList();
} // Closing filePaths automatically invokes close() on every inner Files.lines() stream!
```

### The Null Hazard: Always Return `Stream.empty()`

> [!WARNING]
> If a `flatMap` function returns `null`, the stream **immediately throws a `NullPointerException`**.
> - Never return `null` to represent missing elements.
> - Always return **`Stream.empty()`**.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Intermediate 1-to-N operation that maps each element to a `Stream` and flattens them into one stream.
- **Function Signature:** Takes `Function<? super T, ? extends Stream<? extends R>>` and returns `Stream<R>`.
- **Filtering via FlatMap:** Returning `Stream.empty()` removes elements from the stream pipeline.
- **Null Safety:** Returning `null` throws `NullPointerException`; always return `Stream.empty()`.
- **Resource Management:** Closing the outer stream automatically cascades `.close()` to all inner streams.

**Common Follow-up Questions:**
- *"What happens if `flatMap` encounters an empty list or `Stream.empty()`?"* → The empty stream emits zero elements, and the pipeline seamlessly continues to the next element without throwing errors.
- *"How does `flatMap` interact with short-circuiting operations like `findFirst()`?"* → It evaluates inner streams lazily; as soon as the first element from the first inner stream is found, remaining inner streams are never instantiated.
- *"Why is `flatMap` less parallelizable than `map`?"* → Because the cardinality of output elements per input chunk is non-deterministic ($0 \dots N$), making uniform workload splitting in `Spliterator` difficult.

**Red Flags (DO NOT Say):**
- ❌ *"flatMap is used to map two streams together into a pair."* (That is `zip`, which is not part of standard Java Stream API; `flatMap` flattens nested streams).
- ❌ *"Returning null from flatMap will silently skip the element."* (Returning `null` causes an immediate `NullPointerException`).
- ❌ *"flatMap converts an array to a Map."* (It flattens nested streams).
