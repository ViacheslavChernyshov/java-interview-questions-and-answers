# How to collect Stream into Map?

---

## 🟢 Junior Level

To collect a stream into a `java.util.Map`, use **`Collectors.toMap()`**:

```java
List<User> users = List.of(new User(1L, "Alice"), new User(2L, "Bob"));

// 1. Basic Key-Value Association:
Map<Long, String> idToName = users.stream()
    .collect(Collectors.toMap(
        User::getId,    // Key Mapper (Function<T, K>)
        User::getName   // Value Mapper (Function<T, V>)
    ));

// 2. Mapping to Self (Object Identity):
Map<Long, User> userMap = users.stream()
    .collect(Collectors.toMap(User::getId, Function.identity()));
```

> [!WARNING]
> If the stream contains duplicate keys, the 2-argument `toMap()` throws an immediate **`IllegalStateException: Duplicate key`**.

## 🟡 Middle Level

### The 3 Overloads of `Collectors.toMap()`

```
  ┌─────────────────────────────────────────────────────────────────────────────────────────────────┐
  │ 1. 2-Argument Overload (Throws exception on duplicate keys):                                    │
  │    Collectors.toMap(keyMapper, valueMapper)                                                     │
  │                                                                                                 │
  │ 2. 3-Argument Overload (Resolves duplicate collisions with merge function):                     │
  │    Collectors.toMap(keyMapper, valueMapper, (existing, replacement) -> existing)               │
  │                                                                                                 │
  │ 3. 4-Argument Overload (Custom Map Factory + Merge Function):                                   │
  │    Collectors.toMap(keyMapper, valueMapper, (e, r) -> r, LinkedHashMap::new)                    │
  └─────────────────────────────────────────────────────────────────────────────────────────────────┘
```

```java
// Preserving Insertion Order with LinkedHashMap and resolving collisions:
Map<String, User> orderedMap = users.stream()
    .collect(Collectors.toMap(
        User::getDepartment,
        Function.identity(),
        (first, second) -> first, // Retains the first encountered entity on collision
        LinkedHashMap::new         // Enforces encounter insertion order
    ));
```

## 🔴 Senior Level

### The Null Value Trap in `Collectors.toMap()`

Even though a standard `HashMap` permits `null` values, **`Collectors.toMap()` strictly rejects `null` values and throws a `NullPointerException`**:

```java
// ❌ CRITICAL BUG: Throws NullPointerException if getName() is null!
Map<Long, String> map = users.stream()
    .collect(Collectors.toMap(User::getId, User::getName));
```
- **Why this happens:** `toMap()` internally uses `Map.merge(k, v, mergeFn)`. In the JDK specification, `Map.merge()` explicitly throws `NullPointerException` if either key or value is `null`.
- **Senior Solution:** Filter nulls beforehand or use custom accumulator collection:
  ```java
  Map<Long, String> safeMap = users.stream()
      .collect(HashMap::new, (m, u) -> m.put(u.getId(), u.getName()), HashMap::putAll);
  ```

### High-Performance `EnumMap` Optimization

If your keys are Java `enum` constants, routing collection into an **`EnumMap`** provides array-index performance ($O(1)$) and zero heap hashing overhead:

```java
Map<Role, List<User>> roleMap = users.stream()
    .collect(Collectors.groupingBy(
        User::getRole,
        () -> new EnumMap<>(Role.class), // Array-backed EnumMap factory
        Collectors.toList()
    ));
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Basic Usage:** `Collectors.toMap(keyMapper, valueMapper)` transforms elements into a `Map<K, V>`.
- **Collision Error:** 2-argument `toMap()` throws `IllegalStateException` on duplicate keys.
- **Merge Function:** 3-argument `toMap(k, v, (old, replacement) -> old)` resolves collisions safely.
- **Map Factory:** 4-argument `toMap(..., LinkedHashMap::new)` preserves encounter order.
- **Null Value Hazard:** `toMap()` throws `NullPointerException` on `null` values due to `Map.merge()` constraints.
- **toMap vs groupingBy:** `toMap` creates 1-to-1 mappings; `groupingBy` creates 1-to-Many mappings (`Map<K, List<V>>`).

**Common Follow-up Questions:**
- *"Why should you prefer `Function.identity()` over `x -> x`?"* → `Function.identity()` communicates semantic intent clearly and reuses a shared singleton instance without allocating closure lambda frames.
- *"How can you collect into a thread-safe Map in parallel streams?"* → Use `Collectors.toConcurrentMap()` or `Collectors.groupingByConcurrent()`.
- *"What map implementation is returned by default in `Collectors.toMap()`?"* → It returns a `java.util.HashMap` (unless overridden via the 4th argument map factory).

**Red Flags (DO NOT Say):**
- ❌ *"toMap() silently keeps the latest value when keys collide."* (It throws `IllegalStateException` unless a merge function is provided).
- ❌ *"toMap() supports null values in the map."* (It throws `NullPointerException`).
- ❌ *"groupingBy() and toMap() are identical."* (`groupingBy` gathers items into collections per key).
