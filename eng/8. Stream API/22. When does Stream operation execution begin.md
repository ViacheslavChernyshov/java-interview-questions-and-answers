# When does Stream operation execution begin?

---

## 🟢 Junior Level

Stream execution begins **strictly and exclusively at the exact moment a terminal operation is invoked**.

Until a terminal operation (e.g. `collect()`, `toList()`, `forEach()`, `reduce()`, `findFirst()`) is called, you are merely constructing an **inert computational blueprint**. No data is read, filtered, or transformed:

```java
List<String> names = List.of("Ivan", "Petr", "Anna");

// 1. Intermediate operations: NOTHING EXECUTES YET!
Stream<String> pipeline = names.stream()
    .filter(name -> {
        System.out.println("Filter evaluated: " + name);
        return name.length() > 3;
    })
    .map(String::toUpperCase);

System.out.println(">>> Pipeline declared, but NOT running yet <<<");

// 2. Terminal operation: EXECUTION BEGINS NOW!
List<String> result = pipeline.toList();
```

```
>>> Pipeline declared, but NOT running yet <<<
Filter evaluated: Ivan
Filter evaluated: Petr
Filter evaluated: Anna
```

## 🟡 Middle Level

### Lifecycle Sequence: From Declaration to Evaluation

```
  Step 1: Declaration (Inert)
    names.stream().filter(...).map(...) ──► Creates linked ReferencePipeline stages

  Step 2: Terminal Trigger
    .toList() / .collect() ──► Calls AbstractPipeline.evaluate()

  Step 3: Sink Construction
    Backwards traversal compiles Sink chain: Sink.filter ──► Sink.map ──► Sink.collect

  Step 4: Pull & Push Execution
    Spliterator pushes elements vertically through Sink.accept()
```

### Exception Stack Trace Anatomy

When an exception occurs inside an intermediate lambda expression, the stack trace points directly to the **terminal operation as the execution initiation point**:

```
Exception in thread "main" java.lang.NullPointerException
    at com.example.Service.lambda$process$0(Service.java:18)  <-- Crash inside map()
    at java.base/java.util.stream.ReferencePipeline$3$1.accept(...)
    at java.base/java.util.Spliterators$ArraySpliterator.forEachRemaining(...)
    at java.base/java.util.stream.AbstractPipeline.evaluate(...)
    at java.base/java.util.stream.ReferencePipeline.toList(ReferencePipeline.java:682) <-- Terminal trigger!
    at com.example.Service.process(Service.java:24)
```

## 🔴 Senior Level

### Under the Hood: `invokedynamic` & `LambdaMetafactory`

1. The lambda in `.filter(x -> x > 10)` is compiled by `javac` into an **`invokedynamic` (indy)** bytecode instruction.
2. At first execution, the JVM invokes `LambdaMetafactory` to generate an anonymous class implementing `Predicate`.
3. The body of the lambda is housed in a private synthetic method (e.g. `lambda$main$0`).
4. The actual method body is invoked only when the `Sink.accept()` pipeline requests an element.

### JIT C2 Inlining & Loop Fusion

In high-volume streaming workloads:
- The HotSpot C2 compiler aggressively inlines the nested chain of `Sink.accept()` virtual calls into a **single, flat, high-performance machine code loop**.
- Intermediate functional objects are eliminated via **Escape Analysis (Scalar Replacement)**, reducing memory allocations to zero in steady state.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Exact Trigger:** Stream processing starts only when a terminal operation is called.
- **Intermediate Stage:** Returns `Stream<T>` and lazily configures the pipeline without processing elements.
- **Terminal Stage:** Returns a non-Stream value or `void`, consumes the stream, and marks `linkedOrConsumed = true`.
- **Pipeline Fusion:** Executes in a single vertical pass per element through the `Sink` chain.
- **Exception Origin:** Lambda exceptions originate from the terminal operation call frame.

**Common Follow-up Questions:**
- *"What happens if a method builds a stream pipeline with 10 intermediate operations and returns void without calling a terminal operation?"* → The stream is garbage collected without ever executing a single lambda or reading any collection element.
- *"How can you distinguish an intermediate operation from a terminal operation?"* → Intermediate operations always return `Stream<T>` (or primitive variants `IntStream`, `LongStream`); terminal operations return non-Stream types (`List`, `Optional`, `long`, `boolean`, `void`).
- *"Why does the stack trace point to the line of `.toList()` instead of `.map()` when an exception is thrown?"* → Because `.map()` merely declares the transformation; evaluation is deferred until `.toList()` triggers the pipeline.

**Red Flags (DO NOT Say):**
- ❌ *"A stream begins executing immediately when `collection.stream()` is called."* (Execution is completely deferred until a terminal operation is invoked).
- ❌ *"Intermediate operations execute horizontally, producing intermediate lists between stages."* (They execute vertically in a fused single-pass pipeline).
- ❌ *"You can call two terminal operations on the same stream instance."* (Streams are strictly single-use).
