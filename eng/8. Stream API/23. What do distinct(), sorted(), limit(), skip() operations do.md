# What do distinct(), sorted(), limit(), skip() operations do?

---

## 🟢 Junior Level

All four operations are **intermediate operations** that reshape, reorder, or bound the sequence of stream elements:

```
  ┌──────────────────┬────────────────────────────────────────────────────────┬────────────────────────────────────────┐
  │ Operation        │ Description                                            │ Example Transformation                 │
  ├──────────────────┼────────────────────────────────────────────────────────┼────────────────────────────────────────┤
  │ **`distinct()`** │ Removes duplicates based on `equals()` and `hashCode()`│ `[1, 2, 2, 3, 1] ──► [1, 2, 3]`        │
  │ **`sorted()`**   │ Sorts elements using natural order or `Comparator`     │ `[3, 1, 4, 2] ──► [1, 2, 3, 4]`        │
  │ **`limit(n)`**   │ Restricts output to at most the first $n$ elements     │ `[1, 2, 3, 4, 5].limit(3) ──► [1, 2, 3]`│
  │ **`skip(n)`**    │ Discards the first $n$ elements of the stream          │ `[1, 2, 3, 4, 5].skip(2) ──► [3, 4, 5]` │
  └──────────────────┴────────────────────────────────────────────────────────┴────────────────────────────────────────┘
```

```java
List<Integer> numbers = List.of(5, 2, 8, 2, 9, 1, 5, 8);

List<Integer> result = numbers.stream()
    .distinct()            // [5, 2, 8, 9, 1]
    .sorted()              // [1, 2, 5, 8, 9]
    .skip(1)               // [2, 5, 8, 9] (Skips smallest element)
    .limit(3)              // [2, 5, 8]    (Takes top 3)
    .toList();
```

## 🟡 Middle Level

### Stateless vs. Stateful Intermediate Operations

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ Stateless (`filter`, `map`, `flatMap`, `peek`)         │ Stateful (`distinct`, `sorted`, `limit`, `skip`)       │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ • Elements are processed independently on-the-fly      │ • Requires retaining memory state across elements      │
  │ • Zero intermediate buffering ($O(1)$ memory)          │ • `distinct()` buffers a `LinkedHashSet` ($O(N)$ Heap) │
  │ • Seamlessly parallelizable across CPU cores           │ • `sorted()` is a **Full Pipeline Barrier**            │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

### The `sorted()` Full Pipeline Barrier

> [!IMPORTANT]
> **`sorted()` cannot emit a single element downstream until it has consumed and buffered ALL upstream elements into an internal array.**
> - It halts pipeline flow until the full dataset is gathered, then executes a TimSort/Dual-Pivot Quicksort.

### Stream Characteristic Optimizations (`StreamOpFlag`)

If the stream source already satisfies the target characteristic, the JVM optimizes the operation as a **no-op**:

```java
Set<String> treeSet = new TreeSet<>(List.of("B", "A", "C"));

// The JVM detects SORTED and DISTINCT flags on TreeSet:
treeSet.stream()
    .distinct() // 🚀 NO-OP: Set guarantees distinctness
    .sorted()   // 🚀 NO-OP: TreeSet is pre-sorted
    .toList();
```

## 🔴 Senior Level

### 3 Critical Production Performance Traps

#### 1. The Top-N Anti-Pattern: `sorted().limit(k)`
```java
// ❌ INEFFICIENT ON 10,000,000 ITEMS: Sorts all 10M elements in O(N log N)
List<User> top5 = users.stream()
    .sorted(Comparator.comparing(User::getScore).reversed())
    .limit(5)
    .toList();
```
- **Senior Solution:** Use a bounded **Min-Heap (`PriorityQueue`)** of size $K=5$ to achieve **$O(N \log K)$ time** and **$O(K)$ memory** instead of $O(N \log N)$ and $O(N)$ memory allocations.

#### 2. In-Memory Pagination Anti-Pattern: `skip(N).limit(M)`
- Calling `.skip(100_000).limit(20)` forces the JVM to iterate and discard 100,000 elements in application memory.
- **Senior Solution:** Push pagination down to the database query engine (`LIMIT / OFFSET` or Keyset Pagination).

#### 3. Infinite Stream Hangs
```java
// 💥 OutOfMemoryError / Infinite Hang: sorted() attempts to buffer infinity!
Stream.iterate(0, i -> i + 1)
    .sorted()  // ❌ Full barrier hangs forever trying to gather infinite items!
    .limit(10)
    .toList();

// ✅ CORRECT: limit() MUST precede sorted()!
Stream.iterate(0, i -> i + 1)
    .limit(10)
    .sorted()
    .toList();
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Operation Types:** `distinct`, `sorted`, `limit`, and `skip` are intermediate stateful operations.
- **`sorted()` Barrier:** Buffers all elements before emitting the first element ($O(N)$ memory).
- **`distinct()` Mechanism:** Uses internal `LinkedHashSet` evaluating `equals()` and `hashCode()`.
- **Infinite Streams:** `sorted()` on infinite streams hangs forever unless `limit()` is applied *before* `sorted()`.
- **Stream Flag Elision:** If source is pre-sorted or distinct (`TreeSet`), `sorted()` and `distinct()` are optimized away as no-ops.

**Common Follow-up Questions:**
- *"What happens if a custom class implements `equals()` but forgets `hashCode()` when passed to `distinct()`?"* → `distinct()` will fail to identify duplicates reliably because `LinkedHashSet` buckets objects by hash code first.
- *"Why is `sorted()` problematic in parallel streams?"* → Because all worker threads must pause and synchronize at the `sorted()` barrier, serializing data into a central array before sorting via `Arrays.parallelSort()`.
- *"How does `limit()` support short-circuiting?"* → `limit(n)` decrements an internal counter and cancels upstream pulls once $n$ elements have passed downstream.

**Red Flags (DO NOT Say):**
- ❌ *"sorted() sorts elements lazily on the fly without buffering them."* (It is a strict barrier requiring full buffering).
- ❌ *"distinct() compares objects using reference equality `==`."* (It uses `equals()` and `hashCode()`).
- ❌ *"Calling `skip(1_000_000)` on an ArrayList is an O(1) pointer jump."* (The stream still iterates through 1,000,000 elements linearly).
