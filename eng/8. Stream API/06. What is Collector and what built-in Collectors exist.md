# What is Collector and what built-in Collectors exist?

---

## 🟢 Junior Level

A **`Collector<T, A, R>`** is a specification interface that describes how to accumulate stream elements of type `T` into a mutable container `A` and convert it into a final result `R`.

The **`java.util.stream.Collectors`** utility class provides dozens of pre-built, production-ready collectors:

```java
// 1. Basic Collections
List<String> list = stream.collect(Collectors.toList());
Set<String> set = stream.collect(Collectors.toSet());
LinkedList<String> custom = stream.collect(Collectors.toCollection(LinkedList::new));

// 2. String Concatenation
String joined = stream.collect(Collectors.joining(", ", "[", "]"));

// 3. Counting & Numerical Summaries
long count = stream.collect(Collectors.counting());
double avgAge = users.stream().collect(Collectors.averagingInt(User::getAge));
```

### Categories of Built-in Collectors

### Advanced Multi-Level Downstream Grouping

```java
// Group employees by department, calculating the average salary for each department:
Map<Department, Double> avgSalaryByDept = employees.stream()
    .collect(Collectors.groupingBy(
        Employee::getDepartment,
        Collectors.averagingDouble(Employee::getSalary)
    ));

// Partition active vs inactive users, collecting their usernames into Sets:
Map<Boolean, Set<String>> partitionedUsernames = users.stream()
    .collect(Collectors.partitioningBy(
        User::isActive,
        Collectors.mapping(User::getUsername, Collectors.toSet())
    ));
```

### Bi-Collector Fusion with `teeing()` (Java 12+)

```java
// Compute Minimum and Maximum in a single pass over the stream:
RecordRange range = numbers.stream().collect(
    Collectors.teeing(
        Collectors.minBy(Integer::compareTo),
        Collectors.maxBy(Integer::compareTo),
        (minOpt, maxOpt) -> new RecordRange(minOpt.orElse(0), maxOpt.orElse(0))
    )
);
```

## 🔴 Senior Level

### Anatomy of Custom Collectors: `Collector.of()`

When standard collectors are insufficient, you can create a custom collector using the static factory `Collector.of()`:

```java
public static <T> Collector<T, ?, ImmutableList<T>> toImmutableList() {
    return Collector.of(
        ImmutableList::<T>builder,          // 1. supplier
        ImmutableList.Builder::add,          // 2. accumulator
        (b1, b2) -> b1.addAll(b2.build()),   // 3. combiner (for parallel streams)
        ImmutableList.Builder::build,        // 4. finisher
        Collector.Characteristics.UNORDERED  // 5. characteristics flags
    );
}
```

### Optimization Characteristics

- **`CONCURRENT`:** Accumulator can be called concurrently from multiple threads into a shared container (`ConcurrentHashMap`), **bypassing the `combiner()` step in parallel streams**.
- **`UNORDERED`:** Stream encounter order is not preserved, unlocking faster multi-threaded collection.
- **`IDENTITY_FINISH`:** The intermediate accumulator `A` is directly returned as `R` without invoking `finisher()`.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Specification defining mutable reduction parameters (`supplier`, `accumulator`, `combiner`, `finisher`, `characteristics`).
- **Core Groups:** Collection sinks (`toList`), mappings (`toMap`), groupings (`groupingBy`), reductions (`joining`, `summingInt`).
- **Downstream Collectors:** Nested inside `groupingBy()` or `partitioningBy()` to aggregate subgroups in a single pass.
- **Java 12+ Teeing:** Merges two distinct collectors into one final result in a single stream traversal.
- **Concurrent Collectors:** `groupingByConcurrent()` leverages concurrent data structures for parallel streams.

**Common Follow-up Questions:**
- *"What is the difference between `groupingBy()` and `partitioningBy()`?"* → `groupingBy()` partitions into an arbitrary number of map keys using a `Function<T, K>`; `partitioningBy()` always splits into exactly two boolean buckets (`true` and `false`) using a `Predicate<T>`.
- *"Why does `groupingByConcurrent()` outperform `groupingBy()` in parallel streams?"* → Because all worker threads write directly into a shared `ConcurrentMap` instead of allocating per-thread maps and merging them with the combiner.
- *"What is the difference between `Collectors.toList()` and `Stream.toList()` (Java 16+)?"* → `Collectors.toList()` returns a mutable `ArrayList` (unspecified implementation); `Stream.toList()` produces an unmodifiable list with less allocation overhead.

**Red Flags (DO NOT Say):**
- ❌ *"Collectors store stream data permanently."* (Collectors are stateless algorithms that populate containers during execution).
- ❌ *"You cannot combine multiple collectors together."* (Java 12 `teeing()` and downstream collectors allow arbitrary composition).
- ❌ *"IDENTITY_FINISH means the finisher executes once at the start."* (It means the intermediate container is identical to the final return type, skipping the finisher completely).
