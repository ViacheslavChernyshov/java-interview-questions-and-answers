# What does reduce() operation do?

---

## 🟢 Junior Level

The **`reduce()`** operation is an **eager terminal operation** that performs an **immutable functional reduction (fold)** across all stream elements to produce a **single consolidated scalar result**.

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5);

// Overload 1: Without identity -> Returns Optional<T> (Safe for empty streams)
Optional<Integer> sum1 = numbers.stream()
    .reduce((a, b) -> a + b); // Optional[15]

// Overload 2: With identity -> Returns T (Returns identity if stream is empty)
int sum2 = numbers.stream()
    .reduce(0, (a, b) -> a + b); // 15

// Overload 3: Type transformation with Combiner -> Returns U
int totalChars = List.of("Java", "Stream", "API").stream()
    .reduce(0, 
            (acc, str) -> acc + str.length(), // Accumulator
            Integer::sum);                     // Combiner (for parallel workers)
```

## 🟡 Middle Level

### The 2 Mathematical Contracts of `reduce()`

For `reduce()` to function deterministically across both sequential and parallel streams, the reduction function must satisfy two mathematical laws:

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ Mathematical Property                                  │ Contract & Formula                                     │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **1. Identity Element**                                │ `accumulator(identity, x) == x`                       │
  │                                                        │ ($0$ for addition, $1$ for multiplication, `""` for str)│
  │ **2. Associativity**                                   │ `(a ⊕ b) ⊕ c == a ⊕ (b ⊕ c)`                           │
  │                                                        │ Parentheses grouping must not alter the final result    │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

### The Non-Associative Trap: Subtraction in Parallel Streams

```java
// Sequential execution: ((10 - 2) - 3) = 5
numbers.stream().reduce((a, b) -> a - b);

// 💥 Parallel execution: Subtree splits [10] and [2 - 3 = -1] -> 10 - (-1) = 11 (WRONG!)
numbers.parallelStream().reduce((a, b) -> a - b);
```
> [!WARNING]
> Subtraction is **not associative**. Using subtraction inside a parallel `reduce()` generates mathematically corrupt results.

## 🔴 Senior Level

### Under the Hood: The Role of the `Combiner`

```java
<U> U reduce(U identity, 
             BiFunction<U, ? super T, U> accumulator, 
             BinaryOperator<U> combiner);
```
- **In Sequential Streams:** The `combiner` is **never called**; only `accumulator` executes sequentially.
- **In Parallel Streams (`ForkJoinPool`):**
  1. Each worker thread processes a sub-chunk of elements `T`, folding them into a partial result of type `U` using `accumulator`.
  2. As worker threads complete, `ForkJoinPool` pairs and merges partial results `U` using the **`combiner`**.

```
  Worker 1 ["Java", "8"]   ──► Accumulator ──► Partial: 5  ──┐
                                                             ├──► Combiner (5 + 11) ──► 16
  Worker 2 ["Concurrency"] ──► Accumulator ──► Partial: 11 ──┘
```

### Allocation Efficiency: `reduce()` vs. Primitive Streams

```java
// ❌ MEMORY OVERHEAD: Allocates millions of boxed Integer objects on the Heap
int total = numbers.stream().reduce(0, Integer::sum);

// ✅ HIGH PERFORMANCE: Direct CPU register accumulation with zero heap allocations
int total = numbers.stream().mapToInt(Integer::intValue).sum();
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Terminal operation performing immutable reduction of stream elements into a single value.
- **Overload 1 (No Identity):** Returns `Optional<T>` (`Optional.empty()` if stream is empty).
- **Overload 2 (With Identity):** Returns `T` (returns `identity` value if stream is empty).
- **Mathematical Laws:** Must satisfy **Identity** (`identity + x = x`) and **Associativity** (`(a+b)+c = a+(b+c)`).
- **Combiner Role:** In the 3-argument overload, `combiner` is used exclusively by parallel streams to merge sub-results.
- **Collection Warning:** Never use `reduce()` to accumulate into a `List` or `Set` (use `collect()` to avoid $O(N^2)$ memory copies).

**Common Follow-up Questions:**
- *"What happens if you provide an incorrect identity value like `10` for addition in parallel streams?"* → Every parallel worker thread adds `10` to its initial chunk, multiplying the error across threads.
- *"Why does `reduce()` without identity return an `Optional`?"* → Because if the stream contains zero elements, there is no valid return value, so `Optional.empty()` signals the absence of a value safely.
- *"How does `reduce()` differ from `collect()`?"* → `reduce()` is designed for immutable scalar folding; `collect()` is designed for mutable in-place container accumulation.

**Red Flags (DO NOT Say):**
- ❌ *"reduce() mutates the identity object in place on each iteration."* (`reduce()` is functional and immutable; `collect()` mutates containers).
- ❌ *"You can use subtraction safely inside parallelStream.reduce()."* (Subtraction is non-associative and fails in parallel mode).
- ❌ *"The combiner is called after every single element in sequential streams."* (It is never invoked in sequential execution).
