# What do findFirst() and findAny() operations do?

---

## 🟢 Junior Level

Both **`findFirst()`** and **`findAny()`** are **terminal short-circuiting operations** that search for an element matching upstream filters and return the result wrapped in an **`Optional<T>`**:

```
  ┌──────────────────┬────────────────────────────────────────────────────────┬────────────────────────────────────────┐
  │ Method           │ Encounter Order Behavior                               │ Multi-Threaded Performance             │
  ├──────────────────┼────────────────────────────────────────────────────────┼────────────────────────────────────────┤
  │ **`findFirst()`**│ Guarantees returning the **strictly first element**    │ Slower: Synchronizes thread boundaries │
  │ **`findAny()`**  │ Returns **whichever matching element is found first**  │ **Fastest:** Returns immediately       │
  └──────────────────┴────────────────────────────────────────────────────────┴────────────────────────────────────────┘
```

```java
List<String> users = List.of("guest_1", "admin", "guest_2", "moderator");

// Find the first administrator:
Optional<String> firstAdmin = users.stream()
    .filter(u -> u.startsWith("admin"))
    .findFirst();

String result = firstAdmin.orElse("No admin found"); // "admin"
```

## 🟡 Middle Level

### Encounter Order & Collection Sources

```
  ┌──────────────────────────────────────────┬──────────────────┬──────────────────────────────────────────────┐
  │ Collection Source                        │ Encounter Order  │ Parallel Behavior of `findFirst()`           │
  ├──────────────────────────────────────────┼──────────────────┼──────────────────────────────────────────────┤
  │ **`ArrayList`, `List.of()`, arrays**     │ **Strict**       │ Must verify lower index chunks before return │
  │ **`HashSet`, `HashMap.keySet()`**        │ **Unordered**    │ Acts similarly to `findAny()`                │
  └──────────────────────────────────────────┴──────────────────┴──────────────────────────────────────────────┘
```

### Choosing the Right Terminal Operation

```java
// 1. Need only a boolean check? -> anyMatch() is faster (Zero Optional heap allocations):
boolean hasAdmin = users.stream().anyMatch(u -> u.startsWith("admin"));

// 2. Need to retrieve the object instance? -> findFirst() or findAny():
Optional<String> admin = users.stream().filter(u -> u.startsWith("admin")).findFirst();
```

## 🔴 Senior Level

### Under the Hood: `FindTask` in `ForkJoinPool`

```
  Parallel Execution with 4 Threads:
  Thread 1 (Items 0..250k):      Evaluating...
  Thread 2 (Items 250k..500k):   Evaluating...
  Thread 3 (Items 500k..750k):   FOUND MATCH! ──► findAny() returns IMMEDIATELY & cancels T1, T2, T4!
                                              ──► findFirst() BLOCKS & WAITS for Thread 1 & 2!
  Thread 4 (Items 750k..1000k):  Evaluating...
```

- **`findAny()` Cancellation:** Emits an atomic `shortCircuit()` call that immediately terminates all peer `ForkJoinTask` nodes via `cancelLaterNodes()`.
- **`findFirst()` Synchronization:** Forces right-branch threads to block until left-branch threads confirm that no earlier matching element exists in the dataset.

### The NullPointerException Trap in `findFirst()`

```java
List<String> list = Arrays.asList("A", null, "B");

// ❌ THROWS NullPointerException: Optional cannot wrap null!
Optional<String> result = list.stream()
    .filter(Objects::isNull)
    .findFirst(); // 💥 Throws NullPointerException!
```
> [!WARNING]
> Stream implementations use `Optional.of(value)` internally when wrapping matches. If the matching stream element is `null`, `findFirst()` throws a `NullPointerException`.

### Primitive Zero-Allocation Specializations
- `IntStream.findFirst()` $\rightarrow$ `OptionalInt`
- `LongStream.findFirst()` $\rightarrow$ `OptionalLong`
- `DoubleStream.findFirst()` $\rightarrow$ `OptionalDouble`

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`findFirst()`:** Returns the first element according to strict Encounter Order.
- **`findAny()`:** Returns any matching element; designed for maximum concurrency speed.
- **Parallel Performance:** `findAny()` is vastly superior in `parallelStream()` because it avoids waiting for left-branch task completions.
- **Null Safety:** If a matching element is `null`, `findFirst()` and `findAny()` throw a `NullPointerException`.
- **Primitive Streams:** Use `OptionalInt`, `OptionalLong`, `OptionalDouble` to eliminate GC boxing overhead.

**Common Follow-up Questions:**
- *"Do `findFirst()` and `findAny()` behave identically in sequential streams?"* → On ordered sources, both almost always return the identical first element.
- *"What is returned if the stream is empty or no element matches the filter?"* → Returns an `Optional.empty()`.
- *"Why does `findFirst()` cause thread stalls in parallel streams?"* → Because right-branch workers that find a match must wait for left-branch workers to finish before they can determine if their match is truly the first in encounter order.

**Red Flags (DO NOT Say):**
- ❌ *"findAny() selects an element at random using a random number generator."* (It returns whichever worker thread completes evaluation first).
- ❌ *"findFirst() and findAny() perform identically on a 32-core parallel stream."* (`findFirst()` incurs significant thread synchronization latency).
- ❌ *"Calling `findFirst().get()` without `isPresent()` or `orElse()` is safe."* (Throws `NoSuchElementException` if no element matched).
