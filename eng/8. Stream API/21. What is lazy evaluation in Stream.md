# What is lazy evaluation in Stream?

---

## 🟢 Junior Level

**Lazy Evaluation** (Deferred Execution) is the computational strategy in the Java Stream API where **intermediate operations (`filter`, `map`, `peek`) perform zero element processing upon declaration**, instead recording a blueprint of pipeline stages.

Actual reading and processing of source elements **begins strictly at the exact moment a terminal operation (`collect`, `toList`, `forEach`, `findFirst`, `reduce`) is invoked**:

```java
List<String> fruits = List.of("Apple", "Banana", "Apricot");

// 1. Intermediate operations: NOTHING EXECUTES YET!
Stream<String> stream = fruits.stream()
    .filter(f -> {
        System.out.println("Filter evaluated for: " + f);
        return f.startsWith("A");
    })
    .map(f -> {
        System.out.println("Map evaluated for: " + f);
        return f.toUpperCase();
    });

System.out.println(">>> Terminal operation has NOT been called yet <<<");

// 2. Terminal operation: EXECUTION BEGINS NOW!
List<String> result = stream.toList();
```

```
>>> Terminal operation has NOT been called yet <<<
Filter evaluated for: Apple
Map evaluated for: Apple
Filter evaluated for: Banana
Filter evaluated for: Apricot
Map evaluated for: Apricot
```

## 🟡 Middle Level

### Vertical vs. Horizontal Pipeline Execution

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ Horizontal Iteration (Classic Imperative Loops)        │ Vertical Execution (Java Stream Pipeline Fusion)       │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ • Processes all $N$ items in Step 1 $\to$ Buffers List 1│ • Item 1 passes: [Filter] $\to$ [Map] $\to$ [Collect]   │
  │ • Processes all $N$ items in Step 2 $\to$ Buffers List 2│ • Item 2 passes: [Filter] $\to$ Discarded              │
  │ • Memory overhead: $O(N)$ Heap buffers between steps   │ • Item 3 passes: [Filter] $\to$ [Map] $\to$ [Collect]   │
  │ • Poor CPU L1/L2 cache locality                        │ • Zero intermediate buffers ($O(1)$ memory); Cache Hot │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

## 🔴 Senior Level

### Infinite Streams & Short-Circuiting

Lazy evaluation enables the safe processing of theoretically **infinite streams**:

```java
// Infinite Stream Generator:
List<UUID> matchingTokens = Stream.generate(UUID::randomUUID)
    .filter(uuid -> uuid.toString().startsWith("00")) // Infinite search space
    .limit(5)                                         // Short-circuiting limit!
    .toList();
```
- **On-Demand Pulling:** The source generator emits elements one-by-one only when pulled downstream.
- As soon as `limit(5)` receives its 5th matching element, it cancels downstream pulls, terminating the infinite generator safely.

### Production Traps of Lazy Evaluation

1. **Deferred Runtime Exceptions:**
   - Any runtime exception (e.g. `ArithmeticException: / by zero` or `NullPointerException` inside a `map` lambda) is thrown at the line of the **terminal operation**, not where the stream was declared.
2. **Database Transaction Boundaries (`@Transactional`):**
   - Returning an un-evaluated stream from a transactional repository causes queries to execute *after* the transaction closes, triggering a **`LazyInitializationException`** or **`Closed JDBC Connection`**.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Intermediate operations are deferred until a terminal operation is invoked.
- **Vertical Execution:** Elements flow vertically through the pipeline one-by-one, eliminating intermediate heap collections.
- **Infinite Streams:** Laziness allows handling unbounded sources (`Stream.generate()`, `Stream.iterate()`) with short-circuiting.
- **Single Pass:** The entire pipeline executes in a single coordinated pass over the data.
- **Exception Site:** Exceptions occur at the line of the terminal operation call.

**Common Follow-up Questions:**
- *"What happens if you define a stream with 20 intermediate steps and never call a terminal operation?"* → Zero elements are processed, zero lambda functions are executed, and zero CPU cycles are spent transforming data.
- *"What is Pipeline Fusion?"* → The JVM optimization where consecutive stateless intermediate stages (`filter` followed by `map`) are fused into a single loop pass without intermediate storage.
- *"Why can lazy streams cause bugs with database connections?"* → If a method returns an open stream backed by a database connection, executing the terminal operation outside the method occurs after the connection has already closed.

**Red Flags (DO NOT Say):**
- ❌ *"map() executes immediately in the background on a separate thread."* (Intermediate operations are strictly inert and lazy).
- ❌ *"A stream creates temporary ArrayList buffers between each chained intermediate operation."* (Pipeline fusion passes elements directly without intermediate collections).
- ❌ *"Infinite streams cannot be processed in Java."* (Infinite streams work seamlessly when combined with lazy short-circuiting operations).
