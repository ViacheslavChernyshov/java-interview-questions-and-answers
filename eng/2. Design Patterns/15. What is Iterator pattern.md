# What is the Iterator pattern?

---

## 🟢 Junior Level

The **Iterator pattern** is a Behavioral design pattern that provides a standardized way to **sequentially access elements of an aggregate collection without exposing its underlying internal data structure** (e.g. array, linked list, balanced binary tree, or hash table).

**Why it is needed:** Client code should not care whether a data structure is backed by an `ArrayList`, `LinkedList`, or `TreeSet`; the traversal syntax should remain completely identical.

**Simple analogy:** A TV remote channel flipper. You press the "Next" button repeatedly to view the next channel without needing to understand how the internal tuner circuits process broadcast signals.

```java
List<String> servers = List.of("app-1", "app-2", "app-3");

// 1. Explicit Iterator traversal
Iterator<String> iterator = servers.iterator();
while (iterator.hasNext()) {
    String server = iterator.next();
    System.out.println("Checking server: " + server);
}

// 2. Enhanced For-Loop (Under the hood, the Java compiler uses an Iterator!)
for (String server : servers) {
    System.out.println("Pinging: " + server);
}
```

## 🟡 Middle Level

### `Iterator<E>` vs. `ListIterator<E>`

| Feature | `Iterator<E>` | `ListIterator<E>` |
|---|---|---|
| **Supported Collections** | All `Collection<E>` (List, Set, Queue) | Strictly `List<E>` implementations |
| **Directionality** | Forward-only (`next()`, `hasNext()`) | Bidirectional (`next()`, `previous()`, `hasPrevious()`) |
| **Mutation Capabilities** | Can only remove elements (`remove()`) | Can remove, update (`set()`), and insert (`add()`) |
| **Index Querying** | No index awareness | `nextIndex()`, `previousIndex()` |

### Safe Element Removal during Traversal

```java
List<String> logs = new ArrayList<>(List.of("INFO: ok", "ERROR: 500", "DEBUG: step"));

// ❌ CRITICAL BUG: Calling collection.remove() inside an enhanced for-loop!
for (String log : logs) {
    if (log.startsWith("DEBUG")) {
        logs.remove(log); // 💥 THROWS ConcurrentModificationException!
    }
}

// ✅ SAFE APPROACH 1 (Classic Iterator):
Iterator<String> it = logs.iterator();
while (it.hasNext()) {
    if (it.next().startsWith("DEBUG")) {
        it.remove(); // Safely updates internal modCount pointers!
    }
}

// ✅ SAFE APPROACH 2 (Modern Java 8+ Functional Predicate):
logs.removeIf(log -> log.startsWith("DEBUG"));
```

## 🔴 Senior Level

### Fail-Fast vs. Fail-Safe / Weakly-Consistent Iterators

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │                 Fail-Fast Iterators                    │              Fail-Safe / Weakly Consistent             │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ • Used by: `ArrayList`, `HashMap`, `HashSet`           │ • Used by: `CopyOnWriteArrayList`, `ConcurrentHashMap`  │
  │ • Tracks internal `modCount` state variable            │ • Iterates over an immutable snapshot or lock-free bin │
  │ • Throws `ConcurrentModificationException` immediately │ • NEVER throws `ConcurrentModificationException`       │
  │ • Fast, zero extra memory allocation                   │ • Iterates over snapshot (does not see concurrent adds)│
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

#### How Fail-Fast Works Under the Hood
Standard collections increment a private field `modCount` whenever structural modifications occur (`add`, `remove`, `clear`). When an `Iterator` is spawned, it captures `expectedModCount = modCount`. On every `next()` call, it asserts:

$$\text{if } (\text{modCount} \neq \text{expectedModCount}) \implies \mathbf{throw\ new\ ConcurrentModificationException}()$$

### Custom Binary Search Tree Iterator Implementation

```java
public class BinarySearchTree<T> implements Iterable<T> {
    private Node<T> root;

    private static class Node<T> {
        T value;
        Node<T> left, right;
        Node(T val) { this.value = val; }
    }

    @Override
    public Iterator<T> iterator() {
        return new InOrderBstIterator(root);
    }

    // In-Order Traversal (Left -> Node -> Right) using an explicit Stack:
    private class InOrderBstIterator implements Iterator<T> {
        private final Deque<Node<T>> stack = new ArrayDeque<>();

        public InOrderBstIterator(Node<T> root) {
            pushLeftSubtree(root);
        }

        private void pushLeftSubtree(Node<T> node) {
            while (node != null) {
                stack.push(node);
                node = node.left;
            }
        }

        @Override
        public boolean hasNext() {
            return !stack.isEmpty();
        }

        @Override
        public T next() {
            if (!hasNext()) throw new NoSuchElementException();
            Node<T> current = stack.pop();
            pushLeftSubtree(current.right);
            return current.value;
        }
    }
}
```

### Modern Java Evolution: `Spliterator<T>` (Java 8+)

The Java Stream API replaced traditional single-threaded `Iterator` instances with **`Spliterator` (Splitable Iterator)**:
- Supports parallel decomposition for `ForkJoinPool` (`trySplit()`).
- Informs the engine of performance characteristics (`IMMUTABLE`, `SORTED`, `SIZED`, `CONCURRENT`).

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Core Intent:** Encapsulates the traversal algorithm away from collection storage mechanics.
- **Fail-Fast:** Throws `ConcurrentModificationException` if the collection is structurally modified during iteration (detected via `modCount != expectedModCount`).
- **Fail-Safe:** Iterates over a memory snapshot (`CopyOnWriteArrayList`) or traverses lock-free nodes without throwing exceptions.
- **Safe Removal:** Use `iterator.remove()` or `collection.removeIf(predicate)`.
- **Modern Evolution:** `Spliterator<T>` powers the Java Stream API, enabling parallel stream partitioning.

**Common Follow-up Questions:**
- *"Why does an enhanced for-loop throw `ConcurrentModificationException` when calling `list.remove()`?"* → The enhanced for-loop generates an Iterator under the hood, but `list.remove()` modifies `modCount` directly without updating the iterator's `expectedModCount`.
- *"What is the difference between `Iterator` and `Iterable` in Java?"* → `Iterable<T>` is an interface representing any data structure that can produce an iterator (`iterator()`); `Iterator<T>` is the cursor object that actually performs the traversal (`next()`, `hasNext()`).
- *"What is a Weakly Consistent iterator in ConcurrentHashMap?"* → It can tolerate concurrent modifications without throwing exceptions and guarantees to traverse elements as they existed at iterator construction, possibly reflecting subsequent updates.

**Red Flags (DO NOT Say):**
- ❌ *"You can safely delete elements inside a `for (String s : list)` loop by calling `list.remove(s)`."* (Triggers guaranteed `ConcurrentModificationException`).
- ❌ *"Fail-Safe iterators always reflect all elements added by other threads in real time."* (They iterate over an immutable snapshot created at the moment the iterator was spawned).
- ❌ *"Iterator is obsolete because we have Java Streams."* (Streams, for-each loops, and collection pipelines rely on `Spliterator` and `Iterator` under the hood).
