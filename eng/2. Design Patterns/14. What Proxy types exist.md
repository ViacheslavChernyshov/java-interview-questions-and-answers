# What Proxy types exist?

---

## 🟢 Junior Level

A **Proxy** is a Structural design pattern that provides a surrogate, placeholder, or wrapper for another object to **control, guard, or intercept access to it**.

**Simple analogy:** An executive assistant (secretary). Callers do not speak directly with the CEO; the secretary screens incoming calls, logs meeting requests, and enforces access control before delegating to the CEO.

```
       Client ──────> [ Proxy Wrapper ] ──────> [ Real Target Service ]
                        • Access Checks          • Core Business Logic
                        • Lazy Loading
                        • Transactions
```

**Minimal Lazy Loading Proxy (Virtual Proxy):**
```java
public interface Document {
    void display();
}

public class RealDocument implements Document {
    private final String filename;
    public RealDocument(String filename) {
        this.filename = filename;
        loadHeavyFileFromDisk(); // Expensive 2-second I/O
    }
    private void loadHeavyFileFromDisk() { System.out.println("Loaded " + filename); }
    public void display() { System.out.println("Displaying " + filename); }
}

public class ProxyDocument implements Document {
    private final String filename;
    private RealDocument realDocument; // Lazily allocated

    public ProxyDocument(String filename) {
        this.filename = filename;
    }

    public void display() {
        if (realDocument == null) {
            realDocument = new RealDocument(filename); // Allocated on first demand!
        }
        realDocument.display();
    }
}
```

## 🟡 Middle Level

### Functional Classification of Proxies

1. **Virtual Proxy (Lazy Loading):** Defers heavy object allocation until the first method call (e.g. Hibernate Lazy Entity Proxies for `@ManyToOne(fetch = FetchType.LAZY)`).
2. **Protection Proxy (Security & Auth):** Validates permissions before invoking the real object (e.g. Spring Security `@PreAuthorize("hasRole('ADMIN')")`).
3. **Remote Proxy (RPC / Stubs):** Marshals network packets and abstracts remote calls as local methods (e.g. Spring Cloud OpenFeign, gRPC Stubs).
4. **Caching Proxy (Memoization):** Intercepts method calls to return cached results, bypassing execution (e.g. Spring `@Cacheable`).
5. **Synchronization / Logging Proxy:** Intercepts calls for thread safety locks or audit telemetry.

### JDK Dynamic Proxy vs. CGLIB / ByteBuddy

```
┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
│               JDK Dynamic Proxy                        │                  CGLIB / ByteBuddy                     │
├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
│ • Native to JDK (`java.lang.reflect.Proxy`)           │ • Third-party bytecode manipulation library            │
│ • REQUIRES the target class to implement an Interface  │ • Generates a SUBCLASS of the target concrete class    │
│ • Uses `InvocationHandler.invoke()`                    │ • Uses `MethodInterceptor` interceptors                │
│ • Cannot proxy classes without interfaces              │ • CANNOT proxy `final` classes or `final` methods      │
└────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

#### Spring Boot Proxy Defaults
- **Classic Spring Framework:** Used JDK Dynamic Proxies if the bean implemented an interface; used CGLIB if it was a raw class.
- **Spring Boot 2.x & 3.x:** Sets `spring.aop.proxy-target-class=true` by default, standardizing on **CGLIB / ByteBuddy** subclass proxies across all beans to avoid type-casting errors.

## 🔴 Senior Level

### The Notorious Self-Invocation Anti-Pattern in Spring AOP

Because Spring AOP operates strictly via dynamic proxies, **calling an annotated method from within the same class (`this.method()`) bypasses the proxy entirely**:

```java
@Service
public class OrderService {

    // ❌ TRANSACTION NOT STARTED: The proxy is bypassed on self-invocation!
    public void processBatch(List<Order> orders) {
        for (Order order : orders) {
            this.saveOrder(order); // Direct internal call bypasses Spring Proxy!
        }
    }

    @Transactional // Ignored when called via this.saveOrder()!
    public void saveOrder(Order order) {
        orderRepository.save(order);
    }
}
```

#### 3 Production Remediation Strategies:

```java
// Strategy 1: Refactor to a separate collaborator bean (Best Practice)
@Service
public class OrderService {
    private final OrderWriter orderWriter;
    public OrderService(OrderWriter orderWriter) { this.orderWriter = orderWriter; }

    public void processBatch(List<Order> orders) {
        for (Order order : orders) {
            orderWriter.saveOrder(order); // Cleanly routes through OrderWriter's Proxy!
        }
    }
}

// Strategy 2: Self-Injection via @Autowired / ObjectProvider
@Service
public class OrderService {
    @Autowired private OrderService self; // Injects the Spring Proxy of itself

    public void processBatch(List<Order> orders) {
        for (Order order : orders) {
            self.saveOrder(order); // Routes through Proxy!
        }
    }
}

// Strategy 3: AopContext (Requires exposeProxy = true)
((OrderService) AopContext.currentProxy()).saveOrder(order);
```

### Why `@Transactional` Cannot Intercept `private` Methods

Spring AOP proxies wrap public API boundaries:
- **CGLIB Subclassing:** A generated subclass cannot override `private` methods.
- **JDK Dynamic Proxy:** Interfaces cannot declare `private` methods.
Therefore, adding `@Transactional`, `@Async`, or `@Cacheable` to a `private` method is **silently ignored by the Spring proxy runtime**.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Core Intent:** A structural surrogate controlling access, lazy instantiation, security, or cross-cutting concerns for another object.
- **JDK Dynamic Proxy:** Requires interfaces; uses `InvocationHandler` and reflection.
- **CGLIB / ByteBuddy:** Subclasses target classes; cannot proxy `final` classes or `final` methods; default in Spring Boot 2.x/3.x.
- **Self-Invocation Trap:** Calling `this.annotatedMethod()` bypasses the proxy, disabling `@Transactional`, `@Async`, and `@Cacheable`.
- **Private Methods:** Spring AOP proxies cannot intercept `private` methods.
- **Core Proxy Types:** Virtual (Lazy), Protection (Security), Remote (RPC/Feign), Caching (`@Cacheable`).

**Common Follow-up Questions:**
- *"Why does `@Transactional` fail silently when calling a method internally within the same class?"* → Because `this.method()` calls the target object instance directly in memory rather than calling the outer Spring AOP proxy wrapper.
- *"What happens if you mark a service class as `final` in Spring Boot?"* → CGLIB proxy generation will fail at startup with an `IllegalArgumentException: Cannot subclass final class`.
- *"How does Hibernate implement lazy loading for `@OneToMany` collections?"* → It initializes entity collections with its internal `PersistentBag` / `PersistentSet` Virtual Proxy, which queries the database on first access.

**Red Flags (DO NOT Say):**
- ❌ *"Adding `@Transactional` to a `private` method works fine in Spring."* (Proxies cannot override or intercept private methods).
- ❌ *"Calling `this.method()` executes all Spring aspect annotations."* (Direct self-invocations completely bypass the proxy).
- ❌ *"CGLIB can proxy `final` classes by using reflection."* (CGLIB requires subclass inheritance; `final` classes cannot be extended).
