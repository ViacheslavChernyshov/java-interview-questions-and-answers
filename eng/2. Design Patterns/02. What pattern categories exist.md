# What pattern categories exist?

---

## 🟢 Junior Level

Software design patterns are divided into **three primary Gang of Four (GoF) categories** based on the specific design problem they solve:

```
                                  ┌───────────────────────────┐
                                  │   GoF Design Patterns     │
                                  └─────────────┬─────────────┘
                                                │
                 ┌──────────────────────────────┼──────────────────────────────┐
                 ▼                              ▼                              ▼
     ┌───────────────────────┐      ┌───────────────────────┐      ┌───────────────────────┐
     │      Creational       │      │      Structural       │      │      Behavioral       │
     ├───────────────────────┤      ├───────────────────────┤      ├───────────────────────┤
     │ • Singleton           │      │ • Adapter             │      │ • Strategy            │
     │ • Factory Method      │      │ • Decorator           │      │ • Observer            │
     │ • Abstract Factory    │      │ • Proxy               │      │ • State               │
     │ • Builder             │      │ • Facade              │      │ • Command             │
     │ • Prototype           │      │ • Composite           │      │ • Iterator            │
     └───────────────────────┘      └───────────────────────┘      └───────────────────────┘
```

1. **Creational Patterns (Object Instantiation):**
   - **Goal:** Hide *how* and *when* objects are instantiated. Decouples code from hardcoded `new` constructors.
   - **Examples:** `Singleton`, `Builder`, `Factory Method`.
2. **Structural Patterns (Object Composition):**
   - **Goal:** Assemble classes and objects into larger, flexible structures without class explosion.
   - **Examples:** `Adapter`, `Decorator`, `Proxy`.
3. **Behavioral Patterns (Algorithm Delegation & Flow):**
   - **Goal:** Organize communication, responsibility assignment, and runtime control flow between objects.
   - **Examples:** `Strategy`, `Observer`, `State`.

**Simple analogy (Constructing a Car):**
- **Creational:** The engine foundry and chassis manufacturing robots (`Factory`, `Builder`).
- **Structural:** The wiring harness, OBD-II adapter, and transmission gearbox (`Adapter`, `Decorator`).
- **Behavioral:** Cruise control algorithms and driver dashboard telemetry alerts (`Strategy`, `Observer`).

## 🟡 Middle Level

### Category Breakdown & Modern Java Implementations

#### 1. Creational Patterns in Practice
- **Intent:** Enforce Dependency Inversion (DIP) by eliminating direct constructor coupling in business services.
```java
// Classic Creational: Static Factory Method (JDK 9+)
List<String> immutableList = List.of("USD", "EUR", "GBP"); // Factory method
Optional<String> token = Optional.ofNullable(jwtToken);
```

#### 2. Structural Patterns in Practice
- **Intent:** Extend object capabilities dynamically via composition over rigid inheritance.
```java
// Classic Structural: Decorator in Java I/O
InputStream stream = new BufferedInputStream(new GZIPInputStream(new FileInputStream("data.gz")));

// Modern Structural: Spring AOP Interceptors (Dynamic Proxy)
@Transactional // Injects a Proxy wrapper controlling JDBC commit/rollback
public void transferMoney(Account from, Account to, BigDecimal amount) { ... }
```

#### 3. Behavioral Patterns in Practice
- **Intent:** Replace monolithic procedural `switch`/`if-else` branching with polymorphic dispatching.
```java
// Classic Behavioral: Strategy via Java 8 Lambdas
List<Order> orders = getOrders();
orders.sort(Comparator.comparing(Order::createdAt).reversed()); // Strategy passed inline
```

## 🔴 Senior Level

### Modern Extended Taxonomy: Concurrency & Cloud-Native

Beyond the 23 classical GoF desktop patterns, modern enterprise engineering relies on two specialized categories:

#### 1. Concurrency Patterns
- **Producer-Consumer:** `BlockingQueue<Task>` with thread pool workers.
- **Read-Write Lock:** `ReentrantReadWriteLock` for high-read / low-write concurrent caches.
- **Thread-Local Storage:** `ThreadLocal<SecurityContext>` (and modern Java 21 `ScopedValue`).

#### 2. Cloud-Native Distributed Patterns
- **Circuit Breaker:** Prevents cascading network failures when downstream microservices degrade (e.g. Resilience4j).
- **Saga Pattern:** Manages distributed transactions across microservices via orchestrated or choreographed compensating steps.
- **Transactional Outbox:** Guarantees atomic database writes and Kafka message publication without distributed two-phase commits (2PC).

### Category Interplay in Enterprise Frameworks (Spring Architecture)

In sophisticated architectures, patterns from all three categories work in tight harmony:

```
   ┌───────────────────────────┐
   │ Spring ApplicationContext │ ──> [Creational: Abstract Factory & Singleton Scope]
   └─────────────┬─────────────┘
                 │ Instantiates and wraps beans
                 ▼
   ┌───────────────────────────┐
   │   CGLIB / JDK Proxy       │ ──> [Structural: Proxy & Decorator]
   └─────────────┬─────────────┘
                 │ Intercepts method invocations
                 ▼
   ┌───────────────────────────┐
   │ Strategy / TemplateMethod │ ──> [Behavioral: Routing to Algorithm Impls]
   └───────────────────────────┘
```

### Architectural Anti-Patterns by Category

| Category | Typical Code Smell Indicating Missing Pattern | Correct Architectural Remediation |
|---|---|---|
| **Creational** | Direct `new` instantiations scattered throughout domain business logic | Refactor to **Factory Method** or **Spring DI Injection** |
| **Structural** | Massive subclass inheritance trees (`class EncryptedBufferedSocket`) | Refactor to **Decorator** or **Bridge** composition |
| **Behavioral** | 300-line `switch(eventType)` procedural dispatcher methods | Refactor to **Strategy Registry** with `Map<Enum, Handler>` |

## 🎯 Interview Cheat Sheet

**Must Know:**
- **3 Core Categories:**
  - **Creational (5 patterns):** Singleton, Factory Method, Abstract Factory, Builder, Prototype.
  - **Structural (7 patterns):** Adapter, Bridge, Composite, Decorator, Facade, Flyweight, Proxy.
  - **Behavioral (11 patterns):** Strategy, Observer, Command, State, Template Method, Iterator, Chain of Responsibility, Mediator, Memento, Visitor, Interpreter.
- **Modern Replacements:** Static factory methods (`List.of()`), Lambdas as Strategies (`Comparator`, `Function`), Spring AOP Proxies (`@Transactional`).
- **Distributed Extensions:** Saga (distributed transactions), Circuit Breaker (fault tolerance), Outbox (reliable event publishing).

**Common Follow-up Questions:**
- *"What is the main difference between Decorator and Proxy?"* → Decorator adds new responsibilities/behavior dynamically; Proxy controls, guards, or intercepts access to an object without changing its functional contract.
- *"Why is Spring's ApplicationContext considered a Creational pattern?"* → It acts as a configurable IoC Container and Abstract Factory, controlling the complete instantiation lifecycle and singleton scoping of application beans.
- *"How do you eliminate deep if-else switch statements in payment processing?"* → Use a Behavioral Strategy pattern backed by a Strategy Map (`Map<PaymentType, PaymentStrategy>`).

**Red Flags (DO NOT Say):**
- ❌ *"Creational patterns are obsolete because of the `new` keyword."* (Direct `new` tightly couples business code to concrete classes, destroying testability).
- ❌ *"Structural patterns are only useful in UI/desktop development."* (Spring is built entirely on Structural Proxies, Adapters, and Facades).
- ❌ *"Design patterns dictate every line of code you write."* (They are high-level blueprints to be adapted based on performance and simplicity trade-offs).
