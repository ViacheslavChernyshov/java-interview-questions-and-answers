# When to use Strategy?

---

## 🟢 Junior Level

The **Strategy pattern** is a Behavioral design pattern that defines a family of algorithms, encapsulates each one into a separate class, and makes their execution interchangeable at runtime.

**Why it is needed:** To avoid giant, monolithic `if-else` or `switch` statements when different execution strategies are needed for the same operation.

**Simple analogy:** GPS Navigation. The goal is identical (route from point A to point B), but the navigation strategy differs based on transport mode: Walking, Driving, or Public Transit.

```java
// Strategy Interface
public interface PaymentStrategy {
    void pay(BigDecimal amount);
}

// Concrete Strategies
public class CreditCardPayment implements PaymentStrategy {
    public void pay(BigDecimal amount) {
        System.out.println("Paid $" + amount + " using Credit Card");
    }
}

public class CryptoPayment implements PaymentStrategy {
    public void pay(BigDecimal amount) {
        System.out.println("Paid $" + amount + " using Bitcoin");
    }
}

// Client Context
public class CheckoutService {
    public void processOrder(BigDecimal amount, PaymentStrategy strategy) {
        strategy.pay(amount); // Swapped dynamically at runtime!
    }
}
```

## 🟡 Middle Level

### Eliminating the Sprawling `switch` Statement

```java
// ❌ ANTI-PATTERN: Modifies existing code every time a new payment vendor is added!
public void processPayment(PaymentType type, BigDecimal amount) {
    switch (type) {
        case STRIPE -> processStripe(amount);
        case PAYPAL -> processPayPal(amount);
        case KLARNA -> processKlarna(amount);
        // Every new vendor violates the Open/Closed Principle!
    }
}
```

### Spring Auto-Registry Strategy Pattern

In enterprise Spring Boot applications, the Strategy pattern is implemented via **automatic dependency injection into a Map**:

```java
public interface NotificationStrategy {
    String getChannelType();
    void sendNotification(String recipient, String message);
}

@Component
public class EmailNotificationStrategy implements NotificationStrategy {
    public String getChannelType() { return "EMAIL"; }
    public void sendNotification(String recipient, String message) { /* SMTP logic */ }
}

@Component
public class SmsNotificationStrategy implements NotificationStrategy {
    public String getChannelType() { return "SMS"; }
    public void sendNotification(String recipient, String message) { /* Twilio logic */ }
}

// Auto-wired Registry Service
@Service
public class NotificationDispatcher {
    private final Map<String, NotificationStrategy> strategyMap;

    // Spring automatically discovers and injects ALL matching @Component beans!
    public NotificationDispatcher(List<NotificationStrategy> strategies) {
        this.strategyMap = strategies.stream()
            .collect(Collectors.toMap(NotificationStrategy::getChannelType, Function.identity()));
    }

    public void dispatch(String channel, String to, String msg) {
        NotificationStrategy strategy = strategyMap.get(channel);
        if (strategy == null) {
            throw new IllegalArgumentException("Unsupported channel: " + channel);
        }
        strategy.sendNotification(to, msg);
    }
}
// Adding a new channel (e.g. PUSH) requires ONLY creating a new @Component class!
```

## 🔴 Senior Level

### Modern Java Simplifications: Lambdas & Enum Strategies

For simple algorithms, full class declarations are unnecessary boilerplate:

```java
// 1. Functional Interfaces as Lightweight Strategies:
Map<String, UnaryOperator<BigDecimal>> discountRules = Map.of(
    "BLACK_FRIDAY", price -> price.multiply(BigDecimal.valueOf(0.70)),
    "CYBER_MONDAY", price -> price.multiply(BigDecimal.valueOf(0.80)),
    "REGULAR", price -> price
);

// 2. Closed-Set Enum Strategy (High Performance):
public enum ShippingCalculator {
    STANDARD {
        public BigDecimal calculate(double weightKg) { return BigDecimal.valueOf(weightKg * 1.5); }
    },
    EXPRESS {
        public BigDecimal calculate(double weightKg) { return BigDecimal.valueOf(weightKg * 4.0); }
    };

    public abstract BigDecimal calculate(double weightKg);
}
```

### The Context Object Pattern

When strategy implementations require varying input data, avoid method signature bloat by passing a consolidated **Java Record Context**:

```java
// Encapsulates all domain parameters cleanly:
public record PricingContext(
    Product product,
    Customer customer,
    PromoCode promo,
    Locale userLocale
) {}

public interface PricingStrategy {
    BigDecimal calculatePrice(PricingContext context);
}
```

### JIT Compilation & Polymorphic Call Sites

```
  Call Site Polymorphism in HotSpot JIT:
  ┌───────────────────┐ ──> Monomorphic (1 class)  ──> JIT Inlined (0ns overhead)
  │ Strategy.execute()│ ──> Bimorphic   (2 classes)──> Inlined with branch test
  └───────────────────┘ ──> Megamorphic (>2 classes)──> vtable Virtual Call (~2-5ns overhead)
```

In ultra-low-latency hot-paths (e.g., millions of transactions per second), if there are more than 2 strategy implementations active at a call site, the JIT disables direct method inlining. In such cases, an **`enum` with modern pattern-matching `switch`** compiles to a hardware `tableswitch` instruction, eliminating virtual table lookups.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Core Intent:** Encapsulates interchangeable algorithms behind an interface, enabling runtime algorithm switching and enforcing the Open/Closed Principle.
- **Spring Pattern:** Inject `List<Strategy>` into the constructor to automatically populate a `Map<Type, Strategy>`.
- **Modern Java:** Use lambdas (`Function<T, R>`), method references, or `enum` strategy definitions to reduce boilerplate.
- **Context Object:** Pass a Java Record `Context` into strategy methods to prevent signature breakage when new parameters are added.
- **Performance Trade-Off:** Monomorphic/bimorphic strategies are inlined by the JIT; megamorphic strategies (>2 active implementations) introduce minor virtual dispatch overhead.

**Common Follow-up Questions:**
- *"What is the difference between Strategy and State?"* → Strategy is injected externally by client code to choose how an algorithm runs; State is transitioned internally by the object itself based on state lifecycle changes.
- *"What is the difference between Strategy and Template Method?"* → Strategy uses object composition to swap the entire algorithm; Template Method uses inheritance to override specific steps of an algorithm.
- *"How do you test classes that rely on the Strategy pattern?"* → Pass an inline lambda or a mock strategy into the constructor/method, isolating the client from complex algorithm dependencies.

**Red Flags (DO NOT Say):**
- ❌ *"I use the Strategy pattern for simple 2-branch boolean if-else statements."* (Indicates overengineering; a standard ternary or `if-else` is clearer).
- ❌ *"Strategy requires creating 10 separate class files for 10 simple calculations."* (In modern Java, a `Map<Enum, Function>` or Enum Strategy achieves this in a few lines).
- ❌ *"Spring cannot automatically resolve multiple implementations of the same interface."* (Spring natively injects collections or maps of all matching beans).
