# What is Distributed Tracing?

---

## 🟢 Junior Level

**Distributed Tracing** is an observability technique used to profile, visualize, and monitor the end-to-end execution journey of a single user request as it travels through multiple microservices, message queues, and databases:

```
  Courier Package Tracking Analogy:
  • When you order a package online, you receive a single **Tracking Number (Trace ID)**.
  • As the package travels from Warehouse ➔ Airport ➔ Regional Hub ➔ Delivery Van, each checkpoint 
    scans the package and records a timestamped leg of the journey (**Span**). 
  • If the package is delayed, you can immediately see which specific transit hub held it for 3 days!
```

```
  USER REQUEST: `POST /api/v1/checkout`
  Trace ID: `4bf92f3577b34da6a3ce929d0e0e4736`
  │
  ├── [Span 1] API Gateway: 15ms
  │   │
  │   └── [Span 2] Order Service: 140ms
  │       │
  │       ├── [Span 3] Payment Service (HTTP POST): 95ms
  │       │   └── [Span 4] Stripe External API: 85ms (⏱️ BOTTLENECK IDENTIFIED!)
  │       │
  │       └── [Span 5] Kafka Publish ("order-placed"): 5ms
```

## 🟡 Middle Level

### Core Tracing Primitives & The W3C Trace Context Standard

```
  ┌──────────────────────────────┬─────────────────────────────────────────────────────────────────────────────────┐
  │ Tracing Primitive            │ Technical Definition                                                            │
  ├──────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ **Trace**                    │ The complete end-to-end directed acyclic graph (DAG) of a distributed request.  │
  │ **Trace ID**                 │ Globally unique 128-bit hex string identifying the overall transaction.         │
  │ **Span**                     │ A single timed unit of work executed by one service (e.g. 1 HTTP call, 1 SQL query).│
  │ **Span ID**                  │ Unique 64-bit hex string identifying the individual work segment.               │
  │ **Parent Span ID**           │ Pointer linking child spans back to the calling parent span.                    │
  └──────────────────────────────┴─────────────────────────────────────────────────────────────────────────────────┘
```

### Context Propagation over HTTP & Kafka

To maintain trace continuity across network boundaries, services inject and extract trace headers:

```
  W3C TraceContext Standard Header (`traceparent`):
  traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01
               │  └─────────────┬────────────────┘ └───────┬──────┘ └─┬┘
            Version         Trace ID (32 hex)     Parent Span ID   Flags (01 = Sampled)
```

## 🔴 Senior Level

### Modern Spring Boot 3 Instrumentation: Micrometer Tracing & OpenTelemetry

> [!WARNING]
> **Spring Cloud Sleuth is DEPRECATED in Spring Boot 3.x!** 
> Modern enterprise Spring Boot 3 applications use **Micrometer Tracing** with the **OpenTelemetry (OTel)** bridge.

```xml
<!-- pom.xml: Spring Boot 3 Micrometer Tracing with OpenTelemetry exporter -->
<dependency>
    <groupId>io.micrometer</groupId>
    <artifactId>micrometer-tracing-bridge-otel</artifactId>
</dependency>
<dependency>
    <groupId>io.opentelemetry</groupId>
    <artifactId>opentelemetry-exporter-otlp</artifactId>
</dependency>
```

```java
// Automatic Context Propagation with Spring 6 RestClient:
@Service
@RequiredArgsConstructor
public class OrderService {

    private final RestClient restClient; // Injects W3C `traceparent` headers automatically!
    private final Tracer tracer;         // Micrometer / OTel Tracer

    public OrderConfirmationDTO processOrder(OrderRequestDTO request) {
        // Create custom business span:
        Span customSpan = tracer.nextSpan().name("calculateOrderDiscount").start();
        try (Tracer.SpanInScope ws = tracer.withSpan(customSpan.start())) {
            customSpan.tag("customer.tier", "VIP");
            applyDiscounts(request);
            
            // Outgoing HTTP call automatically propagates the active Trace ID:
            return restClient.post()
                .uri("http://payment-service/api/v1/charge")
                .body(request)
                .retrieve()
                .body(OrderConfirmationDTO.class);
        } finally {
            customSpan.end();
        }
    }
}
```

### High-Scale Tracing: Head vs. Tail Sampling

At 100,000 requests per second, capturing 100% of traces creates gigabytes of network and storage overhead:

```
  ┌──────────────────────────────┬──────────────────────────────────┬──────────────────────────────────────────────────┐
  │ Sampling Strategy            │ Mechanism                        │ Trade-offs                                       │
  ├──────────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **Head-Based Sampling**      │ API Gateway randomly samples $N$%│ 🟢 Low CPU/memory overhead.                      │
  │                              │ of requests at the ingress point.│ 🔴 May miss critical 1-in-a-million error traces.│
  ├──────────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **Tail-Based Sampling**      │ **OpenTelemetry Collector** keeps│ 🏆 **Gold Standard**: Captures **100% of all     │
  │                              │ spans in RAM until trace ends,   │ errors and slow requests (p99)** while sampling  │
  │                              │ sampling based on the outcome.   │ only 1% of normal fast 200 OK traces!            │
  └──────────────────────────────┴──────────────────────────────────┴──────────────────────────────────────────────────┘
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Tracking single user transactions across distributed service and messaging boundaries.
- **Key Terms:** **Trace** (entire journey), **Trace ID** (unique transaction ID), **Span** (single timed step), **Span ID**.
- **Header Standard:** **W3C TraceContext** (`traceparent: 00-traceid-spanid-01`).
- **Spring Boot 3 Standard:** **Micrometer Tracing** + **OpenTelemetry (OTel)** (Spring Cloud Sleuth is deprecated).
- **Sampling:** Use **Tail-Based Sampling** in OpenTelemetry Collector to capture 100% of failures without disk bloat.

**Common Follow-up Questions:**
- *"How does Distributed Tracing propagate across asynchronous Kafka messages?"* → The Kafka Producer intercepts `ProducerRecord` and injects the `traceparent` string into the Kafka record headers; the `@KafkaListener` consumer extracts the headers to continue the trace span.
- *"What is Mapped Diagnostic Context (MDC) in Logging?"* → Micrometer Tracing automatically injects the active `traceId` and `spanId` into SLF4J's `MDC` ThreadLocal, allowing structured JSON logs (Logback/Loki) to print `[traceId=4bf92f..., spanId=00f067...]` on every log line!
- *"What popular open-source backends visualize traces?"* → **Jaeger**, **Zipkin**, and **Grafana Tempo**.

**Red Flags (DO NOT Say):**
- ❌ *"Spring Cloud Sleuth is the recommended tracing library for Spring Boot 3."* (Sleuth is dead in Spring Boot 3; use Micrometer Tracing).
- ❌ *"Tracing always records 100% of all production traffic without sampling."* (At high scale, 100% sampling causes storage exhaustion and high network overhead).
- ❌ *"Trace IDs are generated by the database."* (Trace IDs are generated by the ingress API Gateway or client SDK).
