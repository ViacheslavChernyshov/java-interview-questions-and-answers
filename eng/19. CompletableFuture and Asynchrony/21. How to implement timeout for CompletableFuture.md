# How to Implement Timeout for CompletableFuture?

---

## 🟢 Junior Level

Starting in **Java 9+**, `CompletableFuture` provides two built-in asynchronous timeout methods:

```
  ┌─────────────────────────────────────────────────────────┬─────────────────────────────────────────────────────────┐
  │ ⏱️ `orTimeout(long timeout, TimeUnit unit)`             │ 🛡️ `completeOnTimeout(T value, long timeout, Unit unit)`│
  ├─────────────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ • Completes the future **exceptionally** with a         │ • Completes the future **successfully** with a default  │
  │   **`TimeoutException`** if time expires.               │   **fallback value** if time expires.                   │
  │ • Used for strict SLA enforcement and fail-fast errors. │ • Used for graceful degradation and default responses.  │
  └─────────────────────────────────────────────────────────┴─────────────────────────────────────────────────────────┘
```

```java
// 1. orTimeout() — Fails fast with TimeoutException after 2 seconds:
CompletableFuture<String> strictFuture = CompletableFuture.supplyAsync(() -> slowRemoteCall())
    .orTimeout(2, TimeUnit.SECONDS)
    .exceptionally(ex -> "Timeout Fallback: " + ex.getMessage());

// 2. completeOnTimeout() — Returns default value if not finished in 500ms:
CompletableFuture<String> resilientFuture = CompletableFuture.supplyAsync(() -> slowRemoteCall())
    .completeOnTimeout("GUEST_PROFILE", 500, TimeUnit.MILLISECONDS);
```

## 🟡 Middle Level

### The Java 8 Legacy Timeout Implementation Pattern

Because Java 8 lacked `.orTimeout()`, senior engineers implement timeout decorators using a shared `ScheduledExecutorService`:

```java
public final class AsyncTimeoutUtils {

    // Shared singleton daemon scheduler (Prevents leaking threads):
    private static final ScheduledExecutorService SCHEDULER = 
        Executors.newScheduledThreadPool(1, r -> {
            Thread t = new Thread(r, "cf-timeout-scheduler");
            t.setDaemon(true); // Daemon thread will not block JVM shutdown
            return t;
        });

    public static <T> CompletableFuture<T> withTimeout(
            CompletableFuture<T> target, long timeout, TimeUnit unit) {
        
        // Schedule timeout trigger:
        ScheduledFuture<?> timeoutTask = SCHEDULER.schedule(() -> {
            target.completeExceptionally(new TimeoutException("Operation timed out after " + timeout + " " + unit));
        }, timeout, unit);

        // Cancel the scheduled timer if the target future completes early:
        target.whenComplete((result, ex) -> timeoutTask.cancel(false));

        return target;
    }
}
```

## 🔴 Senior Level

### Internal Architecture: `CompletableFuture.Delayer`

Java 9+ implements timeouts natively inside the JVM using an internal static class **`CompletableFuture$Delayer`**:
1. Uses a shared singleton daemon `ScheduledThreadPoolExecutor`.
2. When `orTimeout()` is invoked, a lightweight `Timeout` task is submitted to the scheduler.
3. If the primary future completes before the deadline, `Delayer` automatically cancels the timer task to prevent memory and scheduler queue bloat.

### The Background Worker Still Runs Hazard

> [!WARNING]
> Triggering a timeout via `orTimeout()` **DOES NOT interrupt the worker thread** executing the background task!
> The future is completed with `TimeoutException`, but the worker thread will continue processing the slow HTTP call or heavy calculation until it finishes.

```
  [Worker Thread]:   Running slow DB query (Takes 10s)......... STILL EXECUTING!
  [Scheduler]:       2s Timer Expires ➔ Marks CompletableFuture as TimeoutException!
  [Caller Thread]:   Receives TimeoutException at 2s.
```

#### Senior Solution: Cooperative Interruption or Java 21 Structured Concurrency

For heavy CPU calculations, poll `Thread.currentThread().isInterrupted()` or use **Java 21 `StructuredTaskScope`** with deadline timeouts to guarantee immediate thread termination upon timeout.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Java 9+ Methods:** `orTimeout()` (throws `TimeoutException`) and `completeOnTimeout()` (returns fallback value).
- **Return Type:** Both methods modify the future in-place and return `this`.
- **Java 8 Workaround:** Use a shared `ScheduledExecutorService` with a daemon thread and cancel the timer via `whenComplete()`.
- **Thread Hazard:** Timeouts complete the future early, but do **NOT** kill or interrupt the underlying worker thread.

**Common Follow-up Questions:**
- *"What is the difference between `orTimeout` and `completeOnTimeout`?"* → `orTimeout` fails the pipeline with `TimeoutException` (requires `.exceptionally()` to catch); `completeOnTimeout` provides a non-exceptional fallback value that continues down normal `thenApply` stages.
- *"How do you handle timeouts in `allOf()`?"* → Call `.orTimeout()` on the composite `allOf` future: `CompletableFuture.allOf(f1, f2).orTimeout(5, TimeUnit.SECONDS)`.
- *"Why should you never instantiate a `new ScheduledThreadPoolExecutor` inside each method call?"* → Creating a new executor per request creates native OS threads and leaks memory; always use a shared singleton scheduler.

**Red Flags (DO NOT Say):**
- ❌ *"orTimeout() immediately kills the background OS thread."* (It only changes the state of the future; the background task continues executing).
- ❌ *"In Java 8, use `Thread.sleep()` in a background thread to implement timeouts."* (Freezes worker threads; use `ScheduledExecutorService`).
- ❌ *"completeOnTimeout throws a TimeoutException."* (It completes successfully with the fallback value; it never throws an exception).
