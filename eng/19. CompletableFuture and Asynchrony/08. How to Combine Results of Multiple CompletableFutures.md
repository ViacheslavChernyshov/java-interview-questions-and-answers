# How to Combine Results of Multiple CompletableFutures?

---

## 🟢 Junior Level

Java provides **4 primary mechanisms** to coordinate and combine multiple `CompletableFuture` instances depending on whether the tasks are independent, parallel, or sequential:

```
  ┌──────────────────────────────┬──────────────┬────────────────────────┬─────────────────────────────────────────────┐
  │ Method                       │ Count        │ Execution Mode         │ Result / Return Type                        │
  ├──────────────────────────────┼──────────────┼────────────────────────┼─────────────────────────────────────────────┤
  │ **`thenCombine()`**          │ Exactly 2    │ **Parallel**           │ Returns `CompletableFuture<V>` (BiFunction) │
  │ **`CompletableFuture.allOf()`│ $N$ Futures  │ **Parallel**           │ Returns `CompletableFuture<Void>`           │
  │ **`CompletableFuture.anyOf()`│ $N$ Futures  │ **Race (First wins)**  │ Returns `CompletableFuture<Object>`         │
  │ **`thenCompose()`**          │ Exactly 2    │ **Sequential**         │ Returns `CompletableFuture<U>` (Dependent)  │
  └──────────────────────────────┴──────────────┴────────────────────────┴─────────────────────────────────────────────┘
```

```java
// 1. thenCombine (Combines 2 parallel tasks):
CompletableFuture<String> nameCF = CompletableFuture.supplyAsync(() -> "Alice");
CompletableFuture<Integer> ageCF = CompletableFuture.supplyAsync(() -> 28);

nameCF.thenCombine(ageCF, (name, age) -> name + " is " + age + " years old")
      .thenAccept(System.out::println); // "Alice is 28 years old"
```

## 🟡 Middle Level

### 1. `thenCombine`: Combining 2 Independent Tasks

When two asynchronous tasks have no dependency on each other, `thenCombine` fires both concurrently. The overall latency is equal to $\max(T_1, T_2)$ rather than $T_1 + T_2$:

```java
public CompletableFuture<UserProfileDTO> buildUserProfile(String userId) {
    CompletableFuture<User> userFuture = userService.getUserAsync(userId);
    CompletableFuture<CreditScore> creditFuture = creditService.getCreditAsync(userId);

    // Both HTTP requests run in parallel:
    return userFuture.thenCombine(creditFuture, (user, credit) -> new UserProfileDTO(user, credit));
}
```

### 2. `CompletableFuture.allOf()`: Scatter-Gather on $N$ Futures

`allOf()` takes a varargs array of futures and completes when **ALL** of them have finished:

```java
List<String> productIds = List.of("p1", "p2", "p3", "p4", "p5");

// 1. Fire N parallel asynchronous requests:
List<CompletableFuture<ProductDTO>> futures = productIds.stream()
    .map(id -> productClient.fetchProductAsync(id))
    .toList();

// 2. Combine into a single allOf future:
CompletableFuture<Void> allDone = CompletableFuture.allOf(
    futures.toArray(new CompletableFuture[0])
);

// 3. Extract results non-blockingly without waiting:
CompletableFuture<List<ProductDTO>> allProductsFuture = allDone.thenApply(v ->
    futures.stream()
        .map(CompletableFuture::join) // 🚀 100% safe & non-blocking because allOf already completed!
        .toList()
);
```

### 3. `CompletableFuture.anyOf()`: Hedging / First-to-Respond Wins

`anyOf()` completes as soon as the **first** future completes, ignoring the slower stragglers:

```java
// Hedged Request Pattern: Call 3 DNS/Geo replicas simultaneously:
CompletableFuture<String> usEast = fetchFromRegionAsync("us-east");
CompletableFuture<String> euWest = fetchFromRegionAsync("eu-west");
CompletableFuture<String> apSouth = fetchFromRegionAsync("ap-south");

CompletableFuture<Object> fastestResponse = CompletableFuture.anyOf(usEast, euWest, apSouth);
fastestResponse.thenAccept(data -> log.info("Fastest replica responded: {}", data));
```

## 🔴 Senior Level

### Parallel vs. Sequential Latency Dynamics

```
  1. SEQUENTIAL DEPENDENT FLOW (`thenCompose`):
     [Task 1 (200ms)] ────────► [Task 2 (300ms)] ────────► Total Latency = 500ms

  2. PARALLEL INDEPENDENT FLOW (`thenCombine` / `allOf`):
     [Task 1 (200ms)] ──┐
                         ├──► Combined Result ───────────► Total Latency = 300ms (max)
     [Task 2 (300ms)] ──┘
```

### Error Aggregation in `allOf`

When combining $N$ futures using `allOf()`:
- If Future #2 fails with an exception, `allOf()` **still waits** for all remaining futures to complete so no zombie tasks are left running unmonitored.
- Once all futures complete, the returned `allOf()` future completes exceptionally containing a `CompletionException` wrapping the first encountered failure.
- If you need to capture *both* successful results and failures without failing the entire batch, attach `.handle()` to each individual future *before* passing them to `allOf()`.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **2 Futures Parallel:** Use `thenCombine(other, BiFunction)` (Latency = $\max(t_1, t_2)$).
- **2 Futures Sequential:** Use `thenCompose(Function)` (Latency = $t_1 + t_2$).
- **$N$ Futures Parallel:** Use `CompletableFuture.allOf(f1, f2, ...)` ➔ extracts results via `.join()`.
- **First to Respond:** Use `CompletableFuture.anyOf(f1, f2, ...)` for hedged requests.
- **`allOf` Gotcha:** `allOf()` returns `CompletableFuture<Void>`, requiring a `.thenApply()` stream mapping step to collect typed results.

**Common Follow-up Questions:**
- *"Why is calling `.join()` inside `allOf.thenApply(...)` safe and non-blocking?"* → Because `thenApply` only executes *after* `allOf` has finished, guaranteeing that every underlying future in the list is already in the completed state.
- *"How do you handle partial failures in `allOf()`?"* → Wrap each individual future with `.handle((res, ex) -> ...)` before passing it to `allOf()` so that individual errors are converted into fallback DTOs rather than failing the entire batch.
- *"What type does `anyOf()` return?"* → `CompletableFuture<Object>`, because the input futures might hold different return types; casting to a specific type is required.

**Red Flags (DO NOT Say):**
- ❌ *"thenCombine and thenCompose do the exact same thing."* (thenCombine executes tasks in parallel; thenCompose executes tasks sequentially).
- ❌ *"allOf() returns a `CompletableFuture<List<T>>` automatically."* (allOf returns `CompletableFuture<Void>`; you must map and collect the results manually).
- ❌ *"Calling `anyOf()` automatically cancels the other slower running futures."* (`anyOf` does not cancel slower tasks; they continue running in the background unless manually cancelled).
