# What is the Difference Between thenCombine() and thenCompose()?

---

## 🟢 Junior Level

The core difference between `thenCombine()` and `thenCompose()` is **task dependency and execution concurrency**:

```
  ┌─────────────────────────────────────────────────────────┬─────────────────────────────────────────────────────────┐
  │ ⚡ `thenCombine()` — Parallel & Independent             │ 🔗 `thenCompose()` — Sequential & Dependent (flatMap)   │
  ├─────────────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ • Coordinates **2 independent tasks** running in        │ • Chains **2 dependent tasks** where Step 2 requires    │
  │   **parallel**.                                         │   the output of Step 1.                                 │
  │ • Takes `(otherFuture, BiFunction<T, U, V>)`.           │ • Takes `Function<T, CompletionStage<U>>`.              │
  │ • Total Latency: $\mathbf{\max(T_1, T_2)}$ (Fastest).   │ • Total Latency: $\mathbf{T_1 + T_2}$ (Sequential).     │
  └─────────────────────────────────────────────────────────┴─────────────────────────────────────────────────────────┘
```

```java
// 1. thenCombine: Fetch User AND Cart in PARALLEL -> Combine into CheckoutDTO:
CompletableFuture<User> userCF = userService.fetchUserAsync(userId);
CompletableFuture<Cart> cartCF = cartService.fetchCartAsync(userId);

CompletableFuture<CheckoutDTO> checkoutCF = userCF.thenCombine(cartCF, (user, cart) -> new CheckoutDTO(user, cart));

// 2. thenCompose: Fetch User FIRST -> Then use user.getAddressId() to fetch ShippingAddress:
CompletableFuture<Address> addressCF = userService.fetchUserAsync(userId)
    .thenCompose(user -> addressService.fetchAddressAsync(user.getAddressId()));
```

## 🟡 Middle Level

### The Performance Trap: Using `thenCompose` for Independent Tasks

> [!WARNING]
> Nesting `thenCompose` for independent tasks turns fast parallel operations into a slow sequential bottleneck!

```java
// ❌ SLOW ANTI-PATTERN (Sequential execution of independent tasks):
// Total Latency: 200ms + 300ms = 500ms!
userService.fetchUserAsync(userId)
    .thenCompose(user -> orderService.fetchOrdersAsync(userId) // ⏳ Waits 200ms before starting order fetch!
        .thenApply(orders -> new Dashboard(user, orders)));

// 🟢 FAST SENIOR ARCHITECTURE (Parallel execution with thenCombine):
// Total Latency: max(200ms, 300ms) = 300ms (40% speedup)!
CompletableFuture<User> userFuture = userService.fetchUserAsync(userId);
CompletableFuture<List<Order>> ordersFuture = orderService.fetchOrdersAsync(userId);

userFuture.thenCombine(ordersFuture, (user, orders) -> new Dashboard(user, orders));
```

## 🔴 Senior Level

### Method Signature & Functional Categorization

```
  ┌──────────────────────────────┬──────────────────────────────────┬──────────────────────────────────────────────────┐
  │ Method                       │ Generic Java Method Signature    │ Functional / Category Theory Role                │
  ├──────────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **`thenCombine`**            │ `<U, V> CompletableFuture<V>`    │ **Applicative Functor Zip / LiftA2**:            │
  │                              │ `thenCombine(CS<U>, BiFn<T,U,V>)`│ Combines two independent computational contexts. │
  ├──────────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **`thenCompose`**            │ `<U> CompletableFuture<U>`       │ **Monadic Bind / FlatMap**:                      │
  │                              │ `thenCompose(Fn<T, CS<U>>)`      │ Sequences dependent computations without nesting.│
  └──────────────────────────────┴──────────────────────────────────┴──────────────────────────────────────────────────┘
```

### Internal JVM Mechanics: `BiApply` vs. `UniCompose`

- **`thenCombine`** allocates a **`BiApply`** completion node that registers completion dependencies on **both** input futures. It only fires its `BiFunction` when both upstream stages have pushed their results.
- **`thenCompose`** allocates a **`UniCompose`** completion node. When the first future completes, it executes the lambda to generate the second future, and attaches an internal relay to unwrap the second future into the downstream result.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`thenCombine`:** Runs 2 independent futures in **parallel** and merges their outputs using a `BiFunction` (Latency = $\max(t_1, t_2)$).
- **`thenCompose`:** Runs 2 dependent futures in **sequence** (flatMap), passing Step 1's output into Step 2 (Latency = $t_1 + t_2$).
- **Anti-Pattern:** Never use `thenCompose` to fetch independent resources; always initiate both futures upfront and merge with `thenCombine`.
- **Analogy:** `thenCombine` = Zip; `thenCompose` = FlatMap.

**Common Follow-up Questions:**
- *"How many futures can `thenCombine` combine at once?"* → Exactly 2. For 3 or more futures, either chain multiple `thenCombine` calls or use `CompletableFuture.allOf()`.
- *"What happens if one future fails in `thenCombine`?"* → The composite future completes exceptionally with the failure from whichever future failed first.
- *"Is there an asynchronous `thenCombineAsync`?"* → Yes; `thenCombineAsync(other, biFunction, executor)` runs the combining `BiFunction` on a dedicated thread pool rather than the completing thread.

**Red Flags (DO NOT Say):**
- ❌ *"thenCombine and thenCompose are synonyms and can be used interchangeably."* (thenCombine is parallel combinator; thenCompose is sequential flatMap).
- ❌ *"thenCombine waits sequentially for future 1 to finish before launching future 2."* (Both futures execute concurrently).
- ❌ *"thenCompose creates a nested `CompletableFuture<CompletableFuture<T>>`."* (thenCompose flattens the result into a clean `CompletableFuture<T>`).
