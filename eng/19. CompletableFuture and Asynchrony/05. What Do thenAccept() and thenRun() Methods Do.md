# What Do thenAccept() and thenRun() Methods Do?

---

## 🟢 Junior Level

Both `thenAccept()` and `thenRun()` are terminal consumer callbacks in a `CompletableFuture` pipeline that return **`CompletableFuture<Void>`**, but they differ in whether they access the previous stage's result:

```
  ┌─────────────────────────────────────────────────────────┬─────────────────────────────────────────────────────────┐
  │ 📥 `thenAccept(Consumer<T> action)`                     │ 🏁 `thenRun(Runnable action)`                           │
  ├─────────────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ • Takes a **`Consumer<T>`** ($T \to \text{void}$).      │ • Takes a **`Runnable`** ($\text{void} \to \text{void}$).│
  │ • **Receives and consumes** the previous stage's result.│ • **Ignores** the result; executes a side-effect action.│
  │ • Example: Logging or writing payload to a database.    │ • Example: Incrementing a metric counter or closing lock│
  └─────────────────────────────────────────────────────────┴─────────────────────────────────────────────────────────┘
```

```java
CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> "Order-1042");

// 1. thenAccept: Receives "Order-1042" and prints it:
future.thenAccept(orderId -> System.out.println("Processing order: " + orderId));

// 2. thenRun: Executes Runnable upon completion without inspecting the orderId:
future.thenRun(() -> System.out.println("Pipeline execution finished successfully!"));
```

## 🟡 Middle Level

### The Functional Method Trio Comparison

```
  ┌──────────────────────────────┬──────────────────────────────┬──────────────────────────────┬────────────────────────┐
  │ Method                       │ Functional Interface         │ Input Parameters             │ Return Future Type     │
  ├──────────────────────────────┼──────────────────────────────┼──────────────────────────────┼────────────────────────┤
  │ **`thenApply(fn)`**          │ `Function<T, U>`             │ Takes previous result $T$    │ `CompletableFuture<U>` │
  ├──────────────────────────────┼──────────────────────────────┼──────────────────────────────┼────────────────────────┤
  │ **`thenAccept(consumer)`**   │ `Consumer<T>`                │ Takes previous result $T$    │ `CompletableFuture<Void>`│
  ├──────────────────────────────┼──────────────────────────────┼──────────────────────────────┼────────────────────────┤
  │ **`thenRun(action)`**        │ `Runnable`                   │ Zero parameters              │ `CompletableFuture<Void>`│
  └──────────────────────────────┴──────────────────────────────┴──────────────────────────────┴────────────────────────┘
```

### Real-World Production Examples

```java
// Example 1: `thenAccept` for saving asynchronous HTTP payload:
userServiceClient.fetchUserAsync(userId)
    .thenAccept(user -> {
        localCache.put(userId, user);
        auditLogger.recordAccess(user.id());
    });

// Example 2: `thenRun` for metric telemetry & cleanup:
emailService.sendWelcomeEmailAsync(email)
    .thenRun(() -> metricsRegistry.counter("emails.sent.total").increment());
```

## 🔴 Senior Level

### The Two-Stage Combinator Family

`CompletableFuture` provides multi-stage variants of `accept` and `run` to handle combinations and races:

```
  ┌──────────────────────────────┬─────────────────────────────────────────────────────────────────────────────────┐
  │ Combinator Method            │ Execution Semantic                                                              │
  ├──────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ **`thenAcceptBoth(other, ..)`│ Waits for **BOTH** futures to complete, passing both results $(T, U)$ to a     │
  │                              │ `BiConsumer<T, U>`.                                                             │
  ├──────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ **`runAfterBoth(other, ..)`**│ Waits for **BOTH** futures to complete, then executes a `Runnable`.             │
  ├──────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ **`acceptEither(other, ..)`**│ Races two futures; consumes the result of whichever completes **FIRST**.        │
  ├──────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ **`runAfterEither(other, ..)`│ Races two futures; executes a `Runnable` as soon as either completes **FIRST**. │
  └──────────────────────────────┴─────────────────────────────────────────────────────────────────────────────────┘
```

```java
CompletableFuture<User> userCF = fetchUserAsync(userId);
CompletableFuture<Cart> cartCF = fetchCartAsync(userId);

// Executes when BOTH user and cart have been fetched:
userCF.thenAcceptBoth(cartCF, (user, cart) -> {
    renderCheckoutPage(user, cart);
});
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`thenAccept`:** Consumes the computation result via `Consumer<T>` (returns `CF<Void>`).
- **`thenRun`:** Executes a parameterless `Runnable` when the previous stage completes (returns `CF<Void>`).
- **Return Type:** Both return `CompletableFuture<Void>`, marking the end of a value transformation pipeline.
- **Async Variants:** `thenAcceptAsync` and `thenRunAsync` offload the callback to a thread pool rather than running on the completing thread.
- **Multi-Stage:** `thenAcceptBoth` (both complete) vs `acceptEither` (first to complete wins).

**Common Follow-up Questions:**
- *"Can you chain `.thenApply()` after `.thenAccept()`?"* → Yes, but the input parameter to `.thenApply()` will be `null` (or `Void`), because `.thenAccept()` returns `CompletableFuture<Void>`.
- *"What happens if an exception occurs before `.thenAccept()`?"* → The exception skips `.thenAccept()` and propagates downstream to the nearest `.exceptionally()` or `.handle()` stage.
- *"Why does `thenRun` exist if it doesn't use the result?"* → For side effects that only care about *completion timing* (e.g. releasing a semaphore lock, updating health check timestamps, triggering metric pings).

**Red Flags (DO NOT Say):**
- ❌ *"thenAccept returns the original value so you can keep transforming it."* (thenAccept returns `CompletableFuture<Void>`; use `thenApply` to transform values).
- ❌ *"thenRun is a blocking method."* (thenRun registers a non-blocking asynchronous callback).
- ❌ *"thenAccept and thenRun always run on a new thread."* (They run on the completing thread unless the `*Async` variant is used).
