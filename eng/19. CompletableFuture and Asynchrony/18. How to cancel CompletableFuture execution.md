# How to Cancel CompletableFuture Execution?

---

## 🟢 Junior Level

You can cancel a `CompletableFuture` by invoking its **`cancel(boolean mayInterruptIfRunning)`** method:

```java
CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> {
    try {
        Thread.sleep(5000); // Simulates long-running task
    } catch (InterruptedException e) {
        System.out.println("Interrupted!");
    }
    return "Result";
});

// Cancel the future:
boolean wasCancelled = future.cancel(true);

System.out.println("isCancelled: " + future.isCancelled()); // true
System.out.println("isDone: " + future.isDone());           // true
```

> [!WARNING]
> **The Critical Cancellation Gotcha:**
> Calling `future.cancel(true)` marks the `CompletableFuture` as cancelled and throws `CancellationException` to downstream callers, but **it DOES NOT reliably stop or interrupt the underlying worker thread**!

---

## 🟡 Middle Level

### Why `CompletableFuture.cancel()` Does Not Stop the Thread

Unlike legacy `FutureTask`, a `CompletableFuture` **does not maintain a direct reference to the active OS worker `Thread`** executing the lambda:

```
  ┌──────────────────────────────────────────┬──────────────────────────────────────────────────┐
  │ What `future.cancel(true)` ACTUALLY Does │ What It DOES NOT Do                              │
  ├──────────────────────────────────────────┼──────────────────────────────────────────────────┤
  │ 🟢 Marks the future state as CANCELLED.  │ 🔴 It **does NOT interrupt the worker thread**.  │
  │ 🟢 Completes with `CancellationException`│ 🔴 A running loop or blocking query **continues  │
  │    for any caller invoking `.join()`.    │    executing in the background** until completion│
  │ 🟢 Skips downstream `.thenApply()` steps.│    unless cooperative cancellation is used!      │
  └──────────────────────────────────────────┴──────────────────────────────────────────────────┘
```

### Implementing Cooperative Cancellation

To guarantee that a running background task actually halts when cancelled, use a **Cooperative Cancellation Token**:

```java
public class CooperativeTask {
    private final AtomicBoolean isCancelled = new AtomicBoolean(false);

    public CompletableFuture<String> executeAsync() {
        return CompletableFuture.supplyAsync(() -> {
            for (int i = 0; i < 1000; i++) {
                // 🛑 Periodic check for cooperative cancellation signal:
                if (isCancelled.get() || Thread.currentThread().isInterrupted()) {
                    log.info("Task aborted cooperatively at iteration {}", i);
                    throw new CancellationException("Task cancelled by caller");
                }
                doExpensiveChunk(i);
            }
            return "SUCCESS";
        });
    }

    public void cancel() {
        this.isCancelled.set(true); // 👈 Sets cooperative abort signal
    }
}
```

## 🔴 Senior Level

### Modern Java 21 Structured Concurrency: `StructuredTaskScope`

In **Java 21+**, the architectural limitation of `CompletableFuture.cancel()` is solved by **Structured Concurrency (JEP 453)**. When a parent task or scope fails or is cancelled, it automatically interrupts and shuts down all child sub-tasks:

```java
// Java 21+ Structured Concurrency with Automatic Sub-Task Cancellation:
public ResponseDTO fetchWithAutoCancellation(String id) throws InterruptedException {
    try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
        Supplier<UserDTO> userSubtask = scope.fork(() -> fetchUser(id));
        Supplier<OrderDTO> orderSubtask = scope.fork(() -> fetchOrders(id));

        scope.join();           // Waits for both tasks
        scope.throwIfFailed();  // 🛡️ If ANY task fails, the other is AUTOMATICALLY CANCELLED & INTERRUPTED!

        return new ResponseDTO(userSubtask.get(), orderSubtask.get());
    }
}
```

### Downstream Exception Handling on Cancelled Futures

When a future is cancelled, any downstream `.join()` or `.get()` calls throw `CancellationException`:

```java
CompletableFuture<String> cf = CompletableFuture.supplyAsync(() -> slowTask());
cf.cancel(true);

cf.exceptionally(ex -> {
    // 🛡️ Handling CancellationException in the pipeline:
    if (ex instanceof CancellationException) {
        log.warn("Operation was cancelled by user/timeout!");
        return "DEFAULT_FALLBACK";
    }
    return "ERROR";
});
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **How `cancel()` Works:** Sets future state to cancelled and completes exceptionally with **`CancellationException`**.
- **The Core Flaw:** `CompletableFuture.cancel(true)` does **not** interrupt the underlying worker thread because it lacks a thread reference; the background task keeps running.
- **Production Solution:** Implement **Cooperative Cancellation** (polling `AtomicBoolean` or `Thread.interrupted()`).
- **Java 21 Solution:** Use **`StructuredTaskScope`** (Structured Concurrency) for guaranteed cascade cancellation of child tasks.
- **Downstream Behavior:** All downstream chained stages are skipped and fail with `CancellationException`.

**Common Follow-up Questions:**
- *"What is the difference between `cancel()` on legacy `FutureTask` and `CompletableFuture`?"* → Legacy `FutureTask` stores `runner = Thread.currentThread()` and calls `thread.interrupt()` when `cancel(true)` is passed; `CompletableFuture` only transitions its internal completion state.
- *"How does `orTimeout()` relate to cancellation in Java 9+?"* → `orTimeout()` automatically completes the future with a `TimeoutException` if the duration expires, but like `cancel()`, cooperative polling is needed to halt the background thread.
- *"Can you cancel a future that is already completed?"* → No; calling `cancel()` on an already completed future returns `false` and has no effect.

**Red Flags (DO NOT Say):**
- ❌ *"Calling `cf.cancel(true)` immediately kills the background OS thread."* (It does NOT kill or interrupt the thread; the thread runs until completion).
- ❌ *"Cancelled futures throw `InterruptedException` when calling `.join()`."* (They throw unchecked `CancellationException`).
- ❌ *"There is no way to cancel asynchronous tasks in Java."* (Use cooperative cancellation tokens or Java 21 Structured Concurrency).
