# What are Callable and Future?

---

## 🟢 Junior Level

**`Callable<V>`** and **`Future<V>`** are core interfaces in `java.util.concurrent` designed to overcome the fundamental limitations of `Runnable`:

```
  ┌──────────────────────────┬────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ Limitation of `Runnable` │ `Callable<V>` Solution                                 │ `Future<V>` Role                                       │
  ├──────────────────────────┼────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ Cannot return a value    │ `V call()` returns a generic typed result              │ Holds the pending result; retrieved via `future.get()` │
  │ Cannot throw checked ex  │ `V call() throws Exception` allows checked exceptions  │ Wraps thrown exceptions inside `ExecutionException`    │
  │ Cannot check task status │ N/A (Functional task descriptor)                       │ Exposes `isDone()`, `isCancelled()`, and `cancel()`    │
  └──────────────────────────┴────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

```java
ExecutorService executor = Executors.newFixedThreadPool(2);

// 1. Submit a Callable task returning an Integer:
Future<Integer> future = executor.submit(() -> {
    Thread.sleep(1000);
    return 42;
});

// 2. Poll completion status:
System.out.println("Is task completed? " + future.isDone()); // false

// 3. Block until completed (or timeout):
Integer result = future.get(2, TimeUnit.SECONDS); // 42
```

## 🟡 Middle Level

### `Callable<V>` vs. `Runnable` Method Contracts

```java
@FunctionalInterface
public interface Runnable {
    void run(); // No return value, cannot throw checked exceptions
}

@FunctionalInterface
public interface Callable<V> {
    V call() throws Exception; // Returns generic value V, throws checked Exception
}
```

### Exception Propagation & `ExecutionException`

When a `Callable` throws an exception, the background worker thread catches it and bundles it inside the `Future`. The exception is re-thrown when the caller invokes `future.get()`:

```java
Future<String> future = executor.submit(() -> {
    throw new IOException("Remote payment gateway unavailable");
});

try {
    String response = future.get();
} catch (ExecutionException ex) {
    // 🔍 Extract original checked exception:
    Throwable rootCause = ex.getCause(); // IOException: Remote payment gateway unavailable
    log.error("Payment failed", rootCause);
} catch (InterruptedException ex) {
    Thread.currentThread().interrupt(); // Caller thread interrupted while waiting
}
```

### Task Cancellation: `future.cancel(boolean mayInterruptIfRunning)`

```java
Future<?> future = executor.submit(() -> {
    while (!Thread.currentThread().isInterrupted()) { // 🚀 Must check interrupt flag!
        processBatch();
    }
});

// Sends Thread.interrupt() to the executing worker thread:
future.cancel(true);
```

> [!WARNING]
> `future.cancel(true)` does **NOT** forcefully kill the thread. It sets the thread's interrupt flag. If your loop does not check `Thread.currentThread().isInterrupted()` or catch `InterruptedException`, the task will continue running.

## 🔴 Senior Level

### Under the Hood: `FutureTask` State Machine

When a task is submitted to an `ExecutorService`, it is wrapped into a **`FutureTask<V>`**:

```
  FutureTask State Machine:
  [NEW] ──► [COMPLETING] ──► [NORMAL]      (Successful return value set)
    │           │
    │           └────────► [EXCEPTIONAL] (Exception caught & stored in 'outcome')
    │
    ├─────────────────────► [CANCELLED]   (Cancelled before execution)
    │
    └─────────────────────► [INTERRUPTING] ──► [INTERRUPTED] (Cancelled while running)
```

- **Outcome Field:** Holds either the successful return value or the thrown `Throwable`.
- **Waiters Queue (`Treiber Stack`):** Calling `future.get()` parks the calling thread on an internal lock-free `WaitNode` queue until the state transitions out of `COMPLETING`.

### The Blocking `Future.get()` Bottleneck

Calling `future.get()` blocks the calling thread, consuming thread pool resources while waiting:

```
  ┌──────────────────────────┬──────────────────────────┬──────────────────────────────────────────────────┐
  │ Paradigm                 │ Construct                │ Execution Characteristics                        │
  ├──────────────────────────┼──────────────────────────┼──────────────────────────────────────────────────┤
  │ **Blocking (Synchronous)│ `Future.get()`           │ Blocks caller thread; risks thread pool starvation│
  │ **Reactive (Asynchronous│ `CompletableFuture`      │ Non-blocking callbacks (`thenApply`, `thenAccept`)│
  │ **Structured (Java 21+)**│ `StructuredTaskScope`    │ Scoped subtask joins with fail-fast cancellation │
  └──────────────────────────┴─────────────────────────────────────────────────────────────────────────────┘
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`Callable<V>` vs `Runnable`:** `Callable` returns a generic value `V` and throws checked `Exception`; `Runnable` returns `void`.
- **`Future<V>` Contract:** Represents an asynchronous computation result; provides `get()`, `get(timeout, unit)`, `isDone()`, `cancel()`.
- **Exception Unwrapping:** Background task exceptions are wrapped inside `ExecutionException`; extract via `ex.getCause()`.
- **Cancellation:** `cancel(true)` calls `Thread.interrupt()`; task logic must cooperatively check `Thread.interrupted()`.
- **`FutureTask`:** Standard JDK implementation using an internal state machine (`NEW` $\to$ `COMPLETING` $\to$ `NORMAL`/`EXCEPTIONAL`).
- **Modern Alternatives:** Use `CompletableFuture` for non-blocking reactive chains, or Java 21 `StructuredTaskScope`.

**Common Follow-up Questions:**
- *"Why should you never call `future.get()` without a timeout in production?"* → An un-timed `future.get()` will block the caller thread indefinitely if the background task hangs, eventually leading to thread pool exhaustion and cascading system failure.
- *"What happens if `cancel()` is called after `future.get()` has already completed?"* → `cancel()` returns `false` and has no effect because the task is already in the `NORMAL` or `EXCEPTIONAL` state.
- *"Why does `invokeAll()` return a `List<Future<T>>` instead of `List<T>`?"* → Because individual subtasks can fail independently with exceptions, which must be inspected per Future.

**Red Flags (DO NOT Say):**
- ❌ *"Future.get() is a non-blocking asynchronous call."* (It synchronously blocks the calling thread until the task finishes).
- ❌ *"cancel(true) immediately kills the OS thread."* (It only sets the interrupt flag; cooperative code must handle the interrupt).
- ❌ *"Future objects can be reused to submit the task a second time."* (Futures are strictly single-use state machines).
