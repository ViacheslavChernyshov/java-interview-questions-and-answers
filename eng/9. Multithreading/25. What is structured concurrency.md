# What is structured concurrency?

---

## 🟢 Junior Level

**Structured Concurrency** (introduced via **JEP 453** in Java 21 Preview) is a programming paradigm that treats multiple concurrent subtasks running in separate threads as a **single, unified unit of work with strict lexical boundaries**:

```
  ┌────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ ❌ Unstructured Concurrency (Classic Thread Pools)      │ ✅ Structured Concurrency (`StructuredTaskScope`)       │
  ├────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ Threads are "orphans" with disconnected lifecycles     │ Parent thread **strictly awaits all child subtasks**   │
  │ If Task A fails, Task B continues running (Thread Leak)│ If Task A fails, **Task B is automatically cancelled** │
  │ Exceptions in child threads are silently lost in heap  │ Exceptions **propagate directly to the parent scope**  │
  └────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

```java
// Idiomatic Structured Concurrency with Fail-Fast Semantics:
try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
    Subtask<UserProfile> userTask   = scope.fork(() -> fetchUserProfile(userId));
    Subtask<OrderHistory> orderTask = scope.fork(() -> fetchOrderHistory(userId));

    scope.join();           // 1. Blocks until both subtasks complete
    scope.throwIfFailed();  // 2. If EITHER task threw an exception, rethrows and cancels the other!

    // 3. Both results are guaranteed complete and available:
    return new AggregatedDashboard(userTask.get(), orderTask.get());
} // 4. Exiting scope GUARANTEES all threads are stopped and cleaned up
```

## 🟡 Middle Level

### Built-in Scope Policies

```
  ┌──────────────────────────────────────┬─────────────────────────────────────────────────┬───────────────────────────────────────────────┐
  │ Policy Class                         │ Completion & Cancellation Semantics             │ Standard Production Use Case                  │
  ├──────────────────────────────────────┼─────────────────────────────────────────────────┼───────────────────────────────────────────────┤
  │ **`ShutdownOnFailure`**              │ If **any subtask fails**, cancel all siblings.  │ Composite RPC calls (All parts required).     │
  │ **`ShutdownOnSuccess<T>`**           │ When the **first subtask succeeds**, cancel rest│ Redundant multi-region mirror queries.        │
  └──────────────────────────────────────┴─────────────────────────────────────────────────┴───────────────────────────────────────────────┘
```

#### Example: Fastest Mirror Fetch via `ShutdownOnSuccess`
```java
try (var scope = new StructuredTaskScope.ShutdownOnSuccess<String>()) {
    scope.fork(() -> queryMirror("https://us-east.api.com/data"));
    scope.fork(() -> queryMirror("https://eu-west.api.com/data"));
    scope.fork(() -> queryMirror("https://ap-south.api.com/data"));

    scope.join(); // Awaits fastest response
    return scope.result(); // 🚀 Returns first result; remaining 2 HTTP queries are cancelled!
}
```

## 🔴 Senior Level

### Hierarchical Observability (JSON Thread Dumps)

Traditional flat thread dumps (`jstack`) cannot correlate which thread spawned another. Structured Concurrency introduces **Hierarchical Thread Trees**:

```bash
# Generate hierarchical JSON thread dump:
jcmd <pid> Thread.dump_to_file -format=json threads.json
```

```json
{
  "thread": {
    "name": "HTTP-Worker-1",
    "scopes": [
      {
        "name": "StructuredTaskScope.ShutdownOnFailure",
        "subtasks": [
          { "thread": "VirtualThread-42", "task": "fetchUserProfile", "state": "SUCCESS" },
          { "thread": "VirtualThread-43", "task": "fetchOrderHistory", "state": "RUNNING" }
        ]
      }
    ]
  }
}
```

### Synergy with `ScopedValue` & Virtual Threads

```java
public class SecureOrderService {
    private static final ScopedValue<SecurityContext> AUTH_CTX = ScopedValue.newInstance();

    public OrderResult process(SecurityContext userAuth, OrderRequest req) throws Exception {
        return ScopedValue.where(AUTH_CTX, userAuth).call(() -> {
            try (var scope = new StructuredTaskScope.ShutdownOnFailure()) {
                // 🚀 AUTH_CTX automatically inherits down into child virtual threads:
                Subtask<Inventory> inv = scope.fork(() -> checkInventory(AUTH_CTX.get(), req));
                Subtask<Payment>   pay = scope.fork(() -> chargeCard(AUTH_CTX.get(), req));

                scope.join().throwIfFailed();
                return new OrderResult(inv.get(), pay.get());
            }
        });
    }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Core Concept:** Structured Concurrency models concurrent subtasks as a single atomic lexical block via `try-with-resources`.
- **Eliminates Thread Leaks:** Guarantees all spawned child threads terminate before the parent method exits.
- **`ShutdownOnFailure`:** Composite fail-fast operations; cancels remaining subtasks if one fails.
- **`ShutdownOnSuccess`:** Speculative execution; returns first successful result and cancels slow peers.
- **Hierarchical Dumps:** Thread dumps in JSON format preserve parent-child task relationships.
- **Preview Status:** In Java 21/22 `StructuredTaskScope` is a Preview API (`--enable-preview`).

**Common Follow-up Questions:**
- *"Why is `StructuredTaskScope` preferred over `CompletableFuture.allOf()`?"* → `CompletableFuture.allOf()` does not automatically cancel remaining tasks if one fails, nor does it guarantee thread cleanup on method exit. `StructuredTaskScope` enforces strict lexical bounds and cascading cancellation.
- *"What happens if an unhandled exception occurs inside a subtask?"* → In `ShutdownOnFailure`, `scope.throwIfFailed()` wraps the subtask's exception in an `ExecutionException` and interrupts all other sibling subtasks.
- *"Can Structured Concurrency be used for long-running daemon background consumers?"* → No. Structured Concurrency is designed for bounded, request-scoped operations that have a defined begin and end point. Use classic `ExecutorService` for standing daemon threads.

**Red Flags (DO NOT Say):**
- ❌ *"Structured Concurrency is a fully finalized LTS feature in Java 21."* (It is currently a Preview API in Java 21 and requires `--enable-preview`).
- ❌ *"Structured Concurrency replaces the need for Virtual Threads."* (They complement each other: Structured Concurrency provides task orchestration, while Virtual Threads provide lightweight execution).
- ❌ *"If a parent thread times out, child threads continue running safely in background."* (Structured concurrency ensures children are cancelled and joined before parent returns).
