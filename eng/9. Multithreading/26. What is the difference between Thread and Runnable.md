# What is the difference between Thread and Runnable?

---

## 🟢 Junior Level

**`Thread`** and **`Runnable`** represent the separation of **the task to execute** from **the worker executing it** (an application of the Command Pattern):

```
  ┌──────────────────────────┬────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ Characteristic           │ `Runnable` (Interface)                                 │ `Thread` (Class)                                       │
  ├──────────────────────────┼────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **Architectural Role**   │ **The Task** ("What to execute")                       │ **The Carrier / Worker** ("Who executes it")           │
  │ **Memory Footprint**     │ Lightweight heap object (**~24 bytes**)                │ Heavyweight OS native stack (**~1 MB**)                │
  │ **Execution Mechanism**  │ `task.run()` executes **synchronously on same thread** │ `thread.start()` allocates a **NEW OS execution thread**│
  │ **Reusability**          │ Unlimited (Can be submitted to any pool or executor)   │ Single-use (Cannot restart a terminated thread)        │
  └──────────────────────────┴────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

```java
// 1. Task Definition:
Runnable task = () -> System.out.println("Processing on: " + Thread.currentThread().getName());

// ❌ WRONG: Executes synchronously on the 'main' caller thread (No new thread created!)
task.run(); 

// ✅ CORRECT: Spawns a separate OS platform thread:
Thread thread = new Thread(task);
thread.start(); // Creates native thread and schedules execution
```

## 🟡 Middle Level

### Composition over Inheritance

```java
// ❌ ANTI-PATTERN: Extending Thread binds task logic to thread lifecycle
public class OrderReportTask extends Thread {
    @Override
    public void run() { generateReport(); }
}

// ✅ IDIOMATIC: Implementing Runnable preserves inheritance & enables pool reuse
public class OrderReportTask extends BaseReportService implements Runnable {
    @Override
    public void run() { generateReport(); }
}
```

```
  Benefits of 'implements Runnable':
  1. Multiple Inheritance: A class can implement Runnable while extending a domain base class.
  2. Pool Compatibility: Can be submitted to ThreadPoolExecutor, ForkJoinPool, or Virtual Threads.
  3. Clean Testing: Task logic can be tested synchronously via task.run() in standard unit tests.
```

### The 6 Formal JVM Thread States

```
                 start()
   [NEW] ──────────────────────► [RUNNABLE] (Ready or Running on CPU)
                                     │
           ┌─────────────────────────┼─────────────────────────┐
           │                         │                         │
     synchronized              wait(), join()            sleep(ms), wait(ms)
           ▼                         ▼                         ▼
      [BLOCKED]                  [WAITING]              [TIMED_WAITING]
           │                         │                         │
           └─────────────────────────┼─────────────────────────┘
                                     │ Task completes
                                     ▼
                               [TERMINATED]
```

## 🔴 Senior Level

### Thread Instantiation: JVM Native Mechanics

When `thread.start()` is invoked:
1. The JVM invokes `JVM_StartThread` (C++ native code).
2. The operating system kernel calls `pthread_create()` (Linux) or `CreateThread()` (Windows).
3. The OS allocates a **1 MB virtual memory stack frame** (`-Xss1m`) and registers the thread with the OS kernel scheduler.
4. The OS scheduler schedules the thread onto an available CPU core, which then invokes Java's `Runnable.run()` entry point.

### Modern Java 21 Builders: Platform vs. Virtual Threads

Java 21 introduced the fluent `Thread.ofPlatform()` and `Thread.ofVirtual()` factory builders:

```java
Runnable task = () -> handleRequest();

// 1. Heavyweight OS Platform Thread (~1 MB stack):
Thread platformThread = Thread.ofPlatform()
    .name("order-worker-", 1)
    .daemon(true)
    .start(task);

// 2. Lightweight Virtual Thread (~1 KB memory):
Thread virtualThread = Thread.ofVirtual()
    .name("virtual-order-", 1)
    .start(task);
```

### Uncaught Exception Handling

Uncaught runtime exceptions in standalone threads terminate the thread and print directly to `System.err`. Production systems configure an **`UncaughtExceptionHandler`**:

```java
Thread thread = new Thread(task);
thread.setUncaughtExceptionHandler((t, e) -> {
    log.error("Thread {} crashed unexpectedly with error: {}", t.getName(), e.getMessage(), e);
    metrics.increment("thread.failures");
});
thread.start();
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Core Distinction:** `Runnable` is the task (Command Pattern); `Thread` is the execution worker.
- **`run()` vs `start()`:** `run()` executes synchronously in the caller thread; `start()` allocates an OS native thread.
- **Memory Difference:** 1,000 `Runnable`s $\approx$ 24 KB; 1,000 `Thread`s $\approx$ 1 GB native RAM.
- **6 Thread States:** `NEW`, `RUNNABLE`, `BLOCKED` (monitor lock), `WAITING` (`wait`/`join`), `TIMED_WAITING` (`sleep`), `TERMINATED`.
- **Composition over Inheritance:** Always implement `Runnable` instead of extending `Thread`.
- **Java 21 Builders:** `Thread.ofPlatform()` and `Thread.ofVirtual()`.

**Common Follow-up Questions:**
- *"Can you restart a thread after it reaches the `TERMINATED` state?"* → No. Calling `start()` on a terminated thread throws `IllegalThreadStateException`.
- *"Does setting thread priority (`thread.setPriority(10)`) guarantee faster execution?"* → No. Modern OS kernel schedulers (such as Linux CFS) largely ignore Java thread priorities.
- *"Why is `Runnable` insufficient when a return value is needed?"* → `Runnable.run()` returns `void` and cannot throw checked exceptions; use `Callable<V>` instead.

**Red Flags (DO NOT Say):**
- ❌ *"Calling `run()` spawns a new background thread."* (It simply executes the method in the current calling thread).
- ❌ *"Extending Thread is best practice because it gives direct access to thread methods."* (It tightly couples task logic to thread lifecycle and breaks class inheritance).
- ❌ *"Java threads can execute indefinitely after being garbage collected."* (Active running threads are GC Roots and cannot be collected until terminated).
