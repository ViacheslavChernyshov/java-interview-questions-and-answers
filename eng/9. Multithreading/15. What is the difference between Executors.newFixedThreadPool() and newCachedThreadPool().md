# What is the difference between Executors.newFixedThreadPool() and newCachedThreadPool()?

---

## 🟢 Junior Level

Both factory methods instantiate an `ExecutorService`, but they manage worker threads and queue buffering with completely opposite strategies:

```
  ┌──────────────────────────┬────────────────────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ Parameter                │ `Executors.newFixedThreadPool(n)`                      │ `Executors.newCachedThreadPool()`                      │
  ├──────────────────────────┼────────────────────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **Core Pool Size**       │ Fixed `n`                                              │ `0`                                                    │
  │ **Maximum Pool Size**    │ Fixed `n`                                              │ **`Integer.MAX_VALUE`** (Unbounded)                    │
  │ **Idle Keep-Alive**      │ `0 ms` (Worker threads never terminate)                │ **`60 seconds`** (Idle threads terminated)             │
  │ **Internal Work Queue**  │ **`LinkedBlockingQueue`** (Capacity: 2.14B tasks)      │ **`SynchronousQueue`** (Zero buffer capacity)          │
  │ **Primary Behavior**     │ Bounded threads; unbounded task queue buffering        │ Dynamic on-demand threads; direct task hand-off       │
  └──────────────────────────┴────────────────────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

```java
// Fixed: 10 threads process tasks; excess tasks wait in queue
ExecutorService fixed = Executors.newFixedThreadPool(10);

// Cached: Spawns new threads on demand; idle threads terminate after 60s
ExecutorService cached = Executors.newCachedThreadPool();
```

## 🟡 Middle Level

### Task Hand-off & Queue Dynamics

```
  FixedThreadPool (Passive Storage):
  Incoming Tasks ──► [LinkedBlockingQueue (Holds millions of tasks)] ──► Fixed 10 Workers

  CachedThreadPool (Direct Rendezvous):
  Incoming Task  ──► [SynchronousQueue (0 Capacity)] ──► Immediate Idle Worker
                                                     └──► OR Spawns NEW Worker Thread immediately!
```

- **`LinkedBlockingQueue`:** Acts as a passive reservoir. Threads pull tasks when idle.
- **`SynchronousQueue`:** A rendezvous mechanism with zero internal capacity. A producer inserting a task must directly hand it off to an available worker thread; if no thread is idle, the pool **instantly creates a new OS thread**.

## 🔴 Senior Level

### Production Failure Modes: Two Flavors of `OutOfMemoryError`

> [!CAUTION]
> Both default factories present critical memory failure hazards under sustained production load:

```
  ┌────────────────────────┬──────────────────────────────────────────┬────────────────────────────────────────────────────────┐
  │ Pool Factory           │ Production Hazard                        │ Resulting Fatal JVM Error                              │
  ├────────────────────────┼──────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **`newFixedThreadPool`**│ Queue grows unbounded during downstream  │ 💥 **`java.lang.OutOfMemoryError: Java heap space`**   │
  │                        │ latency degradation.                     │                                                        │
  ├────────────────────────┼──────────────────────────────────────────┼────────────────────────────────────────────────────────┤
  │ **`newCachedThreadPool`**│ Traffic surge creates thousands of       │ 💥 **`java.lang.OutOfMemoryError: unable to create`**   │
  │                        │ concurrent OS threads simultaneously.    │    **`native thread`**                                 │
  └────────────────────────┴──────────────────────────────────────────┴────────────────────────────────────────────────────────┘
```

### Production Hardened Replacements

```java
// 1. Safe replacement for FixedThreadPool (Bounded Queue Protection):
ExecutorService safeFixed = new ThreadPoolExecutor(
    10, 10,
    0L, TimeUnit.MILLISECONDS,
    new ArrayBlockingQueue<>(500), // Hard limit on pending memory
    new ThreadPoolExecutor.CallerRunsPolicy() // Slows down producers
);

// 2. Safe replacement for CachedThreadPool (Capped Max Burst Protection):
ExecutorService safeCached = new ThreadPoolExecutor(
    0, 200, // Capped maximum capacity!
    60L, TimeUnit.SECONDS,
    new SynchronousQueue<>(),
    new ThreadPoolExecutor.CallerRunsPolicy()
);
```

### Modern Java 21 Replacement: Virtual Threads

For high-throughput, short-lived I/O tasks, **`Executors.newVirtualThreadPerTaskExecutor()`** completely obsoletes `newCachedThreadPool()`:
- Virtual threads cost **~1 KB** (vs **~1 MB** native OS stack).
- Millions of concurrent virtual threads can execute simultaneously without exhausting OS native thread tables or memory.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **FixedThreadPool:** Fixed `n` threads, unbounded `LinkedBlockingQueue`, persistent worker threads.
- **CachedThreadPool:** 0 to `Integer.MAX_VALUE` threads, `SynchronousQueue` (0 capacity), 60-second idle eviction.
- **Heap OOM vs Native OOM:** FixedThreadPool causes Heap space OOM (queue overload); CachedThreadPool causes Native thread OOM (thread explosion).
- **SynchronousQueue Semantics:** Zero-capacity rendezvous; requires an immediate consumer or spawns a new thread.
- **Production Standard:** Use explicit `ThreadPoolExecutor` with `ArrayBlockingQueue` and `CallerRunsPolicy`.
- **Java 21 Loom:** Replace `newCachedThreadPool()` with `newVirtualThreadPerTaskExecutor()`.

**Common Follow-up Questions:**
- *"Why does `SynchronousQueue` have a size of 0?"* → Because it does not hold elements; it only coordinates a direct hand-off between producer and consumer threads.
- *"Under what workload is `newCachedThreadPool` actually beneficial?"* → For lightweight, short-lived tasks with bursty traffic where latency must be minimized and total concurrent requests are strictly bounded by upstream gateways.
- *"What happens when 5,000 tasks are submitted to `newFixedThreadPool(10)`?"* → 10 tasks execute immediately on the 10 worker threads; the remaining 4,990 tasks sit in the `LinkedBlockingQueue`.

**Red Flags (DO NOT Say):**
- ❌ *"SynchronousQueue stores up to 60 tasks."* (It has a capacity of 0; 60 is the keep-alive timeout in seconds).
- ❌ *"FixedThreadPool is safer than CachedThreadPool in all situations."* (FixedThreadPool still risks fatal heap exhaustion due to its unbounded queue).
- ❌ *"CachedThreadPool worker threads never terminate."* (Idle threads terminate after 60 seconds of inactivity).
