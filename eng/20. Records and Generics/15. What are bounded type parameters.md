# What Are Bounded Type Parameters?

---

## 🟢 Junior Level

**Bounded Type Parameters** allow you to **restrict the permissible types** that can be passed to a generic class, interface, or method using the **`extends`** keyword:

```java
// 🔓 Unbounded: Accepts ANY reference type (String, Thread, Socket, etc.):
public class GenericBox<T> {}

// 🔒 Bounded: Accepts ONLY Number or its subclasses (Integer, Double, BigDecimal, etc.):
public class NumberBox<T extends Number> {
    private T value;

    public double getDoubleValue() {
        // 🚀 We can safely call methods from java.lang.Number on T!
        return value.doubleValue();
    }
}

// Usage:
NumberBox<Integer> intBox = new NumberBox<>();       // 🟢 Valid: Integer extends Number
NumberBox<Double> dblBox = new NumberBox<>();         // 🟢 Valid: Double extends Number
// NumberBox<String> strBox = new NumberBox<>();      // 🛑 COMPILE ERROR: String is not a Number!
```

## 🟡 Middle Level

### The Two Core Benefits of Bounds

```
  ┌───┬──────────────────────────────────┬─────────────────────────────────────────────────────────────────┐
  │ # │ Benefit                          │ Why It Matters                                                  │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 1 │ **Compile-Time Type Filter**     │ Prevents invalid types from being passed to generic algorithms. │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 2 │ **Direct Method Invocations**    │ Allows calling all public methods of the bound class/interface  │
  │   │                                  │ directly on `T` without explicit downcasting.                   │
  └───┴──────────────────────────────────┴─────────────────────────────────────────────────────────────────┘
```

```java
// Example: Invoking .compareTo() directly on T because T extends Comparable<T>:
public static <T extends Comparable<T>> T findMax(T a, T b) {
    return (a.compareTo(b) >= 0) ? a : b; // 🚀 compareTo is guaranteed to exist!
}
```

> [!NOTE]
> In Java Generics, the keyword **`extends`** is used for **both classes and interfaces**:
> - `<T extends Number>` (Class bound)
> - `<T extends Serializable>` (Interface bound — NOT `<T implements Serializable>`)

## 🔴 Senior Level

### Multiple Bounds (`&` Operator)

A type parameter can be constrained by multiple bounds using the ampersand (`&`) intersection syntax:

```java
// T MUST extend Number AND implement Comparable<T> AND implement Serializable:
public class FinancialMetric<T extends Number & Comparable<T> & Serializable> {
    private T metricValue;

    public boolean isGreaterThan(T other) {
        return metricValue.compareTo(other) > 0;
    }
}
```

### The 2 Golden Rules of Multiple Bounds

```
  ┌───┬──────────────────────────────────┬─────────────────────────────────────────────────────────────────┐
  │ # │ Rule                             │ Compiler Constraint                                             │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 1 │ **Class Bound Must Come FIRST**  │ If a class bound is present, it must be the first listed bound. │
  │   │                                  │ `T extends Number & Comparable<T>` (Valid)                      │
  │   │                                  │ `T extends Comparable<T> & Number` (Compile Error!)             │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 2 │ **Max 1 Class Bound**            │ Java does not support multiple class inheritance. You cannot    │
  │   │                                  │ specify two classes: `T extends Number & Thread` (Error).       │
  └───┴──────────────────────────────────┴─────────────────────────────────────────────────────────────────┘
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Syntax:** `<T extends SuperType>` restricts `T` to `SuperType` and its subclasses/implementations.
- **Universal Keyword:** Use `extends` for both classes (`<T extends Number>`) and interfaces (`<T extends AutoCloseable>`).
- **Method Access:** Bounded parameters allow invoking methods on the bound without casting.
- **Multiple Bounds:** Separate with `&` (`<T extends ClassA & InterfaceB & InterfaceC>`); class must be first, with max 1 class.
- **Type Erasure:** A bounded parameter `<T extends Number>` erases to the first bound (`Number`) in JVM bytecode.

**Common Follow-up Questions:**
- *"Can a type parameter have a `super` bound (like `<T super Integer>`)?"* → No! Type parameter declarations only support `extends` (`<T extends Number>`). Lower bounds with `super` are **only valid on wildcards** (`<? super Integer>`).
- *"What is a Recursive Type Bound?"* → A bound where the type parameter is constrained by an expression involving itself, e.g. `<T extends Comparable<T>>` (commonly used for sorting and fluent builders).
- *"What does `<T extends Object>` mean?"* → It is functionally equivalent to `<T>`, but explicitly specifies that `T` must be a non-null reference type in some generic tooling contexts.

**Red Flags (DO NOT Say):**
- ❌ *"Use `<T implements Serializable>` to bound a type parameter to an interface."* (The keyword `implements` is illegal in generics; always use `extends`).
- ❌ *"Type parameter declarations support `<T super Number>`."* (Type parameters only support `extends`; `super` is reserved for wildcards `<? super Number>`).
- ❌ *"You can list multiple classes in bounds: `<T extends Number & Date>`."* (Only one class is allowed, and it must be listed first).
