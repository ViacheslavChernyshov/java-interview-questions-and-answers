# Can You Add Additional Methods to a Record?

---

## 🟢 Junior Level

**YES, absolutely!** A `record` is a class and can declare arbitrary **instance methods**, **static factory methods**, **private helper methods**, and **custom accessors**:

```java
public record Money(BigDecimal amount, String currency) {

    // 🟢 1. Static Factory Method:
    public static Money usd(double amount) {
        return new Money(BigDecimal.valueOf(amount), "USD");
    }

    // 🟢 2. Instance Business Method (Value Object calculation):
    public Money add(Money other) {
        if (!this.currency.equals(other.currency)) {
            throw new IllegalArgumentException("Cannot add different currencies: " + currency + " vs " + other.currency);
        }
        return new Money(this.amount.add(other.amount), this.currency);
    }

    // 🟢 3. Derived Helper Method:
    public boolean isZero() {
        return amount.compareTo(BigDecimal.ZERO) == 0;
    }
}
```

```
  What Records CAN Contain:
  • ✅ Instance business methods (`money.add()`)
  • ✅ Static factory methods (`Money.usd()`)
  • ✅ Static constants (`public static final String DEFAULT_CURRENCY = "USD"`)
  • ✅ Private helper methods
  • ✅ Custom secondary constructors (must invoke `this(...)`)
```

## 🟡 Middle Level

### What is Strictly FORBIDDEN Inside a Record Body?

```
  ┌───┬──────────────────────────────────┬─────────────────────────────────────────────────────────────────┐
  │ # │ Forbidden Feature                │ Compiler Error & Architectural Reason                           │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 1 │ ❌ **Instance Fields**           │ `private int extraState;` ➔ **Compile Error!** All instance     │
  │   │                                  │ state must reside strictly in the record header.                │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 2 │ ❌ **Instance Initializer Blocks│ `{ System.out.println("init"); }` ➔ **Compile Error!** Only     │
  │   │                                  │ `static { ... }` blocks are permitted.                          │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 3 │ ❌ **Native Methods**            │ `native void doSomething();` ➔ **Compile Error!**               │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 4 │ ❌ **Altered Accessor Return Type│ `public String x() { ... }` on `record Point(int x)` ➔ **Error**│
  │   │                                  │ (Accessor return type must match component type).               │
  └───┴──────────────────────────────────┴─────────────────────────────────────────────────────────────────┘
```

### Overriding Auto-Generated Accessor Methods

You can override an auto-generated component accessor (e.g. to perform defensive copying or formatting), as long as its signature and return type match the component:

```java
public record SecurityProfile(String username, List<String> roles) {

    // 🟢 Overriding accessor to return an unmodifiable defensive view:
    @Override
    public List<String> roles() {
        return Collections.unmodifiableList(this.roles);
    }
}
```

## 🔴 Senior Level

### Records as Rich Domain-Driven Design (DDD) Value Objects

A common misconception is that Records are purely anemic data structures. In **Domain-Driven Design (DDD)**, Records are the premier choice for **Rich Immutable Value Objects**:

```java
public record Coordinates(double latitude, double longitude) {

    // Validation inside Compact Constructor:
    public Coordinates {
        if (latitude < -90 || latitude > 90) throw new IllegalArgumentException("Latitude out of bounds");
        if (longitude < -180 || longitude > 180) throw new IllegalArgumentException("Longitude out of bounds");
    }

    // Rich domain calculation (Haversine distance formula):
    public double distanceToInKm(Coordinates other) {
        double dLat = Math.toRadians(other.latitude() - this.latitude());
        double dLon = Math.toRadians(other.longitude() - this.longitude());
        double a = Math.sin(dLat / 2) * Math.sin(dLat / 2) +
                   Math.cos(Math.toRadians(this.latitude())) * Math.cos(Math.toRadians(other.latitude())) *
                   Math.sin(dLon / 2) * Math.sin(dLon / 2);
        return 6371 * 2 * Math.atan2(Math.sqrt(a), Math.sqrt(1 - a));
    }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Can Add Methods:** Yes; instance methods, static factory methods, private helpers, and overridden accessors are all permitted.
- **Instance Fields Banned:** You **cannot** declare any non-static instance fields in the body (`private int count;` will not compile).
- **Accessor Overriding:** Permitted, provided the method name, return type, and accessibility match the record component.
- **Initializer Blocks:** Instance initializers (`{ ... }`) are banned; only `static { ... }` is allowed.
- **DDD Value Objects:** Records are designed for immutable value objects with rich domain calculation methods.

**Common Follow-up Questions:**
- *"Can a record method modify one of the record's components?"* → No; all components are `private final`. Business methods must follow the functional transformation pattern: return a *new* Record instance with the updated values (e.g. `withAmount(newAmount)`).
- *"Can you add annotations to record methods and components?"* → Yes; annotations placed on record components can target fields, parameters, or accessor methods (e.g. `@JsonProperty`, `@NotNull`).
- *"Can a record method throw checked exceptions?"* → Yes; custom methods in records follow standard Java method rules and can declare `throws IOException`.

**Red Flags (DO NOT Say):**
- ❌ *"Records are only for data transfer and cannot contain any methods."* (Records can contain rich business behavior and domain calculations).
- ❌ *"You can declare private instance variables inside a record if they are marked `final`."* (All instance fields must be declared in the record header; zero body instance fields are allowed).
- ❌ *"Overriding `equals()` or `hashCode()` in a record is forbidden."* (You can override `equals()` and `hashCode()`, though the compiler defaults are usually sufficient).
