# What Are Raw Types and Why Should You Avoid Them?

---

## 🟢 Junior Level

A **Raw Type** is the name of a generic class or interface used **without any type arguments** (e.g. `List` instead of `List<String>`):

```java
// ❌ RAW TYPE: Disables compiler type checking:
List rawList = new ArrayList();
rawList.add("Hello");
rawList.add(100); // ⚠️ Compiles without error!

// Later in the code:
String s1 = (String) rawList.get(0); // Works
String s2 = (String) rawList.get(1); // 💥 RUNTIME ClassCastException: Integer cannot be cast to String!

// 🟢 PARAMETERIZED TYPE: 100% Compile-time safe:
List<String> safeList = new ArrayList<>();
safeList.add("Hello");
// safeList.add(100); // 🛑 COMPILE ERROR! Caught immediately in IDE!
```

```
  Why Raw Types Exist:
  • Raw types were included in Java 5 strictly for **backward compatibility** with legacy Java 1.0–1.4 codebases.
  • *Effective Java* Item 26: **Do not use raw types** in modern Java!
```

## 🟡 Middle Level

### The 3 Dangers of Using Raw Types

```
  ┌───┬──────────────────────────────────┬─────────────────────────────────────────────────────────────────┐
  │ # │ Hazard                           │ Impact on Production Code                                       │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 1 │ 💥 **Loss of Type Safety**       │ The compiler skips type verification, allowing any `Object` in. │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 2 │ 💥 **Heap Pollution**            │ Corrupted data escapes into parameterized references.           │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 3 │ 💥 **Delayed Runtime Crashes**   │ `ClassCastException` is thrown far away from where the bad data │
  │   │                                  │ was originally inserted, making debugging a nightmare.         │
  └───┴──────────────────────────────────┴─────────────────────────────────────────────────────────────────┘
```

### Raw Type (`List`) vs. `List<Object>` vs. `List<?>`

```
  ┌──────────────────────────────┬──────────────────────────────┬──────────────────────────────────────────────────┐
  │ Type                         │ Type Safety                  │ Behavioral Contract                              │
  ├──────────────────────────────┼──────────────────────────────┼──────────────────────────────────────────────────┤
  │ **`List` (Raw)**             │ 🔴 **UNSAFE** (Opt-out)      │ Can insert any object; compiler checks disabled. │
  ├──────────────────────────────┼──────────────────────────────┼──────────────────────────────────────────────────┤
  │ **`List<Object>`**           │ 🟢 **TYPE-SAFE**             │ Explicitly states it can hold any `Object`.      │
  │                              │                              │ Invariant (cannot pass `List<String>` to it).    │
  ├──────────────────────────────┼──────────────────────────────┼──────────────────────────────────────────────────┤
  │ **`List<?>` (Wildcard)**     │ 🟢 **TYPE-SAFE (Read-Only)** │ Represents a list of *unknown* type.             │
  │                              │                              │ Cannot insert anything (except `null`).          │
  └──────────────────────────────┴──────────────────────────────┴──────────────────────────────────────────────────┘
```

## 🔴 Senior Level

### The Only 2 Legitimate Exceptions Where Raw Types Appear

According to the Java Language Specification (JLS), there are only **2 places** where raw types are legally necessary:

#### 1. Class Literals (`.class`)

You **must** use raw types in class literals; parameterized types are syntax errors:

```java
Class<List> clazz = List.class; // 🟢 Valid

// ❌ COMPILE ERRORS: Parameterized class literals are illegal:
// Class<?> bad1 = List<String>.class; 
// Class<?> bad2 = List<?>.class;
```

#### 2. The `instanceof` Operator

Because generic type arguments are erased at runtime, `instanceof` cannot check parameterized types:

```java
// 🟢 Valid: Checking raw type or unbounded wildcard:
if (obj instanceof Set) { ... }      // Raw type allowed
if (obj instanceof Set<?>) { ... }   // Idiomatic wildcard form (Preferred)

// ❌ COMPILE ERROR: Cannot verify erased type parameter at runtime:
// if (obj instanceof Set<String>) { ... } // 💥 Compile Error!
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Definition:** Using a generic type without type arguments (e.g. `Map` instead of `Map<K, V>`).
- **Rule:** *Effective Java* Item 26: **Do not use raw types**.
- **Reason to Avoid:** Destroys compile-time safety, causes heap pollution, and defers `ClassCastException` to runtime.
- **Alternative:** Use unbounded wildcards `List<?>` when the element type is unknown or doesn't matter.
- **Allowed Exceptions:** Class literals (`List.class`) and `instanceof` checks (`obj instanceof List<?>`).

**Common Follow-up Questions:**
- *"What is the difference between `List` and `List<?>`?"* → `List` completely turns off generic type checking (unsafe); `List<?>` is a type-safe read-only wildcard where you cannot insert elements (other than `null`).
- *"Can passing a raw type corrupt a generic collection?"* → Yes! Passing a `List<String>` to a legacy method accepting a raw `List` allows the legacy method to insert an `Integer`, causing a delayed `ClassCastException` when the original owner reads from it (Heap Pollution).
- *"Does the Java compiler issue a warning when using raw types?"* → Yes; the compiler emits `rawtypes` and `unchecked` warnings, which can be suppressed via `@SuppressWarnings("rawtypes")` only when strictly required for legacy interoperability.

**Red Flags (DO NOT Say):**
- ❌ *"Raw types are faster and consume less memory than generic types."* (They produce identical bytecode at runtime; raw types simply destroy safety).
- ❌ *"Use `List` whenever you want a collection that can accept any type."* (Use `List<Object>` for heterogeneous collections, or `List<?>` for unknown types).
- ❌ *"You can write `List<String>.class` in Java reflection."* (Only raw class literals like `List.class` are legal).
