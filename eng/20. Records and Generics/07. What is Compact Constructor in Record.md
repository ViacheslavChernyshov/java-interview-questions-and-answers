# What is Compact Constructor in Record?

---

## 🟢 Junior Level

A **Compact Constructor** is a special syntax unique to Java Records where the **parameter list and parentheses are omitted**:

```java
public record User(String name, int age) {

    // 🚀 COMPACT CONSTRUCTOR: No parameter list `(String name, int age)` needed!
    public User {
        // Validation logic:
        if (age < 0) {
            throw new IllegalArgumentException("Age cannot be negative: " + age);
        }
        if (name == null || name.isBlank()) {
            throw new IllegalArgumentException("Name cannot be empty");
        }
        // ✨ NO `this.name = name` or `this.age = age` boilerplate required!
    }
}
```

```
  How It Works:
  1. The record component parameters (`name`, `age`) are implicitly available in scope.
  2. You write your validation or normalization code.
  3. The compiler **automatically appends field assignments** (`this.name = name; this.age = age;`) 
     at the very end of the block!
```

## 🟡 Middle Level

### The 3 Superpowers of Compact Constructors

```
  ┌───┬──────────────────────────────────┬─────────────────────────────────────────────────────────────────┐
  │ # │ Superpower                       │ Real-World Example                                              │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 1 │ **State Invariant Validation**   │ Throw `IllegalArgumentException` on invalid or negative inputs. │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 2 │ **Data Normalization**           │ Sanitize incoming strings (`email = email.trim().toLowerCase()`)│
  │   │                                  │ before assignment to final fields.                              │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 3 │ **Defensive Copying**            │ Snapshot mutable collections (`items = List.copyOf(items)`) to  │
  │   │                                  │ guarantee true immutability.                                    │
  └───┴──────────────────────────────────┴─────────────────────────────────────────────────────────────────┘
```

### Parameter Reassignment & Defensive Copying

Inside a compact constructor, the parameters are **mutable local variables**. Reassigning a parameter changes the value that the compiler assigns to the final field:

```java
public record CustomerAccount(String email, List<String> permissions) {

    public CustomerAccount {
        Objects.requireNonNull(email, "Email is required");

        // 🟢 1. Normalization: Parameter reassignment:
        email = email.trim().toLowerCase();

        // 🟢 2. Defensive Copying: Snapshot mutable collection to unmodifiable list:
        permissions = (permissions == null) ? List.of() : List.copyOf(permissions);

        // 👉 Compiler automatically generates:
        // this.email = email;
        // this.permissions = permissions;
    }
}
```

## 🔴 Senior Level

### Common Gotcha: The `this.field` Compile Error

> [!CAUTION]
> Explicitly writing `this.name = name;` inside a compact constructor is a **Compile-Time Error**!
>
> The compiler reserves field initialization exclusively for the generated epilogue of the compact constructor block.

```java
public record Point(int x, int y) {

    public Point {
        // ❌ COMPILE ERROR: Cannot assign to final field this.x in compact constructor!
        // this.x = x * 2;

        // 🟢 CORRECT: Mutate the parameter directly:
        x = x * 2; // The compiler will assign this.x = x at the end!
    }
}
```

### Guaranteed Execution During Deserialization

Because Java Object Serialization for Records is bound to the canonical constructor, **all compact constructor validations and defensive copies are guaranteed to execute during deserialization**, completely preventing corrupted objects from entering the JVM heap.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Syntax:** `public RecordName { ... }` (No parameters in parentheses).
- **Core Purpose:** Validation, normalization (trimming/casing), and defensive copying (`List.copyOf`).
- **Auto-Assignment:** Compiler automatically synthesizes `this.field = param;` at the end of the block.
- **Parameter Reassignment:** Modifying parameters inside the block (e.g. `x = Math.abs(x)`) directly alters the assigned field value.
- **Gotcha:** Explicit `this.field = value;` assignments inside a compact constructor will not compile.

**Common Follow-up Questions:**
- *"Can a compact constructor have a `throws` clause?"* → Yes; `public User throws InvalidInputException { ... }` is valid.
- *"Can you use annotations on a compact constructor?"* → Yes; annotations like `@Deprecated` or custom security interceptors can be placed on compact constructors.
- *"What happens if an exception is thrown in a compact constructor during JSON deserialization (Jackson)?"* → Jackson catches the `IllegalArgumentException` and translates it into an `InvalidDefinitionException` or HTTP 400 Bad Request error.

**Red Flags (DO NOT Say):**
- ❌ *"Compact constructors are used to declare extra fields for the record."* (Compact constructors are for validation and normalization; extra fields are forbidden).
- ❌ *"You must explicitly assign `this.x = x;` at the end of a compact constructor."* (This is a compilation error; the compiler assigns fields automatically).
- ❌ *"Compact constructors only run when creating records manually, not during deserialization."* (They are guaranteed to run during Java object deserialization).
