# What is the Difference Between List<?> and List<Object>?

---

## 🟢 Junior Level

The core difference between `List<?>` and `List<Object>` is **variance and mutation safety**:

```
  ┌─────────────────────────────────────────────────────────┬─────────────────────────────────────────────────────────┐
  │ 📦 `List<Object>` — Concrete & Invariant                │ ❓ `List<?>` — Unbounded Wildcard (Read-Only)           │
  ├─────────────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ • A list specifically holding `Object` elements.        │ • A list holding elements of an **unknown type**.       │
  │ • **INVARIANT**: Cannot accept `List<String>`.          │ • **UNIVERSAL SUPERTYPE**: Accepts any `List<T>`.       │
  │ • **READ / WRITE**: You can insert any `Object`.        │ • **READ-ONLY**: Cannot insert any element (except `null`)│
  └─────────────────────────────────────────────────────────┴─────────────────────────────────────────────────────────┘
```

```java
// 1. List<Object> is strictly INVARIANT:
List<Object> objectList = new ArrayList<>();
objectList.add("Text");
objectList.add(100); // 🟢 Can add any object

List<String> stringList = new ArrayList<>();
// objectList = stringList; // 🛑 COMPILE ERROR! Invariance prevents this!

// 2. List<?> is the SUPERTYPE of all lists:
List<?> wildcardList = stringList; // 🟢 VALID: List<?> accepts List<String>!
Object item = wildcardList.get(0); // 🟢 Safe Read: returns Object
// wildcardList.add("New");        // 🛑 COMPILE ERROR! Cannot write to List<?>!
```

## 🟡 Middle Level

### The Definitive Comparison Matrix

```
  ┌──────────────────────────────┬──────────────────────────────┬──────────────────────────────┬──────────────────────────────┐
  │ Feature                      │ `List` (Raw Type)            │ `List<Object>`               │ `List<?>` (Wildcard)         │
  ├──────────────────────────────┼──────────────────────────────┼──────────────────────────────┼──────────────────────────────┤
  │ **Type Safety**              │ 🔴 **UNSAFE** (Opt-out)      │ 🟢 **100% Safe**             │ 🟢 **100% Safe**             │
  ├──────────────────────────────┼──────────────────────────────┼──────────────────────────────┼──────────────────────────────┤
  │ **Subtyping (Assignment)**   │ Accepts any list (Unchecked) │ Accepts ONLY `List<Object>`  │ **Accepts ANY `List<T>`**    │
  ├──────────────────────────────┼──────────────────────────────┼──────────────────────────────┼──────────────────────────────┤
  │ **Adding Elements (`.add`)** │ 🟢 Any `Object`              │ 🟢 Any `Object`              │ 🔴 **BANNED** (Except `null`)│
  ├──────────────────────────────┼──────────────────────────────┼──────────────────────────────┼──────────────────────────────┤
  │ **Reading Elements (`.get`)**│ ⚠️ Returns `Object` (Casts)  │ 🟢 Returns `Object`          │ 🟢 Returns `Object`          │
  └──────────────────────────────┴──────────────────────────────┴──────────────────────────────┴──────────────────────────────┘
```

### Why Can't You Add Elements to `List<?>`?

If the compiler allowed writing to `List<?>`, it would corrupt the underlying collection:

```java
List<String> strings = new ArrayList<>();
List<?> unknown = strings; // Allowed because List<?> is supertype of all lists

// If Java allowed this:
// unknown.add(12345); // 💥 Inserts an INTEGER into a List<String>!

String s = strings.get(0); // 💥 ClassCastException at runtime!
```

Because the compiler cannot verify the concrete type represented by `?`, it **forbids adding any object** (other than literal `null`).

## 🔴 Senior Level

### Wildcard Capture Helper Pattern

Because `List<?>` is read-only, you cannot directly swap or mutate its elements. To manipulate the list while preserving type safety, use a **generic helper method to capture the wildcard**:

```java
public class ListUtils {

    // Public API accepts any list using wildcard:
    public static void swapFirstAndLast(List<?> list) {
        if (!list.isEmpty()) {
            swapHelper(list); // 🚀 Captures wildcard as type variable T!
        }
    }

    // Private helper method binds '?' to named type parameter T:
    private static <T> void swapHelper(List<T> list) {
        T first = list.get(0);
        T last = list.get(list.size() - 1);
        list.set(0, last);           // 🟢 Valid: T is known and identical!
        list.set(list.size() - 1, first);
    }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`List<Object>`:** A list of objects; **invariant** (does not accept `List<String>`); supports adding any object.
- **`List<?>`:** A list of unknown type; **universal supertype** of all lists; **read-only** (cannot add elements except `null`).
- **Raw `List`:** Legacy type; disables compiler type safety checks (never use in new code).
- **Rule of Thumb:** Use `List<?>` when writing utility methods that only inspect collection structure (e.g. `size()`, `clear()`, `isEmpty()`, printing elements).

**Common Follow-up Questions:**
- *"Can you add `null` to `List<?>`?"* → Yes; `null` is a member of every reference type in Java, so `list.add(null)` is legal.
- *"Why is `List<String>` not a subtype of `List<Object>`?"* → Because if it were, you could assign `List<Object> objs = stringList; objs.add(new Date());`, causing heap pollution and crashing when reading from `stringList`.
- *"What is the difference between `List<?>` and `List<? extends Object>`?"* → They are 100% equivalent in Java semantics and bytecode.

**Red Flags (DO NOT Say):**
- ❌ *"List<?> and List<Object> are identical."* (`List<Object>` is invariant and mutable; `List<?>` is covariant and read-only).
- ❌ *"You can add strings to `List<?>` if the list was created as an ArrayList."* (You cannot add any object to `List<?>` regardless of implementation).
- ❌ *"Use raw `List` instead of `List<?>` because it lets you add elements."* (Raw types destroy compile-time safety and cause heap pollution).
