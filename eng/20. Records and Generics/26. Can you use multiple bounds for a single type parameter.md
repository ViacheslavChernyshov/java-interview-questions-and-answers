# Can You Use Multiple Bounds for a Single Type Parameter?

---

## 🟢 Junior Level

**YES!** Java Generics allows a type parameter to have **multiple bounds** using the ampersand **`&`** intersection operator:

```java
// T MUST extend Number AND implement Comparable<T>:
public class SortedNumberBox<T extends Number & Comparable<T>> {
    private final T value;

    public SortedNumberBox(T value) {
        this.value = value;
    }

    public boolean isGreaterThan(T other) {
        // 🚀 We can invoke methods from BOTH Number (doubleValue) AND Comparable (compareTo)!
        return this.value.compareTo(other) > 0;
    }
}
```

```
  Syntax Rules:
  • 🟢 `<T extends ClassA & InterfaceB & InterfaceC>`
  • ❌ `<T extends InterfaceB & ClassA>` (Compile Error: The class MUST come first!)
  • ❌ `<T extends ClassA & ClassB>` (Compile Error: Multiple class inheritance is illegal!)
```

## 🟡 Middle Level

### The 3 Golden Rules of Multiple Bounds

```
  ┌───┬──────────────────────────────────┬─────────────────────────────────────────────────────────────────┐
  │ # │ Golden Rule                      │ Compiler Specification & Error                                  │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 1 │ **Class Bound Must Come FIRST**  │ If a class bound exists, it must be the first listed bound.     │
  │   │                                  │ `T extends Number & Runnable` (Valid)                           │
  │   │                                  │ `T extends Runnable & Number` (Compile Error!)                  │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 2 │ **Max 1 Class Bound**            │ Only one class can be specified; all other bounds must be       │
  │   │                                  │ interfaces.                                                     │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 3 │ **Erasure to the FIRST Bound**   │ In JVM bytecode, `T` erases to the **first listed bound**.      │
  │   │                                  │ `<T extends Number & Serializable>` erases to `Number`.         │
  └───┴──────────────────────────────────┴─────────────────────────────────────────────────────────────────┘
```

### Erasure to the First Bound in Bytecode

```java
// Source Code:
public class DataProcessor<T extends Reader & AutoCloseable> {
    public void process(T resource) throws IOException {
        resource.read();  // Method from Reader (First Bound)
        resource.close(); // Method from AutoCloseable (Second Bound)
    }
}

// JVM Bytecode after Erasure (T -> Reader):
public class DataProcessor {
    public void process(Reader resource) throws IOException {
        resource.read(); // Direct invocation
        ((AutoCloseable) resource).close(); // 👈 Compiler inserts checkcast to AutoCloseable!
    }
}
```

## 🔴 Senior Level

### Lambda Intersection Types in Distributed Computing (Apache Spark / Flink)

In Java 8+, intersection types can be used in **explicit casts** to attach multiple interface contracts to a single lambda expression:

```java
// 🚀 Creates a Lambda that is BOTH a Runnable AND java.io.Serializable:
Runnable task = (Runnable & Serializable) () -> System.out.println("Processing distributed job");
```

> [!IMPORTANT]
> **Why is this critical in Distributed Systems (Spark, Flink, Hazelcast)?**
> Distributed engines serialize lambdas and send them across network sockets to remote worker nodes. A standard lambda `() -> ...` is NOT serializable and crashes with `NotSerializableException`. Casting to `(Runnable & Serializable)` enables seamless network distribution!

### Conflicting Method Signatures Trap

If two interfaces in multiple bounds declare the same method name with incompatible return types, compilation fails:

```java
interface Alpha { String getId(); }
interface Beta  { Long getId(); }

// ❌ COMPILE ERROR: Cannot inherit getId() with unrelated return types!
// public class EntityBox<T extends Alpha & Beta> {}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Syntax:** Separate multiple bounds with `&` (`<T extends ClassA & InterfaceB & InterfaceC>`).
- **Class Placement:** The class bound **must** be listed first.
- **Max Classes:** Maximum of 1 class bound (multiple classes violate Java's single inheritance model).
- **Erasure Target:** `T` erases to the **first bound** in bytecode; method calls on subsequent bounds insert synthetic `checkcast` instructions.
- **Intersection Casts:** `(Runnable & Serializable)` enables creating serializable lambdas for distributed engines like Spark and Flink.

**Common Follow-up Questions:**
- *"Can you use multiple bounds with wildcards (e.g. `List<? extends Number & Comparable>` )?"* → No! Multiple bounds are only legal on **Type Parameter declarations** (`<T extends A & B>`), not on Wildcards (`?`).
- *"How does Reflection inspect multiple bounds?"* → Call `TypeVariable.getBounds()`, which returns a `Type[]` containing all bounds (`[Number.class, Comparable.class]`).
- *"Does the order of interface bounds matter if there is no class bound?"* → Yes! While both orders compile (`<T extends A & B>` and `<T extends B & A>`), `T` will erase to `A` in the first case and to `B` in the second case in bytecode.

**Red Flags (DO NOT Say):**
- ❌ *"You can specify multiple classes: `<T extends Thread & Exception>`."* (Java strictly prohibits multiple class inheritance).
- ❌ *"Place interfaces first and the class last in the bound list."* (The class bound must always come first).
- ❌ *"You can use multiple bounds on wildcards: `void test(List<? extends A & B> list)`."* (Multiple bounds are forbidden on wildcards).
