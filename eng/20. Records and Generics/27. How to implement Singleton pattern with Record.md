# How to Implement Singleton Pattern with Record?

---

## 🟢 Junior Level

You can implement a **Singleton** using a Java Record by declaring a `public static final` constant or a static `getInstance()` factory method:

```java
public record AppConfig(String environment, int maxPoolSize, Duration timeout) {

    // 🚀 Static Singleton Instance:
    public static final AppConfig INSTANCE = 
        new AppConfig("PRODUCTION", 50, Duration.ofSeconds(30));

    // Optional Static Accessor:
    public static AppConfig getInstance() {
        return INSTANCE;
    }
}

// Usage:
AppConfig config = AppConfig.INSTANCE;
System.out.println(config.environment()); // "PRODUCTION"
```

```
  Why Records Make Great Configuration Holders:
  • 🔒 Built-in Immutability: Components cannot be accidentally mutated at runtime.
  • ⚖️ Automated Contracts: Clean `equals()`, `hashCode()`, and `toString()`.
  • 🧼 Concise Syntax: 1 line replaces dozens of lines of traditional singleton boilerplate.
```

---

## 🟡 Middle Level

### The Crucial Nuance: Record Singleton vs. Enum Singleton

> [!WARNING]
> While records work great as **global immutable configuration objects**, they **DO NOT provide strict singleton enforcement** like Enums!
>
> In Java, a `record` cannot make its canonical constructor `private` if the record class is `public`. Therefore, other classes can still invoke `new AppConfig(...)` to create other instances!

```java
// Other code can still create additional instances:
AppConfig customConfig = new AppConfig("STAGING", 10, Duration.ofSeconds(5));
```

#### The Industry Gold Standard: Enum Singleton (*Effective Java* Item 3)

If you need **100% strict singleton enforcement** (immune to reflection and serialization attacks), **`enum` remains superior**:

```java
// 🏆 Joshua Bloch's Enum Singleton: Strictly enforces exactly ONE instance:
public enum GlobalConfigManager {
    INSTANCE;

    private final String clusterUrl = "https://cluster.internal";

    public String getClusterUrl() { return clusterUrl; }
}
```

### Strict Singleton Enforcement with Record via Compact Constructor

If you must use a Record as a strict singleton, you can guard against multiple instantiations inside the compact constructor:

```java
public record SystemLicense(String key, Instant expiresAt) {

    private static final AtomicBoolean INSTANTIATED = new AtomicBoolean(false);
    public static final SystemLicense INSTANCE = new SystemLicense("LIC-PROD-999", Instant.MAX);

    public SystemLicense {
        // 🛡️ Prevent duplicate instantiation:
        if (INSTANTIATED.getAndSet(true)) {
            throw new IllegalStateException("SystemLicense is a Singleton and cannot be instantiated again!");
        }
    }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **How to Implement:** Declare a `public static final RecordType INSTANCE = new RecordType(...)`.
- **Primary Benefit:** Thread-safe, transparent, immutable global configuration/sentinel data carrier.
- **Constructor Limitation:** A public record's canonical constructor cannot be private; external callers can call `new Record(...)` unless explicitly blocked in a compact constructor.
- **Enum Comparison:** For strict, unbreakable singletons, **`enum`** remains the best approach (*Effective Java* Item 3).
- **Best Use Case:** Use Record singletons for **Domain Sentinels** (`Money.ZERO_USD`, `Point.ORIGIN`, `AppConfig.DEFAULT`).

**Common Follow-up Questions:**
- *"What happens when a record singleton is serialized and deserialized?"* → Object serialization invokes the record's canonical constructor, producing a new distinct instance with matching values (`record1.equals(record2) == true`, but `record1 != record2`).
- *"Can you use `readResolve()` in a record to preserve reference identity during serialization?"* → Yes; implementing `private Object readResolve() { return INSTANCE; }` inside a record will substitute the deserialized record with the singleton instance.
- *"Why does the JVM prohibit reflective instantiation of Enums but allow Records?"* → Enums have special JVM-level protections in `Constructor.newInstance()`, which explicitly throws an `IllegalArgumentException` if the target class is an Enum.

**Red Flags (DO NOT Say):**
- ❌ *"Records make the canonical constructor private by default."* (Record constructors have the same visibility modifier as the record class).
- ❌ *"Record singletons are 100% immune to serialization duplicate creation like Enums."* (Records deserialize via canonical constructors, creating new instances unless `readResolve()` is implemented).
- ❌ *"You should replace all Enum singletons with Records in modern Java."* (Enum singletons remain the safest pattern for strict service singletons; Record singletons are best for immutable sentinel data).
