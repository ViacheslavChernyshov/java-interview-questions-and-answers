# What is Record in Java and Since Which Version are They Available?

---

## 🟢 Junior Level

A **`record`** in Java is a special class type designed to act as an **immutable, transparent data carrier**. 

It was previewed in Java 14/15 and officially finalized as a standard language feature in **Java 16 (JEP 395)**:

```
  Data Carrier Analogy:
  • Regular Java Class: A 60-line boilerplate construction of private fields, telescoping constructors, 
    getter methods, setter methods, equals(), hashCode(), and toString().
  • Java Record: A 1-line declaration where the state header defines the entire class contract!
```

```java
// 🚀 1 Line of Modern Java replaces 60 lines of boilerplate:
public record UserDTO(Long id, String username, String email) {}

// Usage:
UserDTO user = new UserDTO(1L, "alice", "alice@example.com");

System.out.println(user.username()); // "alice" (Accessor method, NO 'get' prefix)
System.out.println(user);            // UserDTO[id=1, username=alice, email=alice@example.com]
```

## 🟡 Middle Level

### What the Java Compiler Automatically Synthesizes

When you declare `public record Point(int x, int y) {}`, the `javac` compiler generates bytecode equivalent to:

```java
// Conceptual bytecode expansion generated by the compiler:
public final class Point extends java.lang.Record {
    private final int x;
    private final int y;

    // 1. Canonical Constructor:
    public Point(int x, int y) {
        this.x = x;
        this.y = y;
    }

    // 2. Component Accessors (No 'get' prefix):
    public int x() { return this.x; }
    public int y() { return this.y; }

    // 3. Value-based equals(), hashCode(), and toString() generated via invokedynamic:
    @Override public boolean equals(Object o) { /* compares all components */ }
    @Override public int hashCode() { /* hashes all components */ }
    @Override public String toString() { /* Point[x=..., y=...] */ }
}
```

## 🔴 Senior Level

### Java 21 Record Patterns & Pattern Matching for `switch` (JEP 440)

In modern Java 21, Records enable powerful structural deconstruction:

```java
public sealed interface Shape permits Circle, Rectangle {}
public record Circle(double radius) implements Shape {}
public record Rectangle(double width, double height) implements Shape {}

// Java 21 Record Pattern Matching:
public static double calculateArea(Shape shape) {
    return switch (shape) {
        case Circle(double r) -> Math.PI * r * r;
        case Rectangle(double w, double h) -> w * h;
    };
}
```

### HotSpot Bytecode Implementation: `invokedynamic` & `ObjectMethods`

Unlike traditional code generation tools (like Lombok), `javac` generates calls to **`java.lang.runtime.ObjectMethods.bootstrap`** via `invokedynamic` (Indy) instructions for `equals()`, `hashCode()`, and `toString()`. This allows the JVM runtime to dynamically optimize and inline record equality checks with zero static boilerplate overhead.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Standardized In:** **Java 16** (JEP 395).
- **Core Definition:** An immutable, transparent data carrier subclassing `java.lang.Record`.
- **Auto-Generated:** `private final` fields, canonical constructor, component accessors (no `get`), `equals()`, `hashCode()`, and `toString()`.
- **Class Modifiers:** Automatically **`final`** (cannot be subclassed).
- **Accessor Naming:** Accessor methods match the component name directly (`user.email()`, NOT `user.getEmail()`).

**Common Follow-up Questions:**
- *"Can a record inherit from another class?"* → No, because all records already implicitly extend `java.lang.Record` and Java does not support multiple class inheritance. However, records can implement any number of interfaces.
- *"Can you declare mutable fields inside a record?"* → No instance fields can be declared outside the record header; header components are always `private final`. However, if a component is a mutable object (e.g. `List`), its internal elements can still be mutated (shallow immutability).
- *"How do records interact with JPA / Hibernate?"* → Records can be used for JPA **DTO Projections** (`SELECT new com.example.UserDTO(...)`), but they cannot be JPA `@Entity` classes because JPA requires non-final classes and no-arg constructors.

**Red Flags (DO NOT Say):**
- ❌ *"Records were introduced in Java 8."* (Records were previewed in Java 14 and standardized in Java 16).
- ❌ *"Records generate JavaBeans getters like `getName()` and setters like `setName()`."* (Records generate accessor methods matching component names `name()` and have NO setters).
- ❌ *"Records are just syntactic sugar for Lombok `@Data`."* (Lombok `@Data` creates mutable classes; Records are JVM-native, immutable classes extending `java.lang.Record`).
