# Can You Use Primitive Types as Generic Parameters?

---

## 🟢 Junior Level

**NO!** In Java, you **cannot use primitive types** (`int`, `double`, `boolean`, `char`, etc.) as generic type arguments:

```java
// ❌ COMPILE ERROR: Primitive types are illegal as generic arguments:
// List<int> numbers = new ArrayList<>();
// Map<String, double> scores = new HashMap<>();

// 🟢 CORRECT: Use boxed Wrapper Classes instead:
List<Integer> numbers = new ArrayList<>();       // Wrapper for int
Map<String, Double> scores = new HashMap<>();     // Wrapper for double
```

```
  Java Primitive to Wrapper Mapping:
  • `byte` ➔ `Byte`         • `int`    ➔ `Integer`       • `float`   ➔ `Float`        • `boolean` ➔ `Boolean`
  • `short`➔ `Short`        • `long`   ➔ `Long`          • `double`  ➔ `Double`       • `char`    ➔ `Character`
```

---

## 🟡 Middle Level

### Why are Primitives Banned in Generics?

The restriction is a direct consequence of **Type Erasure**:
1. At compile time, `<T>` is erased to **`java.lang.Object`**.
2. All generic variables in bytecode become object reference pointers (`Ljava/lang/Object;`).
3. In Java's type system, **primitives do not inherit from `java.lang.Object`** and cannot be represented as memory heap pointers.

```
  Memory Layout Disparity:
  • `int`: 4 bytes of raw scalar bits on stack/registers (Zero header, zero indirection).
  • `Integer`: 24 bytes on the Java Heap (12/16-byte object header + 4-byte payload + 8-byte pointer).
```

### The 2 Hidden Traps of Boxed Generics

#### 1. The `NullPointerException` Unboxing Trap

```java
Map<String, Integer> map = new HashMap<>();
// map.get("missing_key") returns null!

// 💥 THROWS NullPointerException: JVM attempts to invoke .intValue() on null!
int score = map.get("missing_key"); 
```

#### 2. Garbage Collection & Memory Overhead

Storing 1,000,000 integers in `List<Integer>` consumes **~32 MB** of heap memory and creates 1,000,000 objects. A primitive `int[]` array consumes only **4 MB** (8x memory savings) with zero GC pressure!

## 🔴 Senior Level

### High-Performance Solutions for Primitive Collections

When building high-throughput or low-latency systems (HFT, game engines, big data analytics), avoid boxed generics using these alternatives:

```
  ┌───┬──────────────────────────────────┬─────────────────────────────────────────────────────────────────┐
  │ # │ Strategy                         │ Description & Tooling                                           │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 1 │ **JDK Specialized Streams**      │ Use `IntStream`, `LongStream`, `DoubleStream` (Zero boxing).    │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 2 │ **Functional Specializations**   │ Use `IntFunction<R>`, `ToIntFunction<T>`, `LongConsumer`.        │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 3 │ **Specialized Collections Libs** │ Use **fastutil**, **Eclipse Collections**, or **HPPC**          │
  │   │                                  │ (e.g. `IntArrayList`, `Long2ObjectOpenHashMap`).                │
  └───┴──────────────────────────────────┴─────────────────────────────────────────────────────────────────┘
```

```java
// Fastutil primitive collection example (Zero autoboxing, contiguous memory):
IntArrayList fastList = new IntArrayList();
fastList.add(42); // Stored as raw 4-byte primitive int in memory!
```

### The Future: Project Valhalla & Universal Generics (JEP 401)

OpenJDK's **Project Valhalla** introduces **Value Objects** and **Specialized Generics**:
- Enables flat, headerless objects (`value class Point(int x, int y)`).
- Will enable **Universal Generics** where `List<int>` or `List<Point>` can be instantiated directly with contiguous, cache-friendly memory layouts.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Answer:** No; generics only accept reference types because type erasure maps `<T>` to `java.lang.Object`.
- **Workaround:** Use boxed wrapper classes (`Integer`, `Double`, etc.) with automatic Autoboxing.
- **Overhead:** Boxed wrappers cause 4x–8x memory inflation, cache line misses, and GC pressure.
- **NPE Danger:** Automatic unboxing of a `null` wrapper throws `NullPointerException`.
- **JDK Specializations:** Standard JDK provides `IntStream`, `LongStream`, and `IntPredicate` to bypass boxing.

**Common Follow-up Questions:**
- *"What happens behind the scenes during `list.add(5)` on `List<Integer>`?"* → The compiler replaces it with `list.add(Integer.valueOf(5))` (Autoboxing).
- *"How does `Integer.valueOf(int)` optimize memory for small numbers?"* → It caches and reuses `Integer` instances in the range `-128` to `127` from the `IntegerCache`.
- *"What high-performance libraries replace boxed generic collections?"* → Fastutil, Eclipse Collections, and Agrona provide unboxed primitive collections (`Int2ObjectHashMap`, `LongArrayList`).

**Red Flags (DO NOT Say):**
- ❌ *"You can use `List<int>` starting in Java 17."* (Primitive generics are not supported in any released Java version).
- ❌ *"Autoboxing has zero performance overhead."* (Autoboxing allocates heap objects and causes severe memory and GC overhead in hot paths).
- ❌ *"Unboxing a null Integer defaults to 0."* (Unboxing `null` throws an immediate `NullPointerException`).
