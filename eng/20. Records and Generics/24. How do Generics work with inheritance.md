# How Do Generics Work with Inheritance?

---

## 🟢 Junior Level

The most critical rule of Java Generics is: **Generics are INVARIANT!**

Even though `Integer` is a subtype of `Number`, **`List<Integer>` is NOT a subtype of `List<Number>`**:

```java
Integer num = 10;
Number parent = num; // 🟢 Regular inheritance works (Integer IS-A Number)

List<Integer> intList = new ArrayList<>();
// List<Number> numList = intList; // 🛑 COMPILE ERROR! Incompatible types!
```

```
  Why Generics are Invariant (Heap Pollution Defense):
  If `List<Number> numList = intList;` were allowed:
  numList.add(3.14); // 💥 Inserts a DOUBLE into an integer list!
  Integer val = intList.get(0); // 💥 ClassCastException at runtime!
```

### The 2 Dimensions of Generic Subtyping

```
  ┌─────────────────────────────────────────────────────────┬─────────────────────────────────────────────────────────┐
  │ 1. Parameter Type Subtyping (INVARIANT)                 │ 2. Collection Base Type Subtyping (POLYMORPHIC)         │
  ├─────────────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ `List<Integer>` is NOT a `List<Number>`                 │ `ArrayList<String>` **IS-A** `List<String>`             │
  │ `List<String>` is NOT a `List<Object>`                  │ `List<String>` **IS-A** `Collection<String>`            │
  │ `Set<Dog>` is NOT a `Set<Animal>`                       │ `Collection<String>` **IS-A** `Iterable<String>`        │
  └─────────────────────────────────────────────────────────┴─────────────────────────────────────────────────────────┘
```

### Achieving Covariance & Contravariance with Wildcards

To establish subtype relationships between different type arguments, use **Wildcards**:

```java
// Covariance (Upper Bound): List<? extends Number> is the supertype of all numeric lists:
List<? extends Number> covariantList = new ArrayList<Integer>(); // 🟢 Valid!
covariantList = new ArrayList<Double>();                         // 🟢 Valid!

// Contravariance (Lower Bound): List<? super Integer> is the supertype of all integer consumers:
List<? super Integer> contravariantList = new ArrayList<Number>(); // 🟢 Valid!
contravariantList = new ArrayList<Object>();                       // 🟢 Valid!
```

## 🔴 Senior Level

### Subclassing Generic Classes

When a class extends a generic superclass or implements a generic interface, it can choose from **3 architectural approaches**:

```
  ┌───┬──────────────────────────────────┬─────────────────────────────────────────────────────────────────┐
  │ # │ Subclassing Approach             │ Code Example                                                    │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 1 │ **Pass Type Parameter Through**  │ `class CustomList<T> extends ArrayList<T> {}`                   │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 2 │ **Specialize to Concrete Type**  │ `class StringList extends ArrayList<String> {}`                 │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 3 │ **Expand Type Parameters**       │ `class MultiMap<K, V> extends HashMap<K, List<V>> {}`           │
  └───┴──────────────────────────────────┴─────────────────────────────────────────────────────────────────┘
```

```java
// Example: Specializing a Generic Interface:
public interface Repository<T, ID> {
    Optional<T> findById(ID id);
}

// Subclass pins concrete types (triggers compiler Bridge Methods!):
public class UserRepository implements Repository<User, Long> {
    @Override
    public Optional<User> findById(Long id) {
        return Optional.empty();
    }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Invariance Invariant:** `List<Child>` does NOT extend `List<Parent>`.
- **Base Polymorphism:** `ArrayList<T>` extends `List<T>` (as long as type parameter $T$ is identical).
- **Wildcard Subtyping:** `List<? extends Parent>` is the supertype of `List<Child>`.
- **Subclassing:** Subclasses can propagate type parameters (`<T>`), specialize them (`<String>`), or add new ones (`<K, V>`).

**Common Follow-up Questions:**
- *"Why are arrays covariant while generics are invariant?"* → Arrays were made covariant in Java 1.0 (before generics existed) so methods like `Arrays.sort(Object[])` could work. Generics were designed in Java 5 with strict invariance to guarantee compile-time type safety.
- *"What happens under the hood when a class implements `Comparable<String>`?"* → The compiler generates a synthetic **Bridge Method** `compareTo(Object)` in bytecode to preserve virtual method dispatch after type erasure.
- *"Can a class implement the same generic interface with two different type arguments (e.g. `implements List<String>, List<Integer>`)?"* → No! Because both erase to raw `List`, the class would implement the same interface twice with conflicting methods, causing a compile-time error.

**Red Flags (DO NOT Say):**
- ❌ *"List<Integer> is a subtype of List<Number> because Integer extends Number."* (Generics are strictly invariant; they share no subtype relationship).
- ❌ *"ArrayList<String> is not a List<String>."* (`ArrayList<T>` is a subtype of `List<T>` when the type parameter matches).
- ❌ *"You can never pass a `List<Dog>` to a method expecting animals."* (You can if the method accepts `List<? extends Animal>`).
