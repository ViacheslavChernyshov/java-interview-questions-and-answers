# Can You Inherit From Record or Have Record Inherit From Another Class?

---

## 🟢 Junior Level

**NO to both.** Java imposes two strict compile-time rules regarding Record inheritance:

```
  ┌───┬──────────────────────────────────┬─────────────────────────────────────────────────────────────────┐
  │ # │ Inheritance Rule                 │ Reason / Compiler Error                                         │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 1 │ **Cannot inherit FROM a Record** │ Every record is **implicitly `final`**; subclasses are illegal. │
  ├───┼──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ 2 │ **A Record cannot extend another │ Every record already **implicitly extends `java.lang.Record`**; │
  │   │  class**                         │ Java prohibits multiple class inheritance.                      │
  └───┴──────────────────────────────────┴─────────────────────────────────────────────────────────────────┘
```

```java
public record Point(int x, int y) {}

// ❌ COMPILE ERROR: Cannot inherit from final record:
// public class ColoredPoint extends Point {}

// ❌ COMPILE ERROR: Records cannot declare an extends clause:
// public record User(String name) extends BaseEntity {}
```

> [!NOTE]
> **What Records CAN Do:**
> While class inheritance is forbidden, records can implement **any number of interfaces**:
> ```java
> public record User(String name, int age) implements Serializable, Comparable<User> {
>     @Override public int compareTo(User other) { return Integer.compare(this.age, other.age); }
> }
> ```

## 🟡 Middle Level

### Why Did Java Language Architects Ban Record Inheritance?

```
  ┌──────────────────────────────┬─────────────────────────────────────────────────────────────────────────────────┐
  │ Architectural Reason         │ Deep Technical Explanation                                                      │
  ├──────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ **1. Semantic Transparency** │ A record's state must be **100% defined by its component header**. If a         │
  │                              │ superclass had hidden fields, component deconstruction would break.             │
  ├──────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ **2. `equals()` & Symmetry** │ Subclassing value types causes the famous **ColorPoint symmetry violation**     │
  │                              │ (*Effective Java* Item 10), breaking `equals()` transitive consistency.         │
  ├──────────────────────────────┼─────────────────────────────────────────────────────────────────────────────────┤
  │ **3. JIT Optimization**      │ Because records are `final`, HotSpot JIT engines perform **monomorphic call     │
  │                              │ devirtualization** and aggressive scalar replacement.                           │
  └──────────────────────────────┴─────────────────────────────────────────────────────────────────────────────────┘
```

### Idiomatic Alternatives to Inheritance

#### 1. Composition (HAS-A instead of IS-A)

```java
// ❌ WRONG: Trying to inherit from a BaseAuditEntity:
// public record User(Long id, String name) extends BaseAuditEntity {}

// 🟢 SENIOR BEST PRACTICE: Clean composition of a reusable audit record:
public record AuditMetadata(Instant createdAt, String createdBy) {}

public record User(Long id, String name, AuditMetadata audit) {}
```

#### 2. Sealed Interfaces (Algebraic Data Types / Sum Types)

```java
// Modern Java 17/21 Polymorphic Domain Modeling:
public sealed interface PaymentMethod permits CreditCard, PayPal, Crypto {}

public record CreditCard(String cardNumber, String cvv) implements PaymentMethod {}
public record PayPal(String email) implements PaymentMethod {}
public record Crypto(String walletAddress, String network) implements PaymentMethod {}
```

## 🔴 Senior Level

### Algebraic Data Types & Pattern Matching in Java 21

Combining **Records with Sealed Interfaces** creates a complete **Algebraic Data Type (ADT)** system:

```java
public static String processPayment(PaymentMethod method) {
    // Exhaustive pattern matching (No `default:` branch needed because hierarchy is sealed!):
    return switch (method) {
        case CreditCard(var number, var cvv) -> "Charging card ending in " + number.substring(12);
        case PayPal(var email)               -> "Redirecting to PayPal for " + email;
        case Crypto(var wallet, var net)     -> "Generating QR for wallet " + wallet + " on " + net;
    };
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Cannot Extend Other Classes:** All records already implicitly extend `java.lang.Record`.
- **Cannot Be Extended:** All records are implicitly `final`.
- **Can Implement Interfaces:** Supports any number of interfaces (`implements A, B, C`).
- **Best Alternative to Inheritance:** **Composition** (embedding child records) and **Sealed Interfaces** (sum types).
- **Core Rationale:** Preserves state transparency, prevents `equals()` symmetry bugs, and enables JIT devirtualization.

**Common Follow-up Questions:**
- *"Can a record be declared `abstract`?"* → No; records are concrete data carriers and cannot be `abstract` or `sealed` (though they can implement sealed interfaces).
- *"Can you define a local record inside a method?"* → Yes! Local records (introduced in Java 16) are implicitly static and are great for temporary intermediate tuple calculations inside streams.
- *"Why can't JPA `@Entity` classes be records?"* → Because JPA/Hibernate requires proxy generation via subclassing (CGLIB/ByteBuddy) and mutable state management (dirty checking), both of which are strictly forbidden by `final` immutable records.

**Red Flags (DO NOT Say):**
- ❌ *"You can extend a record if you remove the `final` keyword."* (Records are implicitly final by language specification; removing `final` is impossible).
- ❌ *"Records cannot achieve polymorphism."* (Records achieve clean polymorphism by implementing sealed interfaces).
- ❌ *"A record can extend another record."* (Record-to-record inheritance is strictly prohibited).
