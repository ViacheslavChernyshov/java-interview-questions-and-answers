# What is the Difference Between <? extends T> and <? super T>?

---

## 🟢 Junior Level

The difference between `<? extends T>` and `<? super T>` is **Covariance (Reading) vs. Contravariance (Writing)**:

```
  ┌─────────────────────────────────────────────────────────┬─────────────────────────────────────────────────────────┐
  │ 📥 `<? extends T>` — Upper Bound (COVARIANCE)           │ 📤 `<? super T>` — Lower Bound (CONTRAVARIANCE)         │
  ├─────────────────────────────────────────────────────────┼─────────────────────────────────────────────────────────┤
  │ • Represents $T$ or any **subclass** of $T$.            │ • Represents $T$ or any **superclass** of $T$.          │
  │ • **PRODUCER**: You can safely **READ** elements as $T$.│ • **CONSUMER**: You can safely **WRITE** $T$ elements. │
  │ • 🛑 **READ-ONLY**: Cannot write items (except `null`). │ • 🛑 **WRITE-ONLY**: Reading only returns `Object`.     │
  └─────────────────────────────────────────────────────────┴─────────────────────────────────────────────────────────┘
```

```java
// 1. <? extends Number> - Reading is SAFE; Writing is FORBIDDEN:
List<? extends Number> producerList = List.of(1, 2, 3);
Number num = producerList.get(0); // 🟢 Safe Read: Guaranteed to be at least a Number!
// producerList.add(10);          // 🛑 Compile Error! Cannot write to ? extends!

// 2. <? super Integer> - Writing is SAFE; Reading is Object:
List<? super Integer> consumerList = new ArrayList<Number>();
consumerList.add(42);             // 🟢 Safe Write: Integer can always be stored in Number/Object!
Object obj = consumerList.get(0); // ⚠️ Read returns bare Object (exact type unknown).
```

## 🟡 Middle Level

### The Definitive Comparison Matrix

```
  ┌──────────────────────────────┬──────────────────────────────────┬──────────────────────────────────────────────────┐
  │ Characteristic               │ `<? extends T>` (Upper Bound)    │ `<? super T>` (Lower Bound)                      │
  ├──────────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **Variance Type**            │ **Covariant**                    │ **Contravariant**                                │
  ├──────────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **PECS Role**                │ **Producer** (Source of data)    │ **Consumer** (Destination of data)               │
  ├──────────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **Reading Elements (`.get`)**│ 🟢 Returns **`T`**               │ ⚠️ Returns bare **`Object`**                     │
  ├──────────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **Writing Elements (`.add`)**│ 🔴 **BANNED** (Except `null`)    │ 🟢 Accepts **`T`** (and subclasses of `T`)       │
  ├──────────────────────────────┼──────────────────────────────────┼──────────────────────────────────────────────────┤
  │ **Permitted Types**          │ `T` and all types **BELOW** `T`  │ `T` and all types **ABOVE** `T` (up to `Object`) │
  └──────────────────────────────┴──────────────────────────────────┴──────────────────────────────────────────────────┘
```

### Why Can't You Add Elements to `List<? extends Number>`?

Consider what would happen if the compiler permitted `.add()`:

```java
List<Integer> intList = new ArrayList<>();
List<? extends Number> numList = intList; // Allowed by covariance!

// If this were allowed by the compiler:
// numList.add(3.14); // 💥 Inserts a DOUBLE into a List<Integer>!

Integer i = intList.get(0); // 💥 Catastrophic runtime ClassCastException!
```

Because `numList` could point to `List<Integer>`, `List<Double>`, or `List<BigDecimal>`, the compiler **forbids adding any object** (other than literal `null`) to maintain absolute type safety.

## 🔴 Senior Level

### The Canonical Example: `Collections.copy()`

The JDK standard library's `Collections.copy()` is the ultimate real-world demonstration of `extends` and `super` working together:

```java
// JDK java.util.Collections source code:
public static <T> void copy(List<? super T> dest, List<? extends T> src) {
    for (int i = 0; i < src.size(); i++) {
        // 1. Read from Producer (src): returns T safely
        T item = src.get(i); 

        // 2. Write to Consumer (dest): accepts T safely
        dest.set(i, item); 
    }
}
```

```java
// Flexible Invocation: Copying List<Integer> into List<Number>:
List<Number> destination = new ArrayList<>(List.of(0, 0, 0));
List<Integer> source = List.of(10, 20, 30);

Collections.copy(destination, source); // 🚀 T inferred as Integer!
```

### Wildcard Capture Helper Pattern

When you need to read and write to a collection with a wildcard (`List<?>`), use a private generic helper method to **capture the wildcard**:

```java
public static void reverseList(List<?> list) {
    reverseHelper(list); // Wildcard capture!
}

// Private helper captures the unknown wildcard as named type variable T:
private static <T> void reverseHelper(List<T> list) {
    List<T> tmp = new ArrayList<>(list);
    for (int i = 0; i < list.size(); i++) {
        list.set(i, tmp.get(list.size() - i - 1)); // 🟢 Safe read and write!
    }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **`<? extends T>`:** Upper bound (Covariant). Used when reading data (**Producer**). Cannot add elements.
- **`<? super T>`:** Lower bound (Contravariant). Used when writing data (**Consumer**). Reading yields `Object`.
- **PECS Rule:** **P**roducer **E**xtends, **C**onsumer **S**uper.
- **JDK Benchmark:** `Collections.copy(List<? super T> dest, List<? extends T> src)`.
- **Wildcard Capture:** Use a private generic `<T>` helper to operate on `List<?>` when both read and write are needed.

**Common Follow-up Questions:**
- *"Can you use both `extends` and `super` in the same wildcard (e.g. `<? extends A super B>`)?"* → No; Java wildcards support either an upper bound or a lower bound, never both simultaneously.
- *"What does unbounded wildcard `List<?>` mean?"* → It is shorthand for `List<? extends Object>`. You can read `Object` from it, but you cannot write anything except `null`.
- *"What is Use-Site Variance vs Declaration-Site Variance?"* → Java uses **Use-Site Variance** (specifying wildcards at method parameter sites). Languages like Kotlin (`out T` / `in T`) and C# use **Declaration-Site Variance** at class/interface definitions.

**Red Flags (DO NOT Say):**
- ❌ *"You can add elements to a `List<? extends Number>` if they are Integers."* (You cannot add any object to `? extends`, not even Integers).
- ❌ *"Reading from `List<? super Integer>` returns an Integer."* (It only returns `Object` because the list could be a `List<Object>`).
- ❌ *"Use `<? extends T>` for methods that modify collections."* (Modifying/consuming collections requires `<? super T>`).
