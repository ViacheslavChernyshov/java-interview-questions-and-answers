# Can You Override Constructor in Record?

---

## 🟢 Junior Level

**YES!** Java records allow you to customize constructors, supporting **3 constructor styles**:

```
  ┌──────────────────────────────────┬─────────────────────────────────────────────────────────────────┐
  │ Constructor Style                │ Syntax & Purpose                                                │
  ├──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ **1. Compact Constructor**       │ `public User { ... }` (Omits parameter list; ideal for          │
  │                                  │ validation and defensive copying).                              │
  ├──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ **2. Explicit Canonical Ctor**   │ `public User(String name, int age) { ... }` (Full parameter list│
  │                                  │ with explicit `this.x = x` assignments).                        │
  ├──────────────────────────────────┼─────────────────────────────────────────────────────────────────┤
  │ **3. Secondary / Overloaded Ctor**│ `public User(String name) { this(name, 0); }` (Alternative args;│
  │                                  │ **MUST** delegate to canonical constructor via `this(...)`).    │
  └──────────────────────────────────┴─────────────────────────────────────────────────────────────────┘
```

```java
public record User(String name, int age) {

    // 🟢 1. Compact Constructor (Validation):
    public User {
        if (age < 0) throw new IllegalArgumentException("Age cannot be negative");
    }

    // 🟢 2. Secondary Constructor (MUST delegate via this(...)):
    public User(String name) {
        this(name, 18); // Delegates to canonical constructor
    }
}
```

## 🟡 Middle Level

### The Mandatory Delegation Invariant for Secondary Constructors

> [!WARNING]
> Any secondary (non-canonical) constructor in a record **MUST invoke another constructor via `this(...)` on its very first line**.
>
> A record constructor is **never permitted to bypass the canonical constructor**!

```java
public record Point(int x, int y) {

    // 🟢 VALID: Delegates to canonical constructor:
    public Point(int scalar) {
        this(scalar, scalar);
    }

    // ❌ COMPILE ERROR: Fails to delegate via this(...):
    // public Point() {
    //     this.x = 0; // Error: Cannot assign to final field x
    //     this.y = 0;
    // }
}
```

## 🔴 Senior Level

### Explicit Canonical vs. Compact Constructor

You can declare **either** an explicit canonical constructor **or** a compact constructor, but **never both**:

```java
// Option A: Explicit Canonical Constructor (Boilerplate assignments required):
public record Range(int start, int end) {
    public Range(int start, int end) {
        if (start > end) throw new IllegalArgumentException("start > end");
        this.start = start; // 👈 Must explicitly assign all fields!
        this.end = end;
    }
}

// Option B: Compact Constructor (Clean & Idiomatic - Preferred):
public record Range(int start, int end) {
    public Range {
        if (start > end) throw new IllegalArgumentException("start > end");
        // 🚀 No `this.start = start` needed! Compiler automatically appends assignments!
    }
}
```

### Access Modifier Rule

The accessibility of the canonical or compact constructor **cannot be more restrictive than the record itself**:
- A `public record` must have a `public` canonical/compact constructor.
- A package-private record must have package-private or `public` constructor.

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Can Override:** Yes, via Compact Constructor, Explicit Canonical Constructor, or Secondary Constructors.
- **Compact Constructor:** The most idiomatic style (`public RecordName { ... }`); parameters are implicit, and field assignments are generated automatically at the end.
- **Delegation Rule:** Secondary constructors **must** delegate to the canonical constructor via `this(...)`.
- **Exclusivity:** A record cannot have *both* a compact constructor and an explicit canonical constructor.
- **Accessibility Rule:** Constructor access modifier cannot be more restrictive than the record class modifier.

**Common Follow-up Questions:**
- *"Can a secondary constructor mutate fields before calling `this(...)`?"* → No; `this(...)` must be the very first statement in the constructor body.
- *"How does a compact constructor modify parameter values before assignment?"* → You can reassign parameters directly inside the compact constructor (e.g. `name = name.trim();`), and the compiler assigns the modified parameter to the field!
- *"Can a record constructor throw checked exceptions?"* → Yes; record constructors can declare `throws Exception`.

**Red Flags (DO NOT Say):**
- ❌ *"Records do not allow any custom constructors."* (Records fully support compact, canonical, and overloaded constructors).
- ❌ *"A secondary constructor can initialize record fields directly without calling `this(...)`."* (All secondary constructors must delegate via `this(...)`).
- ❌ *"Compact constructors require writing `this.field = field;` at the end."* (Field assignments are automatically synthesized by the compiler).
