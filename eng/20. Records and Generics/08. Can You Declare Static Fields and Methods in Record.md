# Can You Declare Static Fields and Methods in Record?

---

## 🟢 Junior Level

**YES, absolutely!** While records strictly forbid extra *instance* fields outside the header, they **fully support static fields, static methods, and static initializer blocks**:

```java
public record User(String username, int age) {

    // 🟢 1. Static Constant:
    public static final int MIN_AGE = 0;
    public static final int MAX_AGE = 150;

    // 🟢 2. Static Factory Method:
    public static User anonymous() {
        return new User("Anonymous", 0);
    }
}

// Usage:
int max = User.MAX_AGE;            // 150
User guest = User.anonymous();      // User[username=Anonymous, age=0]
```

```
  Why are Static Members Allowed?
  • Static fields and methods belong to the Class type (loaded in Metaspace), NOT the instance state.
  • They do not alter or interfere with the record's header-defined data contract.
```

  └───┴──────────────────────────────────┴─────────────────────────────────────────────────────────────────┘

```java
public record EmailAddress(String value) {

    // 🚀 Performance Optimization: Pre-compile Regex once as static constant:
    private static final Pattern EMAIL_PATTERN = 
        Pattern.compile("^[A-Za-z0-9+_.-]+@[A-Za-z0-9.-]+$");

    // Compact constructor uses the static pattern for high-speed validation:
    public EmailAddress {
        if (value == null || !EMAIL_PATTERN.matcher(value).matches()) {
            throw new IllegalArgumentException("Invalid email format: " + value);
        }
        value = value.trim().toLowerCase();
    }
}
```

## 🔴 Senior Level

### Static Initializers & Nested Static Types

Records can contain complex `static { ... }` initialization blocks and nested static abstractions:

```java
public record SecurityToken(String rawToken, Set<String> claims) {

    private static final Map<String, SecurityToken> SYSTEM_TOKENS;

    // 🟢 Static Initializer Block:
    static {
        SYSTEM_TOKENS = Map.of(
            "ROOT", new SecurityToken("SYS-ROOT", Set.of("ADMIN", "SUPERUSER")),
            "ANON", new SecurityToken("SYS-ANON", Set.of("GUEST"))
        );
    }

    public static SecurityToken getSystemToken(String key) {
        return SYSTEM_TOKENS.getOrDefault(key, SYSTEM_TOKENS.get("ANON"));
    }

    // 🟢 Nested Static Interface & Enum inside a Record:
    public enum TokenType { BEARER, MAC }
}
```

## 🎯 Interview Cheat Sheet

**Must Know:**
- **Static Members Permitted:** Static fields, static methods, static constants, and `static { ... }` blocks are 100% supported.
- **Instance Fields Banned:** Non-static instance fields outside the record header are strictly forbidden (`private int count;` will not compile).
- **Top Best Practice:** Use `private static final Pattern` inside records to pre-compile regexes for compact constructor validation.
- **Static Factories:** Idiomatic way to provide convenience creators (e.g. `Point.origin()`, `Money.zero()`).

**Common Follow-up Questions:**
- *"Are static fields in a record included in `equals()`, `hashCode()`, or `toString()`?"* → No; `equals()`, `hashCode()`, and `toString()` operate strictly and exclusively on the record header components.
- *"Can a record contain mutable static variables (like `public static int counter`)?"* → Yes, the compiler allows it, but it is considered an anti-pattern because global mutable state compromises thread safety.
- *"Are nested records automatically static?"* → Yes! Any record declared inside another class or record is **implicitly static**, even without writing the `static` keyword.

**Red Flags (DO NOT Say):**
- ❌ *"Records cannot contain any static methods or static constants."* (Static members are fully supported and widely used).
- ❌ *"Static fields are included in the record's canonical constructor."* (Constructors only initialize instance components from the header).
- ❌ *"A record can declare a private non-static instance field if it is marked static-final."* (Static fields must be explicitly `static`).
