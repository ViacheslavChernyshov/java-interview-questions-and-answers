# Что делает операция reduce()?

---

## 🟢 Junior Level

### Простое определение

**`reduce()` (Редукция / Свёртка)** — это терминальная операция, которая последовательно комбинирует все элементы стрима в **одно итоговое значение** с помощью заданной функции-аккумулятора.

### 3 перегрузки метода `reduce()`:

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5);

// Вариант 1: Без начального значения -> возвращает Optional<T>
// (так как стрим может быть пустым)
Optional<Integer> sum1 = numbers.stream()
    .reduce((a, b) -> a + b); // Optional[15]

// Вариант 2: С начальным значением (identity) -> возвращает T
int sum2 = numbers.stream()
    .reduce(0, (a, b) -> a + b); // 15

// Вариант 3: Со сменой типа и combiner для параллелизма -> возвращает U
int totalStringLength = List.of("Java", "Stream", "API").stream()
    .reduce(0, 
            (acc, str) -> acc + str.length(), // Accumulator
            Integer::sum);                     // Combiner (для потоков)
```

### Аналогия из жизни

Представьте **бухгалтера, считающего сумму чеков на калькуляторе**:
- Начальное значение на экране калькулятора — $0$ (`identity`).
- Бухгалтер берёт первый чек на 100 руб и нажимает «+»: $0 + 100 = 100$.
- Берёт второй чек на 200 руб: $100 + 200 = 300$.
- В конце на экране остаётся одно итоговое число — $300$ (результат свёртки).

## 🟡 Middle Level

### Математические контракты `reduce()`

Для корректной работы функции свёртки (особенно при переключении на `.parallelStream()`) функция обязана соблюдать строгие математические законы:

1. **Нейтральный элемент (Identity)**:
   $$\text{accumulator}(\text{identity}, v) = v$$
   - Для сложения $\text{identity} = 0$ ($0 + x = x$).
   - Для умножения $\text{identity} = 1$ ($1 \times x = x$).
   - Для `String` конкатенации $\text{identity} = ""$.
   - ❌ *Если для сложения ошибочно задать $\text{identity} = 10$, в параллельном стриме 4 потока прибавят 10 четыре раза, и результат будет катастрофически завышен!*

2. **Ассоциативность (Associativity)**:
   $$(a \circ b) \circ c = a \circ (b \circ c)$$
   Порядок расстановки скобок не должен менять результат. Это позволяет `ForkJoinPool` параллельно свернуть левую и правую части коллекции и затем объединить их:
   ```
   [1 + 2] + [3 + 4] = 3 + 7 = 10
   ```

### Опасность: Неассоциативные операции

Если передать неассоциативную операцию (например, вычитание или деление), `parallelStream()` вернёт **неправильный результат**:
```java
// Последовательный стрим: ( (10 - 2) - 3 ) = 5
numbers.stream().reduce((a, b) -> a - b);

// 💥 Параллельный стрим: [10] и [2 - 3 = -1] -> 10 - (-1) = 11 (НЕВЕРНО!)
numbers.parallelStream().reduce((a, b) -> a - b);
```

## 🔴 Senior Level

### Глубокий разбор 3-й сигнатуры: Зачем нужен `Combiner`?

```java
<U> U reduce(U identity, 
             BiFunction<U, ? super T, U> accumulator, 
             BinaryOperator<U> combiner);
```

В этой сигнатуре тип результата `U` отличается от типа элементов стрима `T`:
- **В последовательном стриме**: `combiner` вообще **никогда не вызывается**, работает только `accumulator`.
- **В параллельном стриме (`ForkJoinPool`)**:
  1. Каждый поток берёт свой чанк элементов `T` и накапливает локальный результат типа `U` через `accumulator`.
  2. Когда потоки завершают расчеты, `ForkJoinPool` объединяет полученные результаты `U` по парам с помощью **`combiner`**.

```
Параллельное вычисление длины строк:
Поток 1 ["Java", "8"]  ──► Accumulator ──► Partial Length: 5  ──┐
                                                                ├──► Combiner (5 + 10) ──► 15
Поток 2 ["Concurrency"] ──► Accumulator ──► Partial Length: 10 ──┘
```

### Производительность: Автобоксинг vs Примитивные стримы

Вызов `.reduce(0, (a, b) -> a + b)` на объектах `Stream<Integer>` создает огромное количество временных `Integer` в Heap на каждом промежуточном сложении.
- **В Highload**: Всегда преобразовывать в примитивные стримы:
  ```java
  // ✅ В 10-20 раз быстрее за счёт отсутствия боксинга и векторизации JIT SIMD:
  int sum = list.stream().mapToInt(Integer::intValue).sum();
  ```

## 🎯 Шпаргалка для интервью

**Обязательно знать:**
- `reduce()` — терминальная операция иммутабельной свёртки стрима в одно значение.
- Вариант с 1 аргументом возвращает `Optional<T>` (на пустом стриме вернет `Optional.empty()`).
- Вариант с `identity` возвращает само значение `T` (на пустом стриме вернет `identity`).
- Требования к аккумулятору: **Identity** (нейтральный элемент) и **Ассоциативность** (порядок объединения скобок не важен).
- В 3-й сигнатуре `combiner` используется только в `parallelStream()` для слияния результатов разных потоков.
- Для коллекций (`List`, `Set`, `Map`) вместо `reduce` следует использовать `collect()` во избежание $O(N^2)$ копирования.

**Частые уточняющие вопросы:**
- **Что будет, если вызвать reduce() без identity на пустом стриме?** — Вернёт `Optional.empty()`.
- **Почему вычитание нельзя использовать в parallelStream.reduce()?** — Вычитание не обладает свойством ассоциативности: $(a - b) - c \neq a - (b - c)$.
- **Зачем нужен Combiner в 3-й сигнатуре?** — Для объединения частичных результатов типа `U`, вычисленных разными потоками ForkJoinPool в параллельном режиме.

**Красные флаги (НЕ говорить):**
- ❌ «`reduce()` мутирует переданный `identity` объект на каждом шаге».
- ❌ «В `reduce()` можно безопасно передать `(a, b) -> a - b` для параллельного вычисления».
- ❌ «`Combiner` вызывается после каждого элемента в обычном однопоточном стриме».
