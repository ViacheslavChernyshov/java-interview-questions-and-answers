# Что делают операции findFirst() и findAny()?

---

## 🟢 Junior Level

### Простое определение

Обе операции — **`findFirst()`** и **`findAny()`** — являются **терминальными операциями короткого замыкания (short-circuiting)**, которые ищут элемент в стриме и возвращают результат в виде обёртки **`Optional<T>`**.

- **`findFirst()`**: возвращает **строго первый** элемент в порядке обхода стрима (Encounter Order).
- **`findAny()`**: возвращает **любой подходящий** элемент (позволяет среде выполнения выбрать самый быстрый вариант).

### В чём разница:

В обычном (последовательном) стриме обе операции почти всегда возвращают один и тот же первый элемент.
**Главная разница раскрывается в многопоточном `parallelStream()`**:
- `findFirst()` заставляет потоки синхронизироваться, чтобы вернуть элемент из самой первой части коллекции.
- `findAny()` возвращает элемент из того потока, который **первым завершил вычисление** (максимальная скорость).

### Базовый пример с обработкой `Optional`

```java
List<String> users = List.of("guest_1", "admin", "guest_2", "moderator");

// Ищем первого администратора:
Optional<String> firstAdmin = users.stream()
    .filter(u -> u.startsWith("admin"))
    .findFirst();

// Безопасное извлечение значения:
String result = firstAdmin.orElse("Пользователь не найден");
System.out.println(result); // admin
```

## 🟡 Middle Level

### Encounter Order (Порядок элементов) и тип источника

Поведение `findFirst()` и `findAny()` напрямую зависит от того, является ли источник стрима упорядоченным (Ordered):

| Источник данных | Порядок (Encounter Order) | Поведение `findFirst()` | Поведение `findAny()` в `parallelStream()` |
| :--- | :--- | :--- | :--- |
| **`ArrayList`, `LinkedHashSet`, массивы** | **Присутствует** (строгий индексный порядок) | Всегда вернёт элемент с наименьшим индексом | Вернёт любой элемент, чей поток финишировал раньше |
| **`HashSet`, `HashMap.keySet()`** | **Отсутствует** (зависит от хеш-бакетов) | Вернёт первый элемент в порядке итератора хеш-таблицы | Вернёт любой найденный элемент |

### Сравнение с `anyMatch()` и `limit(1)`

```java
// 1. Если нужно только проверить наличие (boolean) — anyMatch() эффективнее (нет аллокации Optional):
boolean exists = users.stream().anyMatch(u -> u.equals("admin"));

// 2. Если нужно продолжить трансформацию в стриме — limit(1) (возвращает Stream<T>):
List<String> singleList = users.stream().filter(u -> u.startsWith("g")).limit(1).toList();

// 3. Если нужно получить конкретный объект — findFirst() / findAny() (возвращает Optional<T>):
Optional<String> user = users.stream().filter(u -> u.startsWith("g")).findFirst();
```

## 🔴 Senior Level

### Внутреннее устройство: `FindOp` и координация задач `FindTask`

Внутри OpenJDK класс `FindOp` создаёт подзадачи `FindTask` в `ForkJoinPool`:

1. **Для `findAny()`**:
   - Задача делится на подзадачи с помощью `Spliterator.trySplit()`.
   - Как только любой worker-поток находит элемент, он выполняет атомарный вызов `shortCircuit(result)`.
   - Метод `cancelLaterNodes()` мгновенно отменяет все параллельные ветки дерева вычислений.

2. **Для `findFirst()`**:
   - Потоки обязаны сохранять древовидную топологию.
   - Если правая ветка нашла элемент, она **не может завершить операцию**, пока левая ветка не завершит работу (ведь в левой части массива может быть более ранний подходящий элемент).
   - Это приводит к простоям потоков и значительному оверхеду на блокировки.

```
Массив из 1 000 000 элементов в 4 потока:
Thread 1 [0..250k]      ── (Ищет...)
Thread 2 [250k..500k]   ── (Ищет...)
Thread 3 [500k..750k]   ── НАШЕЛ! ──► findAny() СРАЗУ завершает весь стрим и возвращает ответ!
                                  ──► findFirst() БЛОКИРУЕТСЯ и ждёт потоки 1 и 2!
Thread 4 [750k..1000k]  ── (Ищет...)
```

### Коварный Edge Case: `NullPointerException` внутри `Optional`

`findFirst()` и `findAny()` используют `Optional.of(value)` или `Optional.empty()`:
```java
List<String> list = Arrays.asList("A", null, "B");

// ❌ ОШИБКА: Если первый найденный элемент равен null, выбросится NullPointerException!
Optional<String> result = list.stream()
    .filter(Objects::isNull)
    .findFirst(); // java.lang.NullPointerException
```
> [!WARNING]
> Стримы не могут вернуть `Optional`, содержащий `null`. Если стрим содержит `null`-элементы, фильтрация по `isNull` с последующим `findFirst()` гарантированно приведет к NPE.

### Примитивные специализации для Highload

Чтобы избежать боксинга (создания объектов `Integer` / `Double` в куче) в высоконагруженных вычислениях, всегда используйте примитивные стримы:
- `IntStream.findFirst()` $\rightarrow$ `OptionalInt` (хранит примитивный `int` без аллокаций).
- `LongStream.findFirst()` $\rightarrow$ `OptionalLong`.
- `DoubleStream.findFirst()` $\rightarrow$ `OptionalDouble`.

## 🎯 Шпаргалка для интервью

**Обязательно знать:**
- `findFirst()` гарантирует возврат первого элемента согласно порядку обхода (Encounter Order).
- `findAny()` возвращает любой совпавший элемент (оптимизация без привязки к порядку).
- В `parallelStream()` операция `findAny()` выполняется в разы быстрее, так как не требует ожидания левых веток дерева `ForkJoinTask`.
- Обе операции возвращают `Optional<T>` и являются операциями короткого замыкания (Short-Circuiting).
- Если стрим находит `null`-значение, `findFirst()` выбросит `NullPointerException` (так как `Optional` не может содержать `null`).
- Примитивные стримы (`IntStream`) возвращают специализированные `OptionalInt`, исключая boxing-overhead.

**Частые уточняющие вопросы:**
- **Почему findAny быстрее findFirst в параллельных стримах?** — `findAny` мгновенно возвращает результат первого финишировавшего потока; `findFirst` ждёт завершения всех потоков, обрабатывающих более ранние элементы.
- **В чём разница между findFirst() и anyMatch()?** — `findFirst()` извлекает и возвращает сам объект (`Optional<T>`), а `anyMatch()` только проверяет условие и возвращает `boolean`.
- **Что произойдёт, если стрим пустой?** — Методы вернут `Optional.empty()`.

**Красные флаги (НЕ говорить):**
- ❌ «`findAny()` всегда возвращает псевдослучайный элемент из коллекции».
- ❌ «`findFirst()` и `findAny()` работают с одинаковой скоростью на 64-ядерном сервере».
- ❌ «Из `Optional`, возвращаемого `findFirst()`, можно всегда безопасно вызывать `.get()` без проверок».
