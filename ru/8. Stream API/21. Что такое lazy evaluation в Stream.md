# Что такое lazy evaluation в Stream?

---

## 🟢 Junior Level

### Простое определение

**Lazy Evaluation (Ленивые вычисления / Отложенное выполнение)** — это стратегия вычислений в Stream API, при которой промежуточные (intermediate) операции (`filter`, `map`, `peek`) **НЕ выполняются в момент их объявления**, а лишь записываются в план будущего конвейера.

Реальное чтение и обработка элементов начинаются **исключительно в момент вызова терминальной (terminal) операции** (`collect`, `toList`, `forEach`, `findFirst`):

```java
List<String> fruits = List.of("Apple", "Banana", "Apricot");

// 1. Промежуточные операции — ЗДЕСЬ НИЧЕГО НЕ ПРОИСХОДИТ:
Stream<String> stream = fruits.stream()
    .filter(f -> {
        System.out.println("Фильтр: " + f);
        return f.startsWith("A");
    })
    .map(f -> {
        System.out.println("Преобразование: " + f);
        return f.toUpperCase();
    });

System.out.println("--- Терминальная операция ещё не вызвана ---");

// 2. Терминальная операция — ТОЛЬКО СЕЙЧАС начинается работа:
List<String> result = stream.toList();
```

**Вывод в консоль:**
```
--- Терминальная операция ещё не вызвана ---
Фильтр: Apple
Преобразование: Apple
Фильтр: Banana
Фильтр: Apricot
Преобразование: Apricot
```

### Аналогия из жизни

Представьте **кулинарный рецепт в блокноте**:
- Пока вы записываете шаги: «1. Порезать овощи, 2. Пожарить, 3. Посолить» (промежуточные операции), на сковороде ничего не шкворчит и овощи целы.
- Вы начинаете резать и жарить только тогда, когда гости сели за стол и попросили подать ужин (терминальная операция).

## 🟡 Middle Level

### Вертикальное (Vertical) vs Горизонтальное (Horizontal) выполнение

Ключевое отличие Stream API от классической итерации заключается в способе прохождения данных сквозь цепочку вызовов:

#### ❌ Классический императивный подход (Горизонтальный):
```
[Шаг 1: Filter]  Все 1 000 000 элементов фильтруются  ──► Создается промежуточный List 1 (память $O(N)$)
[Шаг 2: Map]     Все элементы списка трансформируются ──► Создается промежуточный List 2 (память $O(N)$)
[Шаг 3: Limit]   Берутся первые 5 элементов           ──► Итоговый List
```

#### ✅ Stream API подход (Вертикальный конвейер):
```
Элемент 1 ──► [Filter: OK] ──► [Map] ──► [Collect]
Элемент 2 ──► [Filter: Skip]
Элемент 3 ──► [Filter: OK] ──► [Map] ──► [Collect]
```
- **Экономия памяти**: промежуточные коллекции вообще **не создаются в памяти** ($O(1)$ накладных расходов).
- **Слияние операций (Pipeline Fusion)**: элемент проходит всю цепочку стадий за один проход, оставаясь в кэше L1/L2 процессора.

## 🔴 Senior Level

### Взаимодействие ленивости с Short-Circuiting и бесконечными стримами

Ленивость делает возможной работу с бесконечными источниками данных:

```java
// Бесконечный генератор UUID:
List<UUID> tokens = Stream.generate(UUID::randomUUID)
    .filter(uuid -> uuid.toString().startsWith("00")) // Потенциально бесконечный перебор
    .limit(5)                                         // Short-circuiting!
    .toList();
```
Благодаря ленивым вычислениям:
1. `Stream.generate()` выдает ровно по одному объекту по требованию (`on-demand pulling`).
2. Как только `limit(5)` получает 5-й подходящий элемент, он отзывает запрос у источника, и бесконечный цикл прерывается.

### Опасности ленивости в Production: Скрытые исключения и отложенные I/O

1. **Скрытые `RuntimeException`**:
   - Ошибка (например, `ArithmeticException: / by zero` или `NullPointerException` внутри `map`) вылетит не в месте создания стрима, а в строке вызова `stream.toList()`.
2. **Транзакционные границы (`@Transactional`)**:
   - Если ленивый стрим возвращен из сервиса в контроллер, чтение элементов из БД произойдет уже **после закрытия сессии Hibernate и транзакции**, вызвав `LazyInitializationException`.

## 🎯 Шпаргалка для интервью

**Обязательно знать:**
- Lazy Evaluation — промежуточные операции стрима не выполняются до момента вызова терминальной операции.
- До терминальной операции стрим является лишь инертным описанием конвейера (Pipeline).
- **Vertical Execution**: каждый элемент проходит все стадии конвейера поочередно, что исключает создание промежуточных коллекций в памяти.
- Ленивость позволяет безопасно обрабатывать бесконечные стримы в связке с short-circuiting операциями (`limit`, `findFirst`).
- Исключения внутри промежуточных лямбд возникают только в точке вызова терминальной операции.

**Частые уточняющие вопросы:**
- **Почему filter() не выполняется сразу?** — Это промежуточная ленивая операция; она лишь регистрирует узел `Sink` в цепочке `AbstractPipeline`.
- **Что такое вертикальное выполнение стрима?** — Обработка элементов по одному сквозь весь пайплайн («фильтр $\rightarrow$ маппинг $\rightarrow$ сборка»), в отличие от создания промежуточных списков на каждом шаге.
- **Может ли стрим выполниться без терминальной операции?** — Нет, ни один элемент не будет обработан.

**Красные флаги (НЕ говорить):**
- ❌ «Промежуточная операция `map()` сразу применяет трансформацию ко всем элементам массива».
- ❌ «Стрим начинает обрабатывать данные в фоновом потоке сразу после вызова `.stream()`».
- ❌ «Ленивые вычисления в стримах создают много промежуточных коллекций в куче (Heap)».
