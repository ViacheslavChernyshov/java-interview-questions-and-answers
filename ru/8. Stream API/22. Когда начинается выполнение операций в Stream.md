# Когда начинается выполнение операций в Stream?

---

## 🟢 Junior Level

### Простой ответ

Выполнение операций в Stream начинается **строго в момент вызова терминальной (terminal) операции**.

До тех пор, пока вы не вызвали терминальную операцию, вы лишь описываете **рецепт (конвейер)** будущих вычислений. Сами данные **не читаются, не фильтруются и не трансформируются**:

```java
List<String> names = List.of("Ivan", "Petr", "Anna");

// 1. Промежуточные операции — ЗДЕСЬ НИЧЕГО НЕ ВЫПОЛНЯЕТСЯ:
Stream<String> stream = names.stream()
    .filter(name -> {
        System.out.println("Фильтрация: " + name);
        return name.length() > 3;
    })
    .map(String::toUpperCase);

System.out.println("--- Стрим объявлен, но ещё не запущен ---");

// 2. Терминальная операция — ТОЛЬКО СЕЙЧАС начинается реальная работа:
List<String> result = stream.toList();
```

**Вывод в консоль:**
```
--- Стрим объявлен, но ещё не запущен ---
Фильтрация: Ivan
Фильтрация: Petr
Фильтрация: Anna
```

### Аналогия из жизни

Представьте **чертёж конвейерной ленты на заводе**:
- Вы чертите схему: «поставить пресс, затем покрасочный цех, затем упаковку» (промежуточные операции `filter`, `map`). Пока чертеж лежит на столе, ни одна деталь не создана.
- Вы нажимаете красную кнопку «ПУСК» (терминальная операция `collect`, `toList`, `forEach`) — и только в этот момент включаются моторы и по ленте начинают двигаться детали.

## 🟡 Middle Level

### Классификация операций: Промежуточные vs Терминальные

| Категория | Операции | Возвращаемый тип | Запускает выполнение? |
| :--- | :--- | :--- | :--- |
| **Intermediate (Ленивые)** | `filter()`, `map()`, `flatMap()`, `distinct()`, `sorted()`, `peek()`, `limit()`, `skip()` | `Stream<T>` | ❌ **Нет** (только строит пайплайн) |
| **Terminal (Триггеры)** | `collect()`, `toList()`, `forEach()`, `reduce()`, `count()`, `findFirst()`, `anyMatch()`, `min()`, `max()`, `toArray()` | Значение (`List`, `Optional`, `long`, `boolean`, `void`) | ✅ **Да** (запускает весь конвейер) |

### Механика Pipeline Fusion (Слияние конвейера)

В отличие от классической итерации, где каждый шаг создавал бы промежуточную временную коллекцию, Stream API объединяет все промежуточные шаги в **один проход по каждому элементу**:

```
Элемент 1 ──► [Filter] ──► [Map] ──► [Collect]
Элемент 2 ──► [Filter (rejected)]
Элемент 3 ──► [Filter] ──► [Map] ──► [Collect]
```

### Внутренний метод `AbstractPipeline.evaluate()`

В момент вызова любой терминальной операции:
1. Вызывается внутренний метод `evaluate()` в `AbstractPipeline`.
2. Проверяется флаг `linkedOrConsumed`: если стрим уже выполнялся, выбрасывается `IllegalStateException` (стримы одноразовые).
3. Все промежуточные операции компилируются в цепочку связанных объектов `Sink`.
4. `Spliterator` начинает протягивать элементы через цепочку `Sink.accept(element)`.

## 🔴 Senior Level

### Байт-код: `invokedynamic` и `LambdaMetafactory`

Senior разработчик понимает, как JVM инициализирует стримы:
1. Объявление лямбда-выражения внутри `filter(x -> x > 10)` компилируется в байт-код инструкцию **`invokedynamic` (indy)**.
2. При первом проходе JVM через `LambdaMetafactory` динамически генерирует анонимный класс (CallSite), реализующий функциональный интерфейс `Predicate`.
3. Реальное тело лямбды оформляется как приватный статический метод текущего класса (например, `lambda$main$0`).
4. Вызов тела метода происходит только тогда, когда `Sink` терминальной операции запрашивает элемент.

### Стек-трейсы ошибок (Anatomy of Stream Exceptions)

Если внутри промежуточной лямбды возникает ошибка (например, `NullPointerException`), точка выброса в стек-трейсе указывает на **терминальную операцию**:

```
Exception in thread "main" java.lang.NullPointerException
    at com.example.App.lambda$process$1(App.java:24)  <-- Ошибка внутри map()
    at java.base/java.util.stream.ReferencePipeline$3$1.accept(...)
    at java.base/java.util.Spliterators$ArraySpliterator.forEachRemaining(...)
    at java.base/java.util.stream.AbstractPipeline.evaluate(...)
    at java.base/java.util.stream.ReferencePipeline.collect(ReferencePipeline.java:682) <-- Точка запуска!
    at com.example.App.process(App.java:28)
```
*Терминальная операция всегда является точкой сборки и инициации всего вычисления.*

### Оптимизации JIT C2-компилятора

- При выполнении достаточно объемного стрима JIT-компилятор инлайнит цепочку вызовов `Sink.accept()` в один высокоэффективный плоский машинный цикл.
- Накладные расходы на вызовы интерфейсов сводятся к нулю (Escape Analysis позволяет элиминировать промежуточные объекты аллокаций).

## 🎯 Шпаргалка для интервью

**Обязательно знать:**
- Выполнение стрима начинается **исключительно в момент вызова терминальной операции**.
- Промежуточные операции (`map`, `filter`, `peek`) ленивы (Lazy) и лишь конфигурируют цепочку вызовов.
- Pipeline Fusion: стрим обрабатывает элементы по одному сквозь весь конвейер, не создавая промежуточных коллекций.
- Вызов терминальной операции переводит флаг `linkedOrConsumed` в `true`, делая повторный запуск невозможным (`IllegalStateException`).
- Стек-трейс исключения всегда ведет к строке вызова терминальной операции.

**Частые уточняющие вопросы:**
- **Что произойдёт, если не вызвать терминальную операцию?** — Код промежуточных операций никогда не будет выполнен.
- **Как отличить промежуточную операцию от терминальной?** — Промежуточные операции всегда возвращают `Stream<T>` (или примитивные `IntStream`), терминальные возвращают не-Stream тип (`void`, `List`, `Optional`, примитив).
- **Выполняются ли промежуточные операции для всех элементов сразу?** — Нет, элементы проходят конвейер поочередно («вертикально», а не «горизонтально»).

**Красные флаги (НЕ говорить):**
- ❌ «Операция `filter()` сразу отбирает элементы и сохраняет их во внутренний массив стрима».
- ❌ «Стрим начинает выполняться в момент вызова `.stream()`».
- ❌ «Терминальную операцию можно вызывать несколько раз на одном объекте».
