# В чём разница между intermediate и terminal операциями?

---

## 🟢 Junior Level

### Главное отличие

В Stream API все методы строго разделены на две категории: **промежуточные (intermediate)** и **терминальные (terminal)**:

| Характеристика | Intermediate (Промежуточные) | Terminal (Терминальные) |
| :--- | :--- | :--- |
| **Возвращаемое значение** | Всегда `Stream<T>` (или `IntStream` и т.д.) | Значение не-Stream (`List`, `long`, `Optional`, `void`) |
| **Поведение** | **Ленивые (Lazy)** — ничего не вычисляют сразу | **Жадные (Eager)** — немедленно запускают обработку |
| **Количество в цепочке** | Любое количество ($0, 1, 2 \dots N$) | **Ровно одна** в самом конце цепочки |
| **Повторное использование** | Формируют описание пайплайна | Потребляют (сжигают) стрим навсегда |
| **Примеры** | `filter()`, `map()`, `sorted()`, `distinct()`, `limit()` | `collect()`, `toList()`, `forEach()`, `count()`, `reduce()` |

### Аналогия из жизни

Представьте **заказ индивидуальной пиццы на сайте**:
- **Промежуточные шаги (Intermediate)**: Вы отмечаете в конструкторе: «добавить сыр», «убрать лук», «порезать на 8 частей». Пока вы просто кликаете галочки, на кухне ресторана никто ничего не готовит.
- **Терминальный шаг (Terminal)**: Вы нажимаете кнопку «Оформить и оплатить заказ». Только в этот момент повар на кухне достаёт тесто и начинает готовить пиццу по составленному вами рецепту.

```java
List<String> names = List.of("anna", "john", "alex");

// 1. Промежуточные операции — конвейер только описан:
Stream<String> stream = names.stream()
    .filter(name -> name.startsWith("a"))
    .map(String::toUpperCase);

// 2. Терминальная операция — ТОЛЬКО ЗДЕСЬ начинается обработка:
List<String> result = stream.toList(); // ["ANNA", "ALEX"]
```

## 🟡 Middle Level

### Внутренняя классификация операций

```
                                  ┌─── Stateless (map, filter, flatMap, peek)
            ┌─── Intermediate ────┤
            │                     └─── Stateful (sorted, distinct, limit, skip)
Stream API ─┤
            │                     ┌─── Eager (collect, forEach, toArray, reduce, count)
            └─── Terminal ────────┤
                                  └─── Short-circuit (findFirst, findAny, anyMatch, allMatch)
```

#### 1. Intermediate: Stateless vs Stateful
- **Stateless**: обрабатывают каждый элемент независимо за один проход на лету (идеально для многопоточности).
- **Stateful**: требуют знания обо всех или нескольких элементах (например, `sorted()` — барьер, требующий накопления всех элементов в памяти $O(N)$).

#### 2. Terminal: Eager vs Short-circuit
- **Eager (Полные)**: обрабатывают абсолютно все элементы стрима до конца (`collect`, `count`, `reduce`).
- **Short-circuit (Короткое замыкание)**: могут завершить вычисления досрочно, не дожидаясь обхода всех элементов (`findFirst()`, `anyMatch()`).

## 🔴 Senior Level

### Архитектура под капотом: `AbstractPipeline` и цепочка `Sink`

При объявлении промежуточных операций JVM строит односвязный список объектов `ReferencePipeline`:

```
[Head: Source] ──► [Stage 1: filter] ──► [Stage 2: map] ──► [Terminal: collect]
```

Когда вызывается терминальная операция:
1. Метод `evaluate()` класса `AbstractPipeline` проходит по списку стадий с конца в начало и конструирует цепочку связанных обработчиков **`Sink`**:
   ```
   Sink.filter.accept(item) ──► Sink.map.accept(transformed) ──► Sink.collect.accept(result)
   ```
2. **Pipeline Fusion**: Данные не создают промежуточных буферов в куче (Heap). Каждый элемент «прокачивается» вертикально через всю цепочку вызовов `Sink.accept()` за один проход.
3. JIT C2-компилятор инлайнит эту цепочку `Sink`, превращая стрим в монолитный плоский машинный цикл.

### Ловушка ленивости: Транзакционные границы и I/O

```java
// ❌ АНТИПАТТЕРН: Стрим объявлен внутри @Transactional метода, а собран снаружи!
@Transactional
public Stream<User> getActiveUsersStream() {
    return userRepository.findAllAsStream().filter(User::isActive);
}

// В контроллере:
Stream<User> stream = service.getActiveUsersStream();
// 💥 LazyInitializationException / Closed DB Connection:
// Терминальная операция вызвана ПОСЛЕ закрытия транзакции и соединения с БД!
List<User> list = stream.toList();
```

## 🎯 Шпаргалка для интервью

**Обязательно знать:**
- Intermediate операции всегда возвращают `Stream` и ленивы; Terminal операции возвращают не-Stream и запускают вычисления.
- В стриме может быть сколько угодно intermediate операций, но **ровно одна terminal операция**.
- После вызова terminal операции стрим становится «закрытым» (повторный вызов бросит `IllegalStateException`).
- Intermediate делятся на **Stateless** (`filter`, `map`) и **Stateful** (`sorted`, `distinct`).
- Terminal делятся на **Eager** (`collect`, `forEach`) и **Short-circuit** (`findFirst`, `anyMatch`).
- Pipeline Fusion объединяет промежуточные этапы в цепочку `Sink` без промежуточных коллекций.

**Частые уточняющие вопросы:**
- **Что произойдёт, если не вызвать terminal операцию?** — Ни одна строчка intermediate лямбд не будет исполнена.
- **Можно ли вызывать intermediate операции после terminal?** — Нет, стрим закрывается навсегда.
- **Почему sorted() называют барьером конвейера?** — Это stateful операция, которая не может передать данные downstream, пока не получит все элементы источника.

**Красные флаги (НЕ говорить):**
- ❌ «Intermediate операция сохраняет промежуточный результат в новый массив `ArrayList`».
- ❌ «`forEach()` — это промежуточная операция, потому что она обходит элементы».
- ❌ «Один и тот же `Stream` можно повторно собрать в список через `stream.toList()`».
