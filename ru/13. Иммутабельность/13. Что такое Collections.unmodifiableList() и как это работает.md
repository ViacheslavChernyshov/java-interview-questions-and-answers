# Что такое Collections.unmodifiableList() и как это работает?

---

## 🟢 Junior Level

### Простое определение

**`Collections.unmodifiableList()`** — это метод стандартной библиотеки Java, который оборачивает существующий список в специальный **«вид только для чтения» (Read-Only View)**.

Любая попытка изменить коллекцию через эту обёртку (`add()`, `remove()`, `clear()`, `set()`) немедленно завершится ошибкой **`UnsupportedOperationException`**:

```java
List<String> original = new ArrayList<>();
original.add("Java");

List<String> unmodifiable = Collections.unmodifiableList(original);

System.out.println(unmodifiable.get(0)); // "Java" — чтение разрешено!

unmodifiable.add("Kotlin"); // 💥 ИСКЛЮЧЕНИЕ: java.lang.UnsupportedOperationException!
```

### Главная ловушка для начинающих: Это ОБЁРТКА, а НЕ копия!

Если кто-то изменит **оригинальный список `original`**, изменения **мгновенно отобразятся в `unmodifiable`**:

```java
original.add("Kotlin"); // Изменили исходный список
System.out.println(unmodifiable); // [Java, Kotlin] — данные изменились!
```

### Аналогия из жизни

Представьте **витрину в музее**:
- Вы смотрите на драгоценный экспонат через стекло (`unmodifiableList`). Вы не можете протянуть руку и забрать его.
- Однако экскурсовод с ключом с обратной стороны витрины (`original`) может в любой момент заменить или убрать экспонат.

## 🟡 Middle Level

### Паттерн Decorator под капотом

Внутри метод возвращает экземпляр приватного статического класса `java.util.Collections.UnmodifiableList`:

```java
static class UnmodifiableList<E> extends UnmodifiableCollection<E> implements List<E> {
    final List<? extends E> list; // Ссылка на оригинальный список

    UnmodifiableList(List<? extends E> list) {
        super(list);
        this.list = list;
    }

    public E get(int index) { return list.get(index); } // Делегирование чтения
    
    public E set(int index, E element) {
        throw new UnsupportedOperationException(); // Блокировка записи
    }
    public void add(int index, E element) {
        throw new UnsupportedOperationException();
    }
    public E remove(int index) {
        throw new UnsupportedOperationException();
    }
}
```
*Метод `iterator()` также возвращает обёрнутый итератор, чей метод `remove()` бросает исключение.*

### Сравнение: `unmodifiableList()` vs `List.copyOf()` vs `List.of()`

| Критерий | `Collections.unmodifiableList(orig)` | `List.copyOf(orig)` (Java 10+) | `List.of(e1, e2)` (Java 9+) |
| :--- | :--- | :--- | :--- |
| **Что это?** | **Немодифицируемая обёртка (View)** | **Истинная иммутабельная копия** | **Истинный иммутабельный список** |
| **Связь с оригиналом** | ⚠️ **Сохраняется** (оригинал может мутировать) | 🟢 **Разорвана** (полная изоляция) | Нет оригинала |
| **Сложность создания** | **$O(1)$** (просто оборачивает ссылку) | **$O(N)$** (копирует массив элементов) | **$O(1)$** |
| **Поддержка `null`** | ✅ Разрешена (если оригинал поддерживает) | ❌ Запрещена (бросит `NullPointerException`) | ❌ Запрещена |
| **Потокобезопасность** | 🔴 **Нет** (гонки при мутации оригинала) | 🟢 **Да** | 🟢 **Да** |

## 🔴 Senior Level

### Многопоточные риски: Иллюзия потокобезопасности

Часто разработчики ошибочно полагают, что `Collections.unmodifiableList()` делает коллекцию безопасной для многопоточного чтения. **Это опасное заблуждение**:

```
Поток 1 (Reader):  Итерируется по unmodifiableList ──► next() ──► next()
                                                                    ▲
                                                                    │ (modCount++)
Поток 2 (Writer):  originalList.add("New Item") ────────────────────┘
```
- Изменение оригинального списка в фоновом потоке изменяет внутренний счетчик `modCount`.
- Читающий поток получает **`ConcurrentModificationException`** или видит «порванное» некорректное состояние элементов в памяти.

### Оптимизация `List.copyOf()` в Java 10+

Senior разработчик знает тонкость реализации `List.copyOf()`:
```java
List<String> immutable1 = List.of("A", "B");
List<String> immutable2 = List.copyOf(immutable1);

System.out.println(immutable1 == immutable2); // true! (Та же самая ссылка!)
```
Если в `List.copyOf()` передать коллекцию, которая уже создана через `List.of()` или `List.copyOf()`, JVM **не выполняет копирование массива** ($O(1)$), а просто возвращает ту же самую ссылку, экономя память и CPU.

## 🎯 Шпаргалка для интервью

**Обязательно знать:**
- `Collections.unmodifiableList()` — это немодифицируемая обёртка (View) над существующим списком, а не новая копия.
- Любые методы записи бросают `UnsupportedOperationException`.
- Если оригинальный список изменится, изменения будут видны через `unmodifiableList`.
- `unmodifiableList()` **НЕ является потокобезопасным**: если другой поток меняет оригинал, итератор упадет с `ConcurrentModificationException`.
- В современном Java (10+) для гарантированной защиты используется **`List.copyOf()`** (создает независимый иммутабельный снимок).

**Частые уточняющие вопросы:**
- **В чём разница между `Collections.unmodifiableList()` и `List.copyOf()`?** — `unmodifiableList` создает обертку за $O(1)$, но сохраняет связь с мутабельным оригиналом; `List.copyOf` создает полностью изолированный иммутабельный список за $O(N)$ и запрещает `null`.
- **Можно ли в unmodifiableList передать список с null-элементами?** — Да, если оригинальный `ArrayList` содержал `null`, обёртка сохранит его; `List.copyOf()` при наличии `null` выбросит `NullPointerException`.
- **Является ли UnmodifiableList потокобезопасным?** — Нет, потокобезопасность обеспечивает `Collections.synchronizedList()` или `CopyOnWriteArrayList`.

**Красные флаги (НЕ говорить):**
- ❌ «`Collections.unmodifiableList()` копирует все элементы в новый неизменяемый массив».
- ❌ «Обернутый список можно безопасно отдавать в другие потоки, не опасаясь `ConcurrentModificationException`».
- ❌ «`Collections.unmodifiableList()` запрещает добавление элементов в оригинальный список».
