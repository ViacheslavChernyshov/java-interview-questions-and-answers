# Что такое persistent data structures?

---

## 🟢 Junior Level

### Важное терминологическое уточнение

> [!NOTE]
> В Computer Science термин **«Persistent Data Structure» (Персистентная структура данных)** **НЕ означает** запись данных на диск или сохранение в базу данных (это называется *Data Persistence / Хранение данных*).
>
> Персистентная структура данных — это неизменяемая (иммутабельная) структура в оперативной памяти, которая **всегда сохраняет свои предыдущие версии при любых модификациях**.

Когда вы «добавляете» или «удаляете» элемент, создаётся **новая версия** структуры, а старая версия остаётся полностью неизменной и доступной для чтения:

```java
// Пример с персистентным списком (библиотека Vavr):
io.vavr.collection.List<String> v1 = io.vavr.collection.List.of("A", "B");
io.vavr.collection.List<String> v2 = v1.prepend("Z");

System.out.println(v1); // List("A", "B")     <-- Старая версия не изменилась!
System.out.println(v2); // List("Z", "A", "B") <-- Новая версия
```

### Аналогия из жизни

Представьте **систему контроля версий Git**:
- Когда вы делаете новый коммит, Git не копирует заново весь ваш проект целиком (10 гигабайт файлов).
- Git сохраняет только измененные файлы и связывает их со старыми неизменными объектами. Все старые коммиты остаются доступными.

## 🟡 Middle Level

### Принцип разделения структуры (Structural Sharing)

Наивная иммутабельность (как в `List.copyOf()` из JDK) при добавлении одного элемента вынуждена копировать массив целиком за **$O(N)$** по времени и памяти.

Персистентные структуры данных решают эту проблему через **разделение структуры (Structural Sharing)**:

#### 1. Персистентный связный список (Singly Linked List):
```
Версия 1 (v1):                  [Node "A"] ──► [Node "B"] ──► [Node "C"] ──► null
                                     ▲
                                     │ (Разделяемый хвост)
Версия 2 (v2 = v1.prepend("Z")): [Node "Z"] ──┘
```
- Добавление в голову (`prepend`) занимает **$O(1)$** по времени и выделяет память ровно под **один новый узел `Node "Z"`**.
- Обе версии (`v1` и `v2`) разделяют общие узлы `A`, `B`, `C` в Heap без риска повреждения.

#### 2. Персистентные деревья (Path Copying):
При изменении элемента в дереве копируются **только узлы на пути от корня к целевому элементу** ($O(\log N)$ узлов), а все остальные поддеревья переиспользуются старой и новой версиями:

```
Старый корень (Root v1) ──► [Left Subtree (Общее)]   [Node B (Старый)]
                                                           ▲
                                                           │
Новый корень (Root v2)  ──► [Left Subtree (Общее)]   [Node B (Новый)] ──► [New Leaf]
```

### Разница с коллекциями JDK

| Коллекция | Является иммутабельной? | Является персистентной? | Стоимость добавления элемента |
| :--- | :---: | :---: | :--- |
| **`Collections.unmodifiableList(list)`** | ❌ (Обертка над мутабельным) | ❌ Нет | Бросает `UnsupportedOperationException` |
| **`List.of("A", "B")` (JDK 9+)** | ✅ Да (Unmodifiable) | ❌ **Нет** (нет structural sharing) | Нельзя добавить, создание нового списка = $O(N)$ копирование |
| **`io.vavr.collection.List` (Vavr)** | ✅ Да | ✅ **Да** | **$O(1)$** через разделение хвоста |
| **`io.vavr.collection.HashMap` (Vavr)** | ✅ Да | ✅ **Да** | **$O(\log_{32} N) \approx O(1)$** через HAMT |

## 🔴 Senior Level

### HAMT (Hash Array Mapped Trie) — Основа персистентных Map и Set

Самая мощная персистентная структура данных, используемая в Clojure, Scala и Vavr — это **HAMT (Hash Array Mapped Trie)**:
1. **32-ричное ветвление (32-way Branching)**:
   - 32-битный `hashCode()` ключа разбивается на фрагменты по 5 бит ($2^5 = 32$).
   - Каждый уровень дерева анализирует свои 5 бит хеша.
   - Максимальная глубина дерева для $4$ миллиардов элементов составляет всего $\lceil 32 / 5 \rceil = 7$ уровней!
2. **Битовая компрессия (Bitmap Indexing & Popcount)**:
   - Чтобы массив дочерних ссылок узла не занимал 32 ячейки в памяти, узел хранит 32-битное число-маску (`bitmap`) и компактный массив только реально существующих детей.
   - Позиция ребенка вычисляется за 1 такт CPU через аппаратную процессорную инструкцию **`POPCNT`** (подсчет установленных бит в маске):
     ```java
     int index = Integer.bitCount(bitmap & ((1 << bitPos) - 1));
     ```
3. **Производительность**:
   - Чтение и запись занимают $O(\log_{32} N) \le 7$ переходов по ссылкам, что на практике неотличимо от $O(1)$ в `HashMap`, но при этом гарантирует полную потокобезопасность и хранение истории версий.

### Сравнение сложности операций

| Структура | Поиск `get()` | Добавление / Замена `put()` | Создание копии / Снимка |
| :--- | :--- | :--- | :--- |
| **Java `HashMap`** | $O(1)$ | $O(1)$ | $O(N)$ (тяжелое копирование бакетов) |
| **Java `TreeMap`** | $O(\log_2 N)$ | $O(\log_2 N)$ | $O(N)$ |
| **HAMT (`Vavr HashMap`)** | $O(\log_{32} N) \approx O(1)$ | $O(\log_{32} N) \approx O(1)$ | **$O(1)$** (просто скопировать ссылку на Root!) |

### Применение в реальных архитектурах

1. **Lock-Free State Management (Атомарные снимки)**:
   - Состояние системы хранится в `AtomicReference<PersistentMap<K, V>>`.
   - Чтение происходит абсолютно без блокировок.
   - Запись выполняется через безопасный CAS-цикл:
     ```java
     AtomicReference<io.vavr.collection.Map<String, User>> state = new AtomicReference<>(HashMap.empty());
     state.updateAndGet(map -> map.put("user_1", newUser)); // Мгновенный Lock-Free апдейт
     ```
2. **Event Sourcing & Undo/Redo**: история версий сохраняется бесплатно, так как старые корни дерева не удаляются, пока на них есть ссылки.
3. **Автоматическая очистка старых версий Garbage Collector**: когда ветка устаревает и на неё больше нет ссылок, GC утилизирует только уникальные для этой версии узлы, оставляя разделяемые узлы в живых.

## 🎯 Шпаргалка для интервью

**Обязательно знать:**
- Персистентная структура данных (в CS) — это иммутабельная структура в памяти, которая сохраняет все свои прошлые версии при модификациях.
- Основной принцип — **Structural Sharing (разделение структуры)**: новая версия разделяет неизмененные узлы со старой версией, а не копирует всю коллекцию.
- В стандартной Java (JDK) персистентных структур нет (коллекции `List.of` иммутабельны, но не имеют structural sharing).
- Популярные библиотеки для Java: **Vavr**, **PCollections**.
- **HAMT (Hash Array Mapped Trie)** — ключевая структура для быстрых персистентных Map/Set ($O(\log_{32} N)$ благодаря 5-битным чанкам хеша и инструкции `POPCNT`).
- Идеально для: Lock-Free стейта через `AtomicReference`, Undo/Redo, Event Sourcing и функционального программирования.

**Частые уточняющие вопросы:**
- **Означает ли persistent структуру сохранение на жесткий диск?** — Нет, это термин Computer Science о сохранении предыдущих версий графа объектов в памяти.
- **Является ли `Collections.unmodifiableList()` персистентным?** — Нет, это лишь немодифицируемая обёртка над мутабельным списком.
- **Что такое Structural Sharing?** — Переиспользование неизмененных узлов дерева или списка между несколькими версиями структуры данных.
- **Как работает добавление в персистентный связный список?** — Новый элемент становится головой ($O(1)$), ссылаясь на старый список как на свой хвост.

**Красные флаги (НЕ говорить):**
- ❌ «Персистентные структуры данных — это таблицы в базе данных Hibernate/JPA».
- ❌ «Персистентная структура при каждом изменении выполняет полное глубокое копирование (Deep Copy) за $O(N)$».
- ❌ «`List.of()` в Java 17 — это персистентная структура данных».
