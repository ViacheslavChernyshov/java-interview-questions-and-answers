# Что делает метод orTimeout() в Java 9+?

---

## 🟢 Junior Level

### Простое определение

**`orTimeout(long timeout, TimeUnit unit)`** — это метод, добавленный в Java 9, который позволяет установить асинхронный таймаут на выполнение `CompletableFuture`.

Если цепочка асинхронных вычислений не успевает завершиться за указанное время, `CompletableFuture` **исключительно завершается с ошибкой `TimeoutException`** (обёрнутой в `ExecutionException` или `CompletionException`).

### Аналогия из жизни

Представьте **заказ такси в мобильном приложении**:
- Вы нажимаете «Вызвать такси» (асинхронная задача).
- Приложение запускает таймер на 3 минуты (`orTimeout(3, TimeUnit.MINUTES)`).
- Если за 3 минуты машина не найдена, поиск прекращается и на экране появляется уведомление «Время ожидания истекло» (`TimeoutException`), предлагающее вызвать повышенный класс такси.

### Базовый пример использования

```java
CompletableFuture<String> future = CompletableFuture.supplyAsync(() -> {
    // Долгая операция (например, запрос к стороннему шлюзу)
    sleep(10_000); // 10 секунд
    return "Payment Success";
});

// Устанавливаем лимит ожидания в 2 секунды
future.orTimeout(2, TimeUnit.SECONDS)
    .thenAccept(result -> System.out.println("Результат: " + result))
    .exceptionally(ex -> {
        // ex.getCause() вернёт java.util.concurrent.TimeoutException
        System.err.println("Операция прервана по таймауту: " + ex.getMessage());
        return null;
    });
```

## 🟡 Middle Level

### orTimeout() vs completeOnTimeout()

В Java 9 также появился родственный метод **`completeOnTimeout()`**, возвращающий значение по умолчанию вместо исключения:

| Характеристика | `orTimeout(timeout, unit)` | `completeOnTimeout(value, timeout, unit)` |
| :--- | :--- | :--- |
| **Результат при таймауте** | Завершается с ошибкой `TimeoutException` | Завершается успешно со значением `fallbackValue` |
| **Когда использовать** | Ошибка критична, требуется явная обработка сбоя | Допустимо деградировать функционал (fallback кэш) |
| **Обработка** | Перехватывается в `.exceptionally()` / `.handle()` | Идёт дальше по цепочке в `.thenApply()` / `.thenAccept()` |

```java
// Пример с fallback-значением при превышении таймаута:
CompletableFuture<UserProfile> profileFuture = fetchUserProfileAsync(userId)
    .completeOnTimeout(UserProfile.GUEST_PROFILE, 500, TimeUnit.MILLISECONDS);
```

### Важнейший нюанс: `orTimeout()` мутирует исходный Future (`return this`)

В отличие от большинства методов `CompletableFuture` (`thenApply`, `thenCompose`), которые порождают новый зависимый объект Future:
- `orTimeout()` регистрирует таймер на **текущем экземпляре** и возвращает `this`.
- Если на один и тот же `CompletableFuture` навесить несколько `orTimeout()`, сработает самый короткий таймаут.

### Как реализовывали таймауты в Java 8

До появления Java 9 таймаут приходилось эмулировать вручную через фоновый шедулер:

```java
// Решение в стиле Java 8:
public static <T> CompletableFuture<T> timeoutAfter(long timeout, TimeUnit unit) {
    CompletableFuture<T> promise = new CompletableFuture<>();
    scheduler.schedule(() -> promise.completeExceptionally(new TimeoutException()), timeout, unit);
    return promise;
}

CompletableFuture<String> result = targetFuture.applyToEither(timeoutAfter(2, TimeUnit.SECONDS), Function.identity());
```

## 🔴 Senior Level

### Внутреннее устройство: `CompletableFuture$Delayer`

Под капотом `orTimeout()` использует внутренний статический класс `Delayer`:
1. Внутри JVM инициализируется единственный фоновый поток `ScheduledThreadPoolExecutor` (с флагом `daemon = true`).
2. При вызове `orTimeout()` в очередь шедулера помещается задача:
   ```java
   Delayer.delay(new Timeout(this), timeout, unit);
   ```
3. **Отмена таймера при успешном завершении**: Если оригинальный `CompletableFuture` завершается штатно раньше таймаута, шедулер отменяет задачу таймера через `whenComplete((v, e) -> timeoutTask.cancel(true))`, предотвращая утечки памяти.

### Главная иллюзия таймаута: фоновая задача НЕ останавливается!

> [!WARNING]
> Вызов `orTimeout()` **НЕ прерывает** поток, выполняющий тело задачи внутри `ExecutorService`!

```
[Поток пула]:   ══════════════════════════════════ (Продолжает вычисления)
[Delayer]:      ───(2 сек)──► Завершает Future ошибкой
[Клиент]:                     ◄── Получает TimeoutException
```

Если в `supplyAsync()` запущен тяжелый расчет на 10 минут, через 2 секунды клиент получит `TimeoutException`, но рабочий поток пула **продолжит утилизировать 100% CPU все 10 минут**, если в коде нет явной проверки прерывания:

```java
// ✅ ПРАВИЛЬНО для долгих задач:
CompletableFuture.supplyAsync(() -> {
    while (hasMoreWork()) {
        if (Thread.currentThread().isInterrupted()) {
            throw new CancellationException("Aborted by timeout");
        }
        doChunk();
    }
    return result;
});
```

### Архитектурные паттерны: TimeLimiter & Resilience4j

В высоконагруженных распределенных системах:
1. **Каскадные таймауты (Deadline Propagation)**: Таймаут на шлюзе (API Gateway) должен быть больше таймаутов внутренних сервисов ($T_{gateway} > T_{order} > T_{payment}$), иначе шлюз оборвет соединение, а downstream-сервисы продолжат бесполезную работу.
2. **Интеграция с Circuit Breaker**: Частые `TimeoutException` от `orTimeout()` должны регистрироваться в Circuit Breaker (Resilience4j) для перевода сервиса в состояние `OPEN`.

## 🎯 Шпаргалка для интервью

**Обязательно знать:**
- `orTimeout(timeout, unit)` (Java 9+) завершает `CompletableFuture` ошибкой `TimeoutException`, если задача не успела за отведённое время.
- `completeOnTimeout(fallback, timeout, unit)` возвращает дефолтное значение вместо исключения.
- Таймаут **НЕ останавливает** выполнение фонового потока автоматически — поток продолжает работу, если нет проверки `isInterrupted()`.
- Реализован через внутренний демон-шедулер `CompletableFuture.Delayer` (единственный `ScheduledThreadPoolExecutor`).
- При успешном завершении задачи таймер автоматически отменяется, исключая утечки памяти.
- Ошибка `TimeoutException` заворачивается в `CompletionException` при обработке в цепочке.

**Частые уточняющие вопросы:**
- **Что произойдёт с потоком в пуле при срабатывании orTimeout?** — Future завершается с ошибкой, но фоновый поток продолжает выполнение до конца.
- **В чём разница между orTimeout() и completeOnTimeout()?** — orTimeout бросает TimeoutException, completeOnTimeout подставляет fallback-результат без перехода в исключительный сценарий.
- **Мутирует ли orTimeout исходный CompletableFuture?** — Да, в отличие от `thenApply()`, он регистрирует таймер на текущем объекте и возвращает `this`.
- **Как реализовать таймаут в Java 8?** — Через `ScheduledExecutorService` и комбинацию `applyToEither()` / `acceptEither()`.
