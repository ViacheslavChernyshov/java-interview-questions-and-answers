# Чи можна використовувати кілька обмежень (bounds) для одного параметра типу?

---

## 🟢 Junior Level

### Проста відповідь

**Так, можна.** У Java параметр типу може мати кілька обмежень (Multiple Bounds), які перераховуються через символ амперсанда **`&`**.

### Синтаксис і базовий приклад

```java
// T зобов'язаний бути підкласом Number І реалізовувати Comparable<T>
public class SortedNumberBox<T extends Number & Comparable<T>> {
    private T value;

    public SortedNumberBox(T value) {
        this.value = value;
    }

    public boolean isGreaterThan(T other) {
        // Ми можемо викликати методи Number (doubleValue) та Comparable (compareTo)!
        return value.compareTo(other) > 0;
    }
}
```

### Головне правило порядку

- Якщо серед обмежень є **клас**, він зобов'язаний стояти **першим** у списку.
- Усі інші обмеження можуть бути тільки **інтерфейсами**.

```java
// ✅ Правильно: клас на першому місці, потім інтерфейс
<T extends Number & Runnable>

// ❌ Помилка компіляції: інтерфейс перед класом!
<T extends Runnable & Number>
```

## 🟡 Middle Level

### Правила та обмеження Multiple Bounds

1. **Максимум один клас**: У Java заборонено множинне наслідування класів, тому в списку обмежень допускається тільки один клас і будь-яка кількість інтерфейсів.
2. **Порядок слідування (Class First)**: Клас завжди має йти першим, інакше компілятор видасть помилку `interface expected here`.
3. **Механізм стирання (Erasure to First Bound)**:
   - При компіляції параметр `T` стирається до свого **першого обмеження**.
   - Для `<T extends Number & Serializable>` типом у байт-коді буде `Number`.
   - Для виклику методів `Serializable` компілятор автоматично вставляє байт-код інструкцію `checkcast`.

---

### Практичне застосування в архітектурі

Множинні обмеження дозволяють виразити суворі вимоги до типу без створення штучних інтерфейсів-пустушок:

```java
// Метод вимагає, щоб сервіс умів закриватися (AutoCloseable) та клонуватися (Cloneable)
public static <T extends AutoCloseable & Cloneable> void processResource(T resource) {
    try (resource) {
        // Доступні методи close() та clone()
    } catch (Exception e) {
        throw new RuntimeException(e);
    }
}
```

## 🔴 Senior Level

### Вплив на генерацію байт-коду та JIT-компіляцію

```java
public class BoundExample {
    public static <T extends CharSequence & Comparable<T>> void check(T item) {
        int len = item.length();          // Виклик invokevirtual / invokeinterface CharSequence
        int cmp = item.compareTo(item);   // Вставка checkcast java/lang/Comparable перед викликом!
    }
}
```

1. **`checkcast` Overhead**: Оскільки в сигнатурі байт-коду метод приймає `CharSequence`, будь-яке звернення до методів другого обмеження (`Comparable`) вимагає інструкції `checkcast`. У критичних циклах високопродуктивних систем (Low Latency) це слід враховувати.
2. **Intersection Types у лямбдах (Java 8+)**:
   Синтаксис multiple bounds можна використовувати для касту лямбда-виразів:
   ```java
   // Створюємо серіалізований Runnable на льоту:
   Runnable r = (Runnable & Serializable) () -> System.out.println("Hello");
   ```

## 🎯 Шпаргалка для інтерв'ю

**Обов'язково знати:**
- Кілька обмежень (Multiple Bounds) записуються через амперсанд `&` (наприклад, `<T extends Number & Comparable<T>>`).
- **Клас завжди повинен стояти першим**, за ним — довільна кількість інтерфейсів.
- Дозволено тільки **один клас** (через заборону множинного наслідування в Java).
- Параметр `T` стирається до **першого обмеження** (First Bound); для доступу до методів наступних обмежень компілятор додає `checkcast`.
- Intersection Types підтримуються для приведення лямбда-виразів `(Runnable & Serializable)`.

**Часті уточнюючі запитання:**
- **Чому `<T extends Runnable & Number>` не компілюється?** — Клас зобов'язаний стояти на першому місці в списку обмежень.
- **До якого типу стирається `<T extends Number & Comparable<T>>` у байт-коді?** — До `Number` (першого зазначеного обмеження).
- **Чи можна вказати два класи у bounds?** — Ні, множинне наслідування класів у Java заборонено.

**Червоні прапорці (НЕ говорити):**
- ❌ *«У Java не можна вказувати більше одного інтерфейсу для параметра типу»*.
- ❌ *«Порядок класів та інтерфейсів у списку обмежень не має значення»*.
