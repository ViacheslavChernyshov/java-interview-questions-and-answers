## 🎯 Общая стратегия и Критерии качества (Definition of Done)

При проверке каждого MD-файла и темы мы руководствуемся следующими правилами:

1. **Трехуровневая структура ответа:**
   - 🟢 **Junior Level:** четкое определение, концептуальное объяснение, простые жизненные аналогии и базовые примеры кода.
   - 🟡 **Middle Level:** внутреннее устройство (under the hood), нюансы работы, частые ошибки, trade-offs, практическое применение.
   - 🔴 **Senior Level:** глубокие архитектурные детали, подкапотные механики (JVM, ОС, алгоритмы), оптимизации, бенчмарки, форк-джойны, локи, распределенные сценарии, краевые случаи.
2. **Точность и актуальность кода:**
   - Использование современных версий Java (Java 17, Java 21+), Spring Boot 3+, Hibernate 6+, PostgreSQL 15+.
   - Проверка примеров кода на синтаксическую корректность и отсутствие устаревших API (deprecated).
3. **Единообразие форматирования и терминалогии:**
   - Соблюдение единого стиля оформления Markdown (заголовки, бейджи 🟢🟡🔴, подсветка синтаксиса).
   - Корректная терминология на русском языке с сохранением общепринятых англоязычных терминов в скобках (например, *последовательное сканирование (Seq Scan)*).
4. **Связи и навигация:**
   - Проверка рабочих ссылок в `00. Навигатор по разделу.md` и в `ru/README.md`.
   - Проверка ссылок для публикации на GitHub Pages (`ru/questions/`).
